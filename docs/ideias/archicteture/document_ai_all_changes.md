
# DOCUMENT AI – CONSOLIDATED PIPELINE & FRONTEND CHANGES
Version: Final Consolidation of Recent Improvements

This document consolidates **all new changes discussed recently** related to the
Document AI system. The base architecture remains unchanged; the following
sections describe **enhancements added to the pipeline and the frontend editor**
to improve fidelity when converting:

PDF → HTML + CSS + Knockout Template

These improvements target enterprise document layouts such as those generated by
PlanetPress.

---------------------------------------------------------------------
SYSTEM OBJECTIVE
---------------------------------------------------------------------

Automatically convert static PDFs into reusable HTML templates capable of
rendering dynamic documents using structured data.

Key goals:

• preserve layout fidelity
• detect dynamic fields
• detect tables and sections
• support images and charts
• generate robust HTML layouts
• allow human-in-the-loop review

NEW PIPELINE COMPONENTS
---------------------------------------------------------------------

TEXT RECONSTRUCTION

PDF engines frequently fragment words or sentences into multiple text spans.
Example:

Cl
iente

or

Cliente
João

The reconstruction stage merges nearby spans using:

• Y coordinate proximity
• font similarity
• horizontal spacing

This improves detection for:

• anchors
• fields
• grid structures

---------------------------------------------------------------------
FONT EXTRACTION

Fonts are extracted from the PDF metadata.

Extracted attributes:

• font name
• font size
• font weight

Example span:

{
 "text":"Cliente",
 "font":"Helvetica-Bold",
 "size":12
}

These values are normalized into CSS styles:

font-family: Arial, sans-serif;
font-size: 12px;
font-weight: bold;

Purpose:

Preserve visual fidelity of the document.

---------------------------------------------------------------------
IMAGE EXTRACTION

Images such as logos, icons and seals are detected and exported.

Example layout element:

{
 "type":"image",
 "src":"logo.png",
 "width":120,
 "height":40
}

Images are stored under:

/assets/

HTML example:

<img src="/assets/logo.png">

---------------------------------------------------------------------
CHART DETECTION

Some enterprise documents include charts.

Supported chart types:

• bar chart
• line chart
• pie chart

The pipeline detects chart regions and converts them into Chart.js blocks.

Example:

{
 "type":"chart",
 "chartType":"bar",
 "width":300,
 "height":180
}

Generated HTML:

<canvas id="chart1"></canvas>

Charts are rendered using Chart.js during document generation.

---------------------------------------------------------------------
GRID DETECTION

PDF layouts rely on absolute coordinates.

Example:

Cliente     João
CPF         123
Data        01/01

Grid detection clusters X/Y coordinates to detect rows and columns.

Detected structure:

2 columns
3 rows

Generated CSS layout:

display:grid;
grid-template-columns:150px 1fr;

This replaces fragile absolute positioning.

---------------------------------------------------------------------
MULTI‑EXAMPLE DOCUMENT ANALYSIS

When multiple PDFs of the same template are uploaded (typically 3–5 examples),
the system compares them to detect:

• dynamic fields
• optional sections
• repeated table rows
• layout stability

Example:

If "Telefone" appears in some documents but not others,
the system generates a conditional block.

Example template:

<!-- ko if: telefone -->
<span data-bind="text: telefone"></span>
<!-- /ko -->

This produces far more robust templates.

---------------------------------------------------------------------
TEMPLATE CONFIDENCE SCORE

After template generation, the system calculates a confidence score.

Example:

Template Confidence: 92%

Factors contributing to the score:

• layout stability across examples
• anchor detection confidence
• grid detection quality
• field variability
• vision validation agreement

Confidence levels:

95–100%  → Auto‑approved
80–95%   → Review recommended
Below 80% → Human review required

FRONTEND EDITOR ENHANCEMENTS
---------------------------------------------------------------------

The template editor now supports additional element types.

Overlay elements include:

• text blocks
• image blocks

• tables
• sections

---------------------------------------------------------------------
IMAGE BLOCK SUPPORT

Detected images appear in the overlay.

Editor allows:

• confirm detection
• replace image asset
• remove image

UI component:

Asset Inspector

---------------------------------------------------------------------
CHART BLOCK SUPPORT

Charts appear as editable blocks.

UI component:

Chart Inspector

Configuration:

• chart type
• dataset binding
• label field
• width and height

Charts are previewed using Chart.js.

---------------------------------------------------------------------
GRID VISUALIZATION

The editor can display the detected grid structure.

Example overlay:

Detected Layout Grid
Columns: 2
Rows: 3

This helps the operator understand document layout.

---------------------------------------------------------------------
FONT PREVIEW

Extracted font information is visible in the editor.

Example:

Font: Helvetica
Size: 12
Weight: Bold

Operators can override styles when necessary.

---------------------------------------------------------------------
AUTO LAYOUT FIX (SPACING NORMALIZATION)

A new editor action allows automatic spacing correction.

Button:

Auto Fix Layout

The system adjusts:

• column alignment
• row spacing
• grid gaps
• font inconsistencies

This removes small layout imperfections.

---------------------------------------------------------------------
TEMPLATE COVERAGE MODE

Coverage Mode highlights which PDF elements are represented in the template.

Color scheme:

Green → mapped
Red → unmapped
Yellow → detected but not confirmed

Coverage score example:

Coverage: 93%

This helps operators quickly identify missing mappings.
