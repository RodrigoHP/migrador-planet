# Story 21.8 — Tag Taxonomy Controlada

## Story
**Como** investigador registrando tags em uma investigacao,
**Quero** um vocabulario controlado de tags com categorias e definicoes claras,
**Para** que pattern matching entre investigacoes futuras seja consistente e confiavel.

## Status
Done

## Context

### Problema
Cada RCA usa tags ad-hoc: o primeiro usa `type_error, guard, isinstance` (especifico) enquanto o segundo usa `type_error, data_contract, shared_context` (arquitetural). Sem vocabulario controlado, buscas por tag sao frageis — "guard_missing" vs "guard" vs "isinstance_guard" sao a mesma coisa mas nao fazem match.

### Design
Criar taxonomia em 4 categorias:
1. **error_type**: `type_error`, `attribute_error`, `import_error`, `runtime_error`, `logic_error`
2. **root_cause_category**: `guard_missing`, `data_contract`, `import_stale`, `race_condition`, `config_mismatch`
3. **affected_layer**: `backend_stage`, `backend_service`, `frontend_component`, `frontend_page`, `api`, `database`
4. **fix_type**: `guard_added`, `normalization`, `refactor`, `test_added`, `config_fix`

Tags existentes migradas para o vocabulario. Tags novas devem pertencer a uma categoria. Tags custom permitidas com prefixo `custom:`.

## Acceptance Criteria
- [ ] Taxonomia documentada em `docs/qa/rca-knowledge/tag-taxonomy.yaml` (ou section no investigate.md)
- [ ] 4 categorias definidas com tags iniciais e definicoes
- [ ] Tags existentes nas investigacoes migradas para vocabulario controlado
- [ ] Fase 8 do investigate.md referencia taxonomia ao registrar tags
- [ ] Tags custom permitidas com prefixo `custom:` para casos nao previstos
- [ ] Pattern Matcher (Fase 2) usa categorias para weighted matching (mesmo root_cause_category > mesmo error_type)

## Scope
**IN:** Taxonomia, Fase 8 do investigate.md, schema de investigations.yaml
**OUT:** Validacao automatica de tags (futuro)
