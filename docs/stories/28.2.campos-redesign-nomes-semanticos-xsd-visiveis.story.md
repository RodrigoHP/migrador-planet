# Story 28.2 — Campos: redesign problem-first + nomes semânticos + XSD obrigatórios

## Story
**Como** operador revisando cobertura de mapeamento,
**Quero** ver os campos agrupados por status (🔴🟥🟨🟩) com nomes semânticos e campos XSD obrigatórios sem match visíveis,
**Para** identificar rapidamente o que precisa ser corrigido sem decifrar textos raw do PDF.

## Status
Done

## Context

**Problemas atuais na aba Campos:**

1. **Agrupamento errado:** `FieldNavigator.vue` agrupa por TYPE (`TYPE_ORDER = ['string', 'array', 'chart', 'section', 'image']`). Para o operador, a tarefa é "encontrar o que está errado" — o agrupamento por tipo não serve esse propósito.

2. **Nomes sem semântica:** Os nomes exibidos são o raw PDF text: `4.978,54`, `000`, `30/03/2026`. O XSD path (`data.vencimento`) existe mas não é usado como nome principal.

3. **Campos XSD obrigatórios invisíveis:** `validation_result.unmapped_xsd_fields` é calculado no backend mas descartado em `session.ts`. O operador não sabe que há campos XSD obrigatórios que não têm match no PDF.

4. **Botão [Vincular →] ausente:** Campos com status `unmapped` (🟥) não têm ação direta — o operador precisa usar o Inspector (via 28.1) ou drag-and-drop (dead code).

**Referências de design:**
- Comportamento detalhado com wireframes: `frontend/docs/epic-28-campos-behavior-spec.md`
- Audit UX completo: `frontend/docs/epic-28-ux-audit.md`
- Arquitetura de informação: `frontend/docs/epic-28-information-architecture.md`
- Epic: `docs/epics/epic-28-field-mapping-redesign.md`

**Dependência:** Requer 28.1 completa (BindingEditor) para o botão [Vincular →] funcionar.

## Acceptance Criteria

- **AC1:** Campos XSD sem match aparecem na lista com badge 🔴 e label "XSD obrigatório" (surfaçar `unmapped_xsd_fields`)
- **AC2:** Campos com XSD path exibem nome semântico como título principal (ex: `data.vencimento` → "Vencimento"); raw PDF text como subtítulo/tooltip
- **AC3:** Agrupamento por STATUS (problema-primeiro): grupo 🔴 XSD obrigatórios, grupo 🟥 sem binding, grupo 🟨 ambíguos, grupo 🟩 mapeados
- **AC4:** Header da aba mostra contagem separada: `X PDF + Y XSD obrigatórios` (ex: "25 de 55 PDF + 8 XSD obrigatórios")
- **AC5:** Campos 🟥 (sem binding) mostram botão [Vincular →] inline que abre o BindingEditor (via Inspector ou dropdown inline)
- **AC6:** Grupos são colapsáveis; grupo 🟩 começa colapsado por padrão (não polui a visão com o que já está correto)
- **AC7:** Testes: `FieldNavigator.spec.ts` e `FieldNavItem.spec.ts` cobrem novo agrupamento + renderização semântica

## Dev Notes

### Mudança de paradigma: TYPE → STATUS grouping

**ANTES (lógica atual em `FieldNavigator.vue`):**
```typescript
const TYPE_ORDER = ['string', 'array', 'chart', 'section', 'image']

for (const type of TYPE_ORDER) {
  const items = fieldNavItems.filter(f => f.type === type)
  if (items.length) groups.push({ type, items })
}
```

**DEPOIS (problema-primeiro):**
```typescript
const STATUS_GROUPS = [
  { key: 'xsd-only',    label: 'XSD obrigatórios sem match', badge: '🔴', startOpen: true },
  { key: 'unmapped',    label: 'Sem binding',                badge: '🟥', startOpen: true },
  { key: 'unconfirmed', label: 'Ambíguos',                   badge: '🟨', startOpen: true },
  { key: 'mapped',      label: 'Mapeados',                   badge: '🟩', startOpen: false },
]
```

### Layout do `FieldNavItem` — 2 linhas

```
ANTES:  [🟩] 30/03/2026
DEPOIS: [🟩] Vencimento                          ← título semântico
              30/03/2026 · data.vencimento        ← subtítulo (pdf text · xsd path)
```

**Regra do nome semântico:**
1. Tem `xsd_field_path` → `path.split('.').pop()` → capitalizar primeira letra
   - `data.vencimento` → `Vencimento`
   - `boleto.pagador.nome` → `Nome`
2. Tem `label_text` (backend field) → usar `label_text` diretamente
3. Sem nenhum → usar `pdf_text.substring(0, 30)`

### Surfaçar `unmapped_xsd_fields`

**`pipeline.types.ts`** — adicionar à interface `ValidationResult`:
```typescript
interface ValidationResult {
  warnings: string[]
  errors: string[]
  type_format_mismatches: TypeMismatch[]
  unmapped_xsd_fields?: UnmappedXsdField[]  // ← NOVO
}

interface UnmappedXsdField {
  xsd_path: string       // ex: "data.vencimento"
  required: boolean
  reason: string         // ex: "No PDF text matched this XSD field"
}
```

**`session.ts`** — após processar resultado do pipeline:
```typescript
if (result.validation_result?.unmapped_xsd_fields) {
  mappingStore.setUnmappedXsdFields(result.validation_result.unmapped_xsd_fields)
}
```

**`mapping.ts`** — novo state + action:
```typescript
state: () => ({
  // ... existing
  xsdOnlyFields: [] as UnmappedXsdField[],
}),

actions: {
  setUnmappedXsdFields(fields: UnmappedXsdField[]) {
    this.xsdOnlyFields = fields
  }
}
```

### Componente `XsdOnlyField.vue`

Item especial para campos XSD sem match no PDF — visualmente diferente dos FieldNavItems normais:

```vue
<template>
  <div class="xsd-only-field">
    <span class="xsd-only-field__badge">🔴</span>
    <div class="xsd-only-field__content">
      <span class="xsd-only-field__name">{{ semanticName }}</span>
      <span class="xsd-only-field__path">{{ field.xsd_path }}</span>
    </div>
    <span class="xsd-only-field__label">XSD obrigatório</span>
  </div>
</template>
```

Não tem botão [Vincular →] — campos XSD sem match precisam que o template tenha um elemento text/field sem binding para vincular. A ação correta é via StructureTree ou importar novo campo.
