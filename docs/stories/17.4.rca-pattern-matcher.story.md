# Story 17.4 — Pattern Matcher Agent

## Story
**Como** investigador que encontra um bug,
**Quero** que o sistema automaticamente verifique se ja vimos um problema similar antes e sugira a solucao que funcionou,
**Para** que investigacoes recorrentes sejam resolvidas em minutos (nao horas) reutilizando conhecimento passado.

## Status
Ready

## Context

### Problema

Cada RCA comeca do zero. Mesmo que o mesmo tipo de bug tenha sido investigado 3 meses atras, o investigador nao sabe — o conhecimento esta enterrado em relatorios antigos. O `known-anti-patterns.md` ajuda, mas eh manual e busca apenas padroes de codigo, nao padroes de investigacao.

### Inspiracao

- **Flow-of-Action** (WWW 2025): 64% accuracy transformando investigacoes em SOPs executaveis (vs 35% ReAct)
- **Knowledge Graphs**: Correlacao de incidentes via grafos semanticos
- **Meta DrP**: Pattern matching de changes contra historico de incidentes

### Design Proposto

**Knowledge Base de Investigacoes:**

```yaml
# .aios/rca-knowledge/investigations.yaml (cresce com cada RCA)
investigations:
  - id: "rca-2026-03-29-pipeline-traversal"
    date: "2026-03-29"
    symptoms:
      - "TypeError em tree traversal"
      - "isinstance guard ausente"
    domain: complicated
    root_causes:
      - pattern: "missing_type_guard"
        location: "pipeline traversal functions"
    fix_approach: "isinstance guards em pontos de travessia"
    files_affected: ["stage3.py", "stage5.py"]
    tags: ["type_error", "guard", "traversal", "pipeline"]
    effectiveness: "resolved"  # resolved | partial | ineffective
```

**Pattern Matching Flow:**
```
Input: sintomas + classificacao do Classifier

1. SEARCH — buscar em knowledge base:
   - Semantic similarity de sintomas (LLM embedding)
   - Tag matching (type_error, guard, etc.)
   - File overlap (mesmos arquivos afetados)
   - Anti-pattern registry match

2. RANK — resultados por relevancia:
   - Sintomas similares (+3)
   - Mesmos arquivos (+2)
   - Mesmo dominio Cynefin (+1)
   - Fix anterior foi effective (+2)

3. SUGGEST — se match encontrado:
   - "Investigacao similar encontrada: rca-2026-03-29"
   - "Fix que funcionou: isinstance guards em traversal"
   - "Confianca: 85% (mesmos sintomas + mesmos arquivos)"
   - Sugerir SOP baseado na investigacao anterior

4. NO MATCH — se nenhum match:
   - "Problema novo — sem precedentes no knowledge base"
   - Continuar investigacao normal
```

**SOP Auto-Generation:**
Apos cada RCA completado com sucesso, gerar SOP automaticamente:

```yaml
# .aios/rca-knowledge/sops/sop-missing-type-guard.yaml
sop:
  id: "sop-missing-type-guard"
  trigger: "TypeError em funcao que processa dados heterogeneos"
  steps:
    1. Verificar stack trace para identificar funcao sem guard
    2. git blame para ver quem removeu/nunca adicionou guard
    3. grep codebase para funcoes similares sem guard
    4. Adicionar isinstance guard + teste
    5. Registrar anti-pattern
  estimated_time: "15 min"
  source_investigation: "rca-2026-03-29-pipeline-traversal"
```

## Complexity

## Scope

**IN:**
- Knowledge base em `.aios/rca-knowledge/` (investigations + SOPs)
- Search semantico por sintomas, tags, arquivos
- SOP auto-generation apos RCA
- Effectiveness tracking
- Integracao com anti-patterns registry

**OUT:**
- Nao implementar embeddings vetoriais (LLM prompt-based search suficiente)
- Nao implementar ML para pattern matching (heuristica + LLM)
- Nao compartilhar knowledge base entre projetos (futuro)

## Risks

- Knowledge base pode crescer indefinidamente sem cleanup, impactando performance do search. Mitigacao: limitar a 100 investigacoes retidas; mais antigas arquivadas.
- Search semantico via LLM pode retornar false positives (match em sintomas superficiais mas causa diferente). Mitigacao: ranking multi-fator (sintomas + arquivos + dominio), confianca exibida ao investigador.
- SOPs auto-gerados podem ser de baixa qualidade se o RCA original foi superficial. Mitigacao: effectiveness tracking — SOPs de fixes "partial" ou "ineffective" sao marcados e refinados.
