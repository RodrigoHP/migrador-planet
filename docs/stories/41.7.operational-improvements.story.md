## Dev Notes

### SYS-017 — Deep Health Check
- `/api/v1/health` now checks: Redis (ping), Supabase (list_buckets), Storage (list jobs bucket), spaCy (model load)
- All checks run concurrently via `asyncio.gather` with 2s timeout each via `asyncio.wait_for`
- Returns `{"status": "ok"|"degraded"|"error", "redis": {...}, "supabase": {...}, "storage": {...}, "spacy": {...}}`
- Primary services (Redis, Supabase, Storage): failure → `"error"` overall status
- Secondary service (spaCy): failure → `"degraded"` overall status (NER still works without full model)
- `not_configured` is neutral — services not configured don't count as failures

### SYS-018 — spaCy Model Validation
- Added `_EXPECTED_SPACY_MODEL = "pt_core_news_sm"` and `_EXPECTED_SPACY_VERSION = "3.8.0"` constants
- `_validate_spacy_model(nlp)`: logs warning if loaded model name/version differs from expected
- `validate_spacy_on_startup()`: called from FastAPI lifespan handler, logs warning if model unavailable
- Graceful: validation never raises — server starts regardless of spaCy state

### SYS-019 — API Versioning
- All routers now registered under `/api/v1/` prefix (canonical)
- Old `/api/` prefix preserved as backward-compat aliases (`include_in_schema=False`)
- `/api/health` → backward-compat alias for `/api/v1/health`
- Frontend unchanged — existing `/api/` calls still work via aliases
