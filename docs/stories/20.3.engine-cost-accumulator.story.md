# Story 20.3 — Cost Accumulator no State

## Story
**Como** operador que executa workflows,
**Quero** que o engine_state mantenha tracking granular de custo por step, por agent, e total acumulado,
**Para** que a qualquer momento eu saiba quanto foi gasto e onde o custo esta concentrado.

## Status
Draft

## Context

### Problema

Com token extraction (20.1) e pricing table (20.2) implementados, os dados existem mas nao sao acumulados. O engine precisa manter um estado de custo atualizado apos cada step para possibilitar alertas (20.5), circuit breaker (20.6), e reports (20.4).

### Design

#### Novo campo no engine_state: cost_tracking

```yaml
cost_tracking:
  per_step:
    step_id_1:
      input_tokens: 12500
      output_tokens: 3400
      model: "claude-sonnet-4"
      cost_usd: 0.0885
      is_estimated: false
      timestamp: "2026-03-30T14:22:00Z"
    step_id_2:
      input_tokens: 45000
      output_tokens: 8200
      model: "claude-opus-4"
      cost_usd: 1.290
      is_estimated: false
      timestamp: "2026-03-30T14:25:00Z"

  per_agent:
    "@dev":
      total_input_tokens: 57500
      total_output_tokens: 11600
      total_cost_usd: 1.3785
      step_count: 2
      estimated_count: 0
    "@qa":
      total_input_tokens: 8000
      total_output_tokens: 2100
      total_cost_usd: 0.0555
      step_count: 1
      estimated_count: 0

  total_usd: 1.434
  total_input_tokens: 65500
  total_output_tokens: 13700
  estimated_steps_count: 0
  last_updated: "2026-03-30T14:25:00Z"
```

#### Logica de Acumulacao

Apos cada step completion:

```
FUNCTION accumulate_cost(state, step_id, step_agent, token_data, cost_result):
  # Per step
  state.cost_tracking.per_step[step_id] = {
    input_tokens: token_data.input_tokens,
    output_tokens: token_data.output_tokens,
    model: token_data.model,
    cost_usd: cost_result.total_cost_usd,
    is_estimated: token_data.is_estimated,
    timestamp: now()
  }

  # Per agent
  agent_entry = state.cost_tracking.per_agent[step_agent] or init_agent_entry()
  agent_entry.total_input_tokens += token_data.input_tokens
  agent_entry.total_output_tokens += token_data.output_tokens
  agent_entry.total_cost_usd += cost_result.total_cost_usd
  agent_entry.step_count += 1
  IF token_data.is_estimated: agent_entry.estimated_count += 1

  # Totals
  state.cost_tracking.total_usd += cost_result.total_cost_usd
  state.cost_tracking.total_input_tokens += token_data.input_tokens
  state.cost_tracking.total_output_tokens += token_data.output_tokens
  IF token_data.is_estimated: state.cost_tracking.estimated_steps_count += 1
  state.cost_tracking.last_updated = now()
```

#### Persistencia

O cost_tracking eh parte do engine_state e persiste no state file YAML. Em caso de recovery, o custo acumulado nao se perde.

## Acceptance Criteria

- [ ] AC1: engine_state contem campo cost_tracking inicializado com valores zerados no workflow start
- [ ] AC2: cost_tracking.per_step[step_id] registra input_tokens, output_tokens, model, cost_usd, is_estimated, timestamp para cada step
- [ ] AC3: cost_tracking.per_agent[agent] acumula totais de tokens, custo, step_count e estimated_count por agente
- [ ] AC4: cost_tracking.total_usd contem soma de todos os custos de todos os steps
- [ ] AC5: Acumulacao acontece imediatamente apos cada step completion (nao batch)
- [ ] AC6: cost_tracking persiste no state file para recovery — custo nao se perde em crash
- [ ] AC7: Steps com is_estimated=true incrementam estimated_steps_count nos totais
- [ ] AC8: last_updated atualizado apos cada acumulacao para rastreabilidade temporal
- [ ] AC9: Backward compatible — state files antigos sem cost_tracking funcionam normalmente (inicializa com zeros)

## Technical Notes

- O cost_tracking pode crescer com muitos steps, mas o overhead eh minimo (um map entry por step)
- A acumulacao per_agent permite identificar rapidamente qual agente mais consome budget
- Recovery de state antigo sem cost_tracking deve inicializar o campo com valores zerados
