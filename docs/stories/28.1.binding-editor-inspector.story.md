# Story 28.1 — Binding Editor no Inspector

## Story
**Como** operador corrigindo mapeamentos de campos,
**Quero** editar o binding XSD diretamente no Inspector sem trocar de aba,
**Para** corrigir um mapeamento errado em 1 clique + 1 seleção.

## Status
Done

## Context

O Inspector (painel direito) é o **único componente sempre visível** independente de qual aba da LeftPanel está ativa. O campo "Binding" em `ElementInspector.vue:142` atualmente é read-only — o operador vê qual XSD path está vinculado, mas não pode alterá-lo.

**Situação atual:**
- `ElementInspector.vue:142` renderiza `<InspectorField label="Binding" :value="node.binding" />`
- Para alterar o binding, o operador precisa: trocar para aba Estrutura → localizar o nó → right-click → "Remover binding" → voltar para Campos → arrastar (que é dead code)
- `field_tree.flat_paths` vem do backend mas não é persistido no frontend

**Referências de design:**
- Wireframes detalhados: `frontend/docs/epic-28-field-mapping-interaction-spec.md` (seção BindingEditor)
- Audit UX completo: `frontend/docs/epic-28-ux-audit.md`
- Arquitetura de informação: `frontend/docs/epic-28-information-architecture.md`
- Epic: `docs/epics/epic-28-field-mapping-redesign.md`

**Esta story é o pivô do Epic 28** — o Inspector como hub de ação unifica as duas abas sem exigir que co-existam na tela.

## Acceptance Criteria

- **AC1:** Campo "Binding" no Inspector tem dropdown com todos os XSD paths disponíveis (`flat_paths` do field_tree)
- **AC2:** Selecionar um path do dropdown atualiza `node.binding` em tempo real e reflete no FieldNavigator (status badge) e na StructureTree (texto inline)
- **AC3:** Botão "✕ Remover binding" aparece quando binding está definido; ao clicar, limpa `node.binding` e atualiza status para `unmapped`
- **AC4:** Busca por substring funciona no dropdown (ex: "venc" encontra "data.vencimento"); mínimo 100 paths navegáveis sem degradação de performance
- **AC5:** Quando `flat_paths` não está disponível (XSD não fornecido), o dropdown aparece disabled com tooltip "XSD não disponível"
- **AC6:** Testes unitários (`BindingEditor.spec.ts`) cobrem: estado sem binding, estado com binding, busca/filtro, seleção, remoção

### Implementação — `BindingEditor.vue`

Componente molecule em `frontend/src/molecules/BindingEditor.vue`:

```vue
<template>
  <!-- Estado: XSD não disponível -->
  <div v-if="!flatPaths.length" class="binding-editor binding-editor--disabled" :title="'XSD não disponível'">
    <span class="binding-editor__value">—</span>
  </div>

  <!-- Estado: sem binding -->
  <div v-else-if="!modelValue" class="binding-editor binding-editor--empty">
    <button @click="openDropdown" class="binding-editor__vincular">
      [Vincular →]
    </button>
  </div>

  <!-- Estado: com binding -->
  <div v-else class="binding-editor binding-editor--bound">
    <span class="binding-editor__badge" :class="statusClass">●</span>
    <span class="binding-editor__value">{{ modelValue }}</span>
    <button @click="openDropdown" class="binding-editor__edit">✎</button>
    <button @click="removeBinding" class="binding-editor__remove">✕</button>
  </div>

  <!-- Dropdown overlay -->
  <Teleport to="body">
    <div v-if="isOpen" class="binding-dropdown" ...>
      <input v-model="search" placeholder="Buscar campo XSD..." @input="filterPaths" />
      <ul>
        <li v-for="path in filteredPaths" :key="path" @click="selectPath(path)">
          {{ path }}
        </li>
      </ul>
    </div>
  </Teleport>
</template>
```

**Props:**
```typescript
interface Props {
  modelValue: string | null  // node.binding atual
  flatPaths: string[]        // lista de todos XSD paths disponíveis
  status?: 'mapped' | 'unmapped' | 'unconfirmed'  // para cor do badge
}
```

**Emits:**
```typescript
emit('update:modelValue', newPath: string)
emit('remove')
```

**Lógica de filtro:**
```typescript
const filteredPaths = computed(() =>
  search.value
    ? flatPaths.filter(p => p.toLowerCase().includes(search.value.toLowerCase()))
    : flatPaths
)
```

### Implementação — `mapping.ts`

Adicionar ao state:
```typescript
flatPaths: [] as string[]
```

Adicionar getter:
```typescript
hasFlatPaths: (state) => state.flatPaths.length > 0
```

Adicionar actions:
```typescript
setFlatPaths(paths: string[]) {
  this.flatPaths = paths
},

updateNodeBinding(nodeId: string, xsdPath: string) {
  // 1. Atualizar templateStore: node.binding = xsdPath
  // 2. Atualizar fieldNavItems: encontrar item por path, atualizar status
  const templateStore = useTemplateStore()
  templateStore.updateNodeBinding(nodeId, xsdPath)
},

removeNodeBinding(nodeId: string) {
  const templateStore = useTemplateStore()
  templateStore.updateNodeBinding(nodeId, null)
}
```

### Implementação — `ElementInspector.vue`

Localizar linha ~142 onde está:
```vue
<InspectorField label="Binding" :value="node.binding" />
```

Substituir por:
```vue
<BindingEditor
  v-model="node.binding"
  :flat-paths="mappingStore.flatPaths"
  :status="fieldStatus"
  @update:model-value="onBindingChange"
  @remove="onBindingRemove"
/>
```

Adicionar no `<script setup>`:
```typescript
import BindingEditor from '@/molecules/BindingEditor.vue'
import { useMappingStore } from '@/stores/mapping'

const mappingStore = useMappingStore()

function onBindingChange(newPath: string) {
  mappingStore.updateNodeBinding(props.node.id, newPath)
}

function onBindingRemove() {
  mappingStore.removeNodeBinding(props.node.id)
}
```

### Integração com FieldNavigator

Quando `updateNodeBinding` é chamado, o `fieldNavItems` deve ser atualizado reativamente. O status do FieldNavItem correspondente muda de acordo:
- `xsdPath` definido → `status: 'mapped'`
- `xsdPath = null` → `status: 'unmapped'`

Isso deve acontecer via reatividade do Pinia — não é necessário evento manual se `fieldNavItems` for um computed derivado de `templateStore.nodes`.
