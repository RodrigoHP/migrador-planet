# Story 13.13 — AnalyzingPage Redesign: Stepper 5 Estágios + Detail Card + A11y

## Story
**Como** operador do sistema que processa 10+ jobs/dia,
**Quero** uma tela de progresso que mostre claramente onde estou no processo, o que está acontecendo, e o que fazer quando algo falha,
**Para** que eu acompanhe o pipeline sem ansiedade, tome decisões informadas em checkpoints/erros, e saiba quando posso avançar para o editor.

## Status
Done

## Context

### Problema (5 Dores Críticas do Operador)
- **D1:** Tela estática sem sensação de "está vivo"
- **D2:** Não sabia onde estava no processo (28 stages flat)
- **D3:** Falhou mas mostrou verde (falso positivo!)
- **D4:** Só via "concluído" ou "falha", nunca "executando"
- **D5:** Não sabe o que fazer quando dá erro / quando conclui

### AnalyzingPage Atual (v1)
- 8 blocos com 28 stages em pills flat (pendente → rodando → completo → falha)
- SSE inline com event queue 60ms + replay buffer
- Barra de progresso simples + resumo parcial (PDFs, páginas, layouts)
- Erro: card vermelho básico com "Tentar novamente" + "Voltar ao Upload"
- Sem checkpoint, sem detail card, sem stepper, sem accordion

### AnalyzingPage v2 (Wireframe Aprovado + A11y Corrigida)
- **Stepper horizontal** 5 circles (✓ done / spinner active / ○ pending / ✗ error / ⚠ warning)
- **Detail card** do estágio ativo: descrição humana, barra de progresso, sub-etapa, métricas
- **5 estados** com transição automática via SSE: initializing → processing → checkpoint → error → completed
- **Accordions** para estágios concluídos com detalhes expandíveis
- **Checkpoint card** amarelo com thumbnails, sugestão, timer 300s
- **Error card** vermelho com "O que aconteceu" + 3 opções (Tentar Novamente / Continuar sem / Cancelar)
- **Completed summary** com métricas, coverage multidimensional, warnings, botão "Abrir no Editor"
- **A11y WCAG AA** completa (contraste, teclado, ARIA, semântica)

### Wireframe de Referência
`wireframe-progress-screen-v2.html` — 6 abas interativas cobrindo todos os estados

## Acceptance Criteria

1. **Stepper horizontal** com 5 estágios nomeados em PT-BR:
   - 1: Agrupamento de Layouts
   - 2: Extração Profunda
   - 3: Análise Estrutural
   - 4: Mapeamento de Campos
   - 5: Geração de Template
   - Cada circle: done (✓ verde), active (spinner azul + pulse), pending (○ cinza), error (✗ vermelho), warning (⚠ amarelo + pulse)
   - Connector lines entre circles (done=verde, active=gradient, pending=cinza)

2. **Detail card do estágio ativo** com:
   - Label (ESTÁGIO X DE 5), título do estágio, dot pulsante
   - Descrição humana do sub-step ativo (ex: "Extraindo textos e imagens — 45 de 120 páginas")
   - Barra de progresso com porcentagem + animação glow
   - Pill do sub-step atual + tempo estimado
   - Métricas contextuais (páginas processadas, clusters detectados, etc.)

3. **5 estados com transição automática via SSE:**
   - `initializing`: shimmer + "Conectando ao pipeline..."
   - `processing`: stepper + detail card + métricas (estado principal)
   - `checkpoint`: card amarelo + thumbnails + sugestão + timer 300s + botões (Confirmar/Ajustar/Pular)
   - `error`: card vermelho + "O que aconteceu" + 3 opções (Tentar Novamente/Continuar sem estágio/Cancelar análise)
   - `completed`: resumo + métricas + coverage + warnings + botão "Abrir no Editor"

4. **Accordions de estágios concluídos** abaixo do stepper:
   - Cada estágio concluído: ícone ✓, nome, resumo curto, tempo
   - Expandível com grid de detalhes (métricas, sub-steps concluídos)
   - Teclado: Enter/Space para expandir/colapsar

5. **Estado completed — Summary card:**
   - Grid 4 métricas (Tempo Total, Custo API, Layouts, Páginas)
   - Coverage multidimensional: barra + breakdown (campos X% | tabelas Y% | imagens Z%)
   - Lista de warnings (se houver)
   - Botão primário "Abrir no Editor" → navega para editor com `loadFromPipelineResult()`
   - **Nota:** `api_cost` vem do SSE `completed` summary (`summary.api_cost`). Se o campo não estiver presente (pipeline v1 ou backend não envia), exibir "—" em vez de valor. Garantir que Story 13.3 inclui `api_cost` no evento `completed`.

6. **Estado checkpoint:**
   - Thumbnails das páginas que precisam de decisão humana (com role="button")
   - Sugestão do sistema (card azul claro)
   - Timer regressivo (300s default) com aria-live
   - Botões: Confirmar sugestão (primário), Ajustar (secundário), Pular (ghost)
   - Integração com `POST /jobs/{job_id}/handle-failure` (de 13.3)

7. **Estado error:**
   - "O que aconteceu" card vermelho com explicação humana
   - 3 botões como cards clicáveis:
     - Tentar Novamente (retry) — ícone azul
     - Continuar sem este estágio (fallback) — ícone amarelo
     - Cancelar análise (abort) — ícone vermelho
   - Integração com `POST /jobs/{job_id}/handle-failure` (de 13.3)

8. **SSE v2 consumo adaptado:**
   - Parsear novo formato: `{stage, stage_name, status, progress_pct, sub_step, sub_progress_pct, summary}`
   - Preservar replay buffer + event queue 60ms do v1
   - Detectar `status: "service_failure"` → transição para estado checkpoint/error
   - Detectar `status: "completed"` → transição para estado completed
   - Backward compat: se SSE v1 (28 stages), exibir fallback (layout atual simplificado)
   - **Nota:** Se 13.3 Task 5 e/ou 13.11 Task 7 já foram implementadas com adaptação mínima da barra de progresso, esta story SUBSTITUI esse trabalho com o redesign completo. O dev deve desconsiderar a implementação mínima anterior e reescrever a AnalyzingPage.vue inteira.

9. **A11y WCAG AA:**
   - Contraste ≥ 4.5:1 em todos os textos (cores corrigidas: #64748b, #b45309, #15803d)
   - Stepper: `role="list"`, cada step `role="listitem"`, estágio ativo `aria-current="step"`
   - Progress bar: `role="progressbar"`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`
   - Accordions: `aria-expanded`, `tabindex="0"`, Enter/Space toggle
   - Checkpoint/error: `role="alert"` para mudanças de estado
   - Timer: `aria-live="polite"` para countdown
   - Thumbnails: `role="button"`, `tabindex="0"`
   - Focus visible: `outline: 2px solid #6366f1` em todos os interativos
   - Semântica: `<header>`, `<main>`, `<nav>`, `<h2>`

10. **Topbar atualizada:**
    - Breadcrumb: Migrador > Job #{jobId} > Analisando
    - Botão "Cancelar análise" (vermelho, canto direito)
