# Story 5.3: UploadPage v3 — Multi-PDF, XSD Obrigatório e Hints Contextuais

## Status
Draft

## Story
**As a** operador da ferramenta,
**I want** fazer upload de múltiplos PDFs (1 obrigatório, 3-5 recomendado), um XSD (obrigatório) e opcionalmente um arquivo de dados (XML/JSON), com hints contextuais me guiando,
**so that** eu possa fornecer todos os inputs necessários para o pipeline de análise.

## Acceptance Criteria
1. Três dropzones: PDFs (múltiplos, 1 obrigatório), XSD (single, obrigatório), Data (single, opcional XML/JSON)
2. Dropzone PDF mostra lista de arquivos com botão 🗑️ remover e contagem "📊 N PDFs (recomendado: 3-5)"
3. Campo de input para nome do template no topo
4. Hint quando sem arquivos: "Envie ao menos 1 PDF + XSD para continuar"
5. Hint quando 1 PDF apenas: "💡 Adicionar mais PDFs melhora a detecção de variações"
6. Hint quando PDF+XSD sem dados: "💡 Adicionar dados reais melhora a detecção de tipos e formatos"
7. Hint quando PDF+dados sem XSD: "💡 Adicionar o XSD permite validar campos obrigatórios"
8. Botão "Iniciar Análise" desabilitado até ao menos 1 PDF + XSD carregados
9. "Iniciar Análise" chama backend API POST /api/upload e navega para /analyzing
10. "← Voltar" retorna à Home
11. Upload rejeita PDFs maiores que 50MB por arquivo e XSD/Data maiores que 10MB, com mensagem de erro descritiva ("Arquivo excede o tamanho máximo de {limite}")
12. Progresso de upload exibido: barra de progresso por arquivo durante o envio ao backend (XMLHttpRequest.upload.onprogress ou fetch com ReadableStream)
13. `npm run build` passa

## Dev Notes

### Wireframe Referência
- Tela 1 — Upload: 3 dropzones (PDFs, XSD, Data)
- PDFs aceita múltiplos arquivos, os outros são single

### Formatos Aceitos
- PDF: `.pdf` (múltiplos)
- XSD: `.xsd` (único)
- Data: `.xml` ou `.json` (único, opcional)

### Backend Endpoint
- POST /api/upload com multipart form data
- Campos: `pdfs[]` (multiple files), `xsd` (single file), `data` (single file), `template_name` (string)
- Retorna: `{ job_id: string }`

### Estado dos Arquivos
- Armazenar arquivos em refs locais antes de enviar
- Não enviar para backend até clicar "Iniciar Análise"
- sessionStore armazena job_id após upload bem-sucedido

### Layout
- Usar `FullWidthLayout.vue` como layout da página

### FRs Referenciados
- FR1: Upload de PDF(s) para análise
- FR2: Upload de XSD para definição de campos
- FR2a: Upload opcional de dados (XML/JSON) para melhorar detecção

### Stack
- Vue 3 + TypeScript + Tailwind CSS 4.x
- Fetch API ou axios para chamada ao backend

### Testing
- Vitest for unit tests
- Test files alongside source: `*.spec.ts` or `*.test.ts`
