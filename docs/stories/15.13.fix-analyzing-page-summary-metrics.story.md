# Story 15.13 — Fix AnalyzingPage: METRIC_LABELS incompleto + summary cards com 0/—

## Story

**Como** usuário que acabou de processar um documento,
**Quero** ver os detalhes dos estágios em português e os cards de resumo com valores reais (Layouts, Páginas),
**Para** entender o resultado do processamento sem precisar interpretar termos técnicos em inglês.

## Status

Ready

## Context

### Problema 1 — METRIC_LABELS com chaves ausentes (labels em inglês)

A story 15.12 adicionou `METRIC_LABELS` em `analyzingPageConstantsV2.ts` com 17 entradas. Porém, as chaves enviadas pelo backend nos summaries de estágio 3 e 4 não foram mapeadas. O fallback `key.replace(/_/g, ' ')` converte snake_case em inglês legível mas ainda inglês, exibindo strings como "total blocks classified", "vision api calls", "ambiguous count".

**Chaves reais enviadas pelo backend (investigação via código):**

Stage 3 (`stage3_structural_analysis.py`):
- `total_blocks_classified`, `total_labels`, `total_dynamic`, `total_pairs`, `trees_built`, `vision_api_calls`

Stage 4 (`stage4_field_mapping.py`):
- `total_mappings`, `ambiguous_count`, `confirmations`, `warnings`, `errors`

Nenhuma dessas 11 chaves está em `METRIC_LABELS`.

### Problema 2 — Cards de resumo exibindo 0 / — (backend não envia dados)

O frontend popula os cards "LAYOUTS", "PÁGINAS" e "CUSTO API" a partir de `data.summary` no evento `pipeline_completed`. Investigação do backend (`pipeline_orchestrator_v2.py` linhas 376–383) confirmou que esse evento envia `summary: {}` (vazio).

O backend possui os dados necessários nos resultados intermediários:
- **layouts_detected**: count de clusters produzidos pelo Stage 1
- **page_count**: soma dos `page_count` de cada cluster do Stage 1
- **api_cost**: não rastreado no pipeline atual → fora do escopo

Fix requer adicionar esses campos ao `make_pipeline_completed_event()` no orchestrator.

### Backend — onde adicionar o summary do pipeline_completed

Arquivo: `backend/services/pipeline_orchestrator_v2.py`
Função: `make_pipeline_completed_event()` (aproximadamente linha 376)

O Stage 1 result contém uma lista de clusters. Cada cluster tem `page_count`. Extrair:
```python
stage1_result = context.get("stage_1_result", {})
clusters = stage1_result.get("clusters", [])
layouts_detected = len(clusters)
page_count = sum(c.get("page_count", 0) for c in clusters)
```

Adicionar ao payload do evento:
```python
"summary": {
    "layouts_detected": layouts_detected,
    "page_count": page_count,
}
```

### Verificação do contexto do orchestrator

O orchestrator acumula resultados em `context` dict durante a execução. Verificar se `stage_1_result` ou equivalente (pode ser `clusters`, `stage1`, etc.) está disponível no escopo onde o evento `pipeline_completed` é emitido. Adaptar o key de acesso conforme necessário.
