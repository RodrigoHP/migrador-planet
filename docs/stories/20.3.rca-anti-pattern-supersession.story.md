# Story 20.3 — Anti-Pattern Supersession

## Story
**Como** investigador analisando padroes na knowledge base,
**Quero** rastrear evolucao de anti-patterns com campo `superseded_by`,
**Para** que anti-patterns parciais sejam identificados e o Pattern Matcher priorize a versao mais recente.

## Status
Draft

## Context

### Problema
Quando uma investigacao descobre que um anti-pattern anterior era sintoma de algo mais profundo, nao existe forma de registrar essa relacao. O Pattern Matcher pode sugerir um fix parcial (baseado no anti-pattern antigo) em vez do fix completo (baseado no mais recente).

### Design
- Adicionar campo opcional `superseded_by: AP-XXX` no schema de anti-patterns
- Anti-pattern superseded recebe status `superseded` (nao removido para historico)
- Fase 2 (Pattern Matcher) prioriza anti-pattern mais recente na cadeia
- SOPs associados a anti-patterns superseded marcados como `deprecated`

## Acceptance Criteria
- [ ] Schema de known-anti-patterns.md inclui campo opcional `superseded_by: AP-XXX`
- [ ] Anti-pattern superseded eh marcado com status `superseded` (nao removido)
- [ ] Fase 2 (Pattern Matcher) prioriza anti-pattern mais recente na cadeia de supersession
- [ ] SOPs associados a anti-patterns superseded sao marcados como `deprecated` com referencia ao novo
- [ ] Documentacao no investigate.md explica o conceito de supersession

## Scope
**IN:** investigate.md (Fase 2, Fase 8), schema anti-patterns, schema SOPs
**OUT:** Migracao retroativa de anti-patterns existentes (feita manualmente)
