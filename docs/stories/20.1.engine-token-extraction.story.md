# Story 20.1 — Token Extraction from Task Tool

## Story
**Como** operador que executa workflows com custo real,
**Quero** que o engine capture input_tokens e output_tokens reais do response metadata de cada subagent spawn,
**Para** que o tracking de custo seja baseado em dados reais e nao em estimativas.

## Status
Draft

## Context

### Problema

Hoje o engine nao captura nenhum dado de consumo de tokens dos subagent spawns. Cada chamada ao Task tool retorna response metadata que inclui input_tokens e output_tokens, mas esses valores sao ignorados. Sem essa informacao, qualquer calculo de custo seria puramente heuristico.

### Design

#### Captura de Token Metadata

Apos cada subagent spawn (Task tool call), o engine deve extrair do response metadata:

```
token_data = {
  input_tokens: response.metadata.input_tokens,
  output_tokens: response.metadata.output_tokens,
  model: response.metadata.model,
  is_estimated: false,
  timestamp: now()
}
```

#### Fallback Heuristico

Se o response metadata nao contiver token counts (ex: versao antiga, erro de parsing):

```
token_data = {
  input_tokens: estimate_tokens(prompt_text),    # ~4 chars per token
  output_tokens: estimate_tokens(response_text), # ~4 chars per token
  model: step.model or "unknown",
  is_estimated: true,
  timestamp: now()
}
```

O campo `is_estimated` permite distinguir dados reais de estimativas em reports posteriores.

#### Armazenamento no Step Output

```
step_output.token_usage = token_data
```

Esse dado fica disponivel para o Cost Accumulator (Story 20.3).

## Acceptance Criteria

- [ ] AC1: Apos cada subagent spawn, o engine extrai input_tokens e output_tokens do response metadata
- [ ] AC2: Token data inclui campo model identificando qual modelo foi usado no spawn
- [ ] AC3: Token data inclui campo is_estimated = false quando extraido do response metadata real
- [ ] AC4: Quando response metadata nao contem token counts, fallback heuristico estima tokens (~4 chars/token)
- [ ] AC5: Fallback heuristico marca is_estimated = true para distinguir de dados reais
- [ ] AC6: Token data armazenado no step_output.token_usage para consumo por stories posteriores
- [ ] AC7: Timestamp registrado em cada token_data para correlacao temporal
- [ ] AC8: Zero regressao — steps que nao usam subagent spawn continuam funcionando normalmente

## Technical Notes

- O response metadata varia conforme o provider/modelo — o parser deve ser resiliente
- Heuristica de ~4 chars por token eh uma aproximacao razoavel para modelos Claude
- O campo model eh essencial para o pricing correto na Story 20.2
