# Story 30.2 — Converter para Tabela via Context Menu

## Story
**Como** operador editando a estrutura de um documento no canvas,
**Quero** poder clicar com o botão direito em uma seção e selecionar "Converter para Tabela",
**Para** transformar a seção em uma tabela HTML estruturada com os campos como primeira linha, sem precisar reprocessar o PDF.

## Status
InReview

## Business Value
`handleCtxConvertTable` em `HTMLCanvas.vue` atualmente faz apenas `closeContextMenu()`.
O operador perde a intenção e não recebe feedback. Esta story implementa a conversão
real: o nó selecionado muda de tipo para `table`, seus filhos são reorganizados como
uma linha (`tr`) e o DOM do canvas é atualizado via patch imediato.

**Estimativa:** 3 story points

## Scope

**IN:**
- `templateStore.convertToTable(nodeId)`: converte nó `section`/`flow`/`container` → `table`
- Cria um nó `section` filho como primeira linha (`tr`) com os filhos originais como células
- Incrementa `mutationVersion` (watcher do canvas detecta a mudança)
- Patch de DOM via `generationStore.patchAddNode` (ou replace direto da minimal HTML)
- `_generateMinimalNodeHtml` para o tipo `table`: usa `<table>` com estrutura mínima
- `handleCtxConvertTable` em `HTMLCanvas.vue`: chama `templateStore.convertToTable(contextMenuState.nodeId)`
- Feedback visual: toast/console se o nó não for convertível (ex: já é table, ou é field)
- Testes unitários de `convertToTable` (templateStore)

**OUT:**
- Editor visual de colunas/linhas (arrastar, mesclar células)
- Renderização fiel de backend — `loadTemplateDraft` entrega isso após o próximo processamento
- Conversão de tipos `field`, `label`, `value` (inválido — apenas section/flow/container)
- Suporte a `undo` desta operação (undo stack já existe via `pushUndoSnapshot`)

## Risks

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| Nó convertido diverge do HTML de backend | Média | Baixo | Documentado no ADR-029: placeholder aceito até próximo loadTemplateDraft |
| flatNodes map não atualizado após conversão | Baixa | Alto | Usar `mutationVersion++` + renegociar flatNodes via buildFlatMap se necessário |
| contextMenuState.nodeId pode ser null | Baixa | Baixo | Guard `if (!contextMenuState.nodeId) return` (já existe no padrão de handleCtxMapField) |

## Context

**Situação atual:**

```typescript
// HTMLCanvas.vue:700
function handleCtxConvertTable() {
  // MVP: intent registered — table conversion is out of scope for 29.6
  closeContextMenu()
}
```

**Arquitetura relevante:**

- `templateStore.addNode(parentId, type)` — padrão existente para adicionar nós
- `templateStore.removeNode(nodeId)` — remove nó da árvore e flatNodes
- `generationStore.patchAddNode(node, parentId)` — injeta HTML mínimo no canvas
- `_generateMinimalNodeHtml(node)` — gera placeholder HTML para tipos não suportados
- `mutationVersion` — contador observado por `HTMLCanvas.vue` para re-render

**Definição de conversão (MVP):**

```
section/flow/container (id=X, filhos=[A,B,C])
  ↓ convertToTable
table (id=X, name="Tabela", filhos=[
  section (id=NEW_ROW, name="Linha 1", filhos=[A,B,C])  ← primeiro row
])
```

O nó original muda de type para `table`. Os filhos originais são wrappados em um
novo nó `section` (representando a primeira linha). O flat map é atualizado.

- `frontend/src/organisms/HTMLCanvas.vue` — `handleCtxConvertTable` implementado
- `frontend/src/stores/__tests__/templateStore.spec.ts` (ou equivalente) — testes

**HTML mínimo de tabela:**
```html
<table data-node-id="{id}" data-type="table"
       style="position:absolute;left:{x}px;top:{y}px;width:{w}px;height:{h}px">
  <tbody></tbody>
</table>
```

**Guard de tipos válidos para conversão:**
```typescript
const CONVERTIBLE_TO_TABLE: NodeType[] = ['section', 'flow', 'container']
if (!CONVERTIBLE_TO_TABLE.includes(node.type)) return false
if (node.type === 'table') return false
```
