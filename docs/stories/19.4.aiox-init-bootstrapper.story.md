# Story 19.4 — `aiox init` Bootstrapper

## Story
**Como** desenvolvedor que quer adotar AIOS em um projeto existente ou novo,
**Quero** um comando/task `aiox init` que cria toda a estrutura minima necessaria (.aios/, engine-config.yaml, workflows genericos, agents essenciais),
**Para** que eu possa comecar a usar o framework em minutos sem configuracao manual.

## Status
Draft

## Context

### Problema

Hoje para usar AIOS em um novo projeto, o operador precisa:
1. Copiar manualmente dezenas de arquivos do .aios-core/
2. Criar .aios/ com estrutura correta
3. Configurar engine-config.yaml manualmente
4. Copiar workflow templates
5. Copiar agent definitions
6. Ajustar paths e referencias

Esse processo e tedioso, error-prone, e desmotiva a adocao.

### Design

#### Comando `aiox init`

Task que executa o bootstrap completo:

```
aiox init [--tier core|extended|full] [--force]
```

#### Estrutura gerada

```
.aios/
  engine-config.yaml          # Config com defaults (19.2)
  project-context.yaml        # Auto-detectado (19.5) ou template
  handoffs/                   # Runtime handoff artifacts
  state/                      # Engine state persistence
.aios-core/
  development/
    tasks/
      run-workflow-engine.md  # Engine core generico (19.1)
    workflows/
      story-development-cycle.yaml  # SDC generico (19.3)
      rca-investigation.yaml        # RCA generico (19.3)
    templates/
      subagent-step-prompt.md       # Prompt template
  agents/
    dev.md                    # Core agents (19.6)
    qa.md
    devops.md
.claude/
  rules/                      # Regras essenciais
  CLAUDE.md                   # Project instructions base
```

#### Deteccao de projeto existente

```
IF .aios/ exists:
  mode = "upgrade"
  PRESERVE existing config (merge new defaults)
  PRESERVE existing state files
  UPDATE engine core to latest version
  ADD missing files only
ELSE:
  mode = "fresh"
  CREATE full structure
```

#### Tiers (via 19.6)

- `--tier core` — dev, qa, devops (default)
- `--tier extended` — core + architect, pm, sm, po
- `--tier full` — extended + analyst, data-engineer, ux

## Technical Notes

- O init deve ser idempotente: rodar duas vezes nao duplica ou corrompe nada
- Backup automatico antes de upgrade (.aios.bak/)
- Considerar que 19.5 (auto-detect) pode rodar como parte do init
