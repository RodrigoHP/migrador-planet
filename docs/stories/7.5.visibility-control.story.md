# Story 7.5: VisibilityControl

## Status
Done

## Story
**As a** operador,
**I want** definir a visibilidade de elementos como "Sempre visível", "Condicional" ou "Escondido" via construtor visual de condições (SE [campo] [operador] [valor] com E/OU),
**so that** o template gere blocos `<!-- ko if -->` apropriados.

## Acceptance Criteria
1. Dropdown de visibilidade no Inspector (todos os níveis exceto Page): "Sempre visível" (padrão), "Condicional", "Escondido" (FR9)
2. "Condicional" expande construtor de condições abaixo do dropdown
3. Construtor de condição: SE [campo dropdown] [operador dropdown] [valor input]
4. Operadores: existe, não existe, igual a, diferente de, maior que, menor que, contém
5. Condições compostas: botões [+ E] [+ OU] para adicionar condições
6. Preview do código Knockout gerado: `<!-- ko if: expressão -->`
7. "Escondido" remove elemento do HTML gerado inteiramente
8. Campos detectados como opcionais pela análise MultiDoc (pipeline) vêm pré-configurados como "Condicional"
9. Alterações de condição atualizam templateStore → Canvas re-renderiza mostrando/escondendo elementos
10. `npm run build` passa sem erros

## Dev Notes
- FR9: "construtor visual SE [campo] [operador] [valor] com E/OU"
- Wireframe: Inspetor de Seção Opcional mostra construtor de condições
- Campo dropdown: populado de mappingStore.allFields (árvore de campos XSD)
- Geração Knockout: "existe" → `field`, "não existe" → `!field`, "igual a" → `field() === value`, "maior que" → `field() > value`
- Composto: E → `&&`, OU → `||`
- Exemplo: SE [telefone] [existe] OU [email] [existe] → `<!-- ko if: telefone || email -->`
- VisibilityControl molecule: dropdown + construtor de condições expansível
- Condicionais pré-configurados do pipeline: multiDocStore.conditionalSections[] → auto-popular visibilidade
- Stack: Vue 3 + TypeScript + Pinia + Tailwind CSS
