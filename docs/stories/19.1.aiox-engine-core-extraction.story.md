# Story 19.1 — Engine Core Extraction

## Story
**Como** mantenedor do framework AIOS,
**Quero** separar o pseudocode engine core de conteudo project-specific (migrador-planet) em run-workflow-engine.md,
**Para** que o engine possa ser reutilizado em qualquer projeto sem carregar referencias a um projeto especifico.

## Status
Draft

## Context

### Problema

O arquivo `run-workflow-engine.md` tem ~2596 linhas e mistura logica generica do engine (state machine, sequence advancer, subagent spawning, loop guard, output parser) com referencias especificas ao migrador-planet (nomes de workflows, tech stack assumptions, exemplos hardcoded).

Isso impede que o engine seja portavel: ao copiar para outro projeto, o operador precisa manualmente identificar e remover/adaptar dezenas de referencias project-specific.

### Design

#### Auditoria de 2596 linhas

Percorrer todo o arquivo identificando:
1. **Engine core** — logica generica que funciona em qualquer projeto (state machine, step execution, failure handling, recovery, etc.)
2. **Project-specific** — referencias ao migrador-planet, Vue, FastAPI, Supabase, nomes de stories, paths especificos
3. **Configurable** — valores que devem virar parametros (timeouts, token limits, retry counts)

#### Separacao

- Manter engine core em `run-workflow-engine.md` como pseudocode generico
- Extrair project-specific para secao claramente demarcada ou arquivo separado de overrides
- Marcar pontos de extensao com `{{PROJECT_CONTEXT}}` ou similar

#### Backward Compatibility

- O engine deve continuar funcionando identicamente no migrador-planet apos a extracao
- Nenhuma funcionalidade perdida — apenas reorganizacao

### Arquivos a modificar

1. `.aios-core/development/tasks/run-workflow-engine.md` — auditar e separar core vs project-specific
