# Story 16.3 — Token Tracking & Context Window Protection

## Story
**Como** operador que executa workflows longos em `yolo_continuous`,
**Quero** que o engine rastreie o consumo de tokens e proteja contra estouro de context window,
**Para** que workflows com muitos steps e outputs acumulados nao falhem silenciosamente por exceder o limite de tokens.

## Status
Draft

## Context

### Problema

O engine nao rastreia consumo de tokens entre steps. Um workflow com 6+ fases pode acumular 12-60K tokens via `requires` chains e outputs. Se o prompt de um subagente exceder a context window (~200K tokens), a execucao falha silenciosamente ou produz output truncado. Outputs grandes em handoff artifacts (declarados max 500 chars, mas sem enforcement) agravam o problema.

### Referencia

- Engine: `.aios-core/development/tasks/run-workflow-engine.md` (v3.0)
- Handoff max size: 500 chars (spec em `agent-handoff.md`, nao enforced no engine)

### Design Proposto

**Tracking:**
- Estimar tokens de cada prompt antes de spawnar
- Acumular total gasto no state
- Warning ao atingir 80% do limite

**Protection:**
- Truncar outputs em `requires` chain quando excedem threshold
- Enforcar max size de handoff artifacts (500 chars)
- Em `yolo_continuous`: warning + truncamento automatico
- Em step-by-step: warning + perguntar ao usuario

**State fields:**
```yaml
token_tracking:
  total_estimated: 0
  per_step: {}  # {step_id: estimated_tokens}
  context_window_limit: 180000  # 200K - 20K safety buffer
  warnings_issued: []
```

## Acceptance Criteria

- [ ] AC1: Engine estima tokens do prompt antes de cada spawn e registra em `state.token_tracking.per_step`
- [ ] AC2: Total acumulado rastreado em `state.token_tracking.total_estimated`
- [ ] AC3: Warning emitido quando total atinge 80% do `context_window_limit`
- [ ] AC4: Outputs em `requires` chain truncados automaticamente quando excedem 2000 tokens
- [ ] AC5: Handoff artifacts enforced max 500 chars (truncamento com `[truncated]` marker)
- [ ] AC6: Final Report inclui secao "Token Usage" com total e per-step breakdown
- [ ] AC7: `context_window_limit` configuravel no workflow metadata (default 180000)
- [ ] AC8: Em `yolo_continuous`, truncamento eh automatico; em step-by-step, warning apenas

## Complexity

**T-shirt size:** M (Medium)
**Estimativa:** Estimativa de tokens (heuristica words/4), truncamento de requires, enforcement de handoff size, state tracking.

## Scope

**IN:**
- `.aios-core/development/tasks/run-workflow-engine.md` — token tracking, truncamento, warnings
- Heuristica de estimativa (words/4 ou chars/4)
- Enforcement de handoff max size

**OUT:**
- Nao usar biblioteca externa de tokenizacao (heuristica suficiente)
- Nao implementar custo em USD (story separada)
- Nao alterar workflows existentes

## Risks

- Heuristica de estimativa (chars/4) pode divergir significativamente do token count real para idiomas nao-ingleses ou codigo com muitos simbolos. Mitigacao: safety buffer de 20K tokens.
- Truncamento de outputs em requires pode cortar informacao critica. Mitigacao: truncar preservando keys e inicio de cada campo.

## Implementation Notes

### Subtasks

1. Criar funcao `estimate_tokens(text)` — heuristica `len(text.split()) * 1.3` ou `len(text) / 4`
2. Adicionar `token_tracking` ao state init em `yolo_continuous`
3. Antes de cada spawn: estimar tokens do prompt, registrar em `per_step[step_id]`
4. Apos cada spawn: somar ao `total_estimated`
5. Implementar warning ao atingir 80% do limite
6. Implementar truncamento de outputs em `requires` chain (max 2000 tokens por output)
7. Enforcar max 500 chars em handoff artifacts (truncar com marker `... [truncated]`)
8. Atualizar Final Report com secao "Token Usage"
9. Testar: workflow com outputs grandes deve truncar e completar sem falha
