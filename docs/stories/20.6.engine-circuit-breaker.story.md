# Story 20.6 — Cost Circuit Breaker

## Story
**Como** operador que quer protecao contra gastos excessivos,
**Quero** que o engine faca auto-pause quando o custo real atinge o budget limit, com abort em yolo mode e pergunta ao user em interactive mode,
**Para** que o workflow nao continue gastando alem do budget sem autorizacao explicita.

## Status
Draft

## Context

### Problema

Alertas (20.5) notificam, mas nao impedem que o custo ultrapasse o budget. O circuit breaker eh a ultima linha de defesa — quando o custo real atinge 100% do limit, o engine deve parar e decidir baseado no execution mode.

### Design

#### Logica do Circuit Breaker

Apos cada acumulacao de custo (post-step), apos os alertas:

```
FUNCTION check_circuit_breaker(state, cost_config, execution_mode, flags):
  budget = cost_config.budget.per_workflow
  current = state.cost_tracking.total_usd

  IF current >= budget.limit_usd:
    IF flags.force_budget:
      log("[OVERRIDE] Budget limit reached but --force-budget active. Continuing.")
      RETURN "continue"

    IF execution_mode == "yolo" OR execution_mode == "yolo_continuous":
      log("[ABORT] Budget limit reached in yolo mode: ${current:.2f} >= ${budget.limit_usd:.2f}")
      generate_cost_report(state)
      RETURN "abort"

    IF execution_mode == "interactive":
      response = ask_user(
        "[BUDGET LIMIT] Cost ${current:.2f} reached limit ${budget.limit_usd:.2f}. Continue? [y/N]"
      )
      IF response == "y":
        log("[OVERRIDE] User approved budget override.")
        RETURN "continue"
      ELSE:
        log("[ABORT] User declined budget override.")
        RETURN "abort"

  RETURN "continue"
```

#### Flag --force-budget

Override para ignorar o circuit breaker quando o operador sabe que quer continuar:

```bash
# Em YOLO mode, normalmente abortaria. Com --force-budget, continua:
*execute-epic 20 --yolo --force-budget
```

#### Abort com Report

Quando o circuit breaker dispara abort, o engine:
1. Salva estado atual (para possivel resume futuro)
2. Gera final report com secao Cost Breakdown (20.4)
3. Adiciona nota: "Workflow aborted due to budget limit reached"
4. Exit com status budget_exceeded

## Acceptance Criteria

- [ ] AC1: Quando custo real >= budget limit, engine ativa circuit breaker
- [ ] AC2: Em yolo/yolo_continuous mode, circuit breaker faz abort imediato com final report
- [ ] AC3: Em interactive mode, circuit breaker pergunta ao user se deseja continuar
- [ ] AC4: Flag --force-budget permite override do circuit breaker em qualquer mode
- [ ] AC5: Abort salva estado completo para possivel resume futuro
- [ ] AC6: Final report de abort inclui nota "Workflow aborted due to budget limit reached"
- [ ] AC7: Exit status eh budget_exceeded (distinto de outros abort reasons)
- [ ] AC8: Se budget limit nao configurado, circuit breaker eh desabilitado (nao bloqueia)

## Technical Notes

- O circuit breaker roda APOS os alertas de budget (20.5) — assim o alerta de 90% ja foi emitido
- O --force-budget eh flag do workflow execution, nao do cost-config.yaml
- O status budget_exceeded permite automacoes externas identificarem o motivo do abort
- Em interactive mode, o ask_user segue o mesmo padrao do checkpoint @po
