# Story 11.8 — Suporte multi-PDF no pipeline e persistência de pdfBytes

## Story
**Como** usuário do sistema,
**Quero** que todos os PDFs enviados sejam processados pelo pipeline e que o PDF original seja acessível no editor mesmo após refresh da página,
**Para** ter uma experiência consistente de edição com referência ao documento original.

## Status
Done

## Context
O audit identificou dois problemas relacionados a PDFs:

**P10 (Baixo) — Pipeline legacy busca apenas input.pdf:**
```python
# jobs.py — ignora input_2.pdf, input_3.pdf
pdf_path = job_dir / "input.pdf"
```
O `upload.py` salva múltiplos PDFs como `input.pdf`, `input_2.pdf`, etc. O pipeline processa apenas o primeiro.

**P9 (Médio) — pdfBytes perdidos no refresh:**
`session.uploadedPdfs` armazena `ArrayBuffer` na hora do upload. Após refresh da página, os bytes se perdem porque não há endpoint para reobter o PDF original do servidor.

## Acceptance Criteria

1. **Multi-PDF processado** — O pipeline (analyze.py) processa todos os PDFs no diretório do job (`input.pdf`, `input_2.pdf`, etc.), não apenas o primeiro.
2. **Resultado multi-PDF** — O resultado do pipeline referencia todas as páginas de todos os PDFs processados.
3. **PDF acessível no editor** — Após refresh da página, o `PDFReference.vue` consegue exibir o PDF (via endpoint ou sessionStorage).
4. **Endpoint de download do PDF** — `GET /api/jobs/{job_id}/pdf` retorna o `input.pdf` do job (ou o índice de PDFs disponíveis).
5. **Fallback sessionStorage** — Se o endpoint não estiver disponível, o frontend usa sessionStorage para persistir os bytes entre navegações (não entre refreshes, mas entre rotas).

## Tasks

- [x] 1. Verificar quais stages do pipeline (analyze.py) leem `input.pdf` — mapear dependências
- [x] 2. Adaptar Stage de extração de PDF para processar lista de arquivos `input*.pdf`

- [x] 5. Implementar persistência via sessionStorage para `pdfBytes` (complementar, não substituto)
- [x] 6. Atualizar testes de extração para múltiplos PDFs

## Dev Notes

### Endpoint de PDF
```python
# analyze.py ou novo router
@router.get("/jobs/{job_id}/pdf")
async def get_pdf(job_id: str):
    validate_job_id(job_id)
    pdf_path = TMP_BASE / job_id / "input.pdf"
    if not pdf_path.exists():
        raise HTTPException(404)
    return FileResponse(pdf_path, media_type="application/pdf")
```

### sessionStorage
Limitado a ~5MB. Para PDFs grandes, apenas armazenar referência ao endpoint.

### Multi-PDF nos stages
Verificar se os stages de extração já suportam lista de paths ou se assumem path único.
