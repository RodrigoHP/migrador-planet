# Story 17.1 — Classifier Agent

## Story
**Como** investigador que inicia um RCA,
**Quero** que o sistema classifique automaticamente o tipo e complexidade do problema antes de investigar,
**Para** que a estrategia de investigacao seja adaptada ao dominio do problema, evitando aplicar tecnicas simples a problemas complexos (e vice-versa).

## Status
Draft

## Context

### Problema

Hoje o RCA aplica 5 Whys indiscriminadamente para qualquer bug — um typo e uma falha emergente em sistema distribuido recebem a mesma abordagem. Isso causa:
- Over-engineering de bugs triviais (investigacao de 30 min para um typo)
- Under-investigation de problemas complexos (5 Whys linear nao pega multi-causa)
- Nenhuma adaptacao da estrategia ao tipo de problema

### Inspiracao

- **Cynefin Framework** (Dave Snowden): Classifica problemas em Clear/Complicated/Complex/Chaotic
- **GALA** (ICLR 2025): Agentes especializados selecionados conforme tipo de falha
- **Meta DrP**: Heuristica inicial que filtra milhares de candidates para 5

### Design Proposto

**Classifier Agent** — primeiro passo de qualquer investigacao RCA:

```
Input: sintomas (erro, stack trace, log, descricao do usuario)

Analise:
  1. DOMAIN — Cynefin classification:
     - Clear: causa-efeito obvio, padrao conhecido (typo, import faltando)
     - Complicated: requer expertise, mas analisavel (logica errada, race condition)
     - Complex: causa-efeito so visivel em retrospecto (emergente, multi-sistema)
     - Chaotic: sem causa-efeito perceptivel (corrupcao, estado inconsistente)

  2. SEVERITY — impacto:
     - Critical: dados perdidos, seguranca, sistema down
     - High: funcionalidade principal quebrada
     - Medium: funcionalidade secundaria, workaround existe
     - Low: cosmético, edge case raro

  3. SCOPE — amplitude:
     - Single-file: 1 arquivo, causa localizada
     - Multi-file: 2-5 arquivos, mesmo modulo
     - Cross-module: multiplos modulos/servicos
     - Systemic: arquitetura, infraestrutura, processo

  4. STRATEGY — tecnicas selecionadas:
     Clear     → Change Analysis + Quick 5 Whys (fast track)
     Complicated → Change Analysis + FTA + Barrier Analysis
     Complex   → Full pipeline (todos os agentes)
     Chaotic   → Stabilize first, then Full pipeline

Output:
  classification:
    domain: complicated
    severity: high
    scope: cross-module
    strategy: [change_analysis, fta, barrier_analysis]
    estimated_phases: 4
    estimated_duration: "30-60 min"
```

### Fast Track para problemas Clear

Quando `domain == Clear`:
- Pular Causal Reasoner, Pattern Matcher, Hypothesis Challenger
- Ir direto: Archaeologist → fix → Barrier Analysis rapida
- Reduz investigacao de 6 fases para 3

## Acceptance Criteria

- [ ] AC1: Classifier Agent recebe sintomas (erro, stack trace, descricao) e produz classificacao estruturada
- [ ] AC2: Dominio Cynefin classificado: Clear / Complicated / Complex / Chaotic
- [ ] AC3: Severidade classificada: Critical / High / Medium / Low
- [ ] AC4: Scope classificado: Single-file / Multi-file / Cross-module / Systemic
- [ ] AC5: Estrategia de investigacao selecionada automaticamente conforme dominio
- [ ] AC6: Fast track para Clear: pula fases intermediarias, vai direto para fix
- [ ] AC7: Output estruturado em YAML com campos: domain, severity, scope, strategy, estimated_phases
- [ ] AC8: Classificacao registrada no relatorio final do RCA
- [ ] AC9: Override manual possivel — investigador pode reclassificar a qualquer momento

## Implementation Notes

### Subtasks

1. Definir prompt de classificacao com exemplos few-shot para cada dominio Cynefin
2. Definir matriz de strategy selection: dominio → tecnicas
3. Adicionar step `classifier` como primeiro step no workflow
4. Implementar fast track routing: Clear → pular para Archaeologist + fix
5. Output YAML estruturado com classificacao
6. Registrar classificacao no state e no relatorio final
7. Implementar override manual (flag `--reclassify`)
8. Testar: bug trivial deve ser classificado como Clear, bug multi-sistema como Complex

### Matriz de Estrategia

| Dominio | Tecnicas | Agentes Ativados | Fases |
|---------|----------|-------------------|-------|
| Clear | Change Analysis + Quick 5 Whys | Archaeologist, Repair | 3 |
| Complicated | Change Analysis + FTA + Barrier | Archaeologist, Causal Reasoner, Barrier, Repair | 5 |
| Complex | Full pipeline | Todos os 8 agentes | 7+ |
| Chaotic | Stabilize + Full pipeline | Todos + priorizacao de estabilizacao | 8+ |
