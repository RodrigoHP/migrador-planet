# Story 29.4 — Nomes Semânticos na Árvore (Backend)

## Story
**Como** operador visualizando a árvore de estrutura de um documento,
**Quero** ver nomes legíveis e semânticos para cada nó ("Cedente", "Valor Total", "Data Vencimento") em vez de nomes genéricos de tipo ("label", "field", "likely_dynamic"),
**Para** conseguir identificar, navegar e mapear os elementos do documento sem precisar adivinhar o que cada nó representa.

## Status
Done

## Business Value
A árvore atual mostra "label", "field", "likely_dynamic" — o operador não consegue identificar "Cedente" vs "CNPJ" vs "Valor Total". Resultado: 0/66 campos mapeados no Boleto Bancário. Com nomes semânticos, o operador consegue trabalhar e o auto-mapping tem chance de funcionar. Esta story transforma a árvore de ilegível para utilizável.

**Estimativa:** 3 story points

## Scope
**IN:**
- Extrair texto real do PDF como `node.name` para nós `label` e `field`
- Humanizar nós `likely_dynamic` com texto detectado
- Nomes únicos e descritivos para nós `section`
- Avaliação do nível `page` intermediário
- Garantir propagação de `name` pelo stage5
- Testes unitários no backend

**OUT:**
- Mudanças no frontend (`StructureTreeNode.vue` já está correto)
- Tradução ou localização dos nomes
- Auto-bind semântico completo (best-effort, não é AC bloqueante)
- Renaming manual pelo operador via UI

## Risks

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| Remover nível `page` quebra paginação no frontend | Média | Alto | Verificar `usePagination.ts` e `HTMLCanvas.vue` antes de remover — aplinar apenas se seguro |
| Texto extraído do PDF muito longo ou com caracteres especiais | Média | Baixo | Truncar a 50 chars + sanitizar |
| Stage3 processa muitos PDFs em batch — extração de nome adiciona latência | Baixa | Médio | Medir overhead; nomeação é operação simples (texto já disponível no block) |

## Context

**Problema (GAP 4):**

O frontend `StructureTreeNode.vue` está correto — exibe `node.name || node.type`. O problema está no **backend**: o pipeline popula `TreeNode.name` com o mesmo valor do `type` (ou não popula). Resultado visível no Boleto Bancário:

```
📄 document
├ 📄 page
│ ├ 📦 header          0/1
│ ├ 📦 flow            0/66
│ │ ├ 📦 section       0/4
│ │ ├ 📦 section       0/14
│ │ │ ├ abc label
│ │ │ ├ abc field
│ │ │ │ ├ abc label
│ │ │ │ └ abc value
│ │ │ ├ ~ likely_dynamic
```

**Problemas concretos:**
1. "label" aparece 4+ vezes sem distinção — operador não sabe qual é qual
2. "likely_dynamic" exposto cru — deveria mostrar texto detectado no PDF (ex: "R$ 1.500,00")
3. "section" aparece 2x — sem nomes descritivos ("Seção Dados Pessoais", "Seção Valores")
4. Nível "page" intermediário não está na spec (Document > Header/Flow/Footer)
5. 0/66 mapeados — provavelmente porque nomes genéricos dificultam auto-mapping

**Onde corrigir:**
- `stage3_structural_analysis.py` — classifica nós como `likely_dynamic`, extrai texto do PDF
- `stage5_template_generation.py` — gera a árvore entregue ao frontend (converte coords + propaga campos)

**Frontend:** Nenhuma mudança necessária — `StructureTreeNode.vue:37` já está correto.

**Referências:**
- `backend/services/stages/stage3_structural_analysis.py` (linhas 85-204) — classificação de nós
- `backend/services/stages/stage5_template_generation.py` (linha 1310) — conversão de coords
- Gap analysis: `docs/architecture/gap-analysis-frontend-v3.md` (GAP 4)
- Spec: `docs/ideias/ux/template_structure_view_spec.md` (Binding Display)

**Dependências:** Nenhuma — pode ser desenvolvida em paralelo com 29.2 e 29.3.

### Estratégia de naming em stage3

Para nós `label`:
```python
# Ao criar um nó label/field, extrair o texto do bloco PDF correspondente
def extract_semantic_name(block: dict) -> str:
    """Extrai texto legível do bloco para usar como nome do nó."""
    text = block.get("text", "").strip()
    if text:
        # Limpar pontuação final (ex: "Cedente:" → "Cedente")
        return text.rstrip(":").strip()[:50]  # Max 50 chars
    return ""  # Fallback: type será usado pelo frontend

# Ao classificar nó como likely_dynamic:
if classification == "likely_dynamic":
    node["name"] = extract_semantic_name(block) or f"Campo {idx+1}"
```

Para nós `section`:
```python
# Usar o primeiro label filho como nome da seção
def infer_section_name(section_node: dict, child_nodes: list) -> str:
    labels = [n for n in child_nodes if n.get("type") == "label"]
    if labels:
        first_label_text = labels[0].get("name", "")
        if first_label_text:
            return f"Seção {first_label_text}"
    return f"Seção {section_node.get('id', 'sem-nome')[:8]}"
```
