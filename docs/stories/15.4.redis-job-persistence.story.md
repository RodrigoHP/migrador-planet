# Story 15.4 — Redis Job Persistence

## Story

**Como** operador da plataforma,
**Quero** que meus jobs de análise sobrevivam a restarts do servidor,
**Para** não perder trabalho em andamento quando o Railway faz redeploy.

## Status

Draft

## Context

### Problema

Todos os jobs ficam em `_pipeline_jobs` dict in-memory (`routers/analyze.py`, line 51). Quando o servidor reinicia (deploy, crash, Railway redeploy), todos os jobs são perdidos — status, resultados, event logs. TD-01 identificado como blocker CRITICAL.

### Estado Atual do Código

**`backend/routers/analyze.py`** (lines 51-63):
```python
_pipeline_jobs: Dict[str, Dict[str, Any]] = {}   # Line 51 — TUDO em memória
_pipeline_tasks: Set[asyncio.Task] = set()        # Line 54
_JOB_TTL_SECONDS = 3600                           # Line 57 — 1 hour
TMP_BASE = Path(os.environ.get("JOBS_DIR", "/tmp/jobs"))  # Line 60
_ORPHAN_TTL_SECONDS = 86_400                      # Line 63 — 24 hours
```

**Job structure** (lines 39-49):
```python
{
    "status": "pending|running|completed|failed|cancelled",
    "result": dict | None,       # Pipeline result JSON (pode ser grande)
    "error": str | None,
    "cancel_flag": asyncio.Event, # Não serializável!
    "event_log": list,            # Replay buffer para SSE
    "new_event": asyncio.Event,   # Não serializável!
    "pipeline_done": bool,
    "created_at": float           # Unix timestamp
}
```

**SSE replay** (`_event_generator`): lê `event_log` list sequencialmente, espera `new_event` para novos.

### Solução

**Criar `backend/services/job_store.py`** — abstraction layer sobre Redis:
1. `JobStore` class com interface: `create_job()`, `get_job()`, `update_status()`, `append_event()`, `get_events()`, `set_result()`, `delete_job()`
2. **RedisJobStore** implementation — Redis hashes para job state, Redis lists para event_log
3. **InMemoryJobStore** implementation — dict atual, fallback para dev local
4. Factory: `create_job_store()` baseado em `REDIS_URL` env var
5. `cancel_flag` via Redis pub/sub channel per job_id
6. `new_event` notification via Redis pub/sub (SSE listener)

### Scope — IN vs OUT

**IN SCOPE:**
- JobStore abstraction (interface + 2 implementations)
- Migrar `_pipeline_jobs` dict → JobStore em `analyze.py`
- Redis hash para job state (status, error, created_at, pipeline_done)
- Redis list para event_log (SSE replay)
- Redis key com TTL para result JSON
- Cancel via Redis pub/sub
- SSE new_event via Redis pub/sub
- Fallback InMemoryJobStore se `REDIS_URL` não configurado
- `redis` package em `requirements.txt`

**OUT OF SCOPE:**
- Job queue (Celery/ARQ) — jobs continuam como asyncio.Task
- Job resume após crash (job em "running" fica "failed" no restart)
- Per-user job isolation (futuro, pós-auth)
- Result compression

## Technical Notes

- **`asyncio.Event` não é serializável:** Substituir por Redis pub/sub. SSE generator faz `subscribe` no channel do job.
- **Result JSON pode ser grande** (~50KB-200KB): Redis suporta, mas considerar EXPIRE separado.
- **Railway Redis addon:** URL no formato `redis://default:password@host:port`. Instalar via Railway dashboard.
- **Padrão StorageGateway:** Seguir mesmo pattern — ABC + factory + implementations.
