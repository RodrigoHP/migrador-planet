# Story 4.4: Hotfix — Bugs na Tela de Identificação de Campos (CamposPage)

## Status

Superseded

## Story

**As a** operador da ferramenta,
**I want** que a tela de Identificação de Campos exiba corretamente os nomes dos campos XSD e permita confirmar o mapeamento sem bloqueios indevidos,
**so that** eu possa revisar e validar os campos extraídos do PDF antes de avançar no fluxo.

## Acceptance Criteria

1. A coluna "Campo XSD" em `FieldMappingTable.vue` exibe `field.jsonPath` (ex: `"nomeCliente"`) e não `field.id` (UUID)
2. O botão "Confirmar Mapeamento" em `CamposPage.vue` usa a mesma lógica do store getter: campo com `isManual: true` não bloqueia o botão mesmo que `status` tenha sido `not_found` antes da edição manual
3. `hasUnresolvedRequired` em `CamposPage.vue` é consistente com o getter `hasUnresolvedRequired` do `useMappingStore` (verifica `!field.isManual && field.status === 'not_found'`)
4. O backend `Matcher` preenche `candidates` com os N melhores matches alternativos (mínimo 0, máximo 3) para cada campo com `confidence < 'high'`
5. O painel `FieldDetailPanel.vue` exibe a seção "Candidatos alternativos" quando `field.candidates` tem ao menos 1 item
6. Clicar em um candidato no painel substitui o `jsonPath` do campo e salva com `isManual: true` e `status: 'ok'`
7. Nenhuma regressão nos fluxos já funcionando: Upload → Extração → CamposPage → Layout → Geração → Exportar

## Dev Notes

### Causa Raiz dos Bugs

**Bug #1 (Crítico):** `FieldMappingTable.vue` usa `field.id` na primeira coluna, mas `field.id` é gerado pelo backend com `uuid.uuid4()`. O nome do campo XSD está em `field.jsonPath`.

```html
<!-- ERRADO (atual) -->
<td>{{ field.id }}</td>

<!-- CORRETO (fix) -->
<td>{{ field.jsonPath }}</td>
```

**Bug #2 (Moderado):** `CamposPage.vue` define `hasUnresolvedRequired` localmente sem verificar `!field.isManual`, divergindo do getter do store. Após `saveField()`, o `status` é setado para `'ok'` então o bug é mascarado na maioria dos casos — mas a inconsistência é um risco técnico e deve ser corrigida.

**Bug #3 (Menor):** `Matcher.match()` nunca preenche o campo `candidates` do modelo `FieldMapping`. A UI de candidatos alternativos existe mas nunca exibe dados.

### Implementação do fix do Matcher (Task 3)

```python
# Em Matcher.match(), após determinar best_confidence e best_pdf_value:

# Coletar top-3 candidatos alternativos (excluindo o best match)
candidate_scores: List[tuple[float, str]] = []
for norm_text, block in norm_blocks:
    if block.text == best_pdf_value:
        continue  # pula o best match já selecionado
    lev = levenshtein_similarity(norm_text, norm_xsd)
    if (norm_xsd in norm_text or norm_text in norm_xsd) and lev < 0.75:
        lev = 0.75
    if lev >= 0.3:
        candidate_scores.append((lev, block.text))

candidate_scores.sort(reverse=True)
candidates = [text for _, text in candidate_scores[:3]]

# Passar candidates ao FieldMapping:
FieldMapping(
    ...
    candidates=candidates if candidates else None,
    ...
)
```
