# Story 27.1 — Debt: Imagens auto-contidas no HTML gerado (base64, todos os backends)

## Story

**Como** usuário que processa PDFs e faz download do template HTML gerado,
**Quero** que todas as imagens (logos, ícones) estejam embutidas diretamente no arquivo,
**Para** que o template funcione sem dependência de servidor, links expirados ou arquivos externos.

## Context

Durante RCA `rca-20260401-y-axis-inversion` foram corrigidos dois bugs de fidelidade visual. O segundo bug (imagens ausentes no canvas) foi **parcialmente** corrigido: o `LocalStorageGateway.upload_asset` agora retorna data URI base64 para imagens, resolvendo ambiente local.

**Problema pendente:** `SupabaseStorageGateway.upload_asset` ainda retorna o storage path (`jobs/{job_id}/assets/{filename}`), não uma URL browser-acessível nem base64. Em produção (Supabase), as imagens continuam ausentes.

**Decisão arquitetural (@architect):** HTML gerado pelo pipeline deve ser sempre auto-contido — imagens embutidas como base64 data URI, independente do storage backend. Para documentos de boleto/fatura (poucas imagens, ~50-200KB cada), o custo de payload é aceitável e o benefício de portabilidade é essencial para o download funcionar sem dependências externas.

**Referência:** `LocalStorageGateway.upload_asset` — implementação já correta, usar como modelo.

## Acceptance Criteria

**AC-1 — SupabaseGateway retorna base64 para imagens:**
`SupabaseStorageGateway.upload_asset` para extensões de imagem (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.bmp`) deve:
- Continuar fazendo upload para Supabase Storage (sem alteração)
- Retornar `data:{mime};base64,{conteúdo}` em vez do storage path

**AC-2 — Arquivos não-imagem inalterados:**
`SupabaseStorageGateway.upload_asset` para extensões não-imagem (`.xsd`, `.json`, `.xml`, `.pdf`) continua retornando o storage path como antes.

**AC-3 — Testes unitários — SupabaseGateway:**
Novo teste em `test_storage_gateway.py` verifica que `SupabaseStorageGateway.upload_asset` para PNG retorna string começando com `data:image/png;base64,`.

**AC-4 — Testes de integração — mocks corrigidos:**
Os 2 testes pré-existentes com falha em `TestSupabaseMockIntegration` (`test_upload_pdf_supabase_mock`, `test_save_result_supabase_mock`) devem ser investigados e corrigidos — a falha é de mock async não aguardado, não de lógica de negócio.

**AC-5 — HTML auto-contido end-to-end:**
Dado um job processado em produção (Supabase configurado), o HTML retornado no resultado do pipeline contém `<img src="data:image/...` e não `<img src="jobs/...` ou `<img src="http...`.

**AC-6 — LocalGateway não modificado:**
`LocalStorageGateway` permanece como está — nenhuma alteração nesse arquivo.

## Dev Notes

**Implementação em `supabase_gateway.py:upload_asset`:**
```python
# Adicionar imports no topo do arquivo:
import base64
import mimetypes
from pathlib import Path

# Modificar upload_asset:
async def upload_asset(self, job_id: str, filename: str, content: bytes) -> str:
    path = f"jobs/{job_id}/assets/{filename}"
    self._supabase.storage.from_("jobs").upload(path, content)
    # Para imagens, retornar data URI (HTML auto-contido, independe de serving)
    ext = Path(filename).suffix.lower()
    _IMAGE_EXTS = {".png", ".jpg", ".jpeg", ".gif", ".webp", ".svg", ".bmp"}
    if ext in _IMAGE_EXTS:
        mime = mimetypes.types_map.get(ext, "image/png")
        b64 = base64.b64encode(content).decode("ascii")
        return f"data:{mime};base64,{b64}"
    return path
```
