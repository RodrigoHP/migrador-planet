# Story 41.10: SVG Inline — FR32 implementation

## Status
Done

## Story
**As a** operador,
**I want** que ao ativar "Incorporar como SVG inline" no ImageInspector, o template gerado e o export contenham a tag `<svg>` diretamente no HTML,
**so that** imagens vetoriais do PDF sejam reproduzidas fielmente sem depender de arquivo externo ou conversão lossy para PNG.

## Context

### Problema identificado (@architect + @aios-master, 2026-04-09)

O toggle "Incorporar como SVG inline" no `ImageInspector.vue` **já funciona** para:
1. Buscar o SVG pelo src do nó
2. Sanitizá-lo via `sanitizeSvg()` (`svgSanitizer.ts`)
3. Salvar `svgInlineContent` e `svgInline: true` nas propriedades do nó no `templateStore`

Porém a propriedade `svgInlineContent` **nunca é lida** em nenhum ponto downstream:

| Ponto | Comportamento atual | Comportamento esperado |
|-------|--------------------|-----------------------|
| `useExport.ts` | Ignora `svgInline` — gera `<img src="...">` | Substituir por `<svg>` quando `svgInline: true` |
| Canvas (HTMLCanvas) | Exibe HTML do backend — sem substituição | Refletir `svgInlineContent` no preview |
| Template HTML (codeStore) | Não considera `svgInline` | Emitir `<svg>` no lugar de `<img>` |

O resultado: operador ativa o toggle, vê feedback de sucesso ("SVG incorporado!"), mas o export e o canvas continuam usando `<img>`.

### Escopo desta story

Focar no **wiring** — conectar `svgInlineContent` ao pipeline de geração. A infraestrutura (toggle, sanitizador, armazenamento no nó) já existe.

A detecção automática de SVGs vetoriais no PDF (stage3 via PyMuPDF `get_drawings()`) fica **fora do escopo** — é uma story de melhoria futura.

### Lógica de substituição no export

```typescript
// Função pura — fácil de testar
function replaceImgWithSvgInline(html: string, nodes: TreeNode[]): string {
  let result = html
  for (const node of nodes) {
    if (node.type !== 'image') continue
    if (!node.properties['svgInline'] || !node.properties['svgInlineContent']) continue

    const svgContent = node.properties['svgInlineContent'] as string
    const nodeId = node.id

    // Extrair style do <img> para preservar posicionamento
    const imgRegex = new RegExp(
      `<img[^>]*id=["']${nodeId}["'][^>]*style=["']([^"']*)["'][^>]*>`,
      'i'
    )
    result = result.replace(imgRegex, (_, style) => {
      // Injetar style de posicionamento na tag <svg>
      return svgContent.replace('<svg', `<svg id="${nodeId}" style="${style}"`)
    })
  }
  return result
}
```

Chamar após a geração do HTML no export, antes de adicionar ao ZIP.

### Limpar propriedades ao desativar toggle (AC5)

```typescript
// ImageInspector.vue — watch no svgInline
watch(svgInline, (newVal) => {
  if (!newVal && props.node?.id) {
    templateStore.updateNodeProperty(props.node.id, 'svgInline', false)
    templateStore.updateNodeProperty(props.node.id, 'svgInlineContent', '')
```

### Limitação conhecida (fora de escopo)

O canvas exibe `generationStore.templateDraft.html` que vem do backend. A substituição no canvas (AC3) pode requerer um mecanismo de patch do HTML gerado quando propriedades do nó mudam — avaliar durante implementação se isso é viável ou se o canvas AC3 deve ser deferido para uma story de sync.

Se o mecanismo de patch do canvas for complexo, o AC3 pode ser marcado como **DEFERRED** e a story entregue apenas com export (AC1-2) + toggle cleanup (AC5) + testes (AC6-7).
