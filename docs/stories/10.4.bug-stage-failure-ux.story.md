# Story 10.4: Bug — Stage com falha não fica vermelha + TOTAL_STAGES frágil

## Status
Done

## Story
**As a** operador,
**I want** que quando uma stage do pipeline falhar, eu veja exatamente qual stage falhou (em vermelho) e uma mensagem clara do erro,
**so that** eu possa entender o problema e decidir se reprocesso ou reporto ao suporte.

## Acceptance Criteria
1. Quando o backend emite `status: "failed"` para uma stage, essa stage é exibida com ✗ em vermelho na UI
2. Quando o pipeline falha (qualquer stage), a UI para de tentar reconectar e exibe a mensagem de erro da stage com falha
3. A reconexão automática só ocorre para falhas de rede (SSE cai inesperadamente), não para falhas de pipeline
4. A detecção de conclusão do pipeline não depende exclusivamente de `data.stage === TOTAL_STAGES` hardcoded — deve ser robusta a mudanças no número de stages
5. `npm run build` e `vitest` passam sem erros

## Bugs Identificados

### Bug 3 — ALTO: Stage com falha não exibe UI correta + lógica de reconexão errada
- **Causa:** Quando o backend emite um evento `status: "failed"` para uma stage, o frontend atualiza `stagesStatus` corretamente para `'failed'` (linha ~289). MAS, quando o stream fecha (sentinel `None`), o `onerror` do EventSource dispara e o frontend tenta reconectar 3x. Após 3 tentativas, exibe "Conexão perdida" em vez de "Stage X falhou."
- **Sintoma:** Usuário vê "Conexão perdida" após falha de pipeline. A stage com falha fica vermelha por um momento, mas a tela muda para o banner de "Conexão perdida" de cor amarela.
- **Arquivo:** `frontend/src/pages/AnalyzingPage.vue` — `onerror` handler (linha ~338) e `addEventListener('error', ...)` (linha ~326)
- **Fix:**
  - Distinguir entre "falha de pipeline" (backend emitiu `status: failed` → stream fecha normalmente) e "falha de rede" (stream fechou sem event de falha)
  - Adicionar flag `pipelineFailed: boolean` que é setada quando qualquer event com `status: 'failed'` é recebido
  - No `onerror`: se `pipelineFailed === true`, NÃO reconectar — mostrar mensagem da stage que falhou
  - Se `pipelineFailed === false` (queda de rede) → manter lógica de reconexão atual

### Bug 6 — MÉDIO: Detecção de conclusão via `TOTAL_STAGES = 28` hardcoded é frágil
- **Causa:** A condição `data.stage === TOTAL_STAGES && data.status === 'completed'` usa a constante `TOTAL_STAGES = 28` definida em `analyzingPageConstants.ts`. Se o backend adicionar ou remover stages, essa constante fica dessincronizada silenciosamente — o pipeline completará no backend mas o frontend nunca navegará para `/editor`.
- **Sintoma:** Não há sintoma imediato, mas qualquer mudança no número de stages do pipeline quebra o fluxo silenciosamente.
- **Arquivo:** `frontend/src/pages/analyzingPageConstants.ts` e `frontend/src/pages/AnalyzingPage.vue`
- **Fix (pragmático):** O backend deve emitir um evento explícito de "pipeline_completed" ao final. No frontend, escutar por esse evento para acionar `fetchAndLoadResult()`. Como fallback (retrocompatibilidade), manter a detecção por `TOTAL_STAGES` mas também aceitar o evento explícito.
  - **Alternativa mais simples:** O backend emite `status: "completed"` sem `block`/`stage` como evento especial de conclusão. O frontend detecta `data.status === 'completed' && data.block === undefined`.

## Dev Notes
- O `onerror` do EventSource dispara tanto para falhas de rede quanto para fechamento normal do stream após um evento `failed` no backend — não há distinção nativa. A flag `pipelineFailed` é a forma correta de distinguir.
- `addEventListener('error', ...)` no código atual tenta parsear o evento como JSON (linha ~326) — isso está errado porque eventos de erro do EventSource não têm dados JSON. Esse handler pode ser removido ou simplificado.
- Para Bug 6: verificar o número real de stages no backend — `pipeline.total_stages` em `analyze.py` linha 102 vem de `default_registry.build_pipeline().total_stages`. Contar stages em `backend/services/stages/` para confirmar se é exatamente 28.
- O evento explícito `pipeline_completed` é a solução mais robusta e elimina o acoplamento com `TOTAL_STAGES`.
