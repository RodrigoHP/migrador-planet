# Story 18.3 — Workflow Unification

## Story
**Como** operador que executa ciclos de desenvolvimento,
**Quero** um unico workflow canonico que combine as melhores features dos dois workflows existentes (story-development-cycle.yaml + development-cycle.yaml),
**Para** que nao haja ambiguidade sobre qual usar e que self-healing, push e checkpoint funcionem em todos os modos.

## Status
Draft

## Context

### Problema

Existem dois workflows de development cycle com capacidades diferentes:

| Feature | story-development-cycle.yaml | development-cycle.yaml |
|---------|------|------|
| Phases | 4 (SM→PO→Dev→QA) | 6 (PO→Executor→SelfHeal→QA→Push→Checkpoint) |
| Engine yolo_continuous | SIM (usado pelo engine) | NAO (nao integrado) |
| Dynamic executor | NAO (hardcoded @dev) | SIM (`${story.executor}`) |
| Self-healing (CodeRabbit) | NAO | SIM (phase 3) |
| Push integrado (@devops) | NAO | SIM (phase 5) |
| Checkpoint humano | NAO | SIM (phase 6: GO/PAUSE/ABORT) |
| Terminal spawning | NAO | SIM (Story 11.2) |

O `story-development-cycle.yaml` e usado pelo engine mas lhe falta self-healing e push. O `development-cycle.yaml` tem tudo mas nao e usado pelo engine yolo_continuous.

### Design

#### Workflow unificado: `story-development-cycle.yaml` v2.0

Manter o ID `story-development-cycle` (backward compat) e incorporar as features do `development-cycle.yaml`:

```yaml
workflow:
  id: story-development-cycle
  name: Story Development Cycle
  version: "2.0"

  phases:
    - phase_1: Story Creation        # @sm (existente)
    - phase_2: Story Validation      # @po (existente)
    - phase_3: Implementation        # ${story.executor} (upgrade: dynamic)
    - phase_4: Self-Healing          # @dev (NOVO: do development-cycle)
    - phase_5: QA Review             # @qa (existente)
    - phase_6: Push & PR             # @devops (NOVO: do development-cycle)
    - phase_7: Checkpoint            # @po (NOVO: do development-cycle)
```

#### Regras de merge

1. **Dynamic executor** — Phase 3 usa `${story.executor}` do frontmatter da story (fallback: @dev)
2. **Self-healing** — Phase 4 condicional (`condition: coderabbit_integration.enabled`), skip se desabilitado
3. **Push** — Phase 6 so no yolo_continuous; em interactive, checkpoint pergunta primeiro
4. **Checkpoint** — Phase 7 com GO/PAUSE/REVIEW/ABORT; em yolo, auto-GO para proxima story
5. **Failure context** — Usa {{FAILURE_CONTEXT}} da Story 18.1 nos retries
6. **Handoff consumption** — Usa {{HANDOFF_DATA}} da Story 18.2 nas transicoes

#### Backward compatibility

- O workflow ID `story-development-cycle` e mantido — runs existentes nao quebram
- `development-cycle.yaml` renomeado para `development-cycle.yaml.deprecated` com redirect
- State files existentes funcionam normalmente (novos campos sao opcionais)
- O checkpoint em yolo_continuous mode auto-seleciona GO (sem parada)
