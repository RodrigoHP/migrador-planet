# Story 11.6 — Corrigir useSSE.ts endpoint e remover dead code

## Story
**Como** desenvolvedor do sistema,
**Quero** que o composable `useSSE.ts` aponte para o endpoint correto do pipeline canônico,
**Para** que qualquer componente que precise de SSE use o endpoint atualizado (analyze.py) e não o legacy.

## Status
Done

## Context
O audit identificou que `useSSE.ts` está hardcoded para `/api/progress/${id}` — o endpoint do sistema **legacy** (`progress.py`), que será removido em 11.1.

```typescript
// useSSE.ts:30 — ENDPOINT LEGADO (será removido)
eventSource.value = new EventSource(`${API_BASE}/api/progress/${id}`)
```

O `AnalyzingPage.vue` não usa `useSSE.ts` — implementou seu próprio SSE diretamente. Isso levanta a questão: useSSE.ts é usado em algum lugar do editor? Se não, deve ser removido. Se sim, precisa ser atualizado.

## Acceptance Criteria

1. **Audit de uso** — Mapa completo de onde `useSSE.ts` é importado no projeto.
2. **Sem endpoint legacy** — `useSSE.ts` não referencia `/api/progress/` em nenhuma versão final do código.
3. **Opção A (se usado):** `useSSE.ts` atualizado para conectar a `/api/analyze/{id}/progress` com suporte ao formato de evento do novo pipeline.
4. **Opção B (se não usado):** `useSSE.ts` removido do projeto; nenhum import restante.
5. **AnalyzingPage SSE** — O SSE inline do `AnalyzingPage.vue` extraído para composable reutilizável (se Opção A).
6. **Testes** — Composable SSE testado com mock de EventSource.

## Tasks

- [x] 1. Grep por `useSSE` em todo `frontend/src/` — mapear todos os imports e usos
- [x] 2. Decidir: Opção A (atualizar) ou Opção B (remover)
- [x] 3b. **Opção B escolhida:** Remover `useSSE.ts`; verificar se `AnalyzingPage.vue` precisa de refactor para extrair SSE em composable reutilizável
- [x] 4. Atualizar ou remover testes relacionados ao `useSSE.ts`
- [x] 5. Executar suite frontend completa
