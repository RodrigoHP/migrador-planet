# Story 10.11: Bug — Stages 12, 15, 16: Layout Intelligence

## Status
Ready for Review

## Story
**As a** operador,
**I want** que os Stages 12, 15 e 16 (Layout Alignment, Variant Detection, Intelligence Normalization) processem dados reais de layout e escrevam resultados enriquecidos no contexto,
**so that** o `_stability_map` e `intelligence` no contexto contenham dados úteis para o campo-mapping e template draft dos stages seguintes.

## Acceptance Criteria
1. Os três stages estão registrados em `register_bloco4()` do `register_all.py` — nenhum stub residual no registry para os Stages 12, 15 ou 16
2. Após Stage 12 (Layout Alignment): `context["alignment_offsets"]` é um dict não-vazio com `cluster_id → {pdf_index → (dx, dy)}` e `context["_aligned"] == True`; em modo single-document os offsets são `(0.0, 0.0)` para cada pdf_index
3. Após Stage 15 (Variant Detection): `context["_variants"]` e `context["_conditional_sections"]` existem como dicts indexados por `cluster_id`; em modo single-document ambos são dicts com listas vazias (não crash, não KeyError)
4. Após Stage 16 (Intelligence Normalization): `context["intelligence"]` contém pelo menos um cluster com as chaves `labels`, `dynamic_fields`, `stability_map`, `variants`, `conditional_sections`, `metadata`; e `context["layout_types"]` é re-serializado com dados enriquecidos
5. `pytest backend/tests/` passa sem erros após qualquer alteração

### O que cada stage faz atualmente

**Stage 12 — Layout Alignment**
- Lê `_layout_type_objects` (List[LayoutType]) e `_skeleton_objects` (List[LayoutSkeleton])
- Single-document: todos os offsets são `(0.0, 0.0)`, seta `intelligence_metadata["single_document"] = True` e `reduced_accuracy = True`
- Multi-document: para cada cluster, computa `_median_origin` do primeiro text_block de cada skeleton, usa o PDF com menor `pdf_index` como referência, calcula `(dx, dy) = (ref_x - ox, ref_y - oy)` para cada PDF
- Escreve: `context["alignment_offsets"]`, `context["_aligned"] = True`

**Stage 15 — Variant Detection**
- Lê `_stability_map`, `_element_labels`, `_layout_type_objects`, `_skeleton_objects`, `intelligence_metadata`
- Single-document: pula detecção de variantes (impossível sem múltiplos docs), escreve listas vazias
- Multi-document: classifica elementos "absent" como `optional_field`, agrupa adjacentes (Y < 30px) como `conditional_section`, detecta variação de contagem de tabelas como `dynamic_table`
- Constante `_MIN_SECTION_SIZE = 2` — mínimo de elementos absent para declarar seção condicional
- Escreve: `context["_variants"]`, `context["_conditional_sections"]`

**Stage 16 — Intelligence Normalization**
- Lê `_layout_type_objects`, `_element_labels`, `_stability_map`, `_variants`, `_conditional_sections`, `intelligence_metadata`
- Constrói `intelligence[cluster_id]` com labels, dynamic_fields, stability_map, variants, conditional_sections e metadata summary
- Anexa `_intelligence` em cada `LayoutType` object
- Re-serializa `layout_types` list para `context["layout_types"]`
- Escreve: `context["intelligence"]`, `context["layout_types"]`
