# Story 15.17 — Fix summary emit + api_cost + revisão alterações não autorizadas do @qa

## Story
**Como** operador que acompanha o pipeline pela AnalyzingPage,
**Quero** que os stages 1, 2 e 5 emitam métricas reais no accordion e que o custo da API apareça no sumário final,
**Para** ter visibilidade completa do processamento e saber quanto custou a execução.

## Status
Done

## Context

### FIX-PIPELINE-004: Stages 1, 2 e 5 sem emit de summary

O frontend acumula métricas por stage via `stageSummaries` — alimentado por eventos SSE com campo `summary`. Stage 3 emite summary corretamente. Stages 1, 2 e 5 não emitiam → accordion mostra "Concluído com sucesso" sem detalhes.

**Summaries esperados:**
- Stage 1: `{"layouts_detected": N, "pages_processed": M}` — dados reais de `final_clusters`
- Stage 2: `{"pages_processed": N, "blocks_extracted": M}` — dados reais do enrichment
- Stage 5: `{"fields_templated": N, "html_size_bytes": M}` — dados reais do template gerado

### FIX-PIPELINE-005: api_cost ausente do completion event

Completion event original não incluía `api_cost`:
```python
summary={
    "layouts_detected": len(clusters),
    "page_count": sum(c.get("page_count", 0) for c in clusters),
    # ⚠️ FALTANDO: api_cost
}
```
O frontend lê `s.api_cost` para `summaryData.apiCost`. Como nunca era emitido → exibia "—".

**Fix esperado:**
```python
summary={
    "layouts_detected": len(real_clusters),  # excluir _blank/_scanned
    "page_count": total_pages,
    "api_cost": round(context.get("_vision_api_calls", 0) * COST_PER_VISION_CALL, 4),
}
```
Onde `COST_PER_VISION_CALL` é `ESTIMATED_COST_PER_VISION_CALL` já definida em `openrouter_client.py`.
