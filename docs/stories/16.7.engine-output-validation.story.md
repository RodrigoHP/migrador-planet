# Story 16.7 — Output Validation

## Story
**Como** operador que executa workflows com `requires` chains entre steps,
**Quero** que o engine valide que cada step produziu todos os outputs declarados antes de avancar,
**Para** que steps downstream nao recebam valores null por outputs faltantes e falhem de forma obscura.

## Status
Draft

## Context

### Problema

Cada step define `outputs:` no workflow YAML (ex: `["root_cause_statement", "five_whys_chain"]`). O engine NAO valida se o subagente realmente produziu esses outputs. Se um campo eh omitido:
- Engine armazena o que foi fornecido
- Step downstream referencia via `requires` → recebe null
- Downstream falha ou produz garbage
- Routing conditions que dependem do campo avaliam como false

Resultado: falhas cascata silenciosas que sao dificeis de diagnosticar.

### Referencia

- Engine: `.aios-core/development/tasks/run-workflow-engine.md` (v3.0)
- Workflow outputs: campo `outputs` por step no YAML

### Design Proposto

**Validacao pos-parse:**
```
FUNCTION validate_outputs(parsed_output, step):
  expected = step.outputs or []
  provided = keys(parsed_output.outputs)
  missing = expected - provided

  IF missing.length > 0:
    IF retries < max:
      retry com OUTPUT_REMINDER
    ELSE:
      on_failure ou ABORT
```

**Output Reminder** no retry:
```
## OUTPUT REMINDER
You MUST provide ALL of these outputs:
- root_cause_statement: ...
- five_whys_chain: ...
Your previous attempt was missing: five_whys_chain
```

## Acceptance Criteria

- [ ] AC1: Engine valida outputs declarados vs outputs fornecidos apos parse de cada step
- [ ] AC2: Outputs faltantes causam retry automatico com output reminder (max 2 retries)
- [ ] AC3: Output reminder lista campos esperados e quais estao faltando
- [ ] AC4: Apos esgotar retries, segue fluxo normal: `on_failure` se definido, senao ABORT
- [ ] AC5: Outputs extras (nao declarados) sao aceitos silenciosamente com log info
- [ ] AC6: Steps sem campo `outputs` declarado no YAML pulam validacao
- [ ] AC7: Execution log registra eventos `output_validation_failed` e `output_validation_retry`
- [ ] AC8: Final Report inclui secao "Output Validation" com missing fields por step

## Complexity

**T-shirt size:** S (Small)
**Estimativa:** Comparacao de listas, retry com reminder, logging.

## Scope

**IN:**
- `.aios-core/development/tasks/run-workflow-engine.md` — validacao pos-parse, retry, reminder
- Reutilizar mecanismo de retry da Story 16.5 (parse_failure_retry)

**OUT:**
- Nao validar tipo/formato dos outputs (apenas presenca)
- Nao alterar workflows existentes (campo outputs ja existe)
- Nao implementar schema validation (futuro)

## Implementation Notes

### Subtasks

1. Apos parse de output, extrair `expected_outputs` do step definition no workflow
2. Comparar com keys fornecidas no `parsed_output.outputs`
3. Se missing: retry com OUTPUT_REMINDER (reutilizar mecanismo de retry de 16.5)
4. Se extras: log info, aceitar silenciosamente
5. Se step nao tem campo `outputs`: pular validacao
6. Registrar eventos no execution_log
7. Atualizar Final Report com secao "Output Validation"
8. Testar: step que omite 1 de 3 outputs deve ser retried

## Validation & Testing

| # | Cenario | Input | Expected |
|---|---------|-------|----------|
