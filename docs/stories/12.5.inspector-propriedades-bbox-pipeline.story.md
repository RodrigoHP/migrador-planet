# Story 12.5 — Bug: Inspector mostra '—' para todas as propriedades de elemento

## Story
**Como** usuário do editor,
**Quero** que ao selecionar um elemento no canvas ou na árvore, o Inspector mostre suas propriedades reais,
**Para** poder editar posição, tamanho e fonte do elemento.

## Status
Done

## Context

### Problema
O painel Inspector (lado direito) mostra "—" para `x`, `y`, `width`, `height`, `font_family`, `font_size` ao selecionar qualquer elemento.

### Estado Após Story 11.5
A story 11.5 corrigiu que o Inspector inicializava corretamente (`inspectorStore.initFromTree()` é chamado). Porém, o problema persiste porque as **propriedades bbox** não estão presentes nos `TreeNode.properties`.

### Root Cause

**`backend/services/stages/pipeline_result.py`**

Função `_build_tree()` constrói o `document_structure.root`, mas os `properties` de cada nó não incluem `x`, `y`, `width`, `height`:

```python
def _build_node(block):
    return {
        "id": block["id"],
        "type": block.get("semantic_label", "text"),
        "name": block.get("text", "")[:30],
        "binding": None,
        "isOptional": False,
        "children": [],
        "properties": {
            "text": block.get("text", ""),
            "font_name": block.get("font_name"),
            "font_size": block.get("font_size"),
            # ← FALTA: x, y, width, height derivados de bbox!
        }
    }
```

**`frontend/src/organisms/ElementInspector.vue`**
```vue
<InspectorRow label="X" :value="node.properties.x" />  <!-- undefined → "—" -->
<InspectorRow label="Y" :value="node.properties.y" />  <!-- undefined → "—" -->
```

### Solução

**Backend `pipeline_result.py::_build_node()`:**
```python
def _build_node(block, page_width=595, page_height=842):
    bbox = block.get("bbox")
    SCALE_X = 794 / page_width
    SCALE_Y = 1123 / page_height

    properties = {
        "text": block.get("text", ""),
        "font_family": block.get("font_name", ""),
        "font_size": block.get("font_size"),
        "semantic_label": block.get("semantic_label", ""),
        "visibility": True,
    }

    if bbox and len(bbox) == 4:
        x0, y0, x1, y1 = bbox
        # Converter PDF coords (bottom-left origin) para CSS (top-left origin)
        properties.update({
            "x": round(x0 * SCALE_X, 1),
            "y": round((page_height - y1) * SCALE_Y, 1),
            "width": round((x1 - x0) * SCALE_X, 1),
            "height": round((y1 - y0) * SCALE_Y, 1),
            "bbox_raw": bbox,  # Para referência
        })

    return {
        "id": block["id"],
        "type": _classify_node_type(block),
        "name": block.get("text", "")[:40] or block.get("semantic_label", "element"),
        "binding": block.get("xsd_field_path"),
        "isOptional": False,
        "children": [],
        "properties": properties,
    }
```

**Frontend — Sem mudanças necessárias** (ElementInspector.vue já lê `node.properties.x`)

## Acceptance Criteria

1. **AC1 — Propriedades básicas:** x, y, width, height mostram valores numéricos (não "—")
2. **AC2 — Fonte:** font_family e font_size mostram valores extraídos do PDF
3. **AC3 — Sem bbox:** Elementos sem bbox mostram "N/A" ou "0" com tooltip explicativo
4. **AC4 — Edição:** Alterar x/y no inspector move o elemento no canvas (ligado via templateStore)
5. **AC5 — Coordenadas CSS:** Valores exibidos são em pixels CSS (não pontos PDF)
6. **AC6 — Testes:** `pipeline_result.py` coberto com tests verificando properties.x, properties.y
