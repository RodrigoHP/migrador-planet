# Story 41.4 — Database & Redis Resilience

## Status: Done

## Descricao

Melhorar resiliencia da camada de dados: adicionar rollback migrations, implementar soft-delete para jobs com cleanup atomico, e adicionar retry/reconnection para Redis. Resolve 5 debitos relacionados a durabilidade e operacoes de dados.

## Debitos Enderecados

| ID | Debito | Severidade | Esforco |
|----|--------|-----------|---------|
| DB-006 | Sem rollback migrations (down migrations) | MEDIUM | 6h |
| DB-011 | Sem soft-delete para jobs (hard delete perde historico) | MEDIUM | 3h |
| DB-015 | Storage listing recursiva nao atomica (cleanup parcial) | MEDIUM | 3h |
| REDIS-002 | Sem retry/reconnection no Redis client | MEDIUM | 4h |
| REDIS-003 | scan_iter em all_jobs() pode ser lento com muitas keys | LOW | 1h |

## Acceptance Criteria

- [x] Cada migration tem down migration correspondente
- [x] `supabase db reset` funciona com rollbacks
- [x] Jobs deletados marcados com `deleted_at` (soft-delete) em vez de DELETE
- [x] Query de listagem exclui soft-deleted por padrao
- [x] Storage cleanup atomico: deletar arquivos + marcar job como deleted em transacao
- [x] Redis client com retry automatico (3 tentativas, backoff exponencial)
- [x] Redis health check na rota /health
- [x] all_jobs() usa SCAN com cursor em vez de KEYS pattern
- [x] Testes de integracao para retry e soft-delete

## Escopo

### IN
- Down migrations para todas as migrations existentes
- Coluna `deleted_at` em jobs + query filter
- Storage cleanup transacional
- Redis retry com backoff
- Redis health check endpoint
- Otimizacao de all_jobs() com SCAN

### OUT
- Circuit breaker completo (complexidade excessiva para volume atual)
- Redis Sentinel/Cluster (single instance suficiente)
