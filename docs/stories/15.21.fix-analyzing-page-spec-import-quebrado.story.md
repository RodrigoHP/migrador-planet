# Story 15.21 — Fix import quebrado em AnalyzingPage.spec.ts

## Story
**Como** desenvolvedor que roda a suite de testes,
**Quero** que `AnalyzingPage.spec.ts` importe o módulo correto (`analyzingPageConstantsV2`),
**Para** que o arquivo de spec não falhe com erro de transform antes de executar qualquer teste.

## Status
Draft

## Context

### Achado Colateral — RCA 2026-03-29 (PR #42)

Durante investigação RCA da AnalyzingPage, foi identificado que `AnalyzingPage.spec.ts` importa um módulo renomeado:

```typescript
// Atual (QUEBRADO):
import { PIPELINE_BLOCKS, TOTAL_STAGES, getStageIndex } from './analyzingPageConstants'

// Esperado:
import { ... } from './analyzingPageConstantsV2'
```

O arquivo `analyzingPageConstants.ts` (sem sufixo V2) **não existe mais** — foi renomeado para `analyzingPageConstantsV2.ts` em uma story anterior do Epic 13 (pipeline redesign). O spec nunca foi atualizado.

**Sintoma:** Vitest falha na fase de transform com `Cannot find module './analyzingPageConstants'` — nenhum teste do arquivo chega a executar.

**Impacto:** 1 test file falho em toda a suite. Os 1403 testes restantes passam normalmente.

**Anti-pattern registrado:** AP-002 — import de arquivo renomeado em spec sem atualização.

### Análise de Impacto

O spec atual testa com `PIPELINE_BLOCKS`, `TOTAL_STAGES` e `getStageIndex` que existiam no formato V1 (28 stages granulares). O módulo V2 (`analyzingPageConstantsV2.ts`) usa estrutura diferente:
- `PIPELINE_V2_STAGES` (5 stages)
- `TOTAL_V2_STAGES = 5`
- Sem `getStageIndex` (não mais necessário)

O spec precisará ser **atualizado para refletir a API V2**, não apenas ter o import corrigido.

## Scope

### IN
- Atualizar imports em `frontend/src/pages/AnalyzingPage.spec.ts`
- Adaptar ou remover testes que referenciam API V1 (`PIPELINE_BLOCKS`, `TOTAL_STAGES`, `getStageIndex`)
- Adicionar testes equivalentes para API V2 onde fizer sentido

### OUT
- Não recriar `analyzingPageConstants.ts` (arquivo V1) — foi intencionalmente renomeado
- Não alterar `analyzingPageConstantsV2.ts` para compatibilidade retroativa
- Não modificar `AnalyzingPage.vue` ou lógica de runtime
