# Story 22.2: Adicionar validação de migrations Supabase no CI

## Status
Done

## Story
**As a** desenvolvedor,
**I want** que o CI valide as migrations do Supabase a cada push,
**so that** migrations com FK orphan, sintaxe inválida ou dependências quebradas
sejam detectadas antes de chegar em produção.

## Contexto
Durante investigação PGRST205 (2026-03-31), identificou-se que a migration
`20260322000001_create_job_clusters.sql` tinha uma FK para `public.jobs` que não
existia. O CI nunca detectou porque roda apenas com `STORAGE_MODE=local` e
nunca executa `supabase db push`.

O bug chegou em produção e causou falha na Stage 5 do pipeline.

## Acceptance Criteria

1. CI executa `npx supabase db push --dry-run` em cada push para `main` e em PRs
2. Job falha se alguma migration tiver erro de sintaxe ou dependência quebrada
3. `SUPABASE_ACCESS_TOKEN` configurado como secret no repositório GitHub
4. Step de validação roda em menos de 2 minutos
5. Jobs de backend e frontend existentes não são afetados
6. `README` ou comentário no workflow documenta como configurar o secret

## Scope

**IN:**
- Adicionar step de validação de migrations em `.github/workflows/ci.yml`
- Configurar secret `SUPABASE_ACCESS_TOKEN` nas instruções

**OUT:**
- Não alterar jobs `backend` e `frontend` existentes
- Não fazer deploy automático
- Não adicionar `STORAGE_MODE=supabase` nos testes (F-4 descartada)

## Dev Notes

**Step a adicionar em `.github/workflows/ci.yml`:**
```yaml
migrations:
  name: Validate Migrations
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4

    - name: Setup Node.js
      uses: actions/setup-node@v4
      with:
        node-version: "20"

    - name: Validate Supabase migrations
      env:
        SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}
      run: |
        npx supabase link --project-ref xrmlhuytgebovrgtzypl
        npx supabase db push --dry-run
```

**Secret necessário:**
- Nome: `SUPABASE_ACCESS_TOKEN`
- Valor: token gerado em supabase.com/dashboard/account/tokens (formato `sbp_...`)
- Configurar em: GitHub → Settings → Secrets and variables → Actions
