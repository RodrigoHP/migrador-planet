## Story

**As a** template developer,
**I want** the `template_name` provided during upload to be persisted in the job state and propagated through the pipeline result,
**so that** the frontend can display it in the toolbar, use it when saving the project, and default the ZIP export filename to the template name.

## Acceptance Criteria

1. [ ] `template_name` persistido no `job_state` durante upload (hoje aceito mas nao salvo)
2. [ ] Propagado para o pipeline result
3. [ ] Frontend exibe nome na toolbar e no save do projeto
4. [ ] Nome usado como default no filename do ZIP de export

## Scope

**IN:**
- Backend: `upload.py` — salvar `template_name` no job_state apos upload
- Backend: `analyze.py` — propagar `template_name` do job_state para o pipeline result
- Backend: `job_store.py` — incluir `template_name` na estrutura do job_state (ambas implementacoes: InMemory e Redis)
- Frontend: `TopToolbar.vue` — exibir `template_name` na toolbar
- Frontend: `session.ts` — garantir que `template_name` e populado a partir do pipeline result
- Frontend: `useExport.ts` — usar `template_name` como default no filename do ZIP (ja usa, validar integracao)
- Testes unitarios para persistencia e propagacao

**OUT:**
- Alteracao de UI/UX da toolbar (apenas exibir o nome)
- Renomear template_name em runtime (fora do escopo)
- Validacao de caracteres especiais no template_name (extensao futura)
- Alteracao no endpoint de upload alem de salvar o campo

## Dependencies

- `backend/routers/upload.py` — endpoint `/upload` que recebe `template_name: str = Form("")` mas nao persiste
- `backend/routers/analyze.py` — pipeline runner que usa `job_state` e emite resultado
- `backend/services/job_store.py` — `InMemoryJobStore` e `RedisJobStore` com `create_job()`
- `frontend/src/stores/session.ts` — `SessionStore` que ja tem campo `template_name: string | null`
- `frontend/src/organisms/TopToolbar.vue` — toolbar que pode exibir o nome
- `frontend/src/composables/useExport.ts` — export que ja usa `sessionStore.template_name ?? 'template'`

## Risks

## Dev Notes

### Arquitetura do Gap

O `template_name` ja e aceito no endpoint `/upload` (`upload.py` linha 36: `template_name: str = Form("")`), mas o valor e descartado — nao e salvo no `job_state` nem propagado ao pipeline. O frontend ja tem infraestrutura para usar o campo:

- `session.ts` define `template_name: string | null` no `SessionStore` (linha 146)
- `useExport.ts` ja usa `sessionStore.template_name ?? 'template'` como filename do ZIP (linha 280)
- `TopToolbar.vue` ja referencia `template_name`

O gap e exclusivamente na **ponte backend**: salvar no `job_state` durante upload e incluir no `result` do pipeline.

### Estrutura do job_state

`job_store.py` tem duas implementacoes:
- `InMemoryJobStore.create_job()` (linha 39): retorna dict com `status`, `result`, `error`, `cancel_flag`, `event_log`, `new_event`, `pipeline_done`, `created_at`
- `RedisJobStore.create_job()` (linha 115): mesma estrutura com serializacao Redis

Ambas retornam um dict mutavel — basta adicionar `job_state["template_name"] = template_name` apos criacao.

### Pipeline result

Em `analyze.py`, o `_run_pipeline` (linha ~240) seta `job_state["result"] = result` ao final. O result e um dict que e retornado ao frontend via SSE/polling. Incluir `template_name` neste dict.

### Source Tree Relevante

```
backend/
  routers/upload.py          — endpoint /upload, recebe template_name
  routers/analyze.py         — pipeline runner, job_state management
  services/job_store.py      — InMemoryJobStore + RedisJobStore

  src/stores/session.ts      — SessionStore com template_name
  src/organisms/TopToolbar.vue    — toolbar
  src/composables/useExport.ts    — export ZIP
```
