# Story 10.10: Bug — Stage 3: Text Reconstruction

## Status
Ready for Review

## Story
**As a** operador,
**I want** que o Stage 3 (Text Reconstruction) processe e mescle blocos de texto fragmentados corretamente,
**so that** os documentos em `parsed_documents` saiam com texto de qualidade superior ao Stage 2, com palavras e linhas reconstruídas de forma coerente para uso nos stages seguintes.

## Acceptance Criteria
1. `backend/services/stages/text_reconstruction.py` está registrado em `register_all.py` via `register_bloco2()` e é chamado pela `register_all()` no startup — nenhum stub residual no registry para o Stage 3
2. Dado um `parsed_documents` com blocos fragmentados na mesma linha (ex: `"Cl"` + `"iente"` com gap < 1 char width), o Stage 3 produz um único bloco `"Cliente"` (merge correto)
3. Dado dois blocos de fontes diferentes (`Arial` vs `Times`) na mesma posição Y, o Stage 3 NÃO os mescla (respeita `_same_font`)
4. Após a execução do Stage 3, `context["parsed_documents"]` tem `blocks_after <= blocks_before` (nunca cria blocos novos) e o dict de retorno contém as chaves `blocks_before`, `blocks_after`, `merged`
5. `pytest backend/tests/` passa sem erros após qualquer alteração

## Dev Notes

### Arquivo
`backend/services/stages/text_reconstruction.py`

### O que o Stage faz atualmente
O arquivo contém uma implementação real (não um stub). Ele:
- Agrupa TextBlocks por proximidade Y (`Y_THRESHOLD = 3.0` px)
- Dentro de cada linha, mescla blocos adjacentes se: mesma família de fonte (`_same_font`) E gap X < `avg_char_width * X_SPACING_FACTOR (1.2)`
- Adiciona espaço entre blocos se gap X > `avg_char_width * 0.3`, do contrário concatena sem espaço
- Retorna `{"blocks_before": N, "blocks_after": M, "merged": N-M}`

### Stub vs Real
O `register_all.py` já inclui `text_reconstruction.register(registry)` em `register_bloco2()`. O @dev deve **confirmar** que não há sobreposição de stub no registry e que os testes cobrem os cenários de merge e non-merge.

### Thresholds críticos
- `Y_THRESHOLD = 3.0` — blocos dentro de 3px vertical são considerados mesma linha
- `X_SPACING_FACTOR = 1.2` — gap < 1.2 × char_width → merge
- Separador de espaço: gap > 0.3 × char_width → adiciona `" "`, senão concatena direto

### Testing
- Suite de testes: `cd backend && pytest tests/`
- Cenário manual: submeter PDF com texto fragmentado e verificar `blocks_merged` > 0 no log do Stage 3
