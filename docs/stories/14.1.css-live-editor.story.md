# Story 14.1 — CSS Live Editor (F5)

## Story

**Como** operador do editor de templates,
**Quero** editar CSS no Monaco e ver as mudanças refletidas imediatamente no canvas,
**Para** poder ajustar qualquer propriedade CSS (bordas, backgrounds, alinhamentos, etc.) e atingir 100% de fidelidade visual sem depender de inspectors individuais.

## Status

Ready for Review

## Context

### Problema

O Monaco Editor já existe com 4 abas (index.html, style.css, base.js, exemplo.js) — story 7.6 Done. O style.css **não é read-only** (`readOnly: false` em `CODE_FILES`), porém:

1. **CSS não sincroniza com o canvas:** `applyMonacoEdit()` no `codeStore.ts` só faz parse de HTML→store (`_parseHtmlIntoStore`). Quando o operador edita CSS, **nada acontece no canvas** — o canvas renderiza os styles inline do `templateStore.documentTree`, não o CSS do codeStore
2. **Sem autocomplete CSS contextual:** Monaco tem autocomplete genérico CSS, mas não conhece os seletores/classes/IDs do template atual
3. **Sem validação CSS em tempo real:** Erros de syntax não são destacados visualmente
4. **Sem separação global vs inline:** Não há conceito de "CSS do template" (global) vs "CSS do elemento" (inline via style attribute). Tudo é um arquivo monolítico

### Estado Atual do Código

**`codeStore.ts`** (lines 125-139):
```typescript
function applyMonacoEdit(key: CodeFileKey, content: string) {
  // ...
  fileContents.value[key] = content
  if (key === 'html') {
    _parseHtmlIntoStore(content)  // ← só HTML! CSS é ignorado
  }
}
```

**`MonacoTabsInner.vue`** (lines 87-114):
- Editor criado com `readOnly: initialFile.readOnly` (false para CSS)
- `onDidChangeModelContent` → debounce 500ms → `codeStore.applyMonacoEdit()`
- Mas CSS edits são armazenados no store sem efeito visual

**`CenterPanel.vue`** (lines 50-52):
- Canvas e Code são tabs separadas — impossível ver canvas e código ao mesmo tempo
- `v-if="editorStore.activeCenterTab === 'code'"` → MonacoTabs; ou `'canvas'` → HTMLCanvas

### Solução Necessária

1. **CSS→Canvas live sync:** Quando CSS muda no Monaco, injetar o CSS atualizado no canvas via `<style>` tag dinâmica ou CSSStyleSheet API
2. **Split view (canvas + code):** Novo modo onde canvas e Monaco aparecem lado a lado
3. **CSS autocomplete contextual:** Registrar completion provider que sugere seletores do template
4. **CSS validation:** Usar CSS.supports() ou parser para validar e marcar erros
5. **Global vs Inline:** Aba "Template CSS" (global, editável) + painel "Element Style" (inline, read-only refletindo styles do nó selecionado)

### Scope — IN vs OUT

**IN SCOPE (esta story):**
- Edição de CSS no Monaco (aba style.css) com reflexo em tempo real no canvas (CSS→Canvas bidirectional sync)
- Split view para visualização simultânea de canvas + código
- CSS autocomplete contextual baseado em seletores existentes no HTML do template (IDs e classes)
- Validação básica de syntax CSS (braces não fechadas, propriedades inválidas) com markers no Monaco
- Painel read-only de computed styles para o elemento selecionado
- Integração com undo stack existente do templateStore
- Injeção de CSS via `<style>` tag dinâmica no container do canvas

**OUT OF SCOPE (não será implementado nesta story):**
- Parser CSS completo / AST (usa regex e heurísticas leves para validação)
- CSS variables (`--custom-property`) — sem resolução ou autocomplete de variáveis customizadas
- `@media` queries — sem preview responsivo ou detecção de breakpoints
- CSS animations / `@keyframes` — sem preview de animações no canvas
- `@import` ou `@font-face` — sem resolução de imports externos
- Preprocessadores (SASS, LESS, PostCSS) — apenas CSS puro
- CSS-in-JS ou styled-components — fora do modelo de edição

## Acceptance Criteria

1. **AC1 — Live Preview:** Ao editar CSS no Monaco (aba style.css), as mudanças são refletidas no canvas em ≤500ms sem reload do canvas. O mecanismo de sync usa o `setTimeout` debounce de 500ms já existente em `MonacoTabsInner.vue` (`onDidChangeModelContent` → debounce 500ms → `codeStore.applyMonacoEdit()`), estendido para que edições no arquivo CSS disparem `injectTemplateCSS()` no mesmo callback
2. **AC2 — Split View:** Novo botão na tab bar do CenterPanel ativa modo split (canvas esquerda + Monaco direita, ~50/50). Resizável via drag handle
3. **AC3 — CSS Injection:** O CSS editado no Monaco é injetado no canvas HTMLCanvas como `<style id="template-custom-css">` dinâmico, atualizado a cada ciclo de debounce (500ms setTimeout). A injeção é síncrona via `styleElement.textContent = css` (sem requestAnimationFrame adicional necessário — o browser repinta automaticamente na próxima frame após a mutação do DOM)
4. **AC4 — CSS Autocomplete:** Monaco oferece sugestões de seletores baseados nos IDs e classes presentes no HTML do template (ex: `#template-header`, `.field-group`, `.field-value`)
5. **AC5 — CSS Validation:** Erros de syntax CSS são marcados com squiggly lines vermelhas no Monaco e listados em painel de problemas (count badge na aba)
6. **AC6 — Element CSS Viewer:** Quando um elemento está selecionado no canvas (ou no structure tree), o Monaco mostra um painel lateral read-only "Computed Styles" com as propriedades CSS aplicadas a esse elemento
7. **AC7 — Undo Integration:** Edições CSS participam do undo stack do `templateStore` (pushUndoSnapshot antes de aplicar mudanças CSS)
8. **AC8 — Sem Regressão:** Todas as funcionalidades existentes do Code Tab (switching de abas, structural warnings em HTML, read-only exemplo.js, conflict banner) continuam funcionando

### CSS Injection Strategy

**Abordagem recomendada:** Usar `<style id="template-custom-css">` dinâmico dentro do container do HTMLCanvas.

```typescript
// codeStore.ts — nova função
function injectTemplateCSS(css: string) {
  const canvasContainer = document.querySelector('.html-canvas__content') // ou ref
  if (!canvasContainer) return
  let styleEl = canvasContainer.querySelector('#template-custom-css') as HTMLStyleElement
  if (!styleEl) {
    styleEl = document.createElement('style')
    styleEl.id = 'template-custom-css'
    canvasContainer.prepend(styleEl)
  }
  styleEl.textContent = css
}
```

**Alternativa (Shadow DOM):** Se o canvas usar Shadow DOM, usar `adoptedStyleSheets` com `CSSStyleSheet` API. Verificar implementação do HTMLCanvas.
