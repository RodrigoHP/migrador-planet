# Story 22.1: Corrigir async mock failures em test_storage_gateway.py

## Status
Draft

## Story
**As a** desenvolvedor,
**I want** que todos os testes de `test_storage_gateway.py` passem,
**so that** o CI reflita fielmente o estado real do código e regressões sejam detectadas.

## Contexto
Durante investigação PGRST205 (2026-03-31), identificou-se que 7+ testes de
`test_storage_gateway.py` falham com erros de mock assíncrono:

```
AssertionError: Expected upload to have been awaited once. Awaited 0 times.
TypeError: 'coroutine' object is not iterable
```

**Causa raiz:** `supabase-py v2` é **síncrono** — os métodos `.upload()`, `.download()`,
`.list()`, `.remove()`, `.create_signed_url()` retornam valores diretos, não coroutines.
Os mocks estão configurados como `AsyncMock` incorretamente, fazendo `assert_awaited_*`
falhar pois as chamadas nunca são awaited.

## Acceptance Criteria

1. `test_upload_pdf` passa — mock de `.upload()` como `MagicMock` (síncrono)
2. `test_upload_screenshot` passa
3. `test_upload_thumbnail` passa
4. `test_upload_asset` passa
5. `test_get_local_path_cache_miss` passa — mock de `.download()` como `MagicMock`
6. `test_get_signed_url` passa — mock de `.create_signed_url()` como `MagicMock`
7. `test_save_visual_data` passa
8. `test_load_visual_data_exists` passa
9. `test_delete_job` passa — mock de `.list()` e `.remove()` como `MagicMock`
10. Nenhum teste previamente passando regride

## Scope

**IN:**
- Corrigir mocks em `backend/tests/test_storage_gateway.py`
- Trocar `AsyncMock` por `MagicMock` para chamadas síncronas do `supabase-py v2`

**OUT:**
- Não alterar `supabase_gateway.py` (código de produção está correto)
- Não alterar outros arquivos de teste
- Não adicionar novas funcionalidades

## Dev Notes

**Padrão de correção:**
```python
# ANTES (errado — supabase-py v2 é síncrono)
mock_supabase.storage.from_("jobs").upload = AsyncMock(return_value={"Key": "..."})

# DEPOIS (correto)
mock_supabase.storage.from_("jobs").upload = MagicMock(return_value={"Key": "..."})
```

**Referência:** `supabase_gateway.py` usa `supabase-py v2` síncrono. Ver comentário no topo do arquivo:
> `NOTE: The supabase-py v2 client is synchronous. All storage/db calls are sync`

## Tasks / Subtasks
- [ ] Identificar todos os mocks `AsyncMock` incorretos em `test_storage_gateway.py`
  - [ ] Mapear cada método síncrono do `supabase-py v2` usado no gateway
- [ ] Corrigir mocks de storage (`.upload`, `.download`, `.list`, `.remove`, `.create_signed_url`)
  - [ ] Trocar `AsyncMock` por `MagicMock` + ajustar assertions (`assert_called_*` em vez de `assert_awaited_*`)
- [ ] Corrigir mocks de DB (`.execute()` em chains `.table().select()`, `.delete()`, etc.)
- [ ] Rodar `pytest tests/test_storage_gateway.py` — todos devem passar
- [ ] Rodar suite completa `pytest tests/` — zero regressões
