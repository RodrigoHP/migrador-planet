# Story 4.8: Hotfix — Limpeza Dead Code: AppToast e POST /api/preview

## Status

Ready

## Story

**As a** dev agent,
**I want** eliminar o dead code identificado na auditoria QA (AppToast nunca montado e POST /api/preview duplicado),
**so that** o codebase fique limpo, sem componentes e endpoints órfãos que podem causar confusão e divergências futuras de manutenção.

## Acceptance Criteria

1. `AppToast` está integrado ao sistema de notificações — montado em pelo menos um layout global (`WizardLayout` ou `App.vue`) e exibindo mensagens de erro de `session.error`
2. Alternativamente ao AC1: se a decisão for remover `AppToast` como dead code, o componente é deletado e removido dos index exports de `organisms/`
3. A escolha entre AC1 e AC2 deve ser documentada no Dev Agent Record com justificativa
4. `POST /api/preview` em `backend/routers/preview.py` é removido — apenas `GET /api/preview/{job_id}` permanece
5. A lógica de renderização HTML (template injection de `{styles}`, `{content}`, `{js}`) é extraída para função helper compartilhada `_render_html(job)` usada por `GET /api/preview/{job_id}`
6. `tsc --noEmit` passa sem erros após mudanças no frontend
7. `npm run build` conclui sem erros
8. Nenhuma regressão: preview continua funcionando via `GET /api/preview/{job_id}`

## Dev Notes

### Bug B1.1-a — AppToast nunca montado

`AppToast.vue` existe e implementa corretamente variantes success/warning/error/neutral com auto-dismiss de 4s. Porém nenhum layout, template ou página o monta. Erros são exibidos via divs inline (`.upload__error` em `UploadPage.vue`).

**Recomendação:** Opção A (integrar) — o componente está bem implementado e o sistema de notificações unificado é preferível a inline divs por página. Montar em `WizardLayout` e `FullWidthLayout` com watcher em `session.error`.

Se a equipe preferir simplicidade: Opção B (remover) é mais rápida e menos arriscada.

### Bug B3.5-a — POST /api/preview duplicado

`preview.py` tem dois handlers com lógica idêntica (~45 linhas cada):
- `POST /preview` (aceita `{ jobId }` no body) — nunca chamado pelo frontend atual
- `GET /preview/{job_id}` — chamado via `window.open()` em `GeracaoPage.vue`

A duplicação cria risco de divergência: futuras mudanças na lógica de render podem ser aplicadas em apenas um dos dois endpoints.

**Refactor mínimo:**
```python
# backend/routers/preview.py

def _render_html(result: dict) -> str:
    """Render HTML template with job result data."""
    css = result.get("css", "")
    js = result.get("js", "")
    exemplo = result.get("exemplo", "")
    content = result.get("html", "")
    js_combined = f"{exemplo}\n{js}" if exemplo else js

    try:
        base_html = _TEMPLATE_PATH.read_text(encoding="utf-8")
        return (
            base_html
            .replace("{styles}", css)
            .replace("{content}", content)
            .replace("{js}", js_combined)
        )
    except FileNotFoundError:
        return (
            "<!DOCTYPE html><html><head><meta charset='UTF-8'>"
            f"<style>{css}</style></head><body>"
            f'<div id="form-container">{content}</div>'
            '<script src="https://cdnjs.cloudflare.com/ajax/libs/knockout/3.5.1/knockout-min.js"></script>'
            f"<script>{js_combined}</script></body></html>"
        )


# Remover POST /preview inteiro
# Manter apenas:
@router.get("/preview/{job_id}")
async def preview_get(job_id: str):
    job = job_manager.get_job(job_id)
    if job is None:
        raise HTTPException(status_code=404, detail="Job não encontrado")
    if job.status in ("pending", "running"):
        raise HTTPException(status_code=409, detail="Job ainda em processamento")
    if job.status == "error":
        raise HTTPException(status_code=422, detail=job.error_msg or "Erro desconhecido")
    return Response(content=_render_html(job.result or {}), media_type="text/html")
```
