# Story 42.3 — Canvas SVG Inline Sync (41.10 AC3)

## Status: Draft

## Descricao

Completar o AC3 deferido da Story 41.10: quando um nó de imagem tem `svgInline: true` e `svgInlineContent`, o canvas do editor deve exibir o `<svg>` inline em vez do `<img>` original.

## Contexto

Story 41.10 implementou SVG inline no **export** (ZIP/index.html). O canvas foi deixado de fora porque ele renderiza `generationStore.templateDraft.html` que vem do backend — um HTML gerado pelo pipeline (stage5), não controlado diretamente pelo frontend.

O challenge: o backend não sabe que o operador ativou o toggle SVG inline (essa é uma propriedade do templateStore no frontend). O canvas exibe o HTML "cru" do backend.

## Acceptance Criteria

- [ ] AC1: Quando nó tem `svgInline: true` e `svgInlineContent` preenchido, o canvas exibe `<svg>` inline em vez de `<img src="...">`
- [ ] AC2: A substituição preserva posição e dimensões (atributos `style` do nó)
- [ ] AC3: Ao desativar o toggle (`svgInline: false`), o canvas volta a exibir `<img>` normalmente
- [ ] AC4: Zero regressão no CANVAS_INTERACTION_SCRIPT (click, drag, resize continuam funcionando)
- [ ] AC5: Teste unitário para a lógica de patch do HTML do canvas

## Escopo

### IN
- `useCanvasIframe.ts` ou `HTMLCanvas.vue` — mecanismo de patch do HTML antes de montar o srcdoc
- Reusar `replaceImgWithSvgInline()` de `useExport.ts` (já existe e é testada)
- Watch reativo: quando `templateStore` muda propriedades `svgInline`, canvas é re-renderizado

### OUT
- Alterações no backend/stage5 (não sabe do toggle)
- Alterações em `svgSanitizer.ts`
- Novo toggle ou UI — apenas wiring do existente

## Riscos

| Risco | Probabilidade | Mitigacao |
|-------|--------------|-----------|
| Re-render do canvas causa flicker | MEDIA | Debounce no watch |
| CANVAS_INTERACTION_SCRIPT quebra após patch | MEDIA | Teste de regressão antes de entregar |
| srcdoc rebuild é caro para documentos grandes | BAIXA | Patch incremental apenas nos nós afetados |

## Dev Notes

### Abordagem recomendada

`buildPageSrcdoc()` em `useCanvasIframe.ts` já recebe o HTML. Adicionar chamada a `replaceImgWithSvgInline()` antes de construir o srcdoc:

```typescript
import { replaceImgWithSvgInline } from '@/composables/useExport'

// Dentro de buildPageSrcdoc():
const svgNodes = templateStore.flatNodes.value.filter(
  n => n.type === 'image' && n.properties['svgInline']
)
const patchedHtml = svgNodes.length > 0
  ? replaceImgWithSvgInline(html, svgNodes)
  : html
```

O watch que dispara `buildPageSrcdoc()` já existe — basta garantir que re-executa quando `svgInlineContent` muda no templateStore.
