# Story 12.4 — Bug: Aba PDF falha após refresh ou expiração de job

## Story
**Como** usuário do editor,
**Quero** que a aba PDF sempre mostre o documento original,
**Para** comparar o canvas editado com o PDF de referência.

## Status
Draft

## Context

### Problema
Ao clicar na aba "PDF" no editor, ocorre um dos seguintes erros:
1. PDF não carrega (tela em branco)
2. Erro no console (sem mensagem visual para o usuário)
3. Após F5 (refresh), PDF não disponível

### Root Causes (múltiplos)

#### Causa 1: Bytes perdidos no refresh
```typescript
// session.ts - Estado em memória apenas:
uploadedPdfs: [
  { name: "boleto.pdf", bytes: Uint8Array(12345) }  // ← Perdido no F5!
]
```
`Uint8Array` não é serializado para `localStorage` / `sessionStorage` automaticamente.
Após refresh, `bytes = undefined` → PDFReference.vue não consegue renderizar.

#### Causa 2: Endpoint `/api/jobs/{jobId}/pdf` retorna 404
```python
# routers/analyze.py
@router.get("/api/jobs/{job_id}/pdf")
async def get_job_pdf(job_id: str, index: int = 0):
    if job_id not in _pipeline_jobs:  # ← KeyError se server reiniciou
        raise HTTPException(404, "Job not found")
```
Epic 11.9 implementou TTL de limpeza de disco. Se job expirou, arquivo foi removido.
Se servidor reiniciou, `_pipeline_jobs` dict está vazio.

#### Causa 3: Sem feedback visual
```typescript
// PDFReference.vue
async function loadSelectedDoc() {
  try {
    ...
    if (!bytes) return  // ← Silencia erro! Tela fica em branco
  } catch (e) {
    console.error(e)    // ← Apenas no console, não na UI
  }
}
```

### Solução

#### Parte 1 — Persistir bytes no IndexedDB

```typescript
// utils/pdfStorage.ts (novo)
import { openDB } from 'idb'  // ou usar indexedDB diretamente

export async function savePdfBytes(jobId: string, index: number, bytes: Uint8Array) {
  const db = await openDB('migrador-pdfs', 1, {
    upgrade(db) { db.createObjectStore('pdfs') }
  })
  await db.put('pdfs', bytes, `${jobId}-${index}`)
}

export async function loadPdfBytes(jobId: string, index: number): Promise<Uint8Array | null> {
  const db = await openDB('migrador-pdfs', 1)
  return await db.get('pdfs', `${jobId}-${index}`) ?? null
}

export async function clearPdfBytes(jobId: string) {
  const db = await openDB('migrador-pdfs', 1)
  // Limpar todos os índices do job
}
```

```typescript
// session.ts - Ao salvar upload:
async uploadPdfs(files: File[]) {
  for (const [i, file] of files.entries()) {
    const bytes = await file.arrayBuffer()
    const uint8 = new Uint8Array(bytes)
    this.uploadedPdfs.push({ name: file.name, bytes: uint8 })
    await savePdfBytes(this.jobId!, i, uint8)  // NOVO: Persistir
  }
}

// PDFReference.vue - Ao carregar:
async loadSelectedDoc() {
  let bytes = uploadedPdfs.value[selectedDocIndex.value]?.bytes

  // Tentar IndexedDB
  if (!bytes) {
    bytes = await loadPdfBytes(sessionStore.jobId!, selectedDocIndex.value)
  }

  // Tentar endpoint do servidor
  if (!bytes) {
    bytes = await fetchPdfFromServer(selectedDocIndex.value)
  }

  // Erro claro se nada funcionou
  if (!bytes) {
    pdfError.value = 'PDF não disponível. Faça upload novamente.'
    return
  }

  await renderer.loadPdf(bytes)
}
```

#### Parte 2 — Endpoint mais robusto

```python
# routers/analyze.py
@router.get("/api/jobs/{job_id}/pdf")
async def get_job_pdf(job_id: str, index: int = 0):
    # Verificar no disco (independente de _pipeline_jobs)
    pdf_dir = Path(f"/tmp/jobs/{job_id}")
    pdf_files = sorted(pdf_dir.glob("*.pdf")) if pdf_dir.exists() else []

    if not pdf_files or index >= len(pdf_files):
        raise HTTPException(404, detail={
            "error": "pdf_not_found",
            "message": "PDF não encontrado. Job pode ter expirado.",
            "job_id": job_id
        })

    pdf_path = pdf_files[index]
    return FileResponse(pdf_path, media_type="application/pdf")
```

## Acceptance Criteria

1. **AC1 — Carregamento inicial:** PDF renderiza ao clicar na aba "PDF" pela primeira vez
2. **AC2 — Pós-refresh:** Após F5, PDF ainda carrega (via IndexedDB ou servidor)
3. **AC3 — TTL expirado:** Se job expirou, mostra mensagem clara com opção de re-upload
4. **AC4 — Servidor reiniciado:** Endpoint busca PDF no disco independente de memória
5. **AC5 — Erro visível:** Qualquer falha mostra mensagem visual (não apenas console.error)
6. **AC6 — Multi-PDF:** Funciona para documentos com múltiplos PDFs (index 0, 1, 2...)
7. **AC7 — Testes:** Testa os 3 caminhos: bytes em memória, IndexedDB, endpoint
