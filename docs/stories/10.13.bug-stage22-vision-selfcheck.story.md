## Story
**As a** operador,
**I want** que o Stage 22 (Vision Self-Check) verifique a consistência entre análise visual (Stages 20/21) e análise textual (Stages 2-6) e registre discrepâncias de forma estruturada,
**so that** `context["visual_analysis"]` contenha `consistency_score` e `consistency_level` por página, e páginas com baixa consistência sejam marcadas para revisão.

4. Página com score >= 80 recebe `consistency_level = "consistent"`; score 50-79 recebe `"partial"`; score < 50 recebe `"low"` e `vision_low_confidence = True`
5. `pytest backend/tests/` passa sem erros após qualquer alteração

## Dev Notes

### Arquivo
`backend/services/stages/vision_self_check.py`

### O que o Stage faz atualmente
O arquivo contém implementação real (não stub). Ele:

**Scoring (3 dimensões, totalizando 0-100)**
- `_text_coverage_score` (0-33): regiões visuais do tipo header/body/footer/form_area vs count de text_blocks na página
- `_table_agreement_score` (0-33): regiões `table_area` vs tabelas detectadas pelo Stage 17/18 na mesma página
- `_image_agreement_score` (0-34): regiões `image_area`/`chart_area` vs imagens extraídas pela Stage 4

**Thresholds**
- `CONSISTENT_THRESHOLD = 80` → `"consistent"`
- `PARTIAL_THRESHOLD = 50` → `"partial"`
- Abaixo de 50 → `"low"` + `vision_low_confidence = True` + retry via `_retry_segmentation`

**Retry (`_retry_segmentation`)**
- Busca screenshot da página usando `_screenshot_path_for_page`
- Re-chama `chat_with_vision` com `_SEGMENTATION_PROMPT` do visual_segmentation
- Se as novas regiões produzem score maior → usa score novo; se pior → mantém o maior
- Retorna `None` se não há screenshot ou client Vision AI indisponível

**Modo skip**
- Se `VISION_AI_ENABLED` env var é `false`/`0`/`no`/`off` OU `context["vision_unavailable"]` é truthy → retorna `{"pages_checked": 0, "skipped": True}` e emite evento com `status: "skipped"`

**Escrita no contexto**
- `context["visual_analysis"]` — cada `page_data` recebe `consistency_score` e `consistency_level` in-place
- NÃO escreve `context["vision_validation"]` — a chave de saída real é dentro de `visual_analysis` por page_key

## Decision: vision_validation key

**Problema:** A story originalmente mencionava `context["vision_validation"]` como chave de saída, mas a implementação real escrevia apenas dentro de `context["visual_analysis"][page_key]`.

**Decisão tomada (2026-03-19, @dev):** Adicionada a chave `context["vision_validation"]` como sumário consolidado ao final do `execute()` em `vision_self_check.py`. A chave contém:

```python
context["vision_validation"] = {
    "page_results": {page_key: {"consistency_score": int, "consistency_level": str}},
    "overall_score": int,   # média de todos os scores de página (0 se nenhuma página)
    "pages_checked": int,
    "low_confidence_pages": [page_key, ...]
}
```

**Rationale:** A escrita in-place em `context["visual_analysis"][page_key]` foi mantida (é o dado autoritativo, acessado por stages downstream). A chave `vision_validation` é um alias de sumário que facilita o acesso downstream sem iterar `visual_analysis`. Ambas coexistem sem conflito.
