# Story 13.11 — Frontend: PipelineResult Type + Integração Stores

## Story
**Como** editor de templates,
**Quero** receber e renderizar o novo PipelineResult v2 corretamente,
**Para** que layout switch, coverage multidimensional, trees_by_layout, e overlay de tabelas funcionem.

## Status
Done

## Context

### Frontend Atual
- `PipelineResult` type tem campos limitados
- `session.ts` carrega screenshots por path local
- Layout switch não pré-popula todos os layouts
- Coverage é numérico simples
- Overlay não diferencia tabelas

### Frontend v2
- 8 campos novos no PipelineResult type
- Signed URLs para screenshots/assets
- Todos os layouts pre-populados desde o primeiro load
- Coverage multidimensional
- Overlay hierárquico para tabelas (container + cells)

## Acceptance Criteria

1. **PipelineResult type** atualizado com 8 campos novos:
   - `trees_by_layout: Record<string, TreeNode>`
   - `validation_result: ValidationResult`
   - `intelligence: Record<string, LayoutIntelligence>`
   - `block_classifications_confirmed: boolean`
   - `multi_doc: MultiDocResult`
   - `page_config: PageConfig`
   - `document_type_confidence: number`
   - `visual_analysis: Record<string, VisualAnalysisResult>`

2. **Novos types:**
   - `DocumentStructure` (pages + layout_types + root + trees_by_layout)
   - `PageConfig` (width, height, margins)
   - `ValidationResult` (warnings, errors, type_format_mismatches)
   - `LayoutIntelligence` (block_classifications, classification_quality)
   - `VisualAnalysisResult` (regions, consistency_score)
   - Import de `PdfDocument/VariationMatrix/Detection` de `multi-doc.types`

3. `session.ts` carrega screenshots/assets via signed URL (não path local)

4. `session.ts` pre-popula TODOS os layouts (não só ativo) — layout switch funciona desde primeiro load (G19)

5. `loadFromPipelineResult()` conecta ao `multiDocStore.populateFromPipeline()`

6. `templateStore` recebe `trees_by_layout` do layout ativo

7. Coverage multidimensional exibido: `"85% (campos 90% | tabelas 75% | imagens 80%)"`

8. SSE adapta barra de progresso: 5 estágios com nomes + sub-barra

9. Overlay de tabelas hierárquico (G22):
   - `table_container`: bbox da tabela inteira, status = mapped se algum child mapeado
   - `table_cell`: bbox de cada célula, hover-only
   - `BackendOverlayItem` ganha `overlay_type?: 'field' | 'table_container' | 'table_cell'`

  // pipeline v2
