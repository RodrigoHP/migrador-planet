# Story 20.5 — Real-Time Budget Alerts

## Story
**Como** operador que quer evitar surpresas de custo,
**Quero** receber warnings automaticos quando o custo real atinge 50%, 75%, e 90% do budget configurado,
**Para** que eu possa tomar acao antes que o budget seja excedido.

## Status
Draft

## Context

### Problema

Sem alertas em tempo real, o operador so descobre que o budget foi excedido no final report. Com o cost accumulator (20.3) atualizando apos cada step, o engine pode comparar custo acumulado vs budget limit e emitir warnings nos thresholds configurados.

### Design

#### Logica de Alerta

Apos cada acumulacao de custo (post-step):

```
FUNCTION check_budget_alerts(state, cost_config):
  budget = cost_config.budget.per_workflow
  current = state.cost_tracking.total_usd
  percentage = current / budget.limit_usd

  FOR threshold IN budget.alert_thresholds:  # [0.50, 0.75, 0.90]
    IF percentage >= threshold AND threshold NOT IN state.cost_tracking.alerts_fired:
      emit_budget_alert(threshold, current, budget.limit_usd)
      state.cost_tracking.alerts_fired.append(threshold)

FUNCTION emit_budget_alert(threshold, current, limit):
  level = "WARNING" if threshold < 0.90 else "CRITICAL"
  message = "[{level}] Budget {threshold*100}% reached: ${current:.2f} of ${limit:.2f}"
  log_to_execution_log(message)
```

#### Thresholds Configuraveis

Os thresholds vem de cost-config.yaml (Story 20.2):

```yaml
budget:
  per_workflow:
    limit_usd: 50.00
    alert_thresholds: [0.50, 0.75, 0.90]
```

#### Tracking de Alertas Emitidos

Para nao repetir o mesmo alerta, `alerts_fired` no state registra quais thresholds ja foram notificados:

```yaml
cost_tracking:
  alerts_fired: [0.50, 0.75]  # Ja notificou 50% e 75%
```

## Acceptance Criteria

- [ ] AC1: Apos cada step, engine compara custo acumulado real vs budget limit e verifica thresholds
- [ ] AC2: Warning emitido no execution_log quando custo atinge cada threshold configurado (50%, 75%, 90%)
- [ ] AC3: Threshold 90% emite nivel CRITICAL, demais emitem WARNING
- [ ] AC4: Cada threshold eh emitido apenas uma vez por execucao (nao repete)
- [ ] AC5: alerts_fired persiste no state para recovery — alertas nao sao re-emitidos apos crash
- [ ] AC6: Thresholds configuraveis em cost-config.yaml (nao hardcoded)
- [ ] AC7: Se budget limit nao configurado, alertas sao desabilitados silenciosamente (sem erro)

## Technical Notes

- Alertas baseados em custo REAL (nao estimado) para maior confiabilidade
- A persistencia de alerts_fired evita spam apos recovery de estado
- O nivel CRITICAL no threshold 90% prepara o terreno para o circuit breaker (20.6)
