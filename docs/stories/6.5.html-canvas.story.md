# Story 6.5: HTMLCanvas — Preview WYSIWYG do Template com Zoom e Guias Visuais

## Status
Done

## Story
**As a** operador,
**I want** ver o template HTML renderizado ao vivo em um iframe como preview WYSIWYG com controles de zoom e guias visuais,
**so that** eu possa ver exatamente como o template final ficará.

## Acceptance Criteria
1. Organism HTMLCanvas renderiza um iframe na aba "Canvas" do painel central
2. Iframe carrega o HTML+CSS do template draft de `generationStore.templateDraft`
3. Scroll contínuo vertical com páginas empilhadas (gap e sombra entre páginas)
4. Dimensões de página: A4 default (794×1123px), configurável a partir de templateStore
5. Controles de zoom no rodapé: [- 100% +] range 50%-125%
6. Guias visuais: margens da página (linhas pontilhadas), limites Header/Flow/Footer (linhas coloridas), colunas detectadas (guias verticais)
7. Guias ativáveis via `editorStore.showGuides`
8. Linhas de quebra de página visíveis entre páginas: "--- QUEBRA DE PÁGINA ---"
9. Lazy rendering: máximo 5 páginas visíveis, páginas adicionais carregam no scroll
10. CSS isolado no iframe (CSS do template não vaza para CSS do editor)
11. `npm run build` passa

## Dev Notes

### Canvas Renderiza o HTML REAL do Template
- O Canvas mostra o HTML gerado pelo pipeline — NÃO é uma imagem do PDF original
- Wireframe: scroll contínuo vertical, páginas empilhadas com gap
- O iframe é fundamental para isolamento de CSS

### Estratégia de Iframe
```typescript
// Construir srcdoc completo
const srcdoc = computed(() => {
  const { html, css } = generationStore.templateDraft
  return `<!DOCTYPE html>
<html>
<head><style>${css}</style></head>
<body>${html}</body>
</html>`
})
```

### Estrutura HTML do Template Draft
O pipeline gera HTML com a seguinte estrutura:
```html
<div class="page" data-page="1">
  <div class="header">...</div>
  <div class="flow">...</div>
  <div class="footer">...</div>
</div>
<div class="page" data-page="2">
  ...
</div>
```

### Zoom com CSS Transform
```css
.canvas-content {
  transform: scale(var(--zoom));
  transform-origin: top center;
}
```
O container externo mantém scroll, o conteúdo interno é escalado.

### Lazy Rendering com IntersectionObserver
```typescript
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    const pageNum = Number(entry.target.dataset.page)
    if (entry.isIntersecting) visiblePages.add(pageNum)
    else visiblePages.delete(pageNum)
  })
}, { rootMargin: '200px' }) // preload margin
```

### Design Assessment
The implementation follows the established atomic design system (composable + atoms/molecules/organisms). The separation of concerns is clean: `useCanvas` owns zoom state and observer lifecycle, `ZoomControls` and `CanvasGuides` are stateless molecules, and `HTMLCanvas` orchestrates everything. The choice to use `srcdoc` with `sandbox="allow-same-origin"` is the correct approach for CSS isolation — it prevents bidirectional style leakage without requiring complex shadow DOM.

The lazy rendering architecture using `IntersectionObserver` with `rootMargin: 200px` preloading is well-designed. The MAX_VISIBLE_PAGES=5 windowing algorithm correctly handles large documents.

The CSS `transform:scale` zoom approach (scale on inner wrapper, scroll on outer container) is the standard WYSIWYG canvas pattern and avoids layout reflow on every zoom step.

### Decision Log
1. `srcdoc` over `blob URL` — simpler, no revocation needed, works within CSP
2. `IntersectionObserver` over virtual scroll library — lower dependency overhead
3. CSS transform:scale over zoom CSS property — broader browser support, works in iframe context
4. Props-based CanvasGuides — decoupled from stores, testable in isolation
