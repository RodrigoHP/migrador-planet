# Story 30.1 — Validar e Corrigir Auto-mapping no Boleto Bancário

## Story
**Como** operador abrindo o Boleto Bancário no editor após processamento do pipeline,
**Quero** ver pelo menos 10 dos 66 campos XSD já mapeados automaticamente na aba Campos,
**Para** não precisar mapear tudo manualmente e poder focar apenas nos campos ambíguos ou não detectados.

## Status
InReview

## Business Value
Story 29.4 implementou nomes semânticos no backend (`_extract_semantic_name`,
`_infer_section_name`) como pré-requisito para auto-mapping. O AC5 dessa story —
"auto-mapping resulta em > 10/66 campos mapeados" — foi marcado como `N/A para
testes unitários` por não ser testável com mocks. Esta story valida e, se necessário,
corrige o auto-binding com dados reais do Boleto Bancário.

**Estimativa:** 3 story points (S se só validação, M se precisar de fix)

## Scope

**IN:**
- Processar o Boleto Bancário real pelo pipeline completo (stages 1–5)
- Verificar quantos campos são auto-mapeados (`status: 'mapped'`) na resposta
- Se < 10/66: investigar gargalo e implementar correção mínima
- Adicionar teste de regressão que valida a lógica de auto-binding com dados controlados
- Atualizar AC5 da Story 29.4 com resultado real

**OUT:**
- Matching por similaridade semântica ou embeddings (MVP — texto exato suficiente)
- Mudanças no frontend (FieldNavigator, mapping.ts já corretos)
- Refatoração do motor de matching além do mínimo necessário

## Risks

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| PDF real não disponível em CI | Média | Alto | Criar fixture JSON com estrutura do Boleto Bancário para testes |
| Ajuste em auto-binding regride 29.4 | Baixa | Médio | Rodar suite completa antes de commitar |
| Nomes semânticos corretos mas XSD paths não casam | Média | Alto | Mapear manualmente nomes esperados × XSD paths e usar como teste |

## Context

**Background (story 29.4):**

O backend em `stage3_structural_analysis.py` passou a gerar nomes legíveis:
- `_extract_semantic_name(block)` → texto do bloco como nome (ex: "Cedente:", "Data Vencimento")
- `_infer_section_name(blocks, classifications)` → nome da seção a partir do primeiro label filho

**Como o auto-binding funciona:**

O matching de campo para XSD path (auto-binding) ocorre em `stage5_template_generation.py`
(ou em stage anterior). O campo `entry.binding` na resposta `field_mappings` indica
se foi auto-mapeado; `entry.status = 'mapped'` indica sucesso.

**Fluxo para validar:**
1. Processar Boleto Bancário → obter `result.field_mappings`
2. Contar entradas com `status: 'mapped'` → deve ser > 10
3. Inspecionar entradas `status: 'unmapped'` → identificar padrão de falha

**Arquivos relevantes:**
- `backend/services/stages/stage3_structural_analysis.py` — `_extract_semantic_name`, `_infer_section_name`
- `backend/services/stages/stage5_template_generation.py` — geração e eventual auto-binding
- `backend/tests/test_stage3_structural_analysis.py` — testes dos helpers semânticos
- `frontend/src/stores/mapping.ts` — `loadPipelineFields` (lê `entry.binding`)

**Referências:**
- Backlog: `docs/stories/backlog/backlog-epic29-scope-out.md` (item 30.1)
- Story de origem: `docs/stories/29.4.node-semantic-names-backend.story.md` (AC5)

## Dev Notes

**Localização do auto-binding:**

O auto-binding provavelmente ocorre em `stage5_template_generation.py` ou em um stage
de matching (possivelmente stage 7/8 de layout intelligence). Para confirmar, buscar:
```
grep -r "status.*mapped\|auto.*bind\|xsd.*match" backend/services/stages/
```

**Estrutura de `field_mappings` na resposta:**
```typescript
interface FieldMappingEntry {
  name: string        // nome semântico extraído pelo stage3
  path: string        // XSD path se mapeado
  status: 'mapped' | 'unmapped' | 'ambiguous' | 'optional'
  binding?: string    // XSD path no template
  candidates?: Array<{ path: string; score: number }>
}
```

**Normalização esperada no matching:**
- "Cedente:" → "Cedente" (tirar dois-pontos — já feito por `_extract_semantic_name`)
- "SACADO / PAGADOR" → múltiplos termos a serem casados individualmente
- Case-insensitive matching é o mínimo esperado

**Testes para inspecionar:**
- `backend/tests/test_stage3_structural_analysis.py::TestSemanticNames` (Story 29.4)
