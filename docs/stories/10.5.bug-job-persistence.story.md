# Story 10.5: Bug — Jobs perdidos ao reiniciar backend

## Status
Done

## Story
**As a** operador,
**I want** que se o backend reiniciar durante ou após uma análise, eu receba uma mensagem clara informando que a sessão foi perdida e possa reiniciar o processo,
**so that** eu não fique preso em um loop de "Conexão perdida" sem entender o que aconteceu.

## Acceptance Criteria
1. Se `GET /api/analyze/{job_id}/progress` retornar 404 (job não existe mais no backend), a UI exibe mensagem específica: "Sessão de análise perdida. O servidor pode ter sido reiniciado. Faça o upload novamente."
2. Se `GET /api/analyze/{job_id}/result` retornar 404, a mesma mensagem é exibida
3. A mensagem inclui botão "← Voltar ao Upload" para reiniciar o fluxo
4. O frontend NÃO entra em loop de reconexão quando o 404 é por job inexistente (vs. rede caída)
5. `pytest` e `vitest` passam sem erros

## Bugs Identificados

### Bug 4 — ALTO: `_pipeline_jobs` é in-memory — jobs perdidos ao reiniciar backend
- **Causa:** `_pipeline_jobs` em `backend/routers/analyze.py` é um dicionário Python em memória (linha ~15: `_pipeline_jobs: Dict[str, Any] = {}`). Ao reiniciar o servidor uvicorn, todos os jobs ativos são perdidos. O frontend guarda o `jobId` no Pinia store (sessão do browser), mas o backend não tem mais o job.
- **Sintoma:** `GET /api/analyze/{job_id}/progress` retorna 404. O frontend interpreta isso como falha de rede e tenta reconectar 3x, depois mostra "Conexão perdida". O usuário não entende que o servidor reiniciou.
- **Arquivos:**
  - `backend/routers/analyze.py` — `_pipeline_jobs` (linha ~15)
  - `frontend/src/pages/AnalyzingPage.vue` — `onerror` + `fetchAndLoadResult`
- **Escopo desta story:** A solução **NÃO é** persistir os jobs em banco de dados (mudança arquitetural grande). A solução é tratar o cenário de 404 no frontend com mensagem clara + detectar 404 no SSE e não reconectar.
- **Fix frontend:**
  - Em `connectSSE`, se o EventSource receber erro 404 imediatamente (antes de qualquer mensagem), setar `sessionLost.value = true` com mensagem específica
  - Em `fetchAndLoadResult`, se `resp.status === 404`, mostrar mensagem de sessão perdida (não o erro genérico)
  - Adicionar estado `sessionLost: ref<boolean>` e banner específico na UI
- **Fix backend (simples):** Adicionar endpoint `GET /api/analyze/{job_id}/status` que retorna `{ "exists": false }` quando o job não existe — permite ao frontend distinguir "job não existe" de "job existe mas ainda não iniciou"

## Dev Notes
- O EventSource nativo do browser não expõe o status HTTP do erro no `onerror`. Para detectar 404 vs. falha de rede, fazer um `fetch` ao endpoint `/status` imediatamente quando `onerror` dispara com `reconnectAttempts === 0`.
- Não implementar persistência de jobs em banco (Redis, SQLite, etc.) nesta story — isso é uma melhoria arquitetural futura. O objetivo aqui é melhorar a mensagem de erro.
- O endpoint `/status` deve ser leve — apenas verifica se `job_id in _pipeline_jobs` e retorna o status atual.
- `sessionLost` é diferente de `hasError` — deve ter um banner visual diferente (cor diferente, ícone diferente, texto mais explicativo).
