# Story 13.14 — Fix: AnalyzingPage não chama POST /jobs/{job_id}/handle-failure no checkpoint

## Story

**Como** operador da plataforma,
**Quero** poder responder checkpoints do pipeline (Confirmar / Ajustar / Pular),
**Para** que o pipeline continue processando após uma decisão humana necessária.

## Status

Done

## Context

Gap identificado no Epic 13 Gap Report (2026-03-28).

`CheckpointCard.vue` emite o evento `@action` com a decisão do operador (retry/fallback/abort), mas `AnalyzingPage.vue` não tem handler para esse evento e não chama `POST /jobs/{job_id}/handle-failure`. O backend implementou o endpoint em `backend/routers/analyze.py:448`, mas o frontend nunca o invoca. Sem isso, o pipeline fica pendurado indefinidamente esperando resposta.

## Acceptance Criteria

1. `AnalyzingPage.vue` tem handler para o evento `@action` emitido por `CheckpointCard`
2. Handler chama `POST /jobs/{job_id}/handle-failure` via `apiFetch` com body `{"action": "retry" | "fallback" | "abort"}`
3. Após envio bem-sucedido (2xx): estado da página volta para `processing`
4. Em caso de erro no POST (4xx/5xx): exibir mensagem de erro sem bloquear o operador
5. Botões do CheckpointCard ficam desabilitados durante o envio (loading state)
6. Teste unitário cobre o handler e as 3 ações possíveis

## Scope

**IN:** Adicionar handler em `AnalyzingPage.vue` + loading state em `CheckpointCard.vue`
**OUT:** Nenhuma mudança no backend (endpoint já existe)

## Tasks / Subtasks

- [x] Ler `frontend/src/pages/AnalyzingPage.vue` — localizar uso de `CheckpointCard`
- [x] Ler `frontend/src/components/analyzing/CheckpointCard.vue` — verificar evento emitido
- [x] Adicionar handler `handleCheckpointAction(action)` em AnalyzingPage
- [x] Implementar `POST /jobs/{job_id}/handle-failure` via apiFetch
- [x] Adicionar loading state no CheckpointCard durante envio
- [x] Tratar erros de rede/HTTP (inline banner, não bloqueia operador)
- [x] Adicionar/atualizar testes (65 testes passando)
