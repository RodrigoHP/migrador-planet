# Story 10.20 — Bug: Editor — PDF ArrayBuffer, Inspector vazio, nomes de página, progresso simultâneo

## Story
**Como** usuário do editor de templates,
**Quero** que o PDF renderize corretamente, o Inspector mostre as propriedades dos elementos, os nomes das páginas sejam legíveis e o progresso apareça incrementalmente,
**Para** ter uma experiência de edição funcional e compreensível.

## Status
Done

## Context
Quatro bugs identificados no editor após a implementação do Epic 10:
1. PDF falha com "Cannot perform Construct on a detached ArrayBuffer" (pdfjs-dist v5.x)
2. Inspector mostra "—" para todas as propriedades de elementos
3. Nomes de páginas como "{pdf_name} — p{n}" causam impressão de "diff"
4. Página de progresso renderiza todos os stages simultaneamente

## Acceptance Criteria

1. **PDF Viewer** — O PDF renderiza sem erros no console; nenhum "detached ArrayBuffer" é lançado.
2. **Element Inspector** — Ao selecionar um bloco de texto na árvore, `x`, `y`, `width`, `height`, `font_family` e `font_size` aparecem com valores reais (não "—").
3. **Page names** — Nós de página na árvore do documento aparecem como "Página 1", "Página 2", etc.
4. **Progress page** — Os stages do pipeline aparecem sequencialmente (um a um), não todos de uma vez.

## Dev Notes

### Bug 1 — PDF ArrayBuffer Detach (pdfjs-dist v5.x)
pdfjs-dist v5.x usa `postMessage` com transfer list para enviar o ArrayBuffer ao Web Worker, detachando-o no sender. `new TypedArray(detachedBuffer)` lança "Cannot perform Construct on a detached ArrayBuffer". Solução: passar `Uint8Array` em vez de `ArrayBuffer` — pdfjs trata typed arrays via `buffer.slice()` internamente, preservando o original.

### Bug 2 — Inspector vazio
`ElementInspector.vue` lê `node.properties.x`, `node.properties.y`, `node.properties.width`, `node.properties.height`, `node.properties.font_family`, `node.properties.font_size`. Esses campos não existiam no schema de `properties` dos nós de bloco gerados pelo Stage 28 (`pipeline_result.py`). Corrigido adicionando `_bbox_to_layout()` para converter `(x0, y0, x1, y1)` → `{x, y, width, height}` e mapeando `font_name`/`font_size` do `TextBlock`.

### Bug 3 — Nome de páginas
Nós de página recebiam `name = f"{pdf_name} — p{page_number}"`. Com um único documento, isso parecia um "diff". Corrigido para `f"Página {display_number}"` onde `display_number = page_number + 1` (PyMuPDF usa indexação 0-based).

### Bug 4 — Progress simultâneo
SSE replay buffer + TCP coalescing = múltiplos frames SSE chegam juntos. Vue 3 batcheia updates síncronos no mesmo macrotask em um único render. Fix: fila client-side (`_eventQueue`) drenada com `setTimeout(60ms)` entre eventos, forçando um boundary de macrotask (e portanto um render flush) entre cada stage.
