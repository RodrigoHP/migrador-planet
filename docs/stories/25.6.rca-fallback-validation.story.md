# Story 25.6 — Fallback & Validation: Graceful Degradation

## Story
**Como** orquestrador multi-model,
**Quero** fallback automatico se subagent falhar,
**Para** que o pipeline NUNCA pare por causa de falha de subagent.

## Status
Draft

## Context

### Problema
Subagents podem falhar: timeout, resposta incompleta, formato errado, erro de modelo. Se o pipeline para, a investigacao morre. Precisa de fallback robusto.

### Design
Para cada chamada Agent():

1. **Validar resultado:**
   - Campos obrigatorios presentes? (conforme phase contracts)
   - Formato parseavel? (YAML valido)
   - Conteudo coerente? (nao vazio, nao placeholder)

2. **Se falha:** Orquestrador executa fase inline (v7.0 behavior)
   - Log explicito: "FALLBACK: Fase {N} executada inline"
   - Resultado inline substitui resultado do subagent
   
3. **Timeout:** 120s default por fase (configuravel no routing)

4. **Preset single:** Skip ALL subagents, tudo inline

5. **Metricas no relatorio:**
   ```yaml
   pipeline_metrics:
     preset: balanced
     phases_subagent: [0, 1, 2, 3, 4, 5, 6, 8, 9]
     phases_fallback: []
     phases_sdc: [7]
     estimated_cost: $1.40
   ```

## Acceptance Criteria
- [ ] Validacao de resultado apos cada subagent
- [ ] Fallback inline automatico se validacao falha
- [ ] Timeout configuravel por fase
- [ ] Log explicito de fallbacks
- [ ] Preset single = zero subagents
- [ ] pipeline_metrics no relatorio final
- [ ] rca-principle.md atualizado com regras v8.0
