# Story 29.3 — Code Editor → Structure Bidirectional Sync

## Story
**Como** operador editando o código HTML do template,
**Quero** que alterações feitas no Code Editor reflitam na árvore de estrutura e no Canvas,
**Para** ter uma experiência de edição coerente entre os modos de edição visual e de código.

## Status
Done

## Business Value
O Code Editor atualmente é uma ilha — edições no HTML não refletem na árvore nem no canvas. Operadores técnicos que preferem editar código diretamente perdem toda a coerência entre os painéis. Esta story fecha metade do loop bidirecional (código → estrutura), completando o que já existe na direção estrutura → código.

**Estimativa:** 3 story points

## Scope
**IN:**
- Trigger de sync após `codeStore.applyMonacoEdit()` para HTML
- Parser HTML → atualização de propriedades nos nós existentes do `templateStore`
- Debounce de 800ms para evitar sync durante digitação
- Tratamento de HTML inválido sem crash
- Testes de sincronização

**OUT:**
- Parser completo que reconstrói a árvore a partir do HTML (MVP usa sync parcial de propriedades)
- Sync de CSS ou JavaScript (apenas HTML)
- Sync de arquivos além do `html` (ex: CSS, data)

## Risks

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| Loop infinito (code→tree→code→tree) | Alta | Crítico | Flag `isSyncing` no codeStore para interromper ciclos |
| DOMParser não suporta estrutura complexa do HTML gerado | Média | Alto | Usar backend parse (Opção A do ADR) como fallback |
| HTML inválido causa crash no DOMParser | Baixa | Médio | Try/catch + verificar `parseerror` antes de processar |

## Context

**Problema (GAP 2):**

`MonacoTabsInner.vue` edita o HTML e salva via `codeStore.applyMonacoEdit(key, value)`. Este método atualiza `codeStore.fileContents` mas **não conecta com `templateStore`**. Resultado: editar no Code Editor é uma ação isolada — a árvore e o canvas não refletem as mudanças.

A spec define sincronização bidirecional:
- Estrutura/Inspector → regenera código (já existe via `generation.ts`)
- Código → atualiza estrutura (ausente — este é o GAP)

**Estratégia de implementação:**
Parsing completo de HTML → TreeNode é complexo. A abordagem pragmática para MVP:
- **Opção pragmática:** ao salvar no Monaco, enviar HTML ao backend via endpoint de parse → backend retorna `documentTree` atualizado → `templateStore` é atualizado
- **Opção alternativa:** usar DOMParser no frontend para extrações simples (atributos, texto) sem reconstruir a árvore completa

**Depende do ADR 29.1** — se Opção A estiver implementada, o endpoint de parse do backend pode ser o mesmo (ou adjacente) ao de regeneração.

**Referências:**
- `frontend/src/organisms/MonacoTabsInner.vue` (linha 154) — `codeStore.applyMonacoEdit()`
- `frontend/src/stores/codeStore.ts` — `fileContents`, `applyMonacoEdit()`
- `frontend/src/stores/templateStore.ts` — precisa ser atualizado após parse
- Gap analysis: `docs/architecture/gap-analysis-frontend-v3.md` (GAP 2)
- ADR: `docs/architecture/adr-canvas-rerender-strategy.md`

**Dependências:** 29.1 (ADR — define se parse é frontend ou backend)

## Acceptance Criteria

- **AC1:** **Dado** que o operador edita o texto de um elemento no Monaco (ex: `<span>Cedente</span>` → `<span>Sacado</span>`), **Quando** o debounce de 800ms expira, **Então** o nó correspondente na árvore exibe o novo texto
- **AC2:** **Dado** que o operador adiciona um atributo a um elemento no Monaco (ex: `data-field="cliente"`), **Quando** a sync ocorre, **Então** o inspector do nó correspondente reflete o novo atributo
- **AC3:** **Dado** que o operador para de digitar, **Quando** passam 800ms sem nova edição, **Então** a sincronização é disparada automaticamente (sem necessidade de salvar manualmente)
- **AC4:** **Dado** que o operador digita HTML inválido (tag não fechada), **Quando** o debounce expira, **Então** nenhum crash ocorre, o Monaco exibe um marker de erro e a árvore permanece inalterada
- **AC5:** **Dado** os testes de `codeStore.spec.ts`, **Quando** executados após edição no Monaco, **Então** cobrem o trigger de sincronização e atualização do `templateStore`, todos passando

## Dev Notes

### Fluxo de sincronização (Opção A — backend parse)

```typescript
// codeStore.ts — após applyMonacoEdit:
async function applyMonacoEdit(key: string, value: string) {
  fileContents[key] = value
  if (key === 'html') {
    scheduleHtmlSync(value)
  }
}

let syncTimer: ReturnType<typeof setTimeout> | null = null

function scheduleHtmlSync(html: string) {
  if (syncTimer) clearTimeout(syncTimer)
  syncTimer = setTimeout(() => syncHtmlToTree(html), 800)
}

async function syncHtmlToTree(html: string) {
  try {
    const { data } = await api.post('/api/template/parse-html', { html })
    templateStore.updateFromParsedTree(data.tree)
  } catch (err) {
    console.warn('[codeStore] syncHtmlToTree failed:', err)
    // Não propagar erro — árvore permanece inalterada (AC4)
  }
}
```

### Fluxo alternativo (Opção B — DOMParser frontend para MVP)

```typescript
function syncHtmlToTree(html: string) {
  try {
    const parser = new DOMParser()
    const doc = parser.parseFromString(html, 'text/html')
    if (doc.querySelector('parseerror')) return // HTML inválido, ignorar (AC4)

    // Extrações simples: atualizar texto dos nós existentes
    const flatNodes = templateStore.flatNodes
    flatNodes.forEach(node => {
      if (!node.id) return
      const el = doc.querySelector(`[data-node-id="${node.id}"]`)
      if (!el) return
      const textContent = el.textContent?.trim()
      if (textContent && textContent !== node.properties?.text) {
        templateStore.updateNodeProperty(node.id, 'text', textContent)
      }
    })
  } catch (err) {
    console.warn('[codeStore] DOMParser sync failed:', err)
  }
}
```

**Nota:** Opção B não reconstrói a árvore — apenas sincroniza propriedades dos nós existentes. Para casos de adição/remoção de nós no HTML, o backend (Opção A) é necessário.

### Função a adicionar em templateStore.ts

```typescript
function updateFromParsedTree(newTree: DocumentTree) {
  // Preservar seleção atual
  const selectedId = editorStore.selectedElementId
  documentTree.value = newTree
  bumpVersion() // trigger re-render no HTMLCanvas
  // Restaurar seleção se nó ainda existe
  if (selectedId && getNodeById(selectedId)) {
    editorStore.selectElement(selectedId)
  }
}
```
