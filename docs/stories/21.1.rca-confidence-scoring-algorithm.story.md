# Story 21.1 — Algoritmo de Confidence Scoring Normalizado

## Story
**Como** investigador executando `/investigate`,
**Quero** que o confidence score do SOP fast-track seja calculado por um algoritmo definido e normalizado para 0-100%,
**Para** que decisoes de fast-track sejam consistentes e reprodutiveis entre investigadores.

## Status
Done

## Context

### Problema
O v5.0 usa pesos heuristicos (+3 sintomas similares, +2 mesmos arquivos, +1 dominio, +2 fix effective) mas nao normaliza para 0-100%. Um investigador pode calcular 8/8 = 100% enquanto outro interpreta 6/8 = 75%. Sem algoritmo, o threshold de 80% para fast-track eh arbitrario.

### Design
Definir formula de scoring:
1. **Dimensoes** com peso maximo:
   - Symptom match (0-30): exact error type +30, similar +20, same category +10
   - Location match (0-25): same function +25, same file +20, same module +15, same layer +10
   - Domain match (0-15): same Cynefin domain +15
   - Fix effectiveness (0-20): previous fix resolved +20, partial +10, untested +0
   - Recurrence (0-10): 3+ occurrences +10, 2 +5, 1 +0
2. **Score final** = soma / 100 (ja normalizado)
3. **Documentar** no investigate.md com exemplos

## Acceptance Criteria
- [ ] Formula de scoring definida com dimensoes, pesos e normalizacao
- [ ] Score final normalizado para 0-100% (nao depende de interpretacao)
- [ ] Exemplos concretos documentados: score alto (>90%), medio (70-89%), baixo (<70%)
- [ ] Fase 2 do investigate.md usa a formula em vez dos pesos ad-hoc
- [ ] Workflow YAML referencia o algoritmo
- [ ] SOP template inclui campo para pre-calcular score base

## Scope
**IN:** Fase 2 do investigate.md, formula de scoring, documentacao
**OUT:** Implementacao automatizada do calculo (manual por investigador)
