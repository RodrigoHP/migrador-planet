# Story 17.8 — Meta-Learner Agent

## Story
**Como** equipe que realiza multiplas investigacoes ao longo do tempo,
**Quero** que o sistema aprenda com cada RCA — refinando estrategias, atualizando knowledge base, e identificando padroes recorrentes automaticamente,
**Para** que cada investigacao futura seja mais rapida e precisa que a anterior, criando um ciclo virtuoso de melhoria.

## Status
Ready

## Context

### Problema

Cada RCA eh um evento isolado. O conhecimento gerado (root causes, SOPs, anti-patterns) eh registrado mas nao sintetizado. Nao existe:
- Analise de quais tipos de bugs sao mais frequentes
- Feedback loop sobre effectiveness dos fixes
- Refinamento da estrategia de investigacao baseado em resultados
- Deteccao automatica de padroes recorrentes entre investigacoes

### Inspiracao

- **Self-Healing Systems** (2025): Bio-inspirado — cada fix vira training data
- **Flow-of-Action** (WWW 2025): SOPs auto-gerados a partir de investigacoes
- **Reinforcement Learning**: Otimizar estrategia de investigacao por resultado
- **Google SRE**: Postmortems revisados regularmente para extrair padroes

### Design Proposto

**Meta-Learner** — executa apos cada RCA completado:

```
Input: relatorio completo do RCA + evidence grades + fix aplicado

1. REGISTER — gravar investigacao na knowledge base
   - Adicionar investigation record (17.4)
   - Gerar SOP se padrao novo (17.4)
   - Registrar anti-pattern se descoberto

2. ANALYZE TRENDS — comparar com historico
   - Frequencia por area: "pipeline/ teve 4 bugs no ultimo mes"
   - Frequencia por tipo: "TypeError eh 40% dos bugs"
   - Frequencia por causa raiz: "missing guards = causa #1"
   - Mean Time to Resolution por dominio Cynefin

3. EFFECTIVENESS REVIEW — avaliar fixes anteriores
   - Para cada fix com > 30 dias: "bug recorreu?"
   - Se recorreu: marcar fix como `partial` ou `ineffective`
   - Se nao recorreu: marcar como `resolved`
   - Atualizar confidence dos SOPs afetados

4. STRATEGY REFINEMENT — melhorar o processo
   - Quais tecnicas produziram melhores resultados?
   - Classifier estava correto? (domain real vs classificado)
   - Archaeologist encontrou o change suspeito no top 3?
   - Hypothesis Challenger refutou alguma hipotese que seria aceita?
   - Gerar "investigation scorecard" com metricas

5. PATTERN DETECTION — identificar tendencias
   - Clustering de bugs por area/tipo/causa
   - Alerta se padrao recorrente detectado:
     "⚠️ 3o bug de TypeError em pipeline/ no ultimo mes.
      Pattern: missing type guards. Recomendacao: audit proativo."

Output:
  meta_learning:
    investigation_registered: true
    sop_generated: "sop-missing-type-guard.yaml"
    anti_pattern_registered: true
    trends:
      top_area: "pipeline/"
      top_type: "TypeError"
      top_root_cause: "missing_guard"
      mttr_by_domain:
        clear: "15 min"
        complicated: "45 min"
        complex: "3h"
    effectiveness:
      fixes_reviewed: 5
      resolved: 3
      partial: 1
      ineffective: 1
    strategy_scorecard:
      classifier_accuracy: 0.80
      archaeologist_top3_hit: 0.90
      challenger_refutations: 2
    alerts:
      - "Padrao recorrente: TypeError em pipeline/ (3x no mes)"
```

### Ciclo Virtuoso Completo

```
Bug → RCA v4.0 → Fix → Meta-Learner
                           ↓
                  Knowledge Base atualizada
                  SOPs refinados
                  Anti-patterns registrados
                  Estrategias melhoradas
                           ↓
                  Proximo Bug → RCA mais rapido
                           ↓
                  Pattern detected → Audit proativo
                           ↓
                  Bugs prevenidos ANTES de acontecer
```

## Complexity

**Estimativa:** Registro + trend analysis + effectiveness tracking + pattern detection + scorecard. Depende de knowledge base (17.4) e evidence grading (17.7).

## Scope

**IN:**
- Meta-learning loop pos-RCA
- Trend analysis (area, tipo, causa)
- Effectiveness tracking de fixes
- Strategy scorecard
- Pattern detection com alertas
- Novo comando `*rca-insights`

**OUT:**
- Nao implementar ML/RL real (analise baseada em LLM + heuristicas)
- Nao implementar dashboard visual (output textual)
- Nao implementar cross-project learning (futuro)

## Risks

- Trend analysis com poucos data points (<5 investigacoes) pode gerar insights espurios (ex: "TypeError eh 100% dos bugs" com n=2). Mitigacao: exigir minimo de 3 investigacoes antes de reportar trends; exibir n junto com percentuais.
- Effectiveness review depende de verificacao manual (o bug recorreu?) que pode nao ser feita. Mitigacao: alertar quando fix com >30 dias nao tem effectiveness atualizado.
- Strategy scorecard pode ser injusto se classificacao foi overrideada manualmente (Classifier accuracy medida contra override, nao contra realidade). Mitigacao: distinguir classificacao original vs final no scorecard.
