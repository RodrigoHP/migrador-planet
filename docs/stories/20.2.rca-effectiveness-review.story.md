# Story 20.2 — Effectiveness Review Automatico

## Story
**Como** time de qualidade,
**Quero** que investigacoes com effectiveness=pending ha >7 dias sejam revisadas automaticamente via `*audit-patterns`,
**Para** fechar o loop de aprendizado e saber se os fixes realmente funcionaram.

## Status
Draft

## Context

### Problema
Ambas investigacoes existentes estao com `effectiveness: pending` indefinidamente. Nao existe mecanismo que triggere a revisao. O campo nunca eh atualizado, tornando o tracking de eficacia inutil.

### Design
Integrar no `*audit-patterns` (ou criar task se nao existir):
- Ler investigations.yaml, filtrar pending ha >7 dias
- Para cada: verificar se bug recorreu (grep por mesmo erro/tag em commits recentes)
- Atualizar effectiveness para resolved/partial/ineffective
- Se ineffective: gerar alerta recomendando nova investigacao

## Acceptance Criteria
- [ ] `*audit-patterns` inclui step de effectiveness review para investigacoes pending >7d
- [ ] Para cada investigacao pending, verifica se bug recorreu (grep por sintomas em commits recentes)
- [ ] Atualiza effectiveness para `resolved`, `partial`, ou `ineffective` baseado na evidencia
- [ ] Se `ineffective`: gera alerta recomendando nova investigacao
- [ ] Schema de investigations.yaml documenta campo `effectiveness_reviewed_at`
- [ ] Fase 9 do investigate.md referencia o review automatico

## Scope
**IN:** investigate.md (Fase 9), audit-patterns task, schema investigations.yaml
**OUT:** Automacao CI/CD (future work)
