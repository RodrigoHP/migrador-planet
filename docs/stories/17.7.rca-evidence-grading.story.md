# Story 17.7 — Evidence Grading System

## Story
**Como** investigador que le um relatorio RCA,
**Quero** que cada achado seja classificado por nivel de evidencia (confirmado, correlacionado, hipotese),
**Para** que eu saiba a confianca de cada conclusao e priorize fixes baseado em certeza, nao em opiniao.

## Status
Ready

## Context

### Problema

Relatorios RCA atuais misturam fatos confirmados com teorias. "O commit X causou o bug" e "Provavelmente a dependencia Y contribuiu" aparecem lado a lado sem distincao. O leitor nao sabe quais achados sao certos e quais sao especulativos.

AgentRx (Microsoft, 2026) e GALA (2025) mostram que **grounded evidence chains** — onde cada claim cita sua fonte — eliminam hallucination e melhoram a qualidade da investigacao.

### Inspiracao

- **AgentRx** (Microsoft, 2026): Grounded failure taxonomy com evidence chains
- **Medicina baseada em evidencia**: Niveis de evidencia (meta-analise > RCT > estudo observacional > opiniao)
- **Legal**: Proof standards (beyond reasonable doubt > preponderance > probable cause)

### Design Proposto

**4 niveis de evidencia para RCA:**

| Nivel | Nome | Criterio | Exemplo |
|-------|------|----------|---------|
| E1 | **Confirmed** | Reproduzido por teste ou git bisect | "git bisect confirma: commit abc123 introduziu o bug" |
| E2 | **Correlated** | Dados sugerem forte correlacao | "Bug comecou 2h apos deploy, 3 commits na area afetada" |
| E3 | **Hypothesized** | Teoria plausivel sem evidencia direta | "Possivel race condition sob carga alta" |
| E4 | **Speculative** | Possibilidade remota | "Talvez cosmic ray bit flip no servidor" |

**Evidence Chain:**
Cada claim deve citar fonte:
```yaml
claim: "Commit abc123 removeu type guard de stage 5"
evidence_level: E1_confirmed
sources:
  - type: git_diff
    ref: "abc123:src/pipeline/stage5.py:L42"
    detail: "Removed isinstance check in refactor"
  - type: test_reproduction
    ref: "test_stage5_type_guard added, fails on abc123~1"
```

**Relatorio com evidence grading:**
```
## Root Causes

### Primary: Missing type guard in stage 5 traversal [E1 CONFIRMED]
- Evidence: git bisect (abc123), test reproduction, git diff
- Confidence: 0.95

### Contributing: No test coverage for stage 3 return type [E2 CORRELATED]
- Evidence: coverage report (0% for _summarize_extraction), same module
- Confidence: 0.72

### Discarded: Dependency update of lodash [E3→REFUTED]
- Initially hypothesized, refuted by changelog analysis and version pinning test
- Confidence: 0.08
```

## Acceptance Criteria

- [ ] AC1: 4 niveis de evidencia definidos: E1 Confirmed, E2 Correlated, E3 Hypothesized, E4 Speculative
- [ ] AC2: Cada root_cause e contributing_factor no relatorio recebe evidence level
- [ ] AC3: Evidence chain obrigatoria: cada claim cita pelo menos 1 source com type e ref
- [ ] AC4: Source types aceitos: git_diff, git_bisect, test_reproduction, log_analysis, code_analysis, coverage_report, manual_verification
- [ ] AC5: Confidence score (0.0-1.0) derivado do evidence level + numero de sources
- [ ] AC6: Relatorio final agrupa achados por evidence level (E1 primeiro)
- [ ] AC7: Achados E4 (speculative) nao geram action items — apenas registrados
- [ ] AC8: Achados refutados durante challenge incluidos como "Discarded" com motivo

## Complexity

**T-shirt size:** S (Small)
**Estimativa:** Schema de evidence, tagging de claims, formatacao de relatorio. Reutiliza output do Causal Reasoner e Hypothesis Challenger.

## Scope

**IN:**
- Schema de evidence levels e evidence chains
- Tagging de todos os achados no relatorio
- Confidence scoring baseado em evidence
- Formatacao do relatorio com evidence grading
- Integracao com outputs de 17.3 (Causal Reasoner) e 17.5 (Hypothesis Challenger)

**OUT:**
- Nao implementar verificacao automatica de sources (humano valida)
- Nao implementar metricas de accuracy do evidence grading (futuro)

## Risks

- Confidence scores derivados de evidence level podem dar falsa impressao de precisao quantitativa quando sao heuristicas qualitativas. Mitigacao: documentar que scores sao indicativos, nao probabilisticos.
- Evidence chains podem ser incompletas se o investigador nao citar fontes adequadamente. Mitigacao: validacao minima — cada claim requer pelo menos 1 source.

7. Incluir achados refutados como "Discarded" com motivo
8. Testar: relatorio deve ter mix de E1/E2/E3 com sources citadas
