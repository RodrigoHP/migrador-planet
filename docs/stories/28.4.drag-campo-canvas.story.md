# Story 28.4 — Drag de campo para o canvas

## Story
**Como** operador vinculando campos por arrastar e soltar,
**Quero** arrastar um campo da aba Campos e soltá-lo sobre um elemento no canvas visual,
**Para** vincular o campo XSD ao elemento do template de forma intuitiva.

## Status
Done

## Context

**Por que o drag Campos → Estrutura nunca funcionou:**

`LeftPanel.vue` usa `v-if/v-else-if` — quando a aba Campos está ativa, a StructureTree **não existe no DOM**. O handler `handleDropField` da StructureTree nunca pode ser acionado via drag de FieldNavItem. É dead code de interação.

**O Canvas é o drop target correto:**
- O Canvas (`HTMLCanvas.vue`) está no painel central — diferente da LeftPanel
- Quando o usuário está na aba Campos e arrasta, o Canvas está visível e acessível
- O drag é fisicamente possível: LeftPanel (esquerda) → Canvas (centro)

**O que precisa ser implementado:**
- `HTMLCanvas.vue`: handlers `@dragover` + `@drop` que detectem `drag-type === 'field'`
- Lógica para identificar qual elemento do canvas está sob o cursor no drop
- Highlight visual durante dragover ("drop aqui" com outline azul)
- Ao dropar: chamar o mesmo `mappingStore.mapField` que a StructureTree já usa

**Referências de design:**
- Análise do dead code: `frontend/docs/epic-28-ux-audit.md` (seção "🔴 CRÍTICA — Drag dead code")
- Comportamento esperado: `frontend/docs/epic-28-field-mapping-interaction-spec.md` (seção Story 28.4)
- Epic: `docs/epics/epic-28-field-mapping-redesign.md`

**Dependências:** 28.1 (updateNodeBinding), 28.2 (FieldNavItem com drag correto)

## Acceptance Criteria

- **AC1:** Arrastar campo da aba Campos sobre um elemento no canvas mostra highlight "drop aqui" (outline azul no elemento)
- **AC2:** Soltar sobre elemento: vincula o binding (chama `mappingStore.updateNodeBinding(nodeId, xsdPath)`)
- **AC3:** Se o elemento já tem binding: abre dialog de confirmação "Substituir binding de {{atual}} por {{novo}}?"
- **AC4:** Arrastar sobre área sem elemento: cursor `no-drop`, sem highlight, sem ação ao soltar
- **AC5:** Ao cancelar drag (tecla Escape ou arrastar para fora do canvas): highlight removido, sem efeito
- **AC6:** Testes: `HTMLCanvas.spec.ts` cobre dragover/drop com e sem elemento alvo

### Como o drag é iniciado (já funciona em FieldNavItem)

```typescript
// FieldNavItem.vue — já implementado:
function onDragStart(event: DragEvent) {
  if (!event.dataTransfer) return
  event.dataTransfer.setData('drag-type', 'field')
  event.dataTransfer.setData('field-id', props.item.id)
  event.dataTransfer.setData('field-path', props.item.path)  // XSD path
  event.dataTransfer.effectAllowed = 'copy'
}
```

### Handlers em `HTMLCanvas.vue`

Adicionar no template:
```vue
<div
  class="html-canvas"
  @dragover.prevent="onDragOver"
  @dragleave="onDragLeave"
  @drop="onDrop"
  @dragend="onDragEnd"
>
```

```typescript
// Elemento sob o cursor durante dragover
const hoveredNodeId = ref<string | null>(null)

function onDragOver(event: DragEvent) {
  // Verificar que é um drag de campo (não outros tipos)
  if (!event.dataTransfer?.types.includes('drag-type')) return

  // Identificar qual elemento do canvas está sob o cursor
  const target = getNodeAtPosition(event.clientX, event.clientY)
  hoveredNodeId.value = target?.id ?? null

  // Cursor visual
  event.dataTransfer.dropEffect = hoveredNodeId.value ? 'copy' : 'none'
}

function onDragLeave(event: DragEvent) {
  // Só limpar se saiu do canvas inteiro (não de filho para filho)
  if (!event.currentTarget?.contains(event.relatedTarget as Node)) {
    hoveredNodeId.value = null
  }
}

async function onDrop(event: DragEvent) {
  event.preventDefault()
  const dragType = event.dataTransfer?.getData('drag-type')
  if (dragType !== 'field') return

  const xsdPath = event.dataTransfer?.getData('field-path')
  const targetNodeId = hoveredNodeId.value
  hoveredNodeId.value = null

  if (!targetNodeId || !xsdPath) return

  // Verificar se o nó já tem binding
  const targetNode = templateStore.getNodeById(targetNodeId)
  if (targetNode?.binding) {
    const confirmed = await showConfirmDialog(
      `Substituir binding de "${targetNode.binding}" por "${xsdPath}"?`
    )
    if (!confirmed) return
  }

  mappingStore.updateNodeBinding(targetNodeId, xsdPath)
}

function onDragEnd() {
  hoveredNodeId.value = null
}
```

### Identificar nó sob o cursor: `getNodeAtPosition`

O canvas renderiza elementos em posições absolutas. Para identificar qual elemento está sob o cursor:

**Opção A (Element under cursor):**
```typescript
function getNodeAtPosition(x: number, y: number): TemplateNode | null {
  // elementFromPoint retorna o elemento DOM mais específico
  const el = document.elementFromPoint(x, y)
  // Subir na árvore DOM até encontrar data-node-id
  let current = el
  while (current) {
    const nodeId = (current as HTMLElement).dataset?.nodeId
    if (nodeId) return templateStore.getNodeById(nodeId)
    current = current.parentElement
  }
  return null
}
```

Esta abordagem requer que os elementos do canvas tenham `data-node-id="{{node.id}}"` no template. Verificar se já existe ou adicionar.

**Opção B (Bbox matching):**
Se os nós têm `bbox` (coordenadas do PDF), comparar posição do cursor com bboxes transformadas para coordenadas de tela.

**Recomendação:** Verificar `HTMLCanvas.vue` e `CanvasElement.vue` para ver qual abordagem é viável com a renderização atual.
