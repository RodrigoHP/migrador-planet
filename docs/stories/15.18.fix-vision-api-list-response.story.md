# Story 15.18 — Fix Vision API list response crash

## Story
**Como** operador que executa o pipeline,
**Quero** que a Vision API funcione de forma resiliente mesmo quando o modelo retorna um array JSON em vez de objeto,
**Para** que o Stage 3 não quebre com `AttributeError: 'list' object has no attribute 'get'`.

## Status
Done

## Context

### FIX-PIPELINE-007: _parse_visual_response não trata resposta do tipo lista

A função `_parse_visual_response` em `stage3_structural_analysis.py` assume que `json.loads(response)` sempre retorna um dict (`{}`). Porém, o modelo GPT-4o via OpenRouter às vezes retorna apenas o array de regiões diretamente (ex.: `[{"type": "header", ...}]`), especialmente quando `response_format={"type": "json_object"}` não é respeitado pelo provedor.

**Erro observado nos logs de produção:**
```
Vision API call failed for #0: 'list' object has no attribute 'get'
```

**Traceback lógico:**
```python
# stage3_structural_analysis.py:328-332
data = json.loads(cleaned.strip())   # retorna list: [{...}, {...}]
regions = data.get("regions", [])    # AttributeError: 'list' object has no attribute 'get'
```

**Impacto:** Stage 3.2 falha para todos os clusters, `handle_service_failure` é chamado (corretamente, graças a story 15.16), mas o retry também falha → fallback para análise adaptativa em todos os layouts.

## Acceptance Criteria

- [x] AC1: `_parse_visual_response` não lança exceção quando `json.loads` retorna uma lista
- [x] AC2: Quando o response é uma lista, ela é tratada como o array de regiões (`regions`)
- [x] AC3: `consistency_score` e `consistency_notes` recebem valores default quando response é lista
- [x] AC4: O resultado retornado mantém a mesma estrutura: `{"regions": [...], "consistency_score": int, "consistency_notes": str}`
- [x] AC5: Teste unitário cobrindo o caso de resposta lista

## Implementation Notes

**Fix em `_parse_visual_response` (linhas 322-361):**

```python
def _parse_visual_response(raw_json: str) -> Dict[str, Any]:
    try:
        cleaned = re.sub(r"^```(?:\w*)\s*\n?", "", raw_json.strip())
        cleaned = re.sub(r"\n?```\s*$", "", cleaned)
        data = json.loads(cleaned.strip())
    except json.JSONDecodeError:
        return {"regions": [], "consistency_score": 0, "consistency_notes": "parse_error"}

    # NOVO: modelo retornou array diretamente em vez de objeto
    if isinstance(data, list):
        data = {"regions": data, "consistency_score": 0, "consistency_notes": "auto_wrapped"}

    regions = data.get("regions", [])
    # ... resto do código inalterado
```

**Teste a adicionar:**
```python
def test_parse_visual_response_handles_list_response():
    """_parse_visual_response deve tratar lista JSON como array de regiões."""
    raw = '[{"type": "header", "bbox": [0, 0, 595, 80], "description": "header"}]'
    result = _parse_visual_response(raw)
    assert result["regions"] == [{"type": "header", "bbox": [0, 0, 595, 80], ...}]
    assert result["consistency_score"] == 0
    assert result["consistency_notes"] == "auto_wrapped"
```
