# Story 32.5 — Implementar SVG inline (FR32)

## Story
**Como** operador usando o editor de templates,
**Quero** que elementos vetoriais do PDF sejam embeddados como SVG inline no HTML,
**Para** que logos e decoracoes mantenham qualidade vetorial no template.

## Status
Done

## Acceptance Criteria

- [x] AC1: Stage5 reconhece node type "svg" e renderiza como SVG inline
- [x] AC2: SVG node recebe bbox para posicionamento absoluto
- [x] AC3: SVG content e inserido como markup inline (nao base64 img)
- [x] AC4: Fallback para placeholder div quando svg_content esta vazio
- [x] AC5: Testes cobrem rendering de svg nodes com e sem content

## Scope

**IN:**
- Handler para node type "svg" em _tree_to_html
- SVG nodes no document_tree (gerados por futuro stage3 enhancement)
- Testes unitarios

**OUT:**
- Deteccao automatica de SVG no stage3 (requer PyMuPDF avancado — fase futura)
- Conversao de raster para vetor
- Edicao de SVG no frontend

## Tasks

- [x] Task 1: Adicionar handler "svg" em _tree_to_html
- [x] Task 2: Escrever testes para svg nodes
- [x] Task 3: Documentar formato esperado do svg node

## Dev Notes
O document_tree pode conter nodes type=svg com campos:
- svg_content: string SVG markup
- bbox: posicionamento
- id/block_id: identificador
A deteccao automatica (stage3 usando get_drawings) fica para epic futuro.
Esta story garante que o pipeline CONSOME svg nodes corretamente.
