# Story 5.1: Scaffold Reset — Reestruturação de Rotas e Remoção de Páginas Obsoletas do Wizard

## Status
Draft

## Story
**As a** desenvolvedor,
**I want** que o projeto seja reestruturado com novas rotas (Home→Upload→Analyzing→Editor), páginas obsoletas do wizard removidas (CamposPage, LayoutPage, GeracaoPage, ExportarPage) e layouts obsoletos removidos (WizardLayout, SplitPaneLayout),
**so that** o codebase reflita o novo paradigma do editor unificado.

## Acceptance Criteria
1. Vue Router config atualizado: rotas para `/` (Home), `/upload` (Upload), `/analyzing` (Analyzing), `/editor` (Editor)
2. CamposPage.vue, LayoutPage.vue, GeracaoPage.vue, ExportarPage.vue removidos ou marcados como deprecated
3. WizardLayout.vue, SplitPaneLayout.vue removidos
4. WizardStepper.vue removido
5. AnalyzingPage.vue shell criado (placeholder vazio)
6. TemplateEditor.vue shell criado (placeholder vazio)
7. EditorLayout.vue shell criado (placeholder vazio)
8. Navigation guards atualizados (Upload requer arquivos, Analyzing requer job ativo, Editor requer análise completa)
9. `npm run build` passa
10. `tsc --noEmit` passa

## Dev Notes

### Contexto de Navegação
- Rotas atuais (wizard): Home → Upload → Campos → Layout → Geração → Exportar
- Novas rotas (PRD v3.0): Home → Upload → Analyzing → Editor
- O fluxo muda de wizard multi-step para pipeline + editor unificado

### Componentes a Manter
- `HomePage.vue` — será adaptada na Story 5.2
- `UploadPage.vue` — será adaptada na Story 5.3
- `FullWidthLayout.vue` — reutilizável para Home, Upload e Analyzing

### Componentes a Remover
- `CamposPage.vue` — funcionalidade absorvida pelo Editor
- `LayoutPage.vue` — funcionalidade absorvida pelo Editor
- `GeracaoPage.vue` — funcionalidade absorvida pelo pipeline automático
- `ExportarPage.vue` — funcionalidade absorvida pelo Editor
- `WizardLayout.vue` — não há mais wizard
- `SplitPaneLayout.vue` — Editor usa EditorLayout próprio
- `WizardStepper.vue` — não há mais stepper

### Stack Frontend
- Vue 3 + TypeScript + Vite + Pinia + Vue Router 5.x + Tailwind CSS 4.x
- Stores Pinia para estado de sessão (job_id, análise concluída)

### Navigation Guards
- Upload: acessível sem restrições
- Analyzing: requer `sessionStore.job_id` definido (set após POST /api/upload)
- Editor: requer `sessionStore.analysisCompleted === true`

### Referência FR
- FR36 (structure): estrutura do projeto reflete novo paradigma

### Testing
- Vitest for unit tests
- Test files alongside source: `*.spec.ts` or `*.test.ts`
