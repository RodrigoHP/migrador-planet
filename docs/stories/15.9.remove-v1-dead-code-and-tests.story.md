# Story 15.9 — Remove Pipeline v1 Dead Code: Helpers + Testes

## Story

**Como** desenvolvedor do projeto,
**Quero** remover os 24 helper files do pipeline v1 junto com os testes que os testam diretamente,
**Para** eliminar o dead code identificado no audit da story 15.6 sem quebrar a suíte de testes ativa.

## Status

Done

## Context

### Problema

O audit completo realizado na story 15.6 (2026-03-28) identificou:

- **24 de 29 helpers** em `backend/services/stages/` com zero imports em código de produção ativo
- **5 helpers** usados pelo pipeline v2 ativo: `format_detection`, `xsd_parser`, `representative_selection`, `visual_segmentation` (cadeia de dependência transitiva), e `register_all.py`
- **Bloqueador da 15.6:** todos os 24 helpers removíveis são importados por testes v1 — remoção sem retirar esses testes quebra a suíte

A story 15.6 foi bloqueada por estar fora do seu escopo remover testes. Esta story expande o escopo para remover **helpers v1 + testes v1 juntos**, de forma atômica e segura.

### Estado Atual do Código

Referência: Dev Notes da story 15.6 (audit table completa).

**Helpers a manter (usados por stages v2 ativos):**
- `format_detection.py` — importado por `stage4_field_mapping.py`
- `xsd_parser.py` — importado por `stage4_field_mapping.py` e `_deprecated/jobs.py`

**Helpers a remover (zero imports em produção):**
24 arquivos listados na tabela abaixo.

**`register_all.py` e `models/pipeline.py` (StageRegistry):**
- `register_all()` já foi removido de `main.py` no PR #23
- `register_all.py` ainda existe mas não é chamado em produção
- `StageRegistry`, `BlockDefinition`, `build_default_registry()` em `models/pipeline.py` são v1
- `PipelineDefinition` em `models/pipeline.py` DEVE ser mantida (usada como schema)

### Scope — IN vs OUT

**IN SCOPE:**
- Remover `register_all.py` inteiro
- Remover `StageRegistry`, `BlockDefinition`, `build_default_registry()`, `default_registry` de `models/pipeline.py` (manter `PipelineDefinition`)
- Remover os 24 helper files v1 identificados no audit
- Remover os testes v1 que testam exclusivamente os helpers removidos
- Para testes mistos (testam v1 + v2): remover apenas os casos de teste v1, manter os v2
- Validar que zero imports quebrados após remoção

**OUT OF SCOPE:**
- Refactor dos 5 stages ativos (stage1–stage5)
- Mover ou alterar `_deprecated/` directory
- Alterar lógica de negócio de qualquer stage ativo
- Remover `format_detection.py`, `xsd_parser.py` (usados por stage4)
- Remover `representative_selection.py` se ainda em uso transitivo (verificar)
- Remover `visual_segmentation.py` se ainda em uso transitivo (verificar)

## Technical Notes

- **Ordem de remoção:** helpers primeiro → testes que os importam → models/pipeline v1 → validar imports
- **Testes mistos:** Antes de deletar, verificar se o arquivo de teste tem casos para o pipeline v2. Em caso afirmativo, refatorar o arquivo para remover apenas os imports/casos v1.
- **`representative_selection.py`:** Usado apenas por `fingerprint_generation.py` (que é v1). Ao remover `fingerprint_generation`, `representative_selection` torna-se órfão — remover também.
- **`visual_segmentation.py`:** Usado apenas por `vision_self_check.py` (que é v1). Ao remover `vision_self_check`, `visual_segmentation` torna-se órfão — remover também.
- **`_deprecated/jobs.py`:** Importa `xsd_parser` — verificar se `_deprecated/jobs.py` pode ser removido também (está em `_deprecated/`, provavelmente morto).
