# Story 23.10 — Tag Taxonomy: Enforcement Real

## Story
**Como** sistema de knowledge management,
**Quero** que tags sejam validadas contra a taxonomia antes do registro,
**Para** que pattern matching futuro funcione com vocabulario consistente.

## Status
Done

## Context

### Problema
RCA usa tags fora do vocabulario (`guard`, `isinstance`, `wireframe` em vez de `guard_missing`, `guard_added`, `wireframe_divergence`). Taxonomia eh advisory, nao enforced. Nao ha rejeicao nem sugestao de correacao.

### Design
Na Fase 8, ANTES de registrar tags:

```
## Tag Validation (OBRIGATORIO antes de registrar)

1. Ler docs/qa/rca-knowledge/tag-taxonomy.yaml
2. Para cada tag proposta:
   a. SE tag existe no vocabulario → ✅ aceitar
   b. SE tag NAO existe mas existe equivalente proximo → ⚠️ sugerir equivalente
   c. SE tag NAO existe e nao ha equivalente → exigir prefixo "custom:"
3. Mostrar tabela de validacao:

| Tag Proposta | Status | Acao |
|---|---|---|
| type_error | ✅ Valida | — |
| guard | ⚠️ Invalida | Sugerir: guard_missing (root_cause_category) |
| isinstance | ⚠️ Invalida | Sugerir: guard_added (fix_type) |

4. Corrigir tags antes de registrar
```

**Retroativo:** Corrigir tags nos 2 registros existentes:
- `guard` → `guard_missing`
- `isinstance` → `guard_added`
- `wireframe` → `wireframe_divergence`
- `sse_summary` → `custom:sse_summary` (ou promover para taxonomia)

## Acceptance Criteria
- [ ] Fase 8 tem step de tag validation antes do registro
- [ ] Tabela mostrando status de cada tag (valida/invalida/custom)
- [ ] Sugestao automatica de equivalente quando possivel
- [ ] Tags custom exigem prefixo "custom:"
- [ ] Registros existentes corrigidos retroativamente
- [ ] tag-taxonomy.yaml atualizado se tags custom recorrentes promovidas
