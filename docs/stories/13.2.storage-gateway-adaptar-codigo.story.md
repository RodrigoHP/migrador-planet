# Story 13.2 — Adaptar Código Existente para Storage Gateway

## Story
**Como** pipeline de migração,
**Quero** que todos os arquivos que salvam em disco usem StorageGateway,
**Para** que a abstração funcione end-to-end e o pipeline continue operacional.

## Status
InReview

## Context

### Problema
7 arquivos salvam diretamente em `/tmp` via `TMP_BASE` ou `ASSETS_BASE`. Precisam ser migrados para usar `StorageGateway` (Story 13.1).

### Arquivos a Adaptar
| Arquivo | O que faz hoje | Mudança |
|---------|---------------|---------|
| `backend/routers/upload.py` | `TMP_BASE / job_id` + `write_bytes` | `gateway.upload_pdf()` + temp local |
| `backend/routers/analyze.py` | Lê de `/tmp` direto | `gateway.get_local_path()` + cleanup |
| `backend/routers/assets.py` | `ASSETS_BASE = Path("/tmp/templates")` | `gateway.upload_asset()` / `get_signed_url()` |
| `backend/services/stages/screenshot_generator.py` | `Path("/tmp/{job_id}/screenshots/")` | `gateway.upload_screenshot()` |
| `backend/services/stages/image_extraction.py` | `Path("/tmp/{job_id}/assets/")` | `gateway.upload_asset()` |
| `backend/services/stages/pipeline_result.py` | Supabase parcial + disco | `gateway.save_result()` obrigatório |
| `frontend/src/stores/session.ts` | `screenshot_path` como path local | Signed URL via API |

## Acceptance Criteria

1. `upload.py` usa `gateway.upload_pdf()` para cada PDF + `gateway.upload_asset()` para XSD
2. `analyze.py` usa `gateway.get_local_path()` para obter PDFs para processamento e `gateway.cleanup_local()` no final
3. `assets.py` usa `gateway.upload_asset()` e `gateway.get_signed_url()` para servir assets
4. `screenshot_generator.py` usa `gateway.upload_screenshot()` em vez de `Path.write_bytes()`
5. `image_extraction.py` usa `gateway.upload_asset()` em vez de salvar direto em disco
6. `pipeline_result.py` usa `gateway.save_result()` como obrigatório (não opcional)
7. `session.ts` carrega screenshots via signed URL (não path local)
8. Pipeline existente continua funcionando (regressão zero) com `STORAGE_MODE=local`
9. Testes de integração validam ambos modos (local + supabase mock)

## Dev Notes

### Dependência
Depende de **Story 13.1** (StorageGateway ABC + implementações).

### Padrão de Injeção
O `storage` singleton é importado de `backend.services.storage`:
```python
from backend.services.storage import storage
```
Para stages que recebem via `context`, injetar em `analyze.py`:
```python
context["_storage"] = storage
```

### Screenshot Endpoint (novo)
Para o frontend acessar screenshots via signed URL, pode ser necessário um endpoint proxy:
```python
@router.get("/jobs/{job_id}/screenshot/{page_key}")
async def get_screenshot(job_id: str, page_key: str):
    url = await storage.get_signed_url("jobs", f"jobs/{job_id}/screenshots/{page_key}.png")
    return {"url": url}
```
