# Story 15.5 — Rate Limiting + Input Validation

## Story

**Como** administrador da plataforma,
**Quero** que a API limite requisições por IP e rejeite uploads excessivos,
**Para** proteger contra abuso de custos LLM e evitar que PDFs enormes crashem o pipeline.

## Status

Done

## Context

### Problema

1. **Sem rate limiting:** Qualquer IP pode submeter jobs ilimitados. Cada job custa ~$0.20 em LLM calls. 100 jobs = $20. Sem proteção.
2. **Sem validation de upload:** `routers/upload.py` aceita qualquer tamanho de PDF e qualquer quantidade de páginas. Um PDF de 1GB ou 10.000 páginas pode estourar memória do servidor.

### Estado Atual do Código

**`backend/routers/upload.py`** (102 lines):
- 3 upload endpoints (unified, pdf-only, xsd-only)
- Usa `StorageGateway` para salvar arquivos
- **Zero validação** de file size ou page count
- `TMP_BASE` já usa env var (line 13)

**`backend/main.py`** (47 lines):
- Nenhum rate limiting middleware
- `slowapi` não está instalado

### Scope — IN vs OUT

**IN SCOPE:**
- Instalar e configurar `slowapi` como middleware global
- Rate limit diferenciado: `/api/analyze` (10/min/IP), rotas gerais (30/min/IP)
- Validação de file size no upload (max 50MB por PDF)
- Validação de page count no upload (max 500 páginas total)
- Headers de rate limit nas respostas
- Mensagens de erro claras (429, 413, 422)

**OUT OF SCOPE:**
- Rate limiting per-user (requer auth, story 15.3)
- Adaptive rate limiting
- File type validation (apenas PDF aceito, mas já validado pelo frontend)
- Virus scanning

## Acceptance Criteria

- [x] `slowapi` adicionado a `requirements.txt`
- [x] `SlowAPI` middleware configurado em `backend/main.py`
- [x] `/api/analyze` endpoint: 10 req/min por IP
- [x] Rotas gerais: 30 req/min por IP
- [x] Rate limit headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`
- [x] Rate limit excedido retorna 429 com `{"detail": "Rate limit exceeded. Try again in {n} seconds."}`
- [x] Upload endpoint: rejeita PDF > 50MB com 413 `{"detail": "File too large. Maximum size: 50MB"}`
- [x] Upload endpoint: conta páginas do PDF (via PyMuPDF) e rejeita se total > 500 com 422 `{"detail": "Too many pages. Maximum: 500"}`
- [x] Testes: `test_rate_limiting.py` criado — valida configuração de middleware e decoradores
- [x] Testes: `test_upload_validation.py` criado — valida 413 e 422 responses com mocks
- [x] Limites configuráveis via env vars: `RATE_LIMIT_ANALYZE`, `RATE_LIMIT_GLOBAL`, `MAX_FILE_SIZE_MB`, `MAX_PAGE_COUNT`
