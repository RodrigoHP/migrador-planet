# Story 5.9: Blocos 4-5: Table Detection + Semantic Intelligence

## Status
Draft

## Story
**As a** blocos do pipeline,
**I want** detectar e estruturar tabelas (bloco 4) e analisar significado semântico dos blocos de texto (bloco 5),
**so that** tabelas sejam propriamente identificadas antes da detecção de anchors e blocos de texto tenham contexto semântico.

## Acceptance Criteria
1. Stage 13 — Table Detection: identificar regiões de tabela a partir de linhas de grid, blocos de texto alinhados, padrões repetitivos
2. Stage 14 — Table Structuring: extrair headers, linhas, colunas; detectar tabelas multi-página (continuação)
3. Stage 15 — Semantic Analysis: classificar blocos de texto como: label, value, title, header, footer_text, page_number, table_header, table_cell
4. Table detection executa ANTES de anchor detection (decisão arquitetural: evita interpretar headers de tabela como campos de formulário)
5. Tabelas multi-página ligadas entre páginas
6. Todos os estágios registrados no orchestrator, emitindo SSE progress
7. Output: tables[] com { headers[], rows[][], column_widths[], is_multi_page, continuation_pages[] }, semantic_labels por text_block
8. Testes cobrem: precisão de detecção de tabelas, linking multi-página, classificação semântica

  - [ ] Detectar tabelas multi-página:

  - [ ] Linkar páginas de continuação: `continuation_pages[]`

- [ ] Task 3 — Implementar Semantic Analysis (AC: 3)
  - [ ] Criar `backend/services/stages/semantic_analysis.py`
  - [ ] Classificar cada TextBlock em uma categoria semântica:
    - `label`: texto estático que identifica um campo (ex: "Nome:", "CPF:")
    - `value`: texto dinâmico (conteúdo que varia entre documentos)

    - `footer_text`: texto na zona footer da página

## Dev Notes

### Decisão Arquitetural: Table Detection ANTES de Anchors
- Architecture v5.0: tabelas detectadas antes de anchor detection
- Razão: headers de tabela (ex: "Data", "Valor", "Descrição") seriam falsos positivos como labels de formulário
- Com tabelas já identificadas, o matching engine sabe que esses TextBlocks são `table_header`, não `label`

### Detecção de Tabelas — Abordagem Combinada
- Grid lines sozinhas não são suficientes (muitas tabelas sem grid)
- Alinhamento de texto é forte indicador mas tem falsos positivos
- Combinação das 3 fontes com scoring ponderado dá melhor resultado

### Tabelas Multi-Página
- Comuns em extratos bancários (centenas de linhas)
- Detecção: tabela termina perto do footer → verificar se próxima página inicia igual
- Linking: manter referência cruzada entre páginas
- Dados contínuos: rows de todas as páginas formam uma única tabela lógica

### Classificação Semântica → Matching Engine
- Labels classificados aqui alimentam diretamente o matching (Story 5.11)
- `label` adjacente a `value` → par label-valor candidato para mapeamento
- `table_header` + `table_cell` → estrutura de tabela para `foreach` binding
