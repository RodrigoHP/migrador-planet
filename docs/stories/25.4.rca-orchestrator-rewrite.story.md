# Story 25.4 — Orchestrator Rewrite: investigate.md como Pipeline

## Story
**Como** agente executando /investigate,
**Quero** instrucoes claras para orquestrar subagents por fase,
**Para** executar o pipeline multi-model automaticamente.

## Status
Draft

## Context

### Problema
investigate.md atual eh guia para agente unico: "faca X, depois Y, depois Z". Com multi-model, precisa ser "spawne agente A para X, colete resultado, spawne agente B para Y com resultado de X".

### Design
Reescrever investigate.md com estrutura:

1. **Header:** Versao, presets, como usar
2. **Execucao Pipeline:** Steps numerados para o orquestrador
   - Para cada fase: montar briefing, spawnar Agent(), validar resultado
   - Between-phase logic (if/else por domain, fast-track, etc)
3. **SDC Bridge:** Gerar story + disparar SDC (Fase 6.5)
4. **Phase Contracts:** Referencia (25.1)
5. **Model Routing:** Referencia (25.2)
6. **Briefing Templates:** Inline (25.3)
7. **Metodologia de Referencia:** v7.0 completa (para fallback e briefings)
8. **Fallback Protocol:** Referencia (25.6)

O orquestrador (Opus) le o investigate.md e segue os steps:
```
Step 1: Parsear bug report
Step 2: Determinar preset (default: balanced)
Step 3: Se preset == single → executar v7.0 inline
Step 4: Montar briefing_fase_0
Step 5: resultado_0 = Agent(model: routing.fase_0, prompt: briefing_fase_0)
Step 6: Validar resultado_0 → se falha, fallback inline
Step 7: Montar briefing_fase_1 com resultado_0
...
```

## Acceptance Criteria
- [ ] investigate.md reescrito como orquestrador
- [ ] Steps claros para spawnar Agent() por fase
- [ ] Model selection via routing config
- [ ] Briefing montado com outputs de fases anteriores
- [ ] Validacao de resultado apos cada subagent
- [ ] Preset single = v7.0 exato (backward compatible)
- [ ] SDC bridge integrado no fluxo (Fase 6.5)
- [ ] Metodologia v7.0 preservada como referencia

## Scope

**OUT:** Engine de execucao automatica
