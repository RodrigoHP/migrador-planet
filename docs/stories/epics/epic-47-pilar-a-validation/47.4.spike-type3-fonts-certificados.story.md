# Story 47.4 — SPIKE: Investigar Type3 Fonts e Fontes Customizadas nos Certificados

## Status: Done

## Descrição

Dois certificados têm fontes problemáticas que o PyMuPDF pode não conseguir extrair texto:

- `CertiticadoPrevidencia.pdf` — `Type3 (14 0 R)`: fonte bitmap/desenhada, sem mapeamento de caracteres padrão. PyMuPDF retorna texto vazio ou corrompido.
- `CertificadoHinode.pdf` — `SenticoSansDT-Light/Medium`: fonte customizada proprietária. Pode não ter ToUnicode map, gerando caracteres ilegíveis.

Se o Stage 2 não consegue extrair texto dessas fontes, o Stage 3 recebe blocos vazios e o mapeamento falha completamente — independente das correções do Epic 43.

## Acceptance Criteria

- [x] **AC1 — Diagnóstico Type3:** Abrir `CertiticadoPrevidencia.pdf` com PyMuPDF e extrair texto de cada span. Documentar: quantos spans retornam texto legível vs vazio/corrompido
- [x] **AC2 — Diagnóstico SenticoSansDT:** Idem para `CertificadoHinode.pdf`. Verificar se o PDF tem `ToUnicode` table via `doc.get_page_fonts()` e `doc.extract_font()`
- [x] **AC3 — Alternativas avaliadas:**
  - Opção A: Mistral OCR como fallback de texto (não só para rasters) — custo por página
  - Opção B: PyMuPDF com `textpage.extractRAWDICT()` — tenta recuperar glifos sem ToUnicode
  - Opção C: Aceitar limitação — documentar como gap fora do escopo Pilar A
- [x] **AC4 — Recomendação:** Qual opção adotar, com justificativa de custo/accuracy
- [x] **AC5 — Impacto mapeado:** Quantos PDFs do domínio Planet Express provavelmente têm Type3 fonts (buscar padrão nos outros samples)
