# Story 43.3 — SPIKE: Bake-off OCR/Vision para Tabela Raster (Estrutura + Fontes + Cores)

## Status: InReview

## Tipo

**Spike de pesquisa** — produz relatório empírico e recomendação, não código de produção. Resultado alimenta a Story 43.2 (implementação do fallback raster).

## Contexto

Audit empírico (`backend/scripts/audit_boleto_pillar_a.py`) contra `Corporate.Boleto.Convenio.pdf` confirmou:

- **100% da estrutura vetorial está capturada** pelo pipeline (50 text blocks, 119 lines, 5 images, 2 fonts)
- **Único gap real:** conteúdo dentro de **uma imagem raster JPEG 2174×1337px** na página 0, bbox `[27.68, 377.30, 582.92, 718.77]` = tabela de parcelas (~15 colunas de datas, valores, códigos, status)
- PyMuPDF `find_tables()` retorna 0 nessa região (puro raster, sem ruling lines vetoriais)
- Pipeline detecta o `table_area` via GPT-4o Vision mas não extrai estrutura/conteúdo

## Objetivo

O projeto gera **templates visualmente fiéis** (não extrai dados). Regiões raster num PDF podem conter diferentes tipos de conteúdo:

- **Tabela raster** (caso do boleto — JPEG com tabela queimada)
- **Código de barras** (barcode — boleto tem "linha digitável" representada por barras)
- **Gráfico** (charts em relatórios corporativos — bar/line/pie)
- **Imagem genérica** (logos, figuras, diagramas)

Para cada tipo, o spike avalia qual candidato entrega **extração mais fiel** do que é necessário para reconstruir visualmente no template:

| Tipo | O que extrair |
|---|---|
| Tabela | Estrutura (headers, cols, rows, bboxes) + fontes + cores/borders + texto fiel |
| Barcode | Tipo (EAN-13, Code128, PDF417, QR etc), valor decodificado, bbox + tipo de imagem (é renderizável pelo editor ou preservar como imagem?) |
| Gráfico | Tipo (bar/line/pie), eixos, labels, cores, legenda ou (fallback) preservar como imagem fiel |
| Imagem | Classificação (logo / figura / ícone), bbox, fidelidade do crop |

**Fora do escopo deste spike:** classificação de fixo vs dinâmico — isso é trabalho do Stage 3 (`multi_example_analysis`), que compara os outputs dos samples cross-document e decide o que é fixo/dinâmico. O OCR só precisa entregar extração fiel; o pipeline normal faz a classificação depois.

Testar candidatos viáveis nas regiões raster representativas, com ground truth manual, produzir relatório quantitativo e recomendação justificada para Story 43.2.

### Métricas — pseudocódigo

```python
def cell_f1(gt_rows, pred_rows):
    gt = {(r, c): v for r, row in enumerate(gt_rows) for c, v in enumerate(row)}
    pr = {(r, c): v for r, row in enumerate(pred_rows) for c, v in enumerate(row)}
    tp = sum(1 for k, v in gt.items() if pr.get(k) == v)
    fp = sum(1 for k in pr if pr[k] != gt.get(k))
    fn = sum(1 for k in gt if k not in pr)
    p = tp / (tp + fp) if (tp + fp) else 0
    r = tp / (tp + fn) if (tp + fn) else 0
    return 2*p*r / (p+r) if (p+r) else 0

def bbox_iou(a, b):
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0, x2-x1) * max(0, y2-y1)
    area_a = (a[2]-a[0]) * (a[3]-a[1])
    area_b = (b[2]-b[0]) * (b[3]-b[1])
    union = area_a + area_b - inter
    return inter / union if union else 0

def fixed_value_recall(gt_fixed, pred_all_values):
    hits = sum(1 for v in gt_fixed if v in pred_all_values)
    return hits / len(gt_fixed) if gt_fixed else 0
```
