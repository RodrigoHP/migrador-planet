# Story 43.4 — SPIKE: Layout Extraction para Tabelas Raster (col_widths, row_heights, cores)

## Status: InProgress

## Tipo

**Spike** — produz schema de layout + implementação validada empiricamente. Resultado alimenta Story 43.2 (que atualmente extrai só conteúdo, sem layout).

## Descrição

Story 43.3 confirmou que `mistral-ocr-pdf` é o melhor candidato para extração de **conteúdo** de tabelas raster (Header=100%, Cell F1=0.545). Mas o template HTML precisa preservar também o **layout visual**:

- Largura das colunas (col_widths_pct)
- Altura das linhas (row_heights_pct)
- Cor de fundo do header
- Cor de borda

Atualmente nenhum candidato retorna essas informações de forma estruturada. Este spike investiga e implementa as fontes de layout disponíveis:

1. **HTML colspan** — o HTML retornado por `mistral-ocr-pdf` contém `colspan` attributes que informam a proporção relativa de cada coluna
2. **Image sampling** — dado o crop PNG da tabela, amostrar pixels para detectar cor de background do header e cor de borda
3. **Equal distribution fallback** — quando colspan não discrimina (todas as colunas igual), usar distribuição uniforme

## Dev Notes

### Col widths via colspan

O HTML de Seção A (4 colunas iguais, sem colspan explícito):
```html
<td>Beneficiário<br/>...</td>  <!-- colspan=1 implícito -->
<td>Agência/Cód. Beneficiário<br/>...</td>
<td>Data Emissão<br/>...</td>
<td>Vencimento<br/>...</td>
```
→ col_widths_pct = [0.25, 0.25, 0.25, 0.25]

O HTML de Seção B (colspan explícito, cols desiguais):
```html
<td colspan="6">Local de Pagamento...</td>
<td>Vencimento...</td>
```
→ total_units = 7, col_widths_pct = [6/7, 1/7] ≈ [0.857, 0.143]

### Color sampling

Do crop PNG da tabela (2174×1337px), a primeira linha (header row) ocupa aprox. y=0..80px. Amostrar pixels nessa faixa → mediana RGB → hex.

Borda: detectar pixels escuros nas bordas horizontais/verticais.
