# Story 43.7 — SPIKE: Classificação de Tipo de Conteúdo Raster em image_area

## Status: Done

## Descrição

Quando o pipeline encontra uma região raster em um PDF, precisa saber **o que é** antes de decidir como processar. O `visual_analysis.py` já usa GPT-4o para detecção visual, mas `section_utils.py` descarta `image_area` silenciosamente (linha 469) — em parte porque ainda não há uma estratégia definida de classificação de tipo de conteúdo raster.

O tipo determina o handler:

| Tipo detectado | Handler correto |
|----------------|----------------|
| `barcode` | zxing-cpp decode (já existe) |
| `table` | Mistral OCR (decidido em 43.3) |
| `chart` | preservar crop como imagem |
| `logo` / `image` | preservar crop como imagem |

O problema: um mesmo elemento pode chegar ao pipeline como `image_area` genérico (quando o detector não tem certeza) ou ser misclassificado. A spike avalia **qual modelo/abordagem classifica o tipo de conteúdo raster com maior precisão e menor custo**, usando os fixtures e o runner já criados em 43.3.

O `image_classification_ground_truth.json` existente (barcode crop classificado como barcode) é o ponto de partida — os modelos já foram testados nesse cenário em 43.3. Precisamos expandir com mais tipos e formalizar a recomendação.

### Por que a classificação de tipo importa

O tipo determina o handler downstream — não é apenas metadata:

```
barcode  → zxing-cpp → valor decodificado → campo dinâmico
table    → Mistral OCR → estrutura de tabela → grid no template
chart    → crop preservado → <img> estático/dinâmico
logo     → crop preservado → <img> estático
```

Misclassificar `barcode` como `logo` → barcode não decodificado → campo XSD não mapeado.
Misclassificar `chart` como `table` → Mistral tenta OCR de gráfico → output incorreto.

### Hipótese sobre heurística

Charts têm distribuição de cores muito diferente de barcodes (variadas vs preto/branco). Logos tendem a ter áreas de cor sólida com bordas bem definidas. Uma heurística simples via PIL (histograma de cor + razão aspecto) pode distinguir os casos mais comuns sem LLM — a ser testado empiricamente.

### Resultado esperado dos modelos em 43.3 (referência)

Na 43.3, todos os modelos testados identificaram corretamente o barcode crop como "barcode" (não logo). A extensão da ground truth para chart e logo vai validar se esse padrão se mantém.
