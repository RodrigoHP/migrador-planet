# Story 45.2 — Test Performance Optimization: Fixture Scoping + pytest-xdist

## Status: InReview

## Descrição

Após a Story 45.1 separar os tiers, a suite `integration` ainda leva ~7h porque cada teste reconstrói PDFs sintéticos do zero (fixtures `function`-scoped) e roda serialmente. Esta story resolve com duas técnicas:

1. **Fixture scoping**: elevar fixtures de PDF/pipeline de `function` para `session` — construir uma vez, reutilizar por todos os testes da sessão
2. **pytest-xdist**: rodar testes em paralelo com `-n auto` (usa todos os CPUs disponíveis)

**Meta:** suite integration de ~7h para < 35 minutos.

## Dev Notes

### Regra de Elevação de Fixture

Fixture pode ser elevada para `session` se:
- ✅ Cria dados imutáveis (PDF bytes, dict de configuração, objeto fitz.Document em modo leitura)
- ✅ Não usa `monkeypatch`, `patch`, `mock` no setup
- ✅ Não modifica estado global
- ❌ NÃO elevar se usa `patch.dict(os.environ, ...)` — escopo `function` obrigatório

### Padrão de Migração

```python
# ANTES — function scope (default)
@pytest.fixture
def sample_pdf_doc():
    doc = fitz.open()
    page = doc.new_page(width=595, height=842)
    page.insert_text((50, 100), "Texto teste")
    return doc

# DEPOIS — session scope
@pytest.fixture(scope="session")
def sample_pdf_doc():
    doc = fitz.open()
    page = doc.new_page(width=595, height=842)
    page.insert_text((50, 100), "Texto teste")
    return doc
```

### pytest-xdist Compatibilidade

Testes que NÃO são compatíveis com xdist (rodar em processo separado):
- Testes que usam `importlib.reload` (estado de módulo não é compartilhado entre workers)
- Testes que dependem de ordem de execução
- Testes com fixtures de banco de dados sem isolamento

Solução: marcar testes incompatíveis com `@pytest.mark.xdist_group("serial")` para forçar execução serial.
