## Descrição

A suite de testes atual (903 testes) leva 7h14m para rodar porque não existe separação entre testes rápidos (lógica pura) e lentos (pipeline real com fitz/pdfplumber). Isso bloqueia o dev loop: mudanças de 2 linhas requerem 7h de espera para validação de regressão.

## Dev Notes

### Estratégia de Anotação

Anotar no nível de **classe** quando o arquivo tem uma classe por tier. Anotar no nível de **arquivo** via `pytestmark` quando todos os testes do arquivo são do mesmo tier:

```python
# Para arquivo inteiramente unit:
import pytest
pytestmark = pytest.mark.unit

# Para arquivo inteiramente integration:
pytestmark = pytest.mark.integration

# Para arquivo misto (raro):
class TestUnitPart:
    @pytest.mark.unit
    def test_algo(self): ...

class TestIntegrationPart:
    @pytest.mark.integration
    def test_algo(self): ...
```

### pyproject.toml — configuração

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
asyncio_mode = "auto"
markers = [
    "unit: testes sem I/O externo, rodam em < 500ms cada",
    "integration: testes com fitz/pdfplumber/httpx, rodam em < 120s cada",
    "benchmark: testes de performance com timeout >= 60s",
]
filterwarnings = [
    "error::pytest.PytestUnknownMarkWarning",
]
```

### Makefile — template

```makefile
.PHONY: test test-integration test-full

test:
	cd backend && python -m pytest -m unit -q

test-integration:
	cd backend && python -m pytest -m "unit or integration" -q

test-full:
	cd backend && python -m pytest -q

test-stage:
	cd backend && python -m pytest -m unit -k "stage$(N)" -q
```
