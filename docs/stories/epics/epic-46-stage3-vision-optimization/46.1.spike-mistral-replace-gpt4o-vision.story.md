# Story 46.1 — SPIKE: Validar Mistral `images[]` bbox como substituto do GPT-4o Vision

## Status: Done

## Descrição

O Stage 3.2 usa GPT-4o Vision ($0.01/cluster) para detectar regiões da página (table_area, barcode_area, image_area, header/body/footer). O Mistral OCR — já chamado no mesmo stage para extrair conteúdo de tabelas — retorna `pages[].images[]` com `top_left_x/y, bottom_right_x/y` e `pages[].dimensions.dpi`, além de suportar `extract_header=True` / `extract_footer=True`.

Esta spike valida empiricamente se esses campos são precisos o suficiente para substituir o GPT-4o Vision, eliminando a dependência OpenAI no Stage 3.

## Referências Técnicas

- **Spec:** `docs/api-references/mistral-openapi.yaml` — `OCRImageObject`, `OCRPageDimensions`, `OCRRequest`
- **Código alvo:** `backend/services/stages/stage3_structural/visual_analysis.py` — `_extract_raster_table_mistral`, `_run_3_2`
- **PDF de teste:** `backend/tests/fixtures/clustering_ground_truth_real/corp-convenio-1.pdf` (boleto corporate convenio — tem tabela raster JPEG embutida, conforme Epic 43 baseline)

## Acceptance Criteria

### AC1 — Bbox de imagem disponível e preciso

Chamar `mistral-ocr-latest` com `table_format='html'` + `include_image_base64=False` no boleto de teste.
Verificar se `pages[page_com_tabela]["images"]` contém entry com bbox.

**Critério:** bbox (`top_left_x/y`, `bottom_right_x/y`) está presente e não-nulo para a página com tabela raster.

### AC2 — Conversão de coordenadas correta

Converter bbox Mistral (pixels @ `dimensions.dpi`) para pontos PDF (72 DPI):
```
pdf_x = mistral_x / dimensions.dpi * 72
```

Comparar contra o bbox que o GPT-4o Vision retorna para a mesma região.

**Critério:** diferença ≤ 10 pontos PDF em cada coordenada (x0, y0, x1, y1).

**Ground truth:** `backend/tmp_baseline_boleto.json` contém dados de anchor/coverage — **não tem bboxes GPT-4o Vision**. Executar uma chamada GPT-4o Vision (`_run_3_2`) no `corp-convenio-1.pdf`, registrar `regions[].bbox` no relatório, e usar como baseline de comparação.

### AC3 — Correlação images[] ↔ tables[]

Validar o mecanismo de correlação: o markdown contém `![img-X.jpeg]` na posição da tabela, e `tables[]` contém o HTML correspondente.

**Critério:** conseguir identificar qual `images[i]` corresponde a qual `tables[j]` via análise do markdown (sem depender do GPT-4o bbox).

### AC4 — `extract_header` / `extract_footer` retorna zonas úteis

Repetir chamada com `extract_header=True, extract_footer=True`.
Verificar se `pages[i]["header"]` e `pages[i]["footer"]` retornam conteúdo não-vazio.

**Critério:** ao menos uma das duas zonas retorna string não-vazia, confirmando que Mistral segrega header/footer semanticamente.

### AC5 — PIL heuristic funciona direto em `images[]`

Para cada entry em `pages[].images[]`, usar `include_image_base64=True` e aplicar a heurística PIL já implementada (`_classify_image_area_heuristic`) ao base64.

**Critério:** heurística classifica corretamente barcode vs logo sem precisar do screenshot do Stage 2 como input intermediário.

### AC6 — Relatório empírico documentado

Arquivo `docs/reports/epic-46-vision-optimization/46.1-mistral-bbox-spike.md` com:
- Resultado de cada AC (PASS/FAIL/PARTIAL)
- Valores medidos (bbox diff, header/footer content sample)
- Recomendação: eliminar GPT-4o / manter / hibridizar com critério

## Valor de Negócio

Eliminar GPT-4o Vision do Stage 3 reduz custo em ~$0.01/cluster e latência em ~8s/cluster. Para o volume total do projeto (200 templates × 18 clusters × ~2 páginas representativas = ~7.200 chamadas), a economia one-time é ~$72 e melhora a resiliência do pipeline (remove dependência da API OpenAI).

## Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|-------|:------------:|:-------:|-----------|
| `images[]` vazio para tabelas raster atípicas | Baixa | Alto | Fallback para GPT-4o se `images[]` vazio |
| `dimensions.dpi` variável entre PDFs | Média | Médio | Medir drift em 3+ PDFs distintos no relatório |
| `include_image_base64=True` aumenta payload/latência | Alta | Baixo | Medir latência com e sem base64 — AC5 usa chamada separada |
| Spike conclui que Mistral é insuficiente | Média | Baixo | Resultado válido — documenta decisão de manter GPT-4o |

### AC5 — PIL heuristic: base64 → tempfile

`_classify_image_area_heuristic(bbox, screenshot_path)` espera path de arquivo PNG, não base64. Para AC5, salvar o base64 em tempfile antes de chamar:

```python
import base64, tempfile, os

def classify_from_base64(b64_str: str, bbox: list[float]) -> str:
    data = base64.b64decode(b64_str.split(",", 1)[-1])
    with tempfile.NamedTemporaryFile(suffix=".png", delete=False) as f:
        f.write(data)
        tmp_path = f.name
    try:
        return _classify_image_area_heuristic(bbox, tmp_path)
    finally:
        os.unlink(tmp_path)
```

### Correlação image ↔ table via markdown

```python
import re

# Encontra posição de cada placeholder no markdown
img_positions = {m.group(1): m.start() for m in re.finditer(r'!\[(img-\S+)\]', markdown)}
tbl_positions = {m.group(1): m.start() for m in re.finditer(r'\[(tbl-\S+)\]', markdown)}

# Tabela mais próxima de cada imagem = correlação
for img_id, img_pos in img_positions.items():
    closest_tbl = min(tbl_positions, key=lambda t: abs(tbl_positions[t] - img_pos))
```
