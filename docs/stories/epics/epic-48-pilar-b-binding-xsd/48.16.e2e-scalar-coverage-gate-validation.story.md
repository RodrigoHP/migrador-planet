### Root cause persistente — RC-E (novo)
**RC-D funciona no Stage 3 mas Stage 4 não consome os tree nodes.**

Stage 4 step 4.2 (`_step_4_2_pair_validation`) lê de `block_classifications.field_pair` para identificar pares label-valor. RC-D cria `field/label/value` nodes no `documentTree` mas **não popula `field_pair` no `BlockClassification` original**. Resultado:
- Blocos inline (INSCRIÇÃO, TELEFONE, E-MAIL, FORMA DE PAGAMENTO) chegam ao Stage 4 como blocos isolados
- `pdf_text = "TELEFONE: (19) 98189-4732"` sem `label_text`
- Gemini retorna `candidates=[]` para todos → 0/5 campos inline mapeados

**Fix necessário (RC-E):** Stage 4 deve ler `documentTree`'s `field/label/value` nodes para extrair pares inline, além de `block_classifications.field_pair`.
