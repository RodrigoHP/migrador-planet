# Story 48.18 — Fix: Stage 4 Section XSD Wrapper Expansion (RC-F)

## Status: Ready

## Descrição

Durante re-validação E2E pós RC-E (job `968b8117`, run 2026-04-25 18:09), diagnóstico revelou que campos inline como TELEFONE, INSCRIÇÃO, FORMA DE PAGAMENTO retornam `candidates=[]` do Gemini — não por falta de label (RC-E resolve isso), mas porque `_step_4_4_section_xsd_matching` faz match da seção com o nó XSD `Propostas` (wrapper), cujos `child_paths` são `['Propostas.Propostas']` — um único nó complexo/lista, não campos folha.

Gemini recebe `["- Propostas.Propostas"]` como único path disponível e retorna `candidates=[]` para TELEFONE pois `Propostas.Propostas` não é um campo folha.

A correção expande `child_paths` através de nós wrapper (complexos sem folhas diretas) até encontrar os campos folha reais. Padrão recorrente no XSD Planet Express: `Propostas` → `Propostas.Propostas[]` → campos.

**Root cause confirmado via Supabase:** todos os 5 campos inline têm `candidates=[]` no `result_json` do job `968b8117`.

## Implementação Técnica

### Função a adicionar em `section_matching.py`

```python
def _expand_child_paths(node: dict[str, Any]) -> list[str]:
    """
    Retorna leaf paths do nó XSD matched.
    Se todos os filhos diretos são complexos (padrão double-nesting do XSD Planet Express,
    ex: Propostas -> Propostas.Propostas[] -> campos), expande para os netos.
    """
    children = node.get("children", [])
    leaf_paths = [c.get("path", "") for c in children if not c.get("children")]
    if leaf_paths:
        return leaf_paths
    expanded: list[str] = []
    for c in children:
        expanded.extend(gc.get("path", "") for gc in c.get("children", []))
    return expanded or [c.get("path", "") for c in children]
```

### Modificação em `_step_4_4_section_xsd_matching` (linha 134)

## Riscos

- **R1 (baixo):** XSD com triple-nesting (wrapper→wrapper→folha) — `_expand_child_paths` expande apenas 1 nível. Mitigação: nenhum XSD Planet Express observado tem mais de 2 níveis de nesting; se ocorrer, `expanded` ficará vazio e cai no fallback com filhos diretos (comportamento atual).
- **R2 (baixo):** Nó com filhos mistos (alguns leaf, alguns complex) — função retorna só os leaf diretos, ignorando complex. Comportamento conservador e correto para o padrão observado.
- **R3 (médio):** scalar_coverage pode não atingir 0.55 se o `used_paths` dedup ainda bloquear um campo depois da expansão. Mitigação: threshold AC5 em 0.55 já desconta margem.
