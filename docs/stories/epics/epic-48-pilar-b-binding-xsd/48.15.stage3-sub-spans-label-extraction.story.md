# Story 48.15 — Stage 3: Extrair Label de Campos Inline via `sub_spans`

## Status: Done

## Descrição

PDFs Planet Express renderizam campos inline como dois spans separados: `span[0]` em negrito (label) + `span[1]` em regular (valor). Exemplos confirmados no PDF `PosicaoConsolidada.pdf`:

| span[0] (bold) | span[1] (regular) |
|---------------|-------------------|
| `TELEFONE:` | ` (19) 98189-4732` |
| `E-MAIL` | `: TELMATSANCHES@GMAIL.COM` |
| `INSCRIÇÃO:` | ` 1124669542800` |
| `PLANO:` | ` 2800 - WHOLE LIFE DECRESCENTE` |
| `FORMA DE PAGAMENTO:` | ` CARTÃO DE CRÉDITO` |

O Stage 2 funde esses spans em um único `TextBlock` por proximidade física (correto para texto corrido), mas **já preserva o detalhe** em `TextBlock.sub_spans` quando os estilos são mistos.

O problema: Stage 3, Stage 4 e Stage 5 nunca leram `sub_spans`. Resultado: o `TextBlock` resultante tem `label=""` e `value="TELEFONE: (19) 98189-4732"` — o LLM do Stage 4 não consegue fazer o match porque não há label explícito.

**Impacto duplo:**
1. **Gate 80%:** +5 campos mapeados corretamente após fix
2. **Epic 49 (TemplateAstV0):** `ast_emitter.emit()` lê Stage 3's `document_structure` para criar `FieldNode`. Sem o fix, `FieldNode.label = ""` — campo aparece sem nome no editor visual

**Root cause:** `rca-2026-04-25-scalar-coverage-residual-53pct`, RC-D, evidence E1_confirmed.

### Onde adicionar a lógica (Stage 3)

Localizar a função em `multi_example_analysis.py` ou `structural_analysis.py` que constrói entradas de campo dinâmico a partir de `TextBlock`. Identificar onde `label` e `value` são atribuídos.

Adicionar **antes** de enviar o campo para o output do Stage 3:

```python
def _extract_label_value(block: TextBlock) -> tuple[str, str]:
    """
    Para TextBlocks com estilos mistos (inline label+value):
    sub_spans[0] bold = label, sub_spans[-1] regular = value.
    """
    if block.sub_spans and len(block.sub_spans) >= 2:
        first = block.sub_spans[0]
        last = block.sub_spans[-1]
        if first.get("is_bold") and not last.get("is_bold"):
            label = first["text"].strip().rstrip(":").strip()
            value = last["text"].strip().lstrip(":").strip()
            return label, value
    # fallback: comportamento atual
    return block.label or "", block.text
```

### Edge case: E-MAIL

O span `E-MAIL` não tem `:` no span[0] — o `:` está no início do span[1] (`: TELMATSANCHES@...`). O `.lstrip(":")` no `value` resolve isso.
