# Story 48.5 — SPIKE: Validar Stage 4 XSD Binding Accuracy com Resultado Multi-Sample

## Status: Ready

## Descrição

Com o output multi-sample validado em 48.4 (Stage 1 + Stage 3.1 funcionando), validar se o Stage 4 (Field Mapping via Gemini Flash) mapeia corretamente os campos `dynamic` para os paths corretos do XSD Planet Express.

**O que está sendo testado:**
- `field_mappings[]` — cada campo `dynamic` tem um `xsd_field_path` correto?
- Accuracy do mapeamento: % de campos mapeados para o path XSD correto
- Cobertura: % de campos `dynamic` do ground truth que receberam algum mapping
- Falsos positivos: campos `static`/`label` que foram mapeados (não deveriam)

## Acceptance Criteria

- [x] **AC1:** Stage 4 produz `field_mappings[]` com pelo menos 1 entry por campo `likely_dynamic` detectado em 48.4
- [x] **AC2:** Cobertura de mapeamento ≥ 80% — (campos dynamic com xsd_field_path) / (total campos dynamic ground truth)
- [x] **AC3:** Accuracy de mapeamento ≥ 70% — (campos mapeados para xsd_path correto) / (total campos mapeados) — avaliação manual
- [x] **AC4:** Nenhum campo `label`/`static` mapeado para XSD (falso positivo = 0 tolerado)
- [x] **AC5:** Relatório salvo em `docs/reports/epic-48/stage4-xsd-binding-{tipo}.json` com: campo detectado, xsd_field_path atribuído, xsd_field_path esperado, verdict (correct/wrong/missing)
- [x] **AC6:** `confidence_score` do pipeline final ≥ 75% para pelo menos 1 tipo de documento

## Escopo

### IN
- Análise do `field_mappings[]` do resultado de 48.4
- Mapeamento manual "esperado" para campos de boleto Corporate (ex.: `valor_boleto` → `/boleto/valor`, `data_vencimento` → `/boleto/dataVencimento`)
- Comparação automática campo-a-campo
- Identificação de paths XSD candidatos para melhoria se accuracy < 70%

### OUT
- Mudanças no Stage 4 (isso vai para backlog se necessário)
- Ajustes no prompt Gemini Flash (backlog)
- Novos testes de integração (pode ser incluído se simples)

## Notas Técnicas

**XSD do domínio:** O Stage 4 faz XSD parsing (Step 4.1) do XSD carregado no job. Verificar qual XSD está sendo usado no teste — o mesmo XSD subido pelo usuário com os PDFs. Para o spike, usar o XSD Planet Express existente nos fixtures de teste.

**Gemini Flash prompt (Step 4.5):** O prompt recebe campos dynamic + paths XSD candidatos (pré-filtrados por seção em 4.4). Se a accuracy for baixa, investigar se o problema está em:
1. Step 4.4 (section matching filtra paths errados)
2. Step 4.5 (Gemini seleciona path incorreto entre candidatos)
3. Step 4.1 (XSD mal parseado)

**Como avaliar "correto":** Para campos de boleto, o mapeamento esperado é bem definido (ex.: valor → `/Boleto/Instrucoes/ValorCobrado`). Para campos menos óbvios, usar julgamento do domínio Planet Express.
