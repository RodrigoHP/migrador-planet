# Story 48.17 — RC-E: Stage 4 consome field/label/value nodes do tree para pares inline

## Status: Ready

## Descrição

RC-D (48.15) corrigiu o Stage 3: o `documentTree` agora tem nós `field/label/value` corretos para campos inline como TELEFONE, INSCRIÇÃO, E-MAIL, FORMA DE PAGAMENTO. Porém, Stage 4 step 4.2 (`_step_4_2_pair_validation`) lê de `block_classifications.field_pair` — atributo que RC-D **não popula** no `BlockClassification` original.

Resultado: os 5 campos inline chegam ao Stage 4 como blocos isolados com o texto completo (`"TELEFONE: (19) 98189-4732"`) sem `label_text` separado. Gemini retorna `candidates=[]` para todos → 0/5 campos mapeados.

**Este fix faz Stage 4 ler do tree os pares já extraídos pelo RC-D**, em vez de depender exclusivamente de `block_classifications.field_pair`.

## Acceptance Criteria

- [ ] **AC1:** Stage 4 step 4.2 lê `documentTree` e extrai pares de nós com `type="field"` + filhos `type="label"` e `type="value"` — além do caminho atual via `block_classifications.field_pair`
- [ ] **AC2:** Para cada par extraído do tree, o `label_text` é o `text` do filho `label` e o `value_text` é o `text` do filho `value` (sem o texto embutido completo)
- [ ] **AC3:** Campos INSCRIÇÃO, TELEFONE, E-MAIL, FORMA DE PAGAMENTO aparecem com `label_text` correto no `field_mappings` output
- [ ] **AC4:** Sem regressão em testes unitários de Stage 4 (`make test`)
- [ ] **AC5:** E2E contra Railway: `scalar_coverage` melhora de 0.44 para ≥ 0.60 (proxy para RC-E funcionando)
- [ ] **AC6:** Deduplicação — se um par já existe via `block_classifications.field_pair`, não duplicar via tree

## Detalhes Técnicos

### Fluxo atual (quebrado para inline)
```
Stage 3 → documentTree (field/label/value nodes) ✓
Stage 4 step 4.2 → lê block_classifications[id].field_pair → None para inline blocks
→ inline blocks entram como "unpaired dynamics"
→ Gemini recebe "TELEFONE: (19) 98189-4732" sem label → candidates=[]
```

### Fluxo corrigido
```
Stage 4 step 4.2:
  1. [existente] lê block_classifications[id].field_pair → pares tradicionais
  2. [NOVO] lê documentTree field nodes:
     for each node where type="field" and len(children)==2:
       label_child = children where type="label"
       value_child = children where type="value"
       if label_child.text and value_child.text:
         emit pair(label=label_child.text, value=value_child.text, block_id=value_child.block_id)
  3. Dedup por block_id (se já capturado via field_pair, ignorar do tree)
```

### Cuidados
- `document_trees` está em `context["document_trees"]` (dict por `layout_id`)
- Cada tree tem estrutura `{"root": {...}}` — usar `tree.get("root", tree)`
- Block_id de label e value nodes do RC-D é o mesmo que o bloco original (design de RC-D)
- Não quebrar o path existente para pares não-inline
