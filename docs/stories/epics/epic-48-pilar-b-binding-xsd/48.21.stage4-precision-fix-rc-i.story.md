# Story 48.21 — Fix: Stage 4 Precision — 3 mapeamentos incorretos (RC-I)

## Status: Done

## Descrição

Auditoria de precisão pós-E2E (2026-04-26) revelou 3 mapeamentos incorretos nos 21 mapeados (scalar_coverage 0.84):

- **[04]** `"(demais localidades) e 0800 771 5472"` → `ClienteTelefone` — texto corrido (body text) sem label, 7 palavras, jamais deveria chegar ao LLM. `_is_body_text_pair()` estava definida mas **nunca chamada**.
- **[21]** `"INSCRIÇÃO"` (número de inscrição do cliente) → `ClienteCpf` — Gemini mapeou ID de subscrição para campo de CPF. Não existe `ClienteInscricao` no XSD; sem restrição, Gemini escolhe o campo mais próximo.
- **[08]** `"368,95"` (Valor Reserva Acumulada pensão) → `ValorIOF` — Gemini confundiu valor de reserva de previdência com o campo IOF, que é o imposto sobre o prêmio.

**Root cause (RC-I):** `_is_body_text_pair()` era código morto (dead code) — definida em section_matching.py:372 mas nunca invocada no loop de construção de `pairs_json`. Adicionalmente, o prompt Gemini não possuía restrições semânticas para `ClienteCpf` e `ValorIOF`, permitindo mapeamentos de conteúdo semanticamente incompatível.

```python
# ANTES (RC-G loop — body text chega ao LLM):
_local_idx_map: dict[int, int] = {}
pairs_json = []
for _pos, _p in enumerate(group):
    pairs_json.append({...})
    _local_idx_map[_pos] = _p["original_index"]

# DEPOIS (RC-I — body text excluído do LLM):
_local_idx_map: dict[int, int] = {}
pairs_json = []
_llm_pos = 0
for _p in group:
    if _is_body_text_pair(_p):
        continue
    pairs_json.append({"index": _llm_pos, ...})
    _local_idx_map[_llm_pos] = _p["original_index"]
    _llm_pos += 1
```
