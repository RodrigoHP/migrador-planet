# Story 48.4 — Stage 3: Implementar Detecção de Seções Repetidas (Pilar A Gap)

## Status: Done

## Descrição

O Stage 3 atual classifica cada bloco como `label`, `dynamic` ou `static` — mas trata blocos repetidos como N campos isolados. Esta story implementa a detecção de **seções repetidas** no Stage 3: quando N blocos com estrutura idêntica aparecem na mesma página em posições progressivas, o Stage 3 deve reconhecê-los como **uma única seção que se repete N vezes**, não como N campos independentes.

**Sem esta detecção, o Stage 4 não tem como gerar binding de lista.** Este é o gap de Pilar A que bloqueia todo o Pilar B.

**Saída esperada no document tree:**

```json
{
  "type": "repeated_section",
  "section_id": "segurado_row",
  "list_item_count": 12,
  "item_template": {
    "fields": [
      {"name": "nome", "type": "dynamic"},
      {"name": "cpf", "type": "dynamic"},
      {"name": "plano", "type": "static", "value": "Previdência VG"}
    ]
  },
  "instances": [
    {"bbox": [...], "texts": ["JOAO DA SILVA", "123.456.789-00", "Previdência VG"]},
    {"bbox": [...], "texts": ["MARIA SANTOS", "987.654.321-00", "Previdência VG"]}
  ]
}
```

## Acceptance Criteria

- [x] **AC1:** `stage3_structural/repeated_sections.py` implementado — função `detect_repeated_sections(page_blocks, page_height) -> list[RepeatedSection]`

- [x] **AC3:** Para cada `RepeatedSection`: `list_item_count`, `item_template` (estrutura canônica de um item), `instances` (lista de ocorrências com bbox e textos)
- [x] **AC4:** Testes unitários `@pytest.mark.unit` cobrem: detecção de lista simples (2+ blocos idênticos), lista mista (campos fixos + dinâmicos por item), nenhuma falsa detecção em blocos diferentes
- [x] **AC5:** Validação manual contra ground truth de 48.3 — recall ≥ 75% das seções repetidas identificadas no spike
- [x] **AC6:** Blocos que fazem parte de uma `RepeatedSection` não aparecem duplicados como campos isolados no tree (sem double-counting)

**Integração no pipeline context:**
