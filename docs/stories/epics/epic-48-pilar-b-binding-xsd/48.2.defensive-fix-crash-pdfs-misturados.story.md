# Story 48.2 — Defensive: Corrigir Crash Stage 1 com PDFs de Templates Misturados

## Status: Ready

## Descrição

Durante o Epic 47, ao submeter múltiplos PDFs de templates **diferentes** juntos (ex.: PosicaoConsolidada + PrevidenciaExtrato + DirfInformaFinanceiro), o pipeline crasha com:

```
'NoneType' object is not iterable
```

O crash ocorre no Stage 1 (`cluster_validation.py`) quando `_llm_validate` retorna `None` para clusters com PDFs muito heterogêneos. O cenário não é de uso normal (usuário deve submeter PDFs do mesmo template), mas é um crash não-defensivo que piora a experiência em caso de erro do usuário.

## Root Cause

`stage1_clustering/cluster_validation.py` — função `_llm_validate` pode retornar `None` quando o LLM falha ou quando os PDFs são excessivamente heterogêneos. O caller itera sobre o resultado sem guardar contra `None`.

## Acceptance Criteria

- [x] **AC1:** Pipeline não crasha ao receber PDFs de templates diferentes — retorna erro JSON amigável com mensagem `"PDFs parecem ser de templates diferentes — envie PDFs do mesmo template"`
- [x] **AC2:** Testes unitários cobrem o caso `_llm_validate` retorna `None` — `@pytest.mark.unit`
- [x] **AC3:** Pipeline processa normalmente quando PDFs são do mesmo template (regressão)
- [x] **AC4:** Log de warning explícito quando heterogeneidade alta detectada: `"Stage 1: clusters com layouts muito divergentes detectados — possível mistura de templates"`

## Escopo

### IN
- Fix guard em `cluster_validation.py` contra `None` retornado por `_llm_validate`
- Adicionar verificação de homogeneidade cross-PDF antes de iterar clusters
- Erro JSON amigável para frontend
- Testes unitários para o fix

### OUT
- Mudanças na lógica de clustering em si
- Frontend (mensagem de erro já é tratada pelo frontend existente)
- Mudanças em Stage 2, 3, 4, 5
