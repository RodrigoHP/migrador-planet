# Story 48.11 — Stage 1: 4º Sinal Ensemble — Markdown Fingerprint (pymupdf4llm)

## Status: Done

## Descrição

Adicionar o 4º sinal ao ensemble voting do Stage 1: **markdown fingerprint** via `pymupdf4llm`.

O 4º sinal produz um SHA256[:16] do markdown normalizado da página (CPF/CNPJ/datas/valores substituídos por tokens). Sinal **one-sided**: match = SAME vote, mismatch = **abstém** (não penaliza). Esta assimetria é intencional — a normalização é incompleta e mismatch entre instâncias do mesmo template é esperado (apenas 5.7% dos pares SAME fazem match exato).

## Acceptance Criteria

- [x] **AC1:** Função `markdown_fingerprint(page: fitz.Page) -> str | None` em `signals.py`:
  - Usa `pymupdf4llm.to_markdown(page.parent, pages=[page.number])`
  - Aplica `_MD_PATTERNS` (CPF, CNPJ, DATE, BRL, NUM → tokens)
  - Retorna SHA256[:16] do markdown normalizado
  - Retorna `None` se `pymupdf4llm` não disponível (graceful degradation)
- [x] **AC2:** `PageInfo` estendido com campo `md_hash: str | None = None`, preenchido em `_extract_blocks`
- [x] **AC3:** `_ensemble_similarity` aplica sinal como one-sided: `if md_a == md_b: total += 1; votes += 1` — mismatch não incrementa `total` (abstém)
- [x] **AC4:** `ENSEMBLE_SCORES` atualizado para escala 4-signal: `{4: 0.97, 3: 0.90, 2: 0.75, 1: 0.35, 0: 0.05}`
- [x] **AC5:** `pymupdf4llm>=0.0.17` adicionado a `backend/requirements.txt`
- [x] **AC6:** Testes unitários cobrem: md_hash SAME → +1 voto, md_hash DIFF → abstém (count=3), md_hash None → abstém (count=3), `test_page_info_has_ensemble_fields` verifica campo `md_hash`

## Notas Técnicas

**Por que one-sided?**

Calibração (48.9 re-exec 2026-04-18) revelou:
- Pares SAME: apenas 5.7% (2/35) com md_hash idêntico após normalização
- Pares DIFF: 0.0% com md_hash idêntico

O match é raro mas **altamente específico** — zero falsos positivos em DIFF. Mismatch entre instâncias do mesmo template é esperado porque: datas, valores e estruturas de tabela diferem e a normalização não cobre todos os padrões dinâmicos.

Tratamento correto: match = evidência forte de SAME (vota), mismatch = evidência ambígua (abstém).

**Implementação one-sided em `ensemble_match_count`:**
```python
# Signal 4: Markdown fingerprint — one-sided bonus signal.
# Match → strong positive evidence (SAME vote).
# Mismatch → abstain (normalization is incomplete; mismatch ≠ DIFF evidence).
if md_a is not None and md_b is not None and md_a == md_b:
    total += 1
    votes += 1
```
