# Story 48.13 — Stage 4: Corrigir Deduplicação Cross-Layout de `used_paths`

## Status: Done

## Descrição

Bug confirmado em `section_matching.py:~365`: `used_paths: set = set()` é inicializado **dentro** do loop `for layout_id`, causando reset da deduplicação a cada layout.

Em templates multi-layout (ex: carta 4 págs + relatório 11 págs), o mesmo caminho XSD pode ser atribuído a campos em layouts diferentes do mesmo job. Isso amplifica o RC-A (body text rouba o mesmo path em cada layout separadamente) e causará regressões em templates multi-layout no Epic 49.

**Evidência E2E run 2026-04-25:**
- Layout A: `'Pedimos que você verifique'` → `Propostas.Propostas.ClienteTelefone`
- Layout B: `'Conforme seu pedido'` → `Propostas.Propostas.ClienteTelefone` (mesmo path, layout diferente)

**Root cause:** `rca-2026-04-25-scalar-coverage-residual-53pct`, RC-C, evidence E1_confirmed.

## Acceptance Criteria

- [x] **AC1:** `used_paths` inicializado **fora** do loop `for layout_id` — mesmo path XSD não aparece em layouts distintos do mesmo job
- [x] **AC2:** Template com 2 layouts e campos candidatos iguais → path atribuído ao layout com maior score de confiança; o outro layout fica sem esse path
- [x] **AC3:** Nenhuma regressão em templates single-layout (comportamento idêntico ao atual)
- [x] **AC4:** Comentário no código documenta a semântica: `# cross-layout dedup: each XSD path assigned at most once per job`
