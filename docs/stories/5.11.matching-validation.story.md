# Story 5.11: Bloco 7: Matching Semântico — Field Mapping, Format Detection, Confidence Scoring

## Status
Draft

## Story
**As a** bloco do pipeline,
**I want** realizar matching semântico entre conteúdo PDF e campos XSD (bloco 7), incluindo mapeamento de campos, detecção de formatos e scoring de confiança multi-fator,
**so that** o bloco de validação possa verificar a qualidade dos mapeamentos e gerar o template draft.

## Acceptance Criteria
1. Stage 19 — Field Matching: mapear blocos de texto do PDF para campos XSD usando similaridade semântica (Gemini 2.0 Flash via OpenRouter) + contexto (labels, posição, formato)
2. Stage 20 — Format Detection: detectar formatos de campo (moeda BRL, datas, CPF, CNPJ, telefone, porcentagem) e gerar funções de normalização
3. Stage 21 — Confidence Scoring: calcular confiança 5-fatores por Layout Type: layout stability, anchor detection, grid quality, field variability, vision agreement (Claude Sonnet via OpenRouter)
4. Quando múltiplos candidatos para mesmo texto PDF → flag como "ambiguous" para resolução pelo operador (FR5)
5. Format detection inclui: "R$ 1.234,56"→1234.56, "15 de Janeiro de 2025"→"15/01/2025" (FR6)
6. Output parcial: field_mappings[], confidence_scores{}, ambiguous_fields[], format_functions[]
7. Testes cobrem: precisão de matching, detecção de formato, cálculo de confiança

## Tasks / Subtasks
- [ ] Task 1 — Implementar Field Matching (AC: 1, 4)
  - [ ] Criar `backend/services/stages/field_matching.py`
  - [ ] Para cada TextBlock classificado como `value` (semântica Story 5.9):
    - Encontrar label adjacente (se existir)
    - Usar label + posição + formato para determinar campo XSD candidato
  - [ ] Matching semântico via Gemini 2.0 Flash (OpenRouter):
    - Input: label text, value text, XSD field candidates
    - Output: ranked matches com score de confiança
  - [ ] Quando múltiplos candidatos com score similar → `ambiguous_field`
  - [ ] Output: field_mappings[] com { pdf_text_block, xsd_field_path, confidence, is_ambiguous, candidates[] }
  - [ ] Registrar no StageRegistry

- [ ] Task 2 — Implementar Format Detection (AC: 2, 5)
  - [ ] Criar `backend/services/stages/format_detection.py`
  - [ ] Detectar formatos via regex + heurísticas:
    - Moeda BRL: `R$\s?[\d.,]+` → `formatCurrency()`
    - Data: `\d{2}/\d{2}/\d{4}` ou extenso → `formatDate()`
    - CPF: `\d{3}\.\d{3}\.\d{3}-\d{2}` → `formatCPF()`
    - CNPJ: `\d{2}\.\d{3}\.\d{3}/\d{4}-\d{2}` → `formatCNPJ()`
    - Telefone: `\(\d{2}\)\s?\d{4,5}-\d{4}` → `formatPhone()`
    - Porcentagem: `[\d.,]+%` → `formatPercent()`
  - [ ] Para cada campo mapeado, associar função de formatação
  - [ ] Gerar funções JS para base.js: `formatCPF()`, `formatDate()`, `formatCurrency()`, etc.
  - [ ] Registrar no StageRegistry

- [ ] Task 3 — Implementar Confidence Scoring (AC: 3)
  - [ ] Criar `backend/services/stages/confidence_scoring.py`
  - [ ] Calcular 5 fatores por Layout Type:
    - `layout_stability` (%): baseado em classificação de estabilidade (Story 5.8)
    - `anchor_detection` (%): % de labels detectados com alta confiança
    - `grid_quality` (%): qualidade do grid detectado (colunas/linhas claras)
    - `field_variability` (%): % de campos que variam entre documentos (confirmados)
    - `vision_agreement` (%): consistency_score do Vision AI (Story 5.10)
  - [ ] Usar Claude Sonnet via OpenRouter para análise multi-fator:
    - Input: 5 fatores + contexto do documento
    - Output: score global + recomendação
  - [ ] Thresholds: >=95% aprovado, 80-95% revisão recomendada, <80% revisão humana obrigatória
  - [ ] Registrar no StageRegistry

- [ ] Task 4 — Escrever testes (AC: 7)
  - [ ] Teste de matching: label "Nome:" + value "João" → campo `cliente.nome`
  - [ ] Teste de formato: "R$ 1.234,56" detectado como moeda BRL
  - [ ] Teste de confiança: 5 fatores calculados corretamente

| Score | Status | Ação |
|-------|--------|------|
| >= 95% | Aprovado | Template pronto para edição |
| 80-95% | Revisão recomendada | Destacar campos de baixa confiança |
| < 80% | Revisão humana | Operador precisa revisar mapeamentos |
