# Story 5.11: Bloco 7: Matching Semântico — Field Mapping, Format Detection, Confidence Scoring

## Status
Ready for Review

## Story
**As a** bloco do pipeline,
**I want** realizar matching semântico entre conteúdo PDF e campos XSD (bloco 7), incluindo mapeamento de campos, detecção de formatos e scoring de confiança multi-fator,
**so that** o bloco de validação possa verificar a qualidade dos mapeamentos e gerar o template draft.

## Acceptance Criteria
1. Stage 19 — Field Matching: mapear blocos de texto do PDF para campos XSD usando similaridade semântica (Gemini 2.0 Flash via OpenRouter) + contexto (labels, posição, formato)
2. Stage 20 — Format Detection: detectar formatos de campo (moeda BRL, datas, CPF, CNPJ, telefone, porcentagem) e gerar funções de normalização
3. Stage 21 — Confidence Scoring: calcular confiança 5-fatores por Layout Type: layout stability, anchor detection, grid quality, field variability, vision agreement (Claude Sonnet via OpenRouter)
4. Quando múltiplos candidatos para mesmo texto PDF → flag como "ambiguous" para resolução pelo operador (FR5)
5. Format detection inclui: "R$ 1.234,56"→1234.56, "15 de Janeiro de 2025"→"15/01/2025" (FR6)
6. Output parcial: field_mappings[], confidence_scores{}, ambiguous_fields[], format_functions[]
7. Testes cobrem: precisão de matching, detecção de formato, cálculo de confiança

### Issues Found
1. **[MEDIUM] Stage 25 registrado no block_id=8, não block_id=7**: O `confidence_scoring.py` se registra com `block_id=8` e `register_bloco8_confidence()` é a função de registro. O story title é "Bloco 7" mas o Stage 25 pertence ao Bloco 8. A Completion Note confirma "register_bloco8_confidence". O story file menciona "Bloco 7" no título mas descreve Stage 25 como parte do escopo. A divisão de blocos é funcional, porém o title do story é potencialmente confuso.
   - Severity: MEDIUM (documentação/rastreabilidade)
   - Suggested owner: @sm (atualizar título ou adicionar nota de esclarecimento)

2. **[LOW] `_vision_agreement` no Stage 25 normaliza consistency_score como 0-1 mas Stage 22 armazena como 0-100**: `_get_vision_agreement` faz `float(cs) / 1.0` mas `max(0.0, min(1.0, float(cs)))`. Se `consistency_score` do Stage 22 for inteiro 0-100 (ex: 85), o clamp para 1.0 tornaria `vision_agreement = 1.0` incorretamente. O Stage 22 armazena `int` 0-100; Stage 25 espera 0.0-1.0. Isso resulta em `vision_agreement` sempre 1.0 quando Score >= 1.
   - Severity: MEDIUM (bug de normalização de escala)
   - Suggested owner: @dev

3. **[LOW] Regex `currency_brl` não cobre "R$1234,56"** (sem espaço e sem separador de milhar): O padrão `r"^R\$\s?[\d.,]+$"` requer pelo menos um dígito — `R$1234,56` seria capturado. Verificado: `R$100,00` é coberto pelo teste 7. OK.
   - Severity: INFO (sem issue real após verificação)

4. **[LOW] `_find_adjacent_label` usa `blk["bbox"]` sem `.get()`**: Se um text_block não tiver chave `bbox`, gera `KeyError`. Blocos vindos de stages anteriores devem sempre ter `bbox`, mas defensivamente poderia usar `.get("bbox", [0,0,0,0])`.
   - Severity: LOW
   - Suggested owner: @dev (Sprint futura)
