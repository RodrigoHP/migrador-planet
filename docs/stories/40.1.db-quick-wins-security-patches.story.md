# Story 40.1 — DB Quick Wins & Security Patches

## Status: InReview

## Descricao

Resolver debitos de baixo esforco e alto impacto no banco de dados e dependencias vulneraveis. Estes sao fixes pontuais que eliminam riscos imediatos sem exigir refatoracao estrutural. Incluem safeguards de producao, recovery de jobs, constraints de integridade e patch de vulnerabilidade do Vite.

## Debitos Enderecados

| ID | Debito | Severidade | Esforco |
|----|--------|-----------|---------|
| DB-012 | Sem safeguard `AUTH_DISABLED` em producao | MEDIUM | 0.5h |
| DB-016 | `recover_running_jobs()` nao chamado no lifespan | HIGH | 0.5h |
| SEC-003 | Vite vulneravel (path traversal, dev-only) | HIGH | 0.5h |
| DB-004 | `jobs.updated_at` sem trigger | HIGH | 1h |
| DB-005 | `jobs.status` sem CHECK constraint | HIGH | 1h |
| DB-009 | Buckets nao criados nas migrations | MEDIUM | 1h |

## Acceptance Criteria

- [x] `AUTH_DISABLED=true` em `ENVIRONMENT=production` levanta erro no startup
- [x] `recover_running_jobs()` eh chamado no lifespan do FastAPI
- [x] `npm audit` nao reporta vulnerabilidade do Vite (path traversal)
- [x] Trigger `updated_at` existe e funciona na tabela `jobs`
- [x] CHECK constraint em `jobs.status` rejeita valores invalidos (aceita apenas: pending, running, completed, failed, cancelled)
- [x] Storage buckets sao criados via migration SQL (nao mais comentados)
- [x] Testes unitarios validam cada fix

## Dev Notes

- DB-012: Module-level check in `auth.py` — raises `RuntimeError` at import time if `AUTH_DISABLED=true` + `ENVIRONMENT=production`. Defaults to `development` when `ENVIRONMENT` is not set.
- DB-016: `recover_running_jobs()` already existed in `job_store.py` but was never called. Added call in lifespan after orphan cleanup.
- SEC-003: `npm audit fix` updated Vite to patch path traversal vulnerabilities. Remaining moderate issues (dompurify via monaco-editor) are unrelated to Vite and out of scope.
- DB-004: Trigger function `update_updated_at_column()` uses `CREATE OR REPLACE` for idempotency.
- DB-005: Migration normalizes invalid statuses to `failed` before adding CHECK constraint to prevent migration failure on dirty data.
- DB-009: Bucket creation uses `ON CONFLICT DO NOTHING` for idempotency — safe to run on existing environments.
