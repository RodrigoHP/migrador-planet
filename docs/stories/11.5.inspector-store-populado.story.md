# Story 11.5 — Corrigir InspectorPanel — popular inspectorStore no loadFromPipelineResult

## Story
**Como** usuário do editor,
**Quero** que o painel do Inspector exiba as propriedades do elemento selecionado,
**Para** poder inspecionar e editar os atributos do template.

## Status
Done

## Context
O audit identificou que `loadFromPipelineResult()` em `session.ts` popula 6 stores (templateStore, mappingStore, confidenceStore, coverageStore, layoutStore, generationStore) mas **não popula o `inspectorStore`**.

O `InspectorPanel.vue` roteia para 4 inspetores baseado em `inspector.level`. Sem dados no inspectorStore, o painel fica em estado vazio: `selectedNode = null`, `level = null`.

Sintoma: usuário clica em elemento no canvas → painel direito mostra "—" para todas as propriedades (mesmo problema parcialmente resolvido na Story 10.20, mas a raiz não foi endereçada).

## Acceptance Criteria

1. **Estado inicial** — Ao abrir o editor após análise, `inspectorStore` tem um estado inicial válido (ex: nível `page`, primeiro nó da árvore selecionado).
2. **Seleção funcional** — Clicar em elemento no canvas/árvore atualiza `inspectorStore.selectedNode` com o nó correto.
3. **Propriedades reais** — `ElementInspector.vue` exibe `x`, `y`, `width`, `height`, `font_family`, `font_size` com valores reais (não "—").
4. **Level routing** — `InspectorPanel.vue` roteia para o inspector correto (page/section/component/element) baseado em `inspector.level`.
5. **Testes** — `inspectorStore` testado com seleção de nó; inspector renderiza propriedades esperadas.

## Dev Notes

### Fluxo esperado de seleção
```
Usuário clica em bloco no canvas
→ CanvasSelectionOverlay emite evento
→ useCanvasInteraction atualiza inspectorStore.selectedNode
→ InspectorPanel.vue lê inspector.level e renderiza inspector correto
→ ElementInspector.vue exibe node.properties
```

### Dados disponíveis
Os nós do `templateStore` já têm `properties` com `{x, y, width, height, font_family, font_size}` após Story 10.20 (pipeline_result.py corrigido). O problema está na falta de inicialização do inspectorStore.
