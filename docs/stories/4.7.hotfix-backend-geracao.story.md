# Story 4.7: Hotfix — Race Condition SSE Geração e MonacoEdits Vazio

## Status

Ready

## Story

**As a** operador da ferramenta,
**I want** que o progresso da geração de template seja exibido corretamente na barra de progresso e que edições manuais no Monaco Editor com conteúdo vazio sejam respeitadas ao regenerar,
**so that** o feedback visual de geração seja preciso e o controle total sobre o código gerado seja mantido.

## Acceptance Criteria

1. A `ProgressBar` na tela de Geração exibe steps intermediários (30% "Gerando HTML", 70% "Calculando fidelidade") antes de concluir em 100%
2. O backend bufferiza eventos SSE do job de geração por ao menos 2 segundos, permitindo que o cliente conecte antes dos eventos serem perdidos
3. Alternativamente: o frontend conecta o `EventSource` antes de disparar `POST /api/generate`, eliminando a janela de race condition
4. `monacoEdits` com string vazia `""` em qualquer campo (html, css ou js) é tratado como edição válida — o backend usa a string vazia em vez de fallback para o output gerado
5. Ao clicar "Regenerar com edições" após apagar todo o conteúdo de uma aba Monaco, o campo correspondente no resultado gerado é substituído pela string vazia (não pelo template original)
6. Nenhuma regressão na geração normal (sem edições Monaco)

## Dev Notes

### Bug B4.2-a — Race Condition SSE

O pipeline de geração inicia com `asyncio.create_task()` imediatamente após `POST /api/generate` retornar. O frontend só conecta o `EventSource` depois de receber a resposta do POST e atualizar `generation.previewJobId` (via reactivity Vue). Em processamentos rápidos, o backend emite eventos `pct: 30` e `pct: 70` antes do cliente conectar.

**Abordagem frontend (recomendada — sem alterar contrato SSE):**
```typescript
// GeracaoPage.vue — função generate()
import { v4 as uuidv4 } from 'uuid' // ou usar crypto.randomUUID()

async function generate(includeEdits: boolean) {
  const jobId = crypto.randomUUID()
  generation.previewJobId = jobId  // SSE conecta ANTES do POST
  // ... fazer POST /api/generate com jobId no body
}
```

```python
# backend/routers/generate.py — aceitar jobId opcional
class GenerateRequest(BaseModel):
    jobId: Optional[str] = None  # ADICIONAR
    mappingFields: List[dict] = []
    layoutConfig: dict = {}
    monacoEdits: MonacoEdits = MonacoEdits()

@router.post("/generate")
async def start_generate(request: GenerateRequest):
    job_id = request.jobId if request.jobId else str(uuid.uuid4())
    job_manager.create_job(job_id)
    asyncio.create_task(run_generation_pipeline(job_id, request))
    return {"jobId": job_id}
```

**Alternativa backend (mais simples):** Adicionar `await asyncio.sleep(0.5)` no início de `_generation_inner` antes do primeiro emit. Menos elegante mas efetivo.

### Bug B4.2-b — `or` vs `is not None`

```python
# generate.py linha ~75
# PROBLEMA: "" é falsy em Python, então "" or "fallback" == "fallback"
html = request.monacoEdits.html or output["html"]  # ERRADO

# CORRETO:
html = output["html"] if request.monacoEdits.html is None else request.monacoEdits.html
```

O modelo Pydantic `MonacoEdits` tem campos `Optional[str] = None`. Quando o frontend não envia edições (`monacoEdits: {}`), os campos chegam como `None` — correto. Quando o usuário apaga tudo e envia `monacoEdits: { html: "" }`, chega como `""` — deve ser usado como está.
