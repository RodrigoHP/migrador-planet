# Story 11.2 — Adaptar template_draft para formato pages[] no HTMLCanvas

## Story
**Como** usuário do editor,
**Quero** que o canvas do editor renderize o template HTML gerado pelo pipeline,
**Para** visualizar e editar o layout do documento processado.

## Status
Done

## Context
O audit identificou incompatibilidade de formato entre o que o pipeline produz e o que o HTMLCanvas consome:

- **Pipeline produce:** `template_draft: {"html": str, "css": str}` — string monolítica
- **HTMLCanvas espera:** `pages: [{pageNum: number, html: string, css: string}]` — array por página

O resultado: após análise, o canvas fica completamente vazio. O usuário vê o editor mas sem conteúdo.

## Acceptance Criteria

1. **Canvas não vazio** — Após completar a análise e navegar para o editor, o HTMLCanvas exibe conteúdo (pelo menos a página 1 do documento).
2. **Formato pages[]** — `generationStore` contém `pages` como array com pelo menos um item `{pageNum: 1, html: string, css: string}`.
3. **Multi-página** — Se o pipeline retornar HTML com múltiplas páginas, cada uma aparece como item separado no array.
4. **Fallback** — Se `template_draft` vier como string monolítica, o adaptador cria `[{pageNum: 1, html, css}]` sem quebrar.
5. **Testes** — `generationStore.loadTemplateDraft()` testado com entrada monolítica e com entrada paginada.

## Dev Notes

### Estratégia de adaptação
Se o HTML monolítico contém marcadores de quebra de página (e.g., `<div class="page-break">`), pode ser dividido em páginas reais. Caso contrário, tratar o HTML completo como página única.

### Localização do gerador
O HTML é gerado nos stages finais do pipeline (`backend/services/stages/`). Verificar se algum stage já tem informação de paginação.

## Files Expected to Modify

- `frontend/src/stores/generation.ts` — adaptador `loadTemplateDraft()`
- `frontend/src/stores/session.ts` — `loadFromPipelineResult()` pode precisar ajuste
- `backend/services/stages/pipeline_result.py` — opcional: retornar pages[] diretamente
