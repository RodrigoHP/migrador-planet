# Story 29.7 — Canvas Patch: Cobertura Completa de Mutações

## Story
**Como** operador editando um template,
**Quero** que todas as mudanças que faço no Inspector (font, cor, etc.) e na árvore (adicionar, remover, mover nós) se reflitam imediatamente no canvas visual,
**Para** ter feedback visual real de todas as operações de edição sem lacunas.

## Status
Done

## Business Value
A Story 29.2 fechou o loop para drag/resize/text. Esta story fecha os gaps restantes:
- Inspector: `font_size`, `font_weight`, `color` editáveis mas invisíveis no canvas
- Árvore: remover um nó deixa "fantasma" no canvas; adicionar nó não aparece; mover nó na árvore não reorganiza o canvas

Sem esta story, o operador não consegue confirmar visualmente que suas edições tipográficas e estruturais estão corretas.

**Estimativa:** 3 story points

## Scope
**IN:**
- `borderStyleGenerator.ts` — adicionar `font_size`, `font_weight`, `color` com `!important` ao CSS injection
- `generation.ts` — adicionar `patchRemoveNode(nodeId)`, `patchAddNode(node, parentId)`, `patchMoveNode(nodeId, newParentId)`
- `templateStore.ts` — `removeNode` chama `patchRemoveNode`, `addNode` chama `patchAddNode`, `moveNode` chama `patchMoveNode` e incrementa `mutationVersion`
- Testes para as 3 novas patch functions e integração com templateStore
- Testes para CSS injection de font_size/font_weight/color

**OUT:**
- Reimplementação do motor HTML (fora do escopo do ADR-029)
- Sync visual de tipos sem `data-node-id` no stage5 (rect/line/image/chart — depende de Story 29.4)
- patchNodeStyle para propriedades não-visuais (binding, visibility, formatString)
- Debounce das operações structurais (cada operação dispara patch imediato)

## Risks

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| `patchAddNode` gera HTML divergente do backend para tipos complexos | Alta (para table/barcode) | Baixo | Aceito — placeholder visível até próximo loadTemplateDraft |
| `!important` em font overrides conflita com estilos futuros | Baixa | Baixo | Escopar com `[data-node-id="..."]` garante especificidade mínima necessária |
| `patchMoveNode` com position:absolute sem efeito visual | Alta | Baixo | Implementar para manter DOM sincronizado com store — valor: consistência, não visual |
| `mutationVersion` não incrementado em moveNode, addNode, removeNode (antes desta story) | — | Corrigido nesta story | Todos os 3 passam a incrementar |

## Acceptance Criteria

- **AC1:** **Dado** que o operador altera `font_size` de um nó no Inspector, **Quando** a mudança é confirmada, **Então** o tamanho da fonte reflete visualmente no Canvas em até 500ms
- **AC2:** **Dado** que o operador altera `font_weight` (negrito) de um nó no Inspector, **Quando** a mudança é confirmada, **Então** o Canvas exibe o texto em negrito
- **AC3:** **Dado** que o operador altera `color` (cor do texto) de um nó no Inspector, **Quando** a mudança é confirmada, **Então** o Canvas exibe a nova cor do texto
- **AC4:** **Dado** que o operador remove um nó via StructureTree ou context menu, **Quando** a remoção é executada, **Então** o nó desaparece do Canvas (sem "fantasma")
- **AC5:** **Dado** que o operador adiciona um nó via StructureTree, **Quando** o nó é criado, **Então** um elemento placeholder aparece no Canvas na posição x/y/w/h do nó
- **AC6:** **Dado** que o operador move um nó na StructureTree (drag-and-drop estrutural), **Quando** o drop é concluído, **Então** o DOM do Canvas é reorganizado para refletir a nova hierarquia
- **AC7:** **Dado** que `addNode`, `removeNode` e `moveNode` são chamados, **Quando** verificar `mutationVersion`, **Então** o contador foi incrementado para cada operação
- **AC8:** **Dado** os testes do store e componentes, **Quando** executados, **Então** cobrem AC1-AC7, todos passando

### 2. `generation.ts` — patchRemoveNode

```typescript
patchRemoveNode(nodeId: string): void {
  if (!this.templateDraft?.html) return
  if (typeof DOMParser === 'undefined') return

  const parser = new DOMParser()
  const doc = parser.parseFromString(`<div id="_root">${this.templateDraft.html}</div>`, 'text/html')
  const root = doc.getElementById('_root')
  if (!root) return

  const el = root.querySelector(`[data-node-id="${nodeId}"]`)
  if (!el) return

  el.remove()
  const patched = root.innerHTML
  if (patched !== this.templateDraft.html) {
    this.templateDraft = { ...this.templateDraft, html: patched }
  }
},
```

### 3. `generation.ts` — patchAddNode

```typescript
/**
 * Gera HTML mínimo para o nó e insere como filho do elemento parentNodeId.
 * Produz placeholder posicionado com data-node-id — suficiente para canvas MVP.
 * O HTML real (com styling completo) será gerado na próxima chamada ao backend.
 */
patchAddNode(node: import('@/types/template.types').TreeNode, parentNodeId: string): void {
  if (!this.templateDraft?.html) return
  if (typeof DOMParser === 'undefined') return

  const parser = new DOMParser()
  const doc = parser.parseFromString(`<div id="_root">${this.templateDraft.html}</div>`, 'text/html')
  const root = doc.getElementById('_root')
  if (!root) return

  const parentEl = root.querySelector(`[data-node-id="${parentNodeId}"]`)
  if (!parentEl) return  // parent sem data-node-id → sem suporte neste MVP

  const html = _generateMinimalNodeHtml(node)
  if (!html) return

  parentEl.insertAdjacentHTML('beforeend', html)
  const patched = root.innerHTML
  if (patched !== this.templateDraft.html) {
    this.templateDraft = { ...this.templateDraft, html: patched }
  }
},
```

**Helper `_generateMinimalNodeHtml` (module-level em generation.ts):**

```typescript
import type { TreeNode } from '@/types/template.types'

function _generateMinimalNodeHtml(node: TreeNode): string {
  const id = node.id
  const type = node.type
  const x = (node.properties.x as number) ?? 0
  const y = (node.properties.y as number) ?? 0
  const w = (node.properties.width as number) ?? 100
  const h = (node.properties.height as number) ?? 20
  const text = (node.properties.text as string) ?? node.name ?? type
  const style = `position:absolute;left:${x}px;top:${y}px;width:${w}px;height:${h}px`

  switch (type) {
    case 'label':
    case 'field':
    case 'value':
    case 'likely_dynamic':
    case 'dynamic':
      return `<span data-node-id="${id}" data-type="${type}" style="${style}">${text}</span>`
    case 'section':
      return `<div data-node-id="${id}" data-type="section" style="${style}"></div>`
    default:
      // Tipos não suportados no MVP (table, chart, image, barcode) — placeholder div
      return `<div data-node-id="${id}" data-type="${type}" style="${style}"></div>`
  }
}
```

### 4. `generation.ts` — patchMoveNode

```typescript
/**
 * Move o elemento nodeId para dentro do elemento newParentId no HTML.
 * Para elementos position:absolute, o efeito visual pode ser neutro — mas mantém
 * o DOM sincronizado com a estrutura do templateStore.
 */
patchMoveNode(nodeId: string, newParentId: string): void {
  if (!this.templateDraft?.html) return
  if (typeof DOMParser === 'undefined') return

  const parser = new DOMParser()
  const doc = parser.parseFromString(`<div id="_root">${this.templateDraft.html}</div>`, 'text/html')
  const root = doc.getElementById('_root')
  if (!root) return

  const el = root.querySelector(`[data-node-id="${nodeId}"]`)
  const newParent = root.querySelector(`[data-node-id="${newParentId}"]`)
  if (!el || !newParent) return
  if (newParent.contains(el)) return  // já é filho, sem-op

  newParent.appendChild(el)
  const patched = root.innerHTML
  if (patched !== this.templateDraft.html) {
    this.templateDraft = { ...this.templateDraft, html: patched }
  }
},
```

### Nota sobre CSS injection (AC1-AC3)

As propriedades `font_size`, `font_weight`, `color` usam o mecanismo de CSS injection **já existente** via `borderOverrideCss` no HTMLCanvas.vue (linha 271). Quando `updateNodeProperty` é chamado pelo Inspector, `flatNodes` muta → `borderOverrideCss` recomputa (computed Pinia) → `pages` recomputa → `<iframe :srcdoc>` recebe novo CSS.

**Não é necessário nenhum novo patchNode para AC1-AC3** — apenas estender `borderStyleGenerator.ts`.
