# Story 19.5 — Project Context Auto-Detect

## Story
**Como** operador que executa `aiox init` em um projeto existente,
**Quero** que o sistema detecte automaticamente o tech stack a partir de arquivos de manifesto (package.json, requirements.txt, Cargo.toml, etc.) e gere `.aios/project-context.yaml`,
**Para** que workflows e agents saibam qual linguagem, framework e ferramentas usar sem configuracao manual.

## Status
Draft

## Context

### Problema

Os workflows genericos (19.3) usam template variables como `{{TEST_FRAMEWORK}}` e `{{BACKEND_FRAMEWORK}}`. Sem project-context.yaml preenchido, essas variables ficam como placeholders genericos, reduzindo a qualidade das instrucoes geradas.

Configurar manualmente o project-context.yaml exige que o operador saiba quais campos preencher e quais valores usar — friction desnecessaria quando essa informacao ja existe nos arquivos do projeto.

### Design

#### Deteccao por arquivo de manifesto

| Arquivo | Detecta |
|---------|---------|
| `package.json` | Node.js, framework (React/Vue/Angular/Next), test runner (jest/vitest/mocha) |
| `tsconfig.json` | TypeScript habilitado |
| `requirements.txt` / `pyproject.toml` | Python, framework (Django/FastAPI/Flask) |
| `Cargo.toml` | Rust, framework (Axum/Actix/Rocket) |
| `go.mod` | Go, modulos |
| `Dockerfile` | Containerizado |
| `docker-compose.yml` | Multi-service |
| `.env` / `.env.example` | Environment variables pattern |
| `supabase/` | Supabase database |
| `prisma/` | Prisma ORM |

#### Output: `.aios/project-context.yaml`

```yaml
project:
  name: "auto-detected-or-from-package"
  type: "web-app"  # web-app | api | library | cli | monorepo

  languages:
    primary: "typescript"
    secondary: ["python"]

  frontend:
    framework: "vue"
    version: "3.x"
    test_runner: "vitest"
    build_tool: "vite"

  backend:
    framework: "fastapi"
    language: "python"
    test_runner: "pytest"

  database:
    type: "supabase"
    orm: null

  infrastructure:
    containerized: true
    ci_cd: "github-actions"

  detected_from:
    - file: "package.json"
      found: ["vue@3.5", "vitest@2.1"]
    - file: "requirements.txt"
      found: ["fastapi", "uvicorn"]
```

#### Algoritmo de deteccao

```
FOR each known manifest file:
  IF file exists in project root:
    PARSE file
    EXTRACT framework/version/tools
    ADD to context

RESOLVE conflicts:
  IF multiple test runners found → pick the one in scripts.test
  IF multiple frameworks found → pick the one with most imports

GENERATE .aios/project-context.yaml
```

#### Integracao com engine

O engine e workflows resolvem template variables consultando project-context.yaml:
- `{{TEST_FRAMEWORK}}` → `project.frontend.test_runner` ou `project.backend.test_runner`
- `{{BACKEND_FRAMEWORK}}` → `project.backend.framework`

## Acceptance Criteria

- [ ] AC2: Detecta Python projects via requirements.txt e pyproject.toml (framework, test runner)
- [ ] AC3: Detecta Rust projects via Cargo.toml
- [ ] AC4: Detecta Go projects via go.mod
- [ ] AC5: Detecta infraestrutura (Dockerfile, docker-compose.yml, CI/CD config)

## Technical Notes

- A deteccao deve ser conservadora: so afirmar o que encontrou evidencia clara
- O operador pode editar o project-context.yaml gerado para corrigir ou complementar
- Monorepos podem ter multiplos manifestos — detectar o principal (root)
