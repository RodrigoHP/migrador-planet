# Story 10.18: Bug — Vision stages aparecem verde quando Vision AI está desabilitado

## Status
Done

## Story
**As a** operador,
**I want** que os stages Vision AI (especialmente Stage 22 — Self-Check) exibam status amarelo/skipped na tela de análise quando Vision AI está desabilitado,
**so that** a UI não dê a falsa impressão de que análise visual foi realizada com sucesso quando `VISION_AI_ENABLED=false`.

## Acceptance Criteria
1. Quando um stage retorna `{"skipped": True}`, o orquestrador emite `status: "skipped"` no evento SSE — não `"completed"`
2. O frontend define `StageStatus` incluindo `'skipped'` e trata o evento SSE correspondente
3. Stages com status `skipped` são exibidos com fundo amarelo (`bg-yellow-50 text-yellow-600`) e ícone `–`
4. Um bloco cujos stages são todos `completed` ou `skipped` é marcado como `completed` (pipeline concluiu normalmente)
5. `pytest backend/tests/` passa sem erros após as alterações

## Tasks / Subtasks
- [x] Backend: em `backend/routers/analyze.py`, após `stage_result = await stage_def.execute(context)`, verificar `stage_result.get("skipped") is True` e emitir `status="skipped"` em vez de `"completed"` (AC: #1)
- [x] Frontend: adicionar `'skipped'` ao tipo `StageStatus` em `AnalyzingPage.vue` (AC: #2)
- [x] Frontend: adicionar `case 'skipped': return 'bg-yellow-50 text-yellow-600'` em `getStageClass` (AC: #3)
- [x] Frontend: adicionar ícone `–` para stages skipped no template HTML (AC: #3)
- [x] Frontend: adicionar tratamento de `data.status === 'skipped'` no handler SSE (AC: #2)
- [x] Frontend: atualizar `getBlockStatus` para considerar bloco completo quando todos stages são `completed` ou `skipped` (AC: #4)
- [x] Backend: adicionar teste `test_skipped_stage_emits_skipped_status` em `test_pipeline.py` (AC: #5)
- [x] Backend: atualizar asserção de status válidos em `test_sse_event_format` para incluir `"skipped"` (AC: #5)
- [x] Rodar `pytest backend/tests/` — 0 falhas (AC: #5)

## Dev Notes

### Causa raiz

**Backend (`backend/routers/analyze.py`):** O orquestrador sempre emitia `status: "completed"` após um stage retornar sem exceção, ignorando se o resultado continha `{"skipped": True}`.

**Frontend (`frontend/src/pages/AnalyzingPage.vue`):** O tipo `StageStatus` não incluía `'skipped'`, então o evento SSE com esse status era ignorado. O evento `"completed"` subsequente do orquestrador marcava o stage como verde.

### Fix aplicado

**Backend:** Após `stage_result = await stage_def.execute(context)`, verificar:
```python
stage_was_skipped = isinstance(stage_result, dict) and stage_result.get("skipped") is True
status = "skipped" if stage_was_skipped else "completed"
```

**Frontend:** Adicionado `'skipped'` ao tipo, handler SSE, classe CSS amarela, ícone `–`, e lógica de bloco.

### Stages afetados
Stage 22 (`vision_self_check.py`) retorna `{"pages_checked": 0, "skipped": True}` quando `VISION_AI_ENABLED=false`. O fix cobre automaticamente quaisquer outros stages que adotem o mesmo padrão de retorno.

### Arquivos modificados
- `backend/routers/analyze.py` — lógica de emit skipped vs completed
- `frontend/src/pages/AnalyzingPage.vue` — StageStatus, getStageClass, getBlockStatus, template, handler SSE
- `backend/tests/test_pipeline.py` — novo teste + atualização de asserção
