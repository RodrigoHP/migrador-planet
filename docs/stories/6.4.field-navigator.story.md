# Story 6.4: FieldNavigator Auto-Populated — Lista de Campos com Status de Mapeamento

## Status
Draft

## Story
**As a** operador,
**I want** ver todos os campos XSD listados com seu status de mapeamento (mapeado/não mapeado/não confirmado), organizados por tipo,
**so that** eu possa rapidamente ver quais campos ainda precisam de atenção.

## Acceptance Criteria
1. Organism FieldNavigator renderiza campos de `mappingStore.fields` agrupados por tipo: 📋 Campos, 📊 Tabelas, 📈 Gráficos, 📐 Seções, 🖼️ Recursos
2. Cada campo exibe: ícone, nome, badge de status (🟩 mapeado, 🟥 não mapeado, 🟨 não confirmado)
3. Campos opcionais marcados com ⚠
4. Clicar em um campo seleciona o nó correspondente na StructureTree (atualiza inspectorStore)
5. Resumo de contagem no topo: "18 de 20 campos mapeados"
6. Status derivado de mappingStore: mapped = binding confirmado, unmapped = sem binding, unconfirmed = auto-mapeado mas não confirmado pelo operador
7. Campos ordenáveis por: nome, status, tipo
8. `npm run build` passa

### Interface de Campo (de mappingStore)
```typescript
interface FieldMapping {
  name: string;
  path: string;          // XPath ou JSON path do campo
  type: 'string' | 'array' | 'chart' | 'section' | 'image';
  status: 'mapped' | 'unmapped' | 'unconfirmed';
  binding?: string;      // binding no template (ex.: "cliente")
  nodeId?: string;       // ID do nó correspondente no templateStore
  isOptional: boolean;
}
```

### Mapeamento type→ícone e grupo

const typeGroups = {

### Status dos Campos
- `mapped`: campo tem binding confirmado pelo pipeline E pelo operador
- `unmapped`: campo não tem binding — precisa de ação manual
- `unconfirmed`: campo foi auto-mapeado pelo pipeline mas operador ainda não confirmou
- Drag-to-bind (arrastar campo para template) vem no Epic 7 (story 7.3) — por enquanto apenas exibição e clique
