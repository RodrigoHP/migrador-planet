# Story 40.2 — Data Security Chain

## Status: InProgress

## Descricao

Resolver a cadeia de seguranca de dados end-to-end: adicionar multi-tenancy (`user_id`), reescrever RLS policies com owner-based access, separar service role de queries, sanitizar `v-html` contra XSS, e adicionar security headers. Esta eh a story mais critica do epic -- resolve todos os debitos CRITICAL de seguranca e a maioria dos HIGH de seguranca.

Ordem de resolucao validada por @data-engineer: DB-002 (user_id) primeiro, depois DB-001 + DB-003 em paralelo, depois SEC-001 e SYS-015.

## Debitos Enderecados

| ID | Debito | Severidade | Esforco |
|----|--------|-----------|---------|
| DB-002 | Sem multi-tenancy / `user_id` em nenhuma tabela | CRITICAL | 12h |
| DB-001 | RLS policies com `USING (true)` -- acesso blanket | CRITICAL | 4h |
| DB-003 | Service role key -- uso indiscriminado para todas as operacoes | HIGH | 4h |
| SEC-001 | v-html XSS em BibliotecaComponentList sem sanitizacao | HIGH | 2h |
| SYS-015 | Sem security headers (CORS *, sem CSP, HSTS, X-Frame-Options) | HIGH | 4h |

## Acceptance Criteria

- [x] Todas as tabelas (`jobs`, `templates`, `field_mappings`) possuem coluna `user_id` (nullable com enforcement gradual)
- [x] Backend INSERT/UPDATE inclui `user_id` do JWT em todas as operacoes
- [x] RLS policies usam `auth.uid() = user_id` em vez de `USING (true)`
- [x] User A nao consegue ler/modificar/deletar dados de User B
- [x] Dois clientes Supabase: admin (storage ops) + user (queries com JWT)
- [x] Service role usado APENAS para storage operations (upload, download, signed URLs)
- [x] `v-html` em BibliotecaComponentList sanitizado via DOMPurify com allowlist
- [x] Security headers presentes em todas as respostas: CSP, HSTS, X-Frame-Options, X-Content-Type-Options, CORS scoped
- [x] Testes de integracao validam isolamento de dados entre usuarios
- [x] Anon key queries respeitam RLS policies

## Dev Notes

### DB-002 (user_id columns)
- user_id is NULLABLE for gradual enforcement. Backfill strategy documented in migration comments.
- No `field_mappings` table exists in the schema (field mapping is done in-memory during pipeline). AC refers to "all tables" — implemented for jobs, templates, job_clusters.

### DB-001 (RLS policies)
- SELECT/UPDATE/DELETE policies allow `user_id IS NULL` access for pre-migration data (gradual).
- INSERT policies require `user_id = auth.uid()` — new data must have an owner.

### DB-003 (client separation)
- `admin_client` (service role) used for all `storage.from_()` operations.
- `user_client` (anon key) used for all `.table()` operations — respects RLS.
- Falls back to admin_client if SUPABASE_ANON_KEY not configured (backward compat).
- `set_auth_context()` method propagates user_id and JWT token to the gateway.

### SEC-001 (DOMPurify)
- Strict ALLOWED_TAGS: only structural, text formatting, tables, images, SVG, headings.
- No `<a>`, `<form>`, `<iframe>`, `<script>`, `<embed>`, `<object>` allowed.
- ALLOW_DATA_ATTR: false — no data-* attributes.

### SYS-015 (security headers + CORS)
- CSP is permissive to start (includes unsafe-inline for script/style) — tighten incrementally.
- CORS: methods scoped to GET/POST/PUT/DELETE/OPTIONS, headers to Authorization/Content-Type/Accept/X-Requested-With.
- Origins already came from ALLOWED_ORIGINS env var (not wildcard).
