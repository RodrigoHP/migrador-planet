# Story 21.3 — Dedup Check Operacional na Fase 0

## Story
**Como** investigador executando `/investigate`,
**Quero** que a Fase 0 faca cross-reference automatico com RCAs anteriores, PRs abertos e branches ativas,
**Para** evitar investigacoes duplicadas de bugs ja conhecidos.

## Status
Done

## Context

### Problema
Os 2 RCAs reais do projeto (2026-03-29 e 2026-03-31) tratam do mesmo core issue (`.get()` em lista) mas nao se referenciaram. A Fase 0 menciona dedup check mas nao define criterios, janela temporal, nem acao quando duplicata encontrada.

### Design
1. **Busca em 4 fontes**: investigations.yaml (RCAs), `gh pr list` (PRs), `git branch -a` (branches), docs/stories/ (stories recentes)
2. **Match criteria**: mesma mensagem de erro, mesmos arquivos afetados, mesmos tags
3. **Janela temporal**: ultimos 30 dias (configuravel)
4. **Acao**: se match encontrado, apresentar opcoes: (a) Merge com RCA existente, (b) Referenciar e continuar, (c) Ignorar match

## Acceptance Criteria
- [ ] Fase 0 do investigate.md inclui dedup check com busca em 4 fontes
- [ ] Criterios de match definidos: error message similarity, files overlap, tag overlap
- [ ] Janela temporal padrao de 30 dias documentada
- [ ] Quando match encontrado: apresentar opcoes (merge/reference/ignore)
- [ ] Em modo YOLO: auto-selecionar "reference" se match parcial, "merge" se match >90%
- [ ] Cross-reference bidirecional: RCA nova referencia antiga E antiga eh atualizada com referencia
- [ ] Workflow YAML atualizado com dedup step

## Scope
**IN:** Fase 0 do investigate.md, workflow YAML
**OUT:** Automacao de merge entre RCAs (manual)
