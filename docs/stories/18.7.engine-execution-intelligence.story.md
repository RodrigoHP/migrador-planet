# Story 18.7 — Execution Intelligence

## Story
**Como** operador que executa multiplos workflows ao longo do tempo,
**Quero** que o engine acumule padroes de falha e licoes aprendidas de execucoes anteriores e injete essas licoes nos prompts de execucoes futuras,
**Para** que erros repetitivos sejam eliminados progressivamente e o sistema fique mais inteligente a cada run.

## Status
Draft

## Context

### Problema

Cada workflow execution comeca do zero. O state file do run anterior existe em `.aios/` mas nunca e consultado. Se 3 stories do mesmo epic falham no QA pelo mesmo motivo (ex: esqueceu File List), cada uma falha independentemente. O sistema nao aprende.

### Design

#### Persistence: `.aios/execution-intelligence.yaml`

```yaml
execution_intelligence:
  version: 1
  updated_at: "2026-03-30T..."

  failure_patterns:
    - pattern_id: "fp-001"
      description: "@dev esquece de atualizar File List na story"
      occurrences: 3
      first_seen: "2026-03-28"
      last_seen: "2026-03-29"
      workflow: story-development-cycle
      step: implement_story
      agent: "@dev"
      resolution: "Adicionar lembrete explicito no prompt"
      ttl_days: 30

    - pattern_id: "fp-002"
      description: "Parse failure em steps com output complexo (>5 campos)"
      occurrences: 2
      first_seen: "2026-03-29"
      last_seen: "2026-03-29"
      workflow: "*"
      step: "*"
      agent: "*"
      resolution: "Simplificar output esperado ou dar exemplo"
      ttl_days: 30

  lessons_learned:
    - lesson_id: "ll-001"
      description: "Stories com >5 ACs tem maior taxa de retry"
      source: "analytics"
      applicable_to: "all workflows"
      recommendation: "Considerar decomposicao de stories com >5 ACs"

  agent_insights:
    "@dev":
      avg_confidence: 0.82
      common_misses: ["File List update", "edge case tests"]
      strength: "Core logic implementation"
    "@qa":
      avg_confidence: 0.94
      common_misses: []
      strength: "Comprehensive review"
```

#### Coleta (pos-execucao)

Ao final de cada workflow (completed ou aborted), o engine:

1. Analisa step_results por padroes de falha
2. Compara com failure_patterns existentes (incrementa occurrences ou cria novo)
3. Atualiza agent_insights com dados do run
4. Remove entries expiradas (ttl)

```
FUNCTION update_intelligence(state, intelligence):
  FOR each step_result in state.step_results:
    IF step_result.status == "failed" OR step_result.retries > 0:
      pattern = find_or_create_pattern(intelligence, step_result)
      pattern.occurrences += 1
      pattern.last_seen = TODAY()

  # Cleanup expired entries
  intelligence.failure_patterns = filter(p => days_since(p.last_seen) < p.ttl_days)
  intelligence.lessons_learned = filter(l => days_since(l.first_seen) < l.ttl_days)

  save(intelligence)
```

#### Injecao (pre-execucao)

No inicio de cada workflow, o engine:

1. Le `.aios/execution-intelligence.yaml`
2. Filtra patterns relevantes para o workflow/step/agente atual
3. Injeta como `{{INTELLIGENCE_CONTEXT}}` nos prompts

```markdown
{{#if INTELLIGENCE_CONTEXT}}
## LESSONS FROM PREVIOUS EXECUTIONS
{{INTELLIGENCE_CONTEXT}}
Avoid these known issues proactively.
{{/if}}
```

#### Token budget

Intelligence context limitado a **max 300 tokens** por step:
- Top 3 failure patterns mais relevantes
- Top 2 lessons mais aplicaveis
