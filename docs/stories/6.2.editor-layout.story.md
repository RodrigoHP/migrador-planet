# Story 6.2: EditorLayout 5 Regiões + TopToolbar

## Status
Done

## Story
**As a** operador,
**I want** ver o editor unificado com 5 regiões (toolbar, painel esquerdo, painel central, inspetor, painel inferior),
**so that** eu tenha todas as ferramentas acessíveis simultaneamente sem navegar entre telas.

## Acceptance Criteria
1. EditorLayout.vue com 5 regiões: toolbar (topo), painel esquerdo (sidebar), painel central (main), inspetor (direita), painel inferior (collapsible)
2. Painel esquerdo tem 2 botões de aba: [Estrutura] [Campos] — conteúdo troca baseado na aba ativa
3. Painel central tem 4 botões de aba: [🖥️ Canvas] [📄 PDF] [</> Código] [🔗 Sincronizar] — conteúdo troca baseado na aba ativa
4. Painéis redimensionáveis via drag handles entre eles
5. TopToolbar exibe: nome do template (de sessionStore), badge Confiança (% + cor de confidenceStore), badge Cobertura (% + cor de coverageStore), seletor Layout Type (dropdown de layoutStore), botões toggle [🗺️ Cobertura] [🔀 Diff] [🧲 Snap] [🔧 Auto Fix] [💾 Salvar] [📦 Exportar]
6. Badges Confiança e Cobertura são clicáveis (popover implementado na 6.8)
7. Seletor Layout Type exibe layout types de layoutStore; oculto quando apenas 1 layout type
8. Botões toggle atualizam estado do editorStore
9. Botões Salvar e Exportar são placeholder (funcionais no Epic 8)
10. Responsivo: largura mínima 1200px, painéis colapsam graciosamente
11. `npm run build` passa

## Dev Notes

### Layout CSS Grid
O EditorLayout usa CSS Grid para posicionar as 5 regiões:
```css
.editor-layout {
  display: grid;
  grid-template-areas:
    "toolbar toolbar toolbar"
    "left-panel center-panel inspector"
    "bottom-panel bottom-panel bottom-panel";
  grid-template-columns: var(--left-panel-width) 1fr var(--inspector-width);
  grid-template-rows: auto 1fr var(--bottom-panel-height);
  height: 100vh;
  min-width: 1200px;
}
```

### Troca de Layout Type
Quando o operador seleciona um Layout Type diferente no dropdown:
1. `layoutStore.setActiveLayout(layoutId)` é chamado
2. templateStore atualiza a árvore para o layout selecionado
3. coverageStore e confidenceStore atualizam métricas para o layout selecionado
4. Os badges no toolbar refletem os novos valores

## Architect Review

**Reviewer:** Aria (System Architect)
**Date:** 2026-03-17
**Status:** APPROVED_WITH_NOTES

### Design Assessment
- Coupling: LOW. EditorLayout usa Pinia stores via composables sem acoplamento direto a lógica de negócio. CenterPanel e LeftPanel são consumers puros de editorStore sem side effects. TopToolbar depende de 4 stores (session, confidence, coverage, layout) — dependências declaradas e razoáveis para um toolbar de editor.
- Cohesion: HIGH. Cada componente tem responsabilidade única: EditorLayout = estrutura de regiões CSS Grid, TopToolbar = ações e métricas globais, CenterPanel = navegação entre visualizações, LeftPanel = navegação entre painéis de dados.
- Patterns: Composition API corretamente usada em todos os componentes. ResizableHandle como atom reutilizável é decisão correta — pode ser usado em qualquer split pane futuro. ToggleButton genérico com slot para ícone/label permite extensibilidade para Epic 7.
- Scalability: Layout de 5 regiões com CSS Grid com variáveis CSS para dimensões é escalável e permite ajuste via JavaScript sem reflow. Resize via eventos mouse nativos é mais eficiente que bibliotecas externas para este caso de uso.

### Issues Found

**[LOW] ResizableHandle não persiste tamanho entre sessões**
- O redimensionamento dos painéis é perdido ao recarregar a página.
- Severity: LOW — aceitável para MVP. Feature natural para Sprint futura.
- Sugestão: persistir tamanhos no localStorage via composable `useLocalStorage` (VueUse).

### Technical Debt Registered

### Decision Log
- EditorLayout usa `grid-template-areas` com variáveis CSS para dimensões — correto para layout 2D complexo, permite controle programático de dimensões via `style` binding sem rerender do grid.
- CenterPanel tabs usam `editorStore.activeCenterTab` diretamente — correto, o store é o source of truth para estado de navegação e permite que outros componentes (ex.: shortcuts de teclado no Epic 7) alterem a aba ativa.
- ConfidenceBadgeMetric e CoverageBadge emitem eventos `click` sem implementar o popover — decisão correta pois o popover é responsabilidade da Story 6.8.
