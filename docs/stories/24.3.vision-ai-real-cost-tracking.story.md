# Story 24.3: Rastrear custo real via completion.usage

## Status
Draft

## Story
**As a** administrador do sistema,
**I want** que o custo de API exibido reflita o custo real das chamadas Vision AI,
**so that** eu possa monitorar gastos com precisão em vez de ver apenas uma estimativa fixa.

## Contexto
**RCA:** `rca-2026-03-31-custo-api-zero` — Achado F-1 (colateral)
**Prioridade:** LOW — melhoria de qualidade de dados, não corrige comportamento quebrado

Atualmente `chat_with_vision` em `openrouter_client.py:165` retorna apenas o texto da
resposta, descartando `completion.usage` (que contém `prompt_tokens` e `completion_tokens`).

O custo é calculado como `_vision_api_calls × $0.025` (estimativa fixa), independente
do tamanho real da imagem e do prompt. Custo real pode divergir significativamente.

**Rates OpenRouter (gpt-4o):**
- Input: ~$0.005/1K tokens
- Output: ~$0.015/1K tokens

## Acceptance Criteria

1. `chat_with_vision` retorna `tuple[str, float]` — texto + custo calculado de `completion.usage`
2. Custo calculado via: `(prompt_tokens * 0.005 + completion_tokens * 0.015) / 1000`
3. `stage3_structural_analysis.py` acumula custo real em `context["_vision_api_cost"]` (além de manter `_vision_api_calls` para contagem)
4. `pipeline_orchestrator_v2.py` usa `_vision_api_cost` quando disponível; fallback para estimativa quando `_vision_api_cost` é 0 ou ausente
5. Se `completion.usage` for `None` (raro — alguns providers): custo estimado fixo como fallback
6. Testes unitários para: custo real calculado corretamente, fallback quando `usage=None`
7. Nenhum teste existente regride

## Scope

**IN:**
- `backend/services/openrouter_client.py` — modificar `chat_with_vision` para retornar `(text, cost)`
- `backend/services/stages/stage3_structural_analysis.py` — acumular `_vision_api_cost` no context
- `backend/services/pipeline_orchestrator_v2.py` — usar custo real no summary

**OUT:**
- Não alterar frontend (valores já chegam como número, retrocompatível)
- Não alterar rates — usar os valores de `openrouter_client.py` já existentes
- Não remover `_vision_api_calls` — manter para contagem e retrocompatibilidade

**Fix — openrouter_client.py:130:**

async def chat_with_vision(
    client: Any,
    image_b64: str,
    prompt: str,
    model: str = DEFAULT_MODEL,
) -> tuple[str, float]:  # (text, cost_usd)
    # ...
    completion = await _call_with_retry(...)
    text = completion.choices[0].message.content or ""

    # Calculate real cost from usage
    cost = 0.0
    if completion.usage:
        cost = (
            completion.usage.prompt_tokens * COST_PER_1K_INPUT_TOKENS +
            completion.usage.completion_tokens * COST_PER_1K_OUTPUT_TOKENS

    else:
        cost = ESTIMATED_COST_PER_VISION_CALL  # fallback

    return text, cost
