# Story 21.7 — Anti-Pattern Registry Completeness

## Story
**Como** investigador consultando o anti-pattern registry,
**Quero** que todos os anti-patterns tenham campos completos conforme o schema v5.0,
**Para** que audit-patterns e pattern matching funcionem com dados consistentes.

## Status
Done

## Context

### Problema
O schema v5.0 define campos obrigatorios e opcionais para anti-patterns, mas AP-001, AP-002 e AP-003 estao incompletos:
- Falta `recurrence` count real (AP-001 deveria ter 4, nao tem)
- Falta `status` (active/superseded) em todos
- Falta `sop_reference` (link para SOP associado)
- Regex de busca de AP-002 eh especifico demais (so um arquivo)
- Regex de AP-003 pode gerar falsos positivos

### Design
1. Adicionar campos faltantes a todos os APs existentes
2. Melhorar regex de busca para ser generico mas preciso
3. Validar que cada AP com SOP tem cross-reference correto
4. Documentar exemplo de AP "bem formado" como referencia

## Acceptance Criteria
- [ ] AP-001 a AP-003 tem campo `recurrence` com count correto
- [ ] AP-001 a AP-003 tem campo `status: active`
- [ ] AP-001 a AP-003 tem campo `sop_reference` linkando para SOP correspondente (ou `null` se nao tem)
- [ ] AP-002 regex generalizado para detectar imports quebrados em qualquer spec (nao so analyzingPageConstants)
- [ ] AP-003 regex refinado para reduzir falsos positivos
- [ ] Exemplo de anti-pattern "bem formado" documentado no schema section do registry
- [ ] Cross-reference verificado: cada sop_reference aponta para SOP existente

## Scope
**IN:** known-anti-patterns.md, schema section
**OUT:** Novos anti-patterns (serao adicionados por RCAs futuras)

- `docs/qa/rca-knowledge/sops/` (verificar cross-reference)
