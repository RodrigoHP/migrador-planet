# Story 18.10 — Parallel Step Execution

## Story
**Como** operador que executa workflows com steps independentes,
**Quero** que o engine detecte steps que podem ser executados em paralelo e os spawne simultaneamente via multiplos Task tool calls,
**Para** que workflows sejam ate 40% mais rapidos quando steps sao paralelizaveis.

## Status
Draft

## Context

### Problema

Tudo no engine e sequencial. Mesmo steps que nao dependem um do outro (sem `requires` cruzado) rodam um apos o outro. Exemplo no RCA workflow:

```
create_branch (@sm) — 2 min
create_bug_stories (@sm) — 3 min
Total sequencial: 5 min

Se paralelo: 3 min (economia de 40%)
```

### Design

#### Workflow YAML: `parallel_group`

Novo campo opcional nos steps do workflow:

```yaml
sequence:
  - step: create_branch
    id: create_branch
    agent: sm
    parallel_group: "prep"      # NOVO: grupo de execucao paralela
    outputs: [branch_name]

  - step: create_bug_stories
    id: create_stories
    agent: sm
    parallel_group: "prep"      # Mesmo grupo → executa em paralelo com create_branch
    outputs: [story_files]

  - step: implement_and_test
    id: implement
    agent: dev
    requires: [create_branch, create_stories]  # Espera ambos completarem
    outputs: [implementation]
```

#### Engine logic

```
PROCEDURE advance_and_execute_v2(state, workflow):
  ...
  # Quando encontra step com parallel_group:
  IF item has 'parallel_group':
    group_name = item.parallel_group
    group_steps = collect_all_steps_in_group(sequence, index, group_name)

    # Spawn todos simultaneamente
    tasks = []
    FOR each step in group_steps:
      prompt = build_prompt(step, state)
      tasks.append(spawn_task_async(step, prompt))

    # Aguardar todos completarem
    results = await_all(tasks)

    # Processar resultados
    FOR each (step, result) in zip(group_steps, results):
      parsed = parse_output(result)
      state.step_results[step.id] = parsed
      state.step_outputs[step.id] = parsed.outputs

    # Avancar index alem do grupo
    index = index + len(group_steps)
    CONTINUE LOOP
```

#### State management para paralelo

Problema: State locking (16.6) assume escrita sequencial. Com paralelo, multiplas tasks podem tentar escrever simultaneamente.

Solucao: **Batch write** — state so e salvo APOS todo o grupo completar:

```
# NAO salva durante execucao paralela
# Salva UMA vez apos todos os steps do grupo completarem
FOR each step in group_steps:
  state.step_results[step.id] = result
save_state_with_locking(state)  # Uma escrita atomica
```

#### Handoff para grupos paralelos

Se os steps do grupo paralelo usam agentes diferentes, handoffs sao gerados APOS o grupo completar (nao durante):

```
FUNCTION generate_group_handoffs(group_steps, next_step, state):
  # Gera handoffs consolidados de cada agente diferente no grupo para o proximo step
  agents_in_group = unique(s.agent for s in group_steps)
  FOR each agent in agents_in_group:
    IF agent != next_step.agent:
      steps_by_agent = filter(group_steps, s => s.agent == agent)
      generate_consolidated_handoff(steps_by_agent, next_step, state)
```

#### Fallback: sequencial

Se o Task tool nao suporta execucao paralela (ou steps falham em paralelo), fallback para execucao sequencial:

```
IF parallel_execution_failed:
  Log: "⚠️ Parallel execution failed — falling back to sequential"
  Execute group_steps sequencialmente (como hoje)
```

#### Limitacoes

- Max steps por parallel_group: 5 (prevenir overload)
- Todos os steps do grupo devem ter `requires` satisfeitos ANTES do grupo iniciar
- Se qualquer step do grupo falha, os outros continuam (fail-fast opcional via config)
- Parallel groups nao podem ser aninhados
