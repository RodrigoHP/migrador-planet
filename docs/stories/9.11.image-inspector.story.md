# Story 9.11: Image Inspector Avançado — Upload, Remoção e Gestão de Assets

## Status
InReview

## Story
**As a** operador,
**I want** funcionalidade avançada de gestão de imagens: upload com persistência no servidor, remoção completa (template + tree + assets), validação de formato/tamanho, preview antes de confirmar substituição e detecção de SVG inline,
**so that** eu possa gerenciar os assets visuais do projeto com confiança, sabendo que as alterações são persistidas e validadas.

## Scope Boundary (vs. Stories 6.7 e 7.4)

| Capacidade | 6.7 (Display) | 7.4 (Editing) | **9.11 (Avançado)** |
|------------|---------------|---------------|---------------------|
| Exibir dimensões, escala, alinhamento, fonte | Read-only labels | Inputs editáveis | -- (já coberto) |
| Botões Substituir / Download | Placeholder (desabilitados) | File picker local + download | **Upload para servidor + persistência em assets/** |
| Remover imagem | -- | Botão "Remover do template" genérico (nó) | **Remoção completa: nó + arquivo em assets/ + referências HTML** |
| Validação de arquivo (tipo, tamanho) | -- | -- | **Validação client-side antes do upload** |
| Preview antes de confirmar substituição | -- | -- | **Modal de preview com comparação antes/depois** |
| SVG inline (FR32) | -- | -- | **Detecção de SVG + opção incorporar como SVG inline** |
| Galeria de assets do projeto | -- | -- | **Painel listando todos os assets em assets/** |

> **Regra:** 9.11 NÃO reimplementa display de propriedades (6.7) nem inputs editáveis básicos (7.4). Esta story estende o ImageInspector com funcionalidades server-side, validação e gestão de assets.

## Acceptance Criteria
1. **Upload com persistência**: ao substituir uma imagem via file picker, o arquivo é enviado ao servidor via `POST /api/templates/{template_id}/assets` e armazenado na pasta `assets/` do pacote de template; a referência `<img src="assets/{nome}">` no HTML é atualizada automaticamente.
2. **Remoção completa**: botão "Remover" no ImageInspector remove: (a) o nó da StructureTree, (b) a referência `<img>` do template HTML, (c) o arquivo físico em `assets/` via `DELETE /api/templates/{template_id}/assets/{filename}`; confirmação obrigatória antes de executar.
3. **Validação client-side**: antes do upload, validar: tipo de arquivo (PNG, JPG, WEBP, SVG — outros rejeitados com mensagem), tamanho máximo (5 MB — configurável), dimensões mínimas (10x10 px); exibir mensagem de erro específica para cada violação.
4. **Preview de substituição**: ao selecionar nova imagem no file picker, exibir modal com preview lado a lado (imagem atual vs. nova) com dimensões de ambas; operador confirma ou cancela antes do upload.
5. **SVG inline (FR32)**: quando a imagem selecionada ou extraída é SVG, oferecer toggle "Incorporar como SVG inline" que insere o conteúdo SVG diretamente no `index.html` em vez de referência `<img>`.
6. **Galeria de assets**: seção colapsável no ImageInspector listando todos os arquivos em `assets/` do projeto atual, com thumbnail, nome e tamanho; clicar em um asset seleciona-o como substituição (sem novo upload).
7. `npm run build` passa sem erros.
