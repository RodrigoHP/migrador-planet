# Story 15.2 — Deploy Frontend Vercel

## Story

**Como** equipe de desenvolvimento,
**Quero** o frontend Vue 3 rodando no Vercel com API apontando para o Railway,
**Para** que a aplicação seja acessível publicamente via URL.

## Status

Draft

## Context

### Problema

O frontend roda em `localhost:5173` e usa Vite proxy para `localhost:8000`. Em produção, precisa apontar para a URL real do Railway. Não existe `vercel.json`. SPA routing precisa de fallback para `index.html`.

### Estado Atual do Código

**`frontend/vite.config.ts`** — proxy configurado para dev:
```typescript
server: {
  proxy: {
    '/api': 'http://localhost:8000'
  }
}
```

**`frontend/src/router/index.ts`** — 4 rotas com lazy loading:
- `/` → HomePage
- `/upload` → UploadPage
- `/analyzing` → AnalyzingPage (guard: requires jobId)
- `/editor` → TemplateEditor (guard: requires analysisCompleted)

**API calls** — usam paths relativos (`/api/...`), passando pelo Vite proxy em dev.

### Scope — IN vs OUT

**IN SCOPE:**
- Criar `vercel.json` com SPA rewrites
- Configurar `VITE_API_URL` env var para URL do Railway
- Atualizar API calls para usar `VITE_API_URL` como base (ou manter relativo com Vercel rewrite)
- Configurar Vercel project + env vars
- Validar preview URLs em PRs

**OUT OF SCOPE:**
- Custom domain
- Autenticação (story 15.3)
- SSR/ISR (app é SPA pura)

### Decisão Técnica: API Routing

**Opção recomendada: Vercel Rewrites** — manter API calls relativos (`/api/...`) e usar Vercel rewrites para proxy ao Railway. Zero mudança no código fonte.

```json
{
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://RAILWAY_URL/api/:path*" }
  ]
}
```

## Technical Notes

- Vercel detecta Vue 3 + Vite automaticamente (`framework: vite`)
- Rewrites são preferíveis a env var para evitar CORS issues (same-origin)
- Se usar rewrites, SSE precisa funcionar via proxy (Vercel suporta SSE em rewrites)
- Verificar timeout de rewrites para SSE long-lived connections
