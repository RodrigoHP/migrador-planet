# Story 26.5 — Cost Tracking Calibrado com Dados Reais

## Story
**Como** gestor de custos,
**Quero** que o cost tracking use dados reais de execuções passadas como calibração,
**Para** que o budget guard seja preciso e não aborte workflows desnecessariamente.

## Context

### Problema
A estimativa atual usa `len(text)/4` para tokens e uma fórmula heurística fixa:
```
estimated_cost = (total_tokens * 0.6 * 3 / 1M) + (total_tokens * 0.4 * 15 / 1M)
```
Isso assume 60% input / 40% output e preços fixos. Na prática, a distribuição varia e os preços mudam.

### Design
1. Ao final de cada workflow, registrar nas métricas (26.6): tokens estimados vs custo real (se disponível via API usage)
2. Manter um `calibration_factor` em `engine-config.yaml` que ajusta a heurística
3. Se métricas históricas existem, calcular ratio médio `estimated/real` e aplicar como fator de correção
4. Atualizar preços por modelo na config (ao invés de hardcoded)

## Acceptance Criteria
- [x] Preços por modelo configuráveis em `engine-config.yaml` (não hardcoded)
- [x] Campo `cost.model_pricing` com input/output prices por modelo (opus, sonnet, haiku)
- [x] `calibration_factor` calculado a partir de métricas históricas (de 26.6)
- [x] Se não há histórico, usar fator 1.0 (comportamento atual)
- [x] Budget guard usa custo calibrado em vez do heurístico puro
- [x] Heurística de tokens melhorada: usar ratio diferente para código vs texto natural
