# Story 16.1 — Engine Mode yolo_continuous

## Story
**Como** operador que executa workflows multi-agente (ex: RCA Investigation),
**Quero** que o engine mode tenha um modo `yolo_continuous` que executa todos os steps sequencialmente sem parar para validacao entre cada step,
**Para** que workflows YOLO com delegacao multi-agente rodem de ponta a ponta sem intervencao manual.

## Status
Done

## Context

### Problema

O `run-workflow-engine.md` atual executa **1 step por invocacao** e para para validacao do usuario entre cada step. Isso eh correto para o modo interativo, mas incompativel com workflows YOLO que precisam de execucao continua.

O workflow `rca-investigation.yaml` v3.0 define 6 fases com 5 agentes diferentes (@qa, @sm, @dev, @devops, @architect). No modo YOLO, o usuario espera execucao continua sem paradas. Atualmente, o fallback eh o modo `guided` (persona-switch), que funciona mas nao spawna subagentes reais.

### Referencia

- Engine atual: `.aios-core/development/tasks/run-workflow-engine.md`
- Workflow que requer: `.aios-core/development/workflows/rca-investigation.yaml` → `engine_requirements`
- Template de prompt: `.aios-core/development/templates/subagent-step-prompt.md`

### Design Proposto

Adicionar ao engine um terceiro modo de execucao alem de `start` e `continue`:

```
yolo_continuous: executa TODOS os steps sequencialmente sem parar
```

**Comportamento:**
1. Inicializa state (como `start`)
2. Loop: spawna step → parse output → avanca para proximo (sem STOP)
3. Handoff artifacts gerados automaticamente entre transicoes de agente
4. So para em: erro bloqueante, QA gate REJECT, ou workflow_end
5. QA gate REJECT → loop automatico de volta ao step alvo (sem pedir ao usuario)

**Diferenca do loop atual:**
```
# Hoje (step-by-step):
spawn step → save → STOP → user: continue → load → spawn next → STOP

# yolo_continuous:
spawn step → save → spawn next → save → ... → COMPLETE (ou REJECT loop)
```

### Handoff Automatico

Quando o agente muda entre steps consecutivos, o engine deve:
1. Coletar outputs do step completado
2. Gerar handoff artifact em `.aios/handoffs/` (formato padrao AIOS)
3. Passar outputs via `requires` chain no prompt do proximo subagente
4. Logar transicao no state file

### Controle de Loop (REJECT)

Quando um step com `on_failure` aponta para outro step:
1. Avaliar output do step (ex: `gate_verdict == REJECT`)
2. Encontrar o step alvo no sequence
3. Resetar `current_step_index` para o alvo
4. Continuar execucao (sem parar)
5. Max loops: 3 (configuravel no workflow via `failure_recovery`)

## Implementation Notes

### Subtasks (sequencia de implementacao)

1. **Adicionar action `yolo_continuous`** ao engine — aceitar como parametro, inicializar state com `mode: yolo_continuous`
2. **Modificar Sequence Advancer** — quando `mode == yolo_continuous`, substituir `RETURN (STOP)` por `CONTINUE LOOP`
3. **Implementar deteccao de falha** — o engine detecta falha via:
   - Campo `status: failed` no `step_output` parseado
   - Campo `gate_verdict: REJECT` para steps de QA gate
   - Ausencia de `step_output` apos parse (subagente nao retornou formato esperado)
4. **Implementar handoff generation** — quando `next_step.agent != current_step.agent`, gerar artifact em `.aios/handoffs/`
5. **Implementar loop guard** — contador por `target_step_id`, max 3 (configuravel), ABORT se exceder
6. **Implementar auto-detect YOLO** — ler `execution_modes` do workflow YAML, se default mode eh `yolo` → usar `yolo_continuous` automaticamente
7. **Implementar fallback** — se Task tool nao disponivel, aviso + cair para guided mode
8. **Testar** — validar com workflow de teste (ver secao Validation & Testing)

### Sequence Advancer — Modificacao

O `advance_and_execute` atual faz `RETURN (STOP)` apos cada action step. Para `yolo_continuous`, substituir por `CONTINUE LOOP`:

```
# Dentro do bloco "Action Step":
IF mode == "yolo_continuous":
  # Verificar on_failure conditions
  IF step has on_failure AND output_status in ["failed", "REJECT"]:
    route to on_failure target (max loops check)
    CONTINUE LOOP
  ELSE:
    # Gerar handoff se agente muda
    IF next_step.agent != current_step.agent:
      generate_handoff_artifact(current_step, next_step, outputs)
    index = index + 1
    CONTINUE LOOP  # <-- nao para
ELSE:
  RETURN (STOP — modo step-by-step existente)
```

### Deteccao de Falha

O engine determina se um step falhou verificando o `step_output` parseado:

```
FUNCTION step_failed(parsed_output, step):
  # 1. Status explicito
  IF parsed_output.status == "failed":
    RETURN true
  # 2. QA gate verdict
  IF step.id contains "qa_gate" OR step.id contains "gate":
    IF parsed_output.outputs.gate_verdict == "REJECT":
      RETURN true
  # 3. Parse failure (subagente nao retornou formato)
  IF parsed_output is null:
    RETURN true
  RETURN false
```

### Handoff Artifact Format

```yaml
handoff:
  from_agent: "{current_agent}"
  to_agent: "{next_agent}"
  workflow: "{workflow_id}"
  step_completed: "{step_id}"
  step_next: "{next_step_id}"
  outputs:
    {key}: "{value}"
  timestamp: "{ISO}"
```

### Loop Guard

```yaml
loop_guard:
  max_loops_per_target: 3  # default, overridable by workflow
  current_loops:
    {target_step_id}: {count}
```

## Validation & Testing

### Como validar

1. **Workflow de teste:** Criar um workflow YAML simples com 3 steps e 2 agentes diferentes. Rodar com `yolo_continuous` e verificar que executa sem parar.
2. **Handoff check:** Apos execucao, verificar que `.aios/handoffs/` contem artifacts para cada transicao de agente.
3. **Loop guard:** Criar workflow com step que sempre retorna `status: failed` e `on_failure` apontando para si. Verificar que ABORT acontece apos 3 loops (nao loop infinito).
4. **State recovery:** Interromper execucao (kill) no meio. Verificar que state file existe e `*run-workflow {name} continue --mode=engine` retoma do ponto correto.
5. **Fallback:** Testar em ambiente sem Task tool disponivel. Verificar que cai para guided mode com aviso.

### Cenarios de teste

| # | Cenario | Input | Expected |
|---|---------|-------|----------|
| T1 | Happy path 3 steps | Workflow simples, 2 agentes | Executa tudo, Final Report gerado |
| T2 | QA REJECT + retry | Step com gate_verdict=REJECT | Loop para on_failure target, retry, PASS na 2a |
| T3 | Max loops exceeded | Step que sempre falha | ABORT apos 3 loops com relatorio |
| T4 | Erro bloqueante | Subagente retorna null | ABORT imediato com relatorio |
| T5 | Auto-detect YOLO | Workflow com default mode=yolo | Engine usa yolo_continuous automaticamente |
| T6 | Fallback gracioso | Task tool indisponivel | Guided mode com aviso |
