# Story 14.0 — Visual Data Persistence

## Story

**Como** sistema de auto-fix do editor,
**Quero** que os dados visuais brutos do PDF (drawn_elements, text_blocks) sejam persistidos como artefato auxiliar no StorageGateway,
**Para** que a Story 14.10 (AutoFix: 4 novos fix types) possa comparar elementos visuais do PDF com o CSS gerado, sem inflar o PipelineResult.

## Context

### Problema

A Story 14.10 precisa de 3 tipos de dados visuais brutos do PDF para implementar auto-fix de refinamento:
- **`drawn_elements`** — linhas, retângulos, curvas vetoriais (extraídos por `_extract_drawn_elements()` no Stage 2)
- **`text_blocks`** — blocos de texto com bbox, font_name, font_size, color (extraídos no Stage 2)
- **`filled_rects`** — subset de `drawn_elements` com `type=rect` e `fill_color`

Esses dados **existem no pipeline** — o Stage 2 (Deep Extraction) os extrai e o Stage 5 (Template Generation) os consome para gerar CSS (borders de `drawn_elements[type=line]`, backgrounds de `drawn_elements[type=rect]`). Porém, após o Stage 5 consumir internamente, os dados são **descartados** — não fazem parte do `result_json` (PipelineResult).

### Decisão Arquitetural

**Opção escolhida: Backend-only (persistir como artefato auxiliar)**

Razões:
1. **PipelineResult permanece enxuto** — zero impacto nas 12 outras stories do Epic 14
2. **Dados visuais só são carregados quando auto-fix é acionado** — sob demanda, não em todo page load
3. **StorageGateway já tem a abstração pronta** — seguir o padrão `save_result`/`save_clusters`
4. **Volume estimado: ~20-50KB por job** — impacto desprezível no storage

**Alternativa descartada:** Adicionar `visual_extraction` ao PipelineResult. Descartada porque inflaria o payload JSON para dados usados apenas pelo auto-fix.

## Acceptance Criteria

1. **ABC Extended:** `StorageGateway` tem `save_visual_data(job_id, data) -> None` e `load_visual_data(job_id) -> dict | None` como métodos abstratos
2. **Local Implementation:** `LocalStorageGateway.save_visual_data` persiste como `visual_data.json` no diretório do job; `load_visual_data` retorna o dict ou `None` se não existir
3. **Supabase Implementation:** `SupabaseStorageGateway.save_visual_data` persiste no bucket Storage como `jobs/{job_id}/visual_data.json`; `load_visual_data` baixa e retorna o dict ou `None`
4. **Stage 5.7 Integration:** `_step_5_7_persist` extrai `drawn_elements` e `text_blocks` de `context["enriched_documents"]` e chama `storage.save_visual_data(job_id, data)` após salvar result_json
5. **Data Format:** Dados persistidos seguem a estrutura `{ "pages": [{ "page_index": int, "cluster_id": str, "drawn_elements": list, "text_blocks": list }] }`
6. **Graceful Failure:** Se `save_visual_data` falhar, logar warning e continuar — não bloqueia o pipeline (visual data é auxiliar)
7. **Round-Trip Test:** Testes comprovam que dados salvos via `save_visual_data` são idênticos aos retornados por `load_visual_data`
8. **Sem Regressão:** Todos os testes existentes de StorageGateway e Stage 5 continuam passando

### Padrões a Seguir

**LocalStorageGateway (padrão de `save_result`):**
```python
async def save_visual_data(self, job_id: str, data: dict) -> None:
    job_dir = self._tmp_base / job_id
    job_dir.mkdir(parents=True, exist_ok=True)
    path = job_dir / "visual_data.json"
    path.write_text(json.dumps(data, ensure_ascii=False, indent=2))

async def load_visual_data(self, job_id: str) -> dict | None:
    path = self._tmp_base / job_id / "visual_data.json"
    if not path.exists():
        return None
    return json.loads(path.read_text())
```

**SupabaseStorageGateway (padrão de bucket upload):**
```python
async def save_visual_data(self, job_id: str, data: dict) -> None:
    import json as _json
    path = f"jobs/{job_id}/visual_data.json"
    content = _json.dumps(data, ensure_ascii=False).encode("utf-8")
    await self._supabase.storage.from_("jobs").upload(
        path, content, file_options={"content-type": "application/json"}
    )

async def load_visual_data(self, job_id: str) -> dict | None:
    import json as _json
    path = f"jobs/{job_id}/visual_data.json"
    try:
        raw = await self._supabase.storage.from_("jobs").download(path)
        return _json.loads(raw)
    except Exception:
        return None
```

**Extração de visual data do context:**
```python
def _extract_visual_data(context: dict) -> dict:
    pages = []
    for doc in context.get("enriched_documents", []):
        for page in doc.get("pages", []):
            pages.append({
                "page_index": page.get("page_index"),
                "cluster_id": page.get("cluster_id"),
                "drawn_elements": page.get("drawn_elements"),
                "text_blocks": page.get("text_blocks"),
            })
    return {"pages": pages}
```

**Integração em `_step_5_7_persist` (após save_result):**
```python
# Save visual data (auxiliary — non-blocking)
try:
    visual_data = _extract_visual_data(context)
    if visual_data["pages"]:
        await storage.save_visual_data(job_id, visual_data)
        logger.info("[Stage 5] Visual data persisted for job %s", job_id)
except Exception as exc:
    logger.warning("[Stage 5] Visual data persistence failed (non-blocking): %s", exc)
```
