# Story 19.6 — Minimal Agent Set

## Story
**Como** operador que bootstrapa AIOS em projetos de diferentes tamanhos,
**Quero** que os agents sejam organizados em tiers (core, extended, specialist) e que `aiox init` instale apenas o tier core por default,
**Para** que projetos simples nao carreguem agents desnecessarios e projetos complexos possam escalar conforme necessidade.

## Status
Done

## Context

### Problema

Hoje o AIOS instala todos os agents (~12) independente do tamanho do projeto. Um projeto simples com 1 desenvolvedor nao precisa de @pm, @sm, @po, @analyst, @data-engineer, @ux-design-expert. Esses agents consomem contexto e adicionam complexidade desnecessaria.

### Design

#### Tier definitions

| Tier | Agents | Use Case |
|------|--------|----------|
| **core** | @dev, @qa, @devops | Solo dev, small teams, MVPs |
| **extended** | core + @architect, @pm, @sm, @po | Medium teams, structured process |
| **full** | extended + @analyst, @data-engineer, @ux-design-expert | Large teams, enterprise |

#### Core agents — sempre presentes

- `@dev` — Implementation, git local operations
- `@qa` — Quality gate, code review
- `@devops` — Push, PR, CI/CD

#### Extended agents — processo estruturado

- `@architect` — Design decisions, complexity assessment
- `@pm` — Epic management, requirements
- `@sm` — Story creation
- `@po` — Story validation

#### Specialist agents — dominio especifico

- `@analyst` — Research, reports
- `@data-engineer` — Database, schema, queries
- `@ux-design-expert` — Frontend, UX patterns

#### Integracao com `aiox init`

```
aiox init                    # Instala core (default)
aiox init --tier extended    # Instala core + extended
aiox init --tier full        # Instala todos
```

#### Upgrade de tier

```
aiox init --tier extended    # Em projeto com core → adiciona extended agents
```
