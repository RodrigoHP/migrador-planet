# Story 17.9 — RCA v4.0 Integration

## Story
**Como** operador que utiliza o sistema RCA,
**Quero** que todos os artefatos (skill, workflow, task, guia) sejam atualizados para refletir a arquitetura v4.0 multi-tecnica agent-first,
**Para** que a documentacao, comandos e workflow estejam alinhados e o sistema funcione de ponta a ponta.

## Status
Draft

## Context

### Problema

As stories 17.1-17.8 implementam componentes individuais (Classifier, Archaeologist, Causal Reasoner, etc.). Esta story integra tudo em um sistema coeso, atualizando:
- Skill (`investigate.md`): source of truth da metodologia
- Workflow (`rca-investigation.yaml`): pipeline operacional
- Task (`rca-investigation.md`): wrapper AIOS
- Guia (`rca-investigation-guide.md`): documentacao

### O que muda v3.0 → v4.0

| Aspecto | v3.0 | v4.0 |
|---------|------|------|
| Tecnica | 5 Whys linear | Multi-tecnica adaptativa |
| Primeiro passo | Triagem direta | Classification (Cynefin) |
| Coleta de dados | Manual | Archaeologist automatico |
| Analise causal | 5 Whys (1 cadeia) | Grafo causal AND/OR multi-branch |
| Conhecimento | Anti-patterns manual | Knowledge graph + SOPs auto-gerados |
| Desafio | Nenhum | Hypothesis Challenger adversarial |
| Defesas | Nao analisadas | Barrier Analysis Swiss Cheese |
| Evidencia | Texto livre | Evidence grading E1-E4 |
| Aprendizado | Nenhum | Meta-Learner com trends e alerts |
| Fases workflow | 6 (single technique) | 8+ (adaptive por dominio) |

### Nova Pipeline v4.0

```
Fase 0: CLASSIFY → Classifier Agent (17.1)
  Output: domain, severity, scope, strategy

Fase 1: GATHER → Archaeologist Agent (17.2)
  Output: top_suspects, timeline, blast_radius

Fase 2: MATCH → Pattern Matcher (17.4)
  Output: similar_investigations, suggested_sops
  [Se SOP match com alta confianca: fast track para fix]

Fase 3: ANALYZE → Causal Reasoner (17.3)
  Output: causal_graph (nodes + AND/OR gates)

Fase 4: CHALLENGE → Hypothesis Challenger (17.5)
  Output: confirmed/weakened/refuted hypotheses

Fase 5: BARRIERS → Barrier Analyst (17.6)
  Output: defense_analysis, recommendations

Fase 6: GRADE → Evidence Grading (17.7)
  Output: evidence_levels, confidence_scores

Fase 7: FIX → Stories + Implementacao + Testes
  [Reutiliza fases existentes v3.0: @sm → @dev → @qa]

Fase 8: LEARN → Meta-Learner (17.8)
  Output: knowledge_base_updated, trends, alerts

Fase 9: DELIVER → Push + PR
  [Reutiliza fase existente v3.0: @devops]
```

### Fast Tracks por Dominio

| Dominio | Fases executadas | Fases puladas |
|---------|-----------------|---------------|
| Clear | 0→1→7→8→9 | 2,3,4,5,6 |
| Complicated | 0→1→2→3→5→6→7→8→9 | 4 (challenge leve) |
| Complex | Todas (0-9) | Nenhuma |
| Chaotic | Stabilize → Todas (0-9) | Nenhuma |
