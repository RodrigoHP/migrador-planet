# Story 10.22 — Debt: Remover isinstance guards dead code em stage5

## Story
**Como** desenvolvedor que mantém o pipeline,
**Quero** remover os `isinstance` guards remanescentes em `stage5_template_generation.py` que se tornaram dead code após o fix do RCA,
**Para** que o código reflita o contrato real (document_trees é sempre dict) e não induza futuros desenvolvedores a perpetuar o anti-pattern AP-003.

## Context
O commit `2623d8b` adicionou guards `isinstance(x, dict)` em vários pontos de travessia da árvore dentro de `stage5_template_generation.py` como mitigação do crash `'list' object has no attribute 'get'`. Após o RCA `rca-2026-03-31-stage5-document-trees-contract`, a normalização foi movida para Stage 3 (na fonte). Os guards de stage5 que verificam `isinstance(document_trees, list)` ou similares viraram dead code e mascaram o contrato real, podendo encorajar o anti-pattern novamente.

## Acceptance Criteria

1. **Audit completo** — Identificar todos os `isinstance` guards relacionados a `document_trees` introduzidos pelo commit `2623d8b` em `stage5_template_generation.py`.
2. **Remoção segura** — Remover guards que são dead code após a normalização em Stage 3, mantendo apenas guards que protegem contra inputs genuinamente polimórficos de fontes externas.
3. **Sem regressão** — Todos os testes existentes (incluindo os criados pela story 10.21) continuam passando após a remoção.
4. **Código reflete contrato** — Após a remoção, leituras de `context["document_trees"]` em stage5 não precisam de guard `isinstance`.
