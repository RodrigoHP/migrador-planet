# Story 14.8 — Z-Index Layer Panel + Group/Ungroup (F8 + F7)

## Story
**Como** usuário do editor visual,
**Quero** um painel de camadas (layers) com reordenação por z-index e a capacidade de agrupar/desagrupar elementos,
**Para** controlar a sobreposição visual de elementos e manipular conjuntos de elementos como unidade única.

## Status
Done

## Context

### Problema
O editor possui elementos posicionados com `position:absolute` no canvas, mas não há controle visual de z-index. Quando elementos se sobrepõem (ex: logo Bradesco sobre barra separadora, número "237" sobre fundo de célula), o usuário não consegue reordenar camadas. Além disso, elementos relacionados (ex: 6 células "Data/Número/Espécie/Aceite/Data Processamento/Valor") precisam ser manipulados como grupo para mover/redimensionar proporcionalmente.

### Estado Atual do Código

**`frontend/src/stores/editorStore.ts`**
- `selectedElementId` — seleção única
- `activeLeftTab` — tipo `LeftTab = 'structure' | 'fields' | 'files'` (não inclui 'layers')
- Não existe conceito de layer order ou z-index no store

**`frontend/src/stores/templateStore.ts`**
- `documentTree` — árvore de nós do template
- `updateNode()` — atualiza propriedades de um nó
- `flatNodes` — mapa plano de nós por ID
- `groupNodes(nodeIds, targetParentId)` — já existe função de agrupamento na store, mas opera apenas na árvore (sem z-index, sem propagação de move/resize)

**`frontend/src/composables/useCanvasInteraction.ts`**
- `multiSelection` — `ref<Set<string>>` para seleção múltipla com Ctrl+Click
- `isMultiSelecting` — computed para detectar multi-seleção
- Drag e resize aplicam a todos os `multiSelection`, mas sem conceito de grupo persistente

**`frontend/src/organisms/StructureTree.vue`**
- Tree view no left panel — exibe hierarquia de nós
- Não exibe z-index nem permite reordenação de camadas

**`frontend/src/types/editor.types.ts`**
- `LeftTab = 'structure' | 'fields' | 'files'` — precisa adicionar `'layers'`
- `CenterTab = 'canvas' | 'pdf' | 'code' | 'sync'`

**ElementInspector** — tem campo "layer" (string) mas não há painel visual dedicado.

### Gaps Identificados
1. Nenhum painel de layers no sidebar esquerdo
2. `LeftTab` não inclui opção 'layers'
3. `groupNodes()` agrupa na árvore mas sem propagação de transformações (move/resize)
4. Nenhuma propriedade `zIndex` nos nós do template
5. Sem operações batch (aplicar propriedade a todos do grupo)

### Exemplos de Uso
- **Layer Panel:** Logo Bradesco (z-index: 3) sobre barra separadora (z-index: 2), Número "237" (z-index: 4) sobre fundo de célula (z-index: 1)
- **Group:** 6 células "Data/Número/Espécie/Aceite/Data Processamento/Valor" como grupo — mover grupo inteiro reposiciona todas as 6 células proporcionalmente

## Acceptance Criteria

1. **AC1 — Layer Panel visível:** Aba "Layers" disponível no left sidebar (`LeftTab` inclui `'layers'`), com lista de todos os elementos da página atual ordenados por z-index (maior no topo)
2. **AC2 — Drag-to-reorder:** Arrastar item no Layer Panel altera z-index de todos os elementos afetados e atualiza imediatamente o canvas
3. **AC3 — Botões de camada:** Botões "Bring to Front", "Send to Back", "Move Up", "Move Down" funcionam para o elemento selecionado
4. **AC4 — Seleção sincronizada:** Clicar em item no Layer Panel seleciona o elemento no canvas (e vice-versa); highlight visual no canvas indica a camada selecionada
5. **AC5 — Group:** Selecionar múltiplos elementos (Ctrl+Click ou seleção no Layer Panel) e acionar "Group" cria grupo lógico persistente no `documentTree`
6. **AC6 — Ungroup:** Acionar "Ungroup" em um grupo desfaz o agrupamento, restaurando elementos como independentes
7. **AC7 — Grupo move/resize:** Mover ou redimensionar grupo no canvas aplica transformação proporcional a todos os filhos
8. **AC8 — Operações batch:** Aplicar propriedade (ex: font-size, color, visibility) a um grupo aplica a todos os elementos filhos
9. **AC9 — Persistência:** z-index e grupos são persistidos no `documentTree` e sobrevivem a reload da sessão
10. **AC10 — Testes:** Cobertura mínima 80% para `LayerPanel.vue`, `useLayerOrder.ts`, `useGrouping.ts` com Vitest
11. **AC11 — Regressão canvas:** Interações existentes do canvas (drag, resize, multi-select, snap) permanecem funcionais após integração do Layer Panel e funcionalidades de agrupamento
12. **AC12 — Acessibilidade Layer Panel (keyboard):** Layers navegáveis via Arrow Up/Down. Alt+Arrow Up/Down reordena o layer selecionado (alternativa acessível ao drag). Usa roving tabindex pattern (apenas item focado tem tabindex="0", demais tabindex="-1")
13. **AC13 — Acessibilidade Layer Panel (ARIA):** Container: `role="listbox"`, `aria-label="Camadas do template"`. Items: `role="option"`, `aria-selected`. Grupos: `role="group"`, `aria-expanded`. Visibilidade toggle: `aria-pressed`. Reordenação anunciada via `aria-live="polite"` com texto descritivo (ex: "Logo Bradesco movido para camada 2 de 4")

## Dev Notes

### Referência Arquitetural
- **Stack:** Vue 3 + TypeScript + Pinia + Vitest
- **Layer Panel:** Sidebar esquerdo, nova aba ao lado de Structure/Fields/Files
- **Drag library:** Considerar `vuedraggable` (já no projeto?) ou implementação nativa com HTML5 Drag API
- **z-index range:** Sugerir 1-1000, incrementos de 10 para permitir inserção entre camadas

### Código Existente Reutilizável
- `templateStore.groupNodes()` — base para agrupamento; estender com propagação de transformações
- `useCanvasInteraction.ts` — `multiSelection` para detectar elementos a agrupar
- `CanvasSelectionOverlay.vue` — já usa z-index (99-102) para overlays; evitar conflito
- `StructureTree.vue` — referência para UI de árvore no sidebar

### Considerações de UX
- Layer Panel deve mostrar thumbnail ou ícone do tipo de elemento (texto, imagem, linha, grupo)
- Grupos colapsáveis no painel — clicar em grupo expande/colapsa filhos
- Operação de group/ungroup deve ter undo/redo integrado se disponível
