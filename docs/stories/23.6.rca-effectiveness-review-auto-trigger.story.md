# Story 23.6 — Effectiveness Review: Trigger Automatico

## Story
**Como** sistema de quality assurance,
**Quero** que effectiveness reviews acontecam automaticamente,
**Para** que fixes nao fiquem eternamente com `effectiveness: pending`.

## Status
Done

## Context

### Problema
Ambas RCAs tem `effectiveness: pending`. Effectiveness review deveria rodar apos 7 dias mas nao ha trigger. Depende de alguem lembrar de rodar `*audit-patterns` manualmente.

### Design
Implementar trigger em 2 pontos:

**Trigger 1 — Fase 0 de qualquer nova investigacao:**
```
ANTES de classificar o novo bug:
1. Ler investigations.yaml
2. Filtrar: effectiveness == "pending" E date < (hoje - 7 dias)
3. Para cada pending:
   a. Verificar se mesmos sintomas/tags recorreram (grep no codebase)
   b. SE recorreu: effectiveness = "ineffective"
   c. SE nao recorreu: effectiveness = "effective"  
   d. Atualizar effectiveness_reviewed_at = "{data-atual}"
4. Mostrar resumo: "X investigacoes revisadas inline"
5. Continuar com classificacao do novo bug
```

**Trigger 2 — Documentar cadencia semanal:**
Adicionar ao `*guide` do aios-master:
```
## Cadencia Recomendada
- Semanal: `*audit-patterns` (inclui effectiveness review como Passo 1)
- Mensal: revisar SOPs com needs_review = true
```

## Acceptance Criteria
- [ ] Fase 0 do investigate.md inclui effectiveness review inline
- [ ] Criterios claros: pending > 7 dias = elegivel
- [ ] Output mostra quantas investigacoes revisadas
- [ ] Nao bloqueia investigacao nova (review eh inline, nao gate)
- [ ] Guide do aios-master atualizado com cadencia recomendada

## Scope
**IN:** Fase 0 do investigate.md, guide do aios-master
**OUT:** Cron jobs ou automacao por codigo
