# Story 14.12 — Table Inspector Editável + Box Model + ConditionalStyle Expandido (M3 + M4 + M7)

## Story
**Como** usuário do editor de templates,
**Quero** editar colunas de tabela diretamente no inspector, visualizar o box model de elementos e aplicar estilos condicionais expandidos,
**Para** ter controle granular sobre layout de tabelas, spacing de elementos e regras visuais dinâmicas.

## Status
Done

## Context

### M3 — Table Inspector Editável

**Problema atual:** O `TableInspector.vue` exibe colunas em modo read-only. O bloco de colunas mostra campo, largura e alinhamento mas sem nenhuma possibilidade de edição. O usuário não consegue ajustar largura ou alinhamento de colunas, nem adicionar/remover/reordenar.

**Código atual** (`frontend/src/organisms/inspectors/TableInspector.vue`):
```html
<div v-for="(col, i) in columns" :key="i" class="table-inspector__col-row">
  <span>{{ col.field ?? '—' }}</span>
  <span>{{ col.width ?? '—' }}</span>
  <span>{{ col.align ?? '—' }}</span>
</div>
```

**Solução:** Substituir spans por inputs editáveis para width e align. Adicionar botões de adicionar/remover coluna e drag handle para reordenação.

### M4 — Box Model Visualization

**Problema atual:** O `ElementInspector.vue` mostra position (X, Y) e dimensions (width, height) mas não exibe margin, border e padding de forma visual. O usuário não tem referência visual do spacing real do elemento.

**Solução:** Adicionar componente `BoxModelVisualization.vue` ao `ElementInspector`, estilo Chrome DevTools. Mostrar margin/border/padding com valores numéricos. Valores clicáveis para edição inline. Depende de propriedades F1 (borders) e F11 (padding) que já existem no node.

### M7 — ConditionalStyle Expandido

**Problema atual:** O `ConditionalStyleRule.vue` suporta apenas 4 propriedades CSS:
```typescript
property: 'color' | 'background' | 'image' | 'visibility'
```
Constante `PROPERTIES` em `ConditionalStyleRule.vue`:
```typescript
const PROPERTIES = [
  { value: 'color', label: 'Cor do texto' },
  { value: 'background', label: 'Cor de fundo' },
  { value: 'image', label: 'Imagem' },
  { value: 'visibility', label: 'Visibilidade' },
]
```

**Solução:** Expandir `StyleRule['property']` para incluir `border-color`, `font-weight`, `text-decoration` e `opacity`. Adicionar UI correspondente (color picker para border-color, dropdown para font-weight e text-decoration, slider para opacity). Atualizar `generateStyleBindings()` e `toCssProperty()`.

### Scope Boundaries with Other Stories

> **Important:** The Table Inspector (M3) in this story focuses on the **inspector panel UI** for table column properties (width, alignment, add/remove/reorder columns). It does NOT handle border rendering or border editing at the cell level. **Table Cell Borders** (F2) are covered in **story 14.4**, which deals with the actual border rendering pipeline. This story provides a higher-level table property inspector (column management, column-level styles) — there is no duplication with 14.4's cell border editing.

## Acceptance Criteria

### M3 — Table Inspector Editável
1. **AC1 — Width editável:** Coluna "Largura" do TableInspector é um input numérico editável; alterar o valor dispara `updateNodeProperty` com o novo width
2. **AC2 — Align editável:** Coluna "Alinhamento" do TableInspector é um dropdown (`left|center|right`); alterar dispara `updateNodeProperty`
3. **AC3 — Adicionar coluna:** Botão "+ Coluna" no final da seção Colunas adiciona nova coluna com defaults (`field: ''`, `width: 'auto'`, `align: 'left'`)
4. **AC4 — Remover coluna:** Cada linha de coluna tem botão "×" para remover; confirmação não necessária
5. **AC5 — Reordenar colunas:** Drag handle (⠿) em cada linha permite reordenar via drag-and-drop; ordem atualizada no node

### M4 — Box Model Visualization
6. **AC6 — Visualização:** Componente `BoxModelVisualization.vue` renderiza diagrama box model com 4 camadas (margin → border → padding → content) usando cores distintas
7. **AC7 — Valores numéricos:** Cada lado (top, right, bottom, left) de cada camada exibe o valor numérico atual do node
8. **AC8 — Edição inline:** Clicar em um valor numérico abre input inline; ao sair ou Enter, o valor é persistido via `updateNodeProperty`
9. **AC9 — Integração:** BoxModelVisualization aparece no ElementInspector entre "Dimensões" e "Tipografia"

### M7 — ConditionalStyle Expandido
10. **AC10 — Novas propriedades:** `StyleRule['property']` aceita 8 valores: `color`, `background`, `image`, `visibility`, `border-color`, `font-weight`, `text-decoration`, `opacity`
11. **AC11 — UI border-color:** Color picker (mesmo pattern de `color`/`background`)
12. **AC12 — UI font-weight:** Dropdown com opções: `normal`, `bold`, `lighter`, `bolder`
13. **AC13 — UI text-decoration:** Dropdown com opções: `none`, `underline`, `line-through`, `overline`
14. **AC14 — UI opacity:** Input numérico (0-1, step 0.1) ou range slider
15. **AC15 — generateStyleBindings:** `toCssProperty()` retorna CSS correto para as 4 novas propriedades
16. **AC16 — Backward compat:** Regras existentes com as 4 propriedades originais continuam funcionando sem migração

### Acessibilidade
20. **AC20 — Acessibilidade BoxModel:** Cada valor editável usa `role="spinbutton"` com `aria-label` contextual (ex: "margin top"), `aria-valuenow`, `aria-valuemin="0"`. Labels textuais ("margin", "border", "padding", "content") visíveis dentro de cada camada. Tab navega entre os 16 valores no sentido horário (top→right→bottom→left por camada). Arrow Up/Down incrementa/decrementa em 1, Shift+Arrow em 10.
21. **AC21 — Acessibilidade TableInspector:** Container: `role="grid"`, `aria-label="Colunas da tabela"`. Width inputs: `aria-label="Largura da coluna {campo}"`. Align dropdowns: `aria-label="Alinhamento da coluna {campo}"`. Remove buttons: `aria-label="Remover coluna {campo}"`. Alt+Arrow Up/Down reordena coluna (alternativa ao drag). Mudanças anunciadas via `aria-live="polite"`.

### Testes

18. **AC18 — Testes BoxModel:** Testes para renderização do diagrama, edição inline de valores

### Box Model CSS Reference
```
┌─────────────── margin ───────────────┐
│  ┌────────── border ──────────────┐  │
│  │  ┌─────── padding ─────────┐   │  │
│  │  │  ┌──── content ─────┐   │   │  │
│  │  │  │   width × height │   │   │  │
│  │  │  └──────────────────┘   │   │  │
│  │  └─────────────────────────┘   │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```
Cores sugeridas (como Chrome DevTools):
- margin: `hsla(30, 100%, 50%, 0.3)` (laranja)
- border: `hsla(50, 100%, 50%, 0.3)` (amarelo)
- padding: `hsla(120, 60%, 40%, 0.3)` (verde)
- content: `hsla(210, 80%, 55%, 0.3)` (azul)

### Drag-and-Drop para Colunas
Usar HTML5 Drag API nativa (evitar dependência nova). Pattern:
```typescript
function onDragStart(e: DragEvent, fromIdx: number) { ... }
function onDragOver(e: DragEvent) { e.preventDefault() }
function onDrop(e: DragEvent, toIdx: number) { ... }
```

### ConditionalStyle — Template Routing
Atualizar o `v-if`/`v-else-if` chain no ConditionalStyleRule.vue para as novas propriedades:
- `border-color` → mesmo template de `color`/`background` (color picker)
- `font-weight` → dropdown (como `visibility`)
- `text-decoration` → dropdown (como `visibility`)
- `opacity` → input number (template `v-else` existente pode servir, mas com min/max/step)
