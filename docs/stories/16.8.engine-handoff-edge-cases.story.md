# Story 16.8 — Handoff Edge Cases & Robustez

## Story
**Como** operador que executa workflows multi-agente com transicoes frequentes,
**Quero** que o engine trate edge cases de handoff: same-agent steps, falha de escrita, contexto intermediario, e cleanup de artifacts duplicados,
**Para** que handoffs sejam confiaveis e nao percam contexto critico entre transicoes.

## Status
Done

## Context

### Problema

O engine gera handoff artifacts quando `next_step.agent != current_step.agent`. Porem, varios edge cases nao sao tratados:

1. **Same-agent steps consecutivos**: @qa executa 5 steps seguidos. No handoff para @sm, apenas o output do ultimo step eh passado — outputs intermediarios sao perdidos
2. **Falha de escrita**: Se o handoff nao puder ser escrito (permissoes, disco cheio), falha eh silenciosa — workflow continua sem handoff
3. **Truncamento cego**: Max 500 chars trunca sem criterio — pode cortar informacao critica no meio
4. **Artifacts duplicados**: Loop guard causa retry que gera multiplos handoffs para a mesma transicao — clutter sem cleanup
5. **Primeiro step**: Nao recebe contexto de "antes do workflow" (trigger info, user input)

### Referencia

- Engine: `.aios-core/development/tasks/run-workflow-engine.md` (v3.0, handoff generation)
- Handoff protocol: `.claude/rules/agent-handoff.md` (max 500 chars)

### Design Proposto

**Same-agent context accumulation:**
- Quando agent nao muda, acumular summaries dos outputs no state
- No handoff, incluir `prior_steps_same_agent[]` com summaries de todos os steps do mesmo agente

**Write failure handling:**
- Try/catch no write de handoff
- Se falha: log warning, registrar em `state.handoff_write_failures[]`, continuar workflow

**Smart truncation:**
- Truncar por campo (preservar keys), nao por bloco
- Cada campo max ~100 chars, priorizar campos referenciados em `requires` downstream

**Cleanup:**
- Ao final do workflow (ou abort), remover handoff artifacts de retry loops, manter apenas o ultimo por transicao

**Initial context:**
- Primeiro step recebe handoff sintetico com: workflow trigger, user input, timestamp

## Acceptance Criteria

- [ ] AC1: Handoff para agente diferente inclui `prior_steps_same_agent[]` com summaries de steps intermediarios
- [ ] AC2: Falha de escrita de handoff eh logada como warning e registrada em `state.handoff_write_failures[]`
- [ ] AC3: Falha de escrita NAO aborta o workflow (graceful degradation)
- [ ] AC4: Truncamento preserva keys de todos os campos e prioriza campos referenciados em requires downstream
- [ ] AC5: Cleanup de handoff artifacts duplicados executado ao final do workflow (manter ultimo por transicao)
- [ ] AC6: Primeiro step recebe initial context com trigger info e user input
- [ ] AC7: State field `handoff_write_failures[]` registrado para audit
- [ ] AC8: Execution log registra `handoff_write_failed` quando falha ocorre

## Risks

- Acumulacao de same-agent summaries pode crescer significativamente em workflows com muitos steps do mesmo agente (ex: 10 steps @dev). Mitigacao: limitar a 5 summaries acumulados, mais antigos descartados.
- Smart truncation pode perder informacao critica se campo referenciado em requires downstream eh truncado. Mitigacao: campos em requires tem prioridade e recebem quota maior no truncamento.
