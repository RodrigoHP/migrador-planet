# Story 15.6 — Remove Old 28-Stage Pipeline + Dead Code Audit

## Story

**Como** desenvolvedor do projeto,
**Quero** remover o pipeline antigo de 28 stages e código morto associado,
**Para** reduzir confusão, manter o codebase limpo, e evitar que futuros devs confundam pipeline v1 com v2.

## Status

Draft

## Context

### Problema

O Epic 13 redesenhou o pipeline de 28 stages → 5 stages. Porém o código antigo ainda existe:
1. `models/pipeline.py` (202 lines): `StageRegistry`, `BlockDefinition`, `StageDefinition`, `build_default_registry()` com 8 blocks e 28 stages
2. `services/stages/register_all.py` (243 lines): `register_all()` que registra os 28 stages no `StageRegistry`
3. 31 helper files em `services/stages/` — alguns usados pelo pipeline v2 (5 stages), outros são dead code do v1
4. `main.py` (line 14): chama `register_all()` na startup

O pipeline v2 usa `pipeline_orchestrator_v2.py` que **não usa** o `StageRegistry`. Ele chama diretamente `stage1_layout_clustering.py` a `stage5_template_generation.py`.

### Estado Atual do Código

**`backend/models/pipeline.py`** (202 lines):
- Lines 1-40: `PipelineDefinition`, `StageDefinition`, `BlockDefinition` classes
- Lines 42-136: `StageRegistry` class (register, get, build, remove)
- Lines 138-196: `build_default_registry()` — 8 blocks, 28 stages
- Line 202: `default_registry = build_default_registry()` — module-level singleton

**`backend/services/stages/register_all.py`** (243 lines):
- 9 `register_blocoN()` functions que registram stages no `StageRegistry`
- `register_all()` master function (line 231)
- Called from `main.py` at startup

**`backend/services/pipeline_orchestrator_v2.py`** (397 lines):
- Pipeline v2 que chama stage1-5 diretamente
- **Não importa** `StageRegistry` nem `register_all`

### Scope — IN vs OUT

**IN SCOPE:**
- Remover `StageRegistry`, `BlockDefinition`, `build_default_registry()` de `models/pipeline.py`
- Remover `register_all.py` inteiro
- Remover chamada `register_all()` de `main.py`
- Auditar cada um dos 31 helper files em `stages/`:
  - Se importado por stage1-5: MANTER
  - Se não importado por nenhum stage ativo: REMOVER
- Corrigir imports quebrados
- Validar com grep que nenhum import referencia entidades removidas

**OUT OF SCOPE:**
- Refactor dos 5 stages ativos
- Mover `_deprecated/` directory
- Mudanças em testes dos 5 stages (devem passar sem modificação)

## Technical Notes

- **Auditoria de helpers:** Usar `grep -r "from.*stages.*import" backend/services/stages/stage[1-5]*.py` para identificar quais helpers são usados.
- **Cuidado:** Alguns helpers podem ser importados por testes, não por stages. Testes que importam helpers removidos precisam ser atualizados.
- **`models/pipeline.py`:** Pode manter `PipelineDefinition` se usada como Pydantic schema em responses.
