# Story 16.9 — Global Workflow Limits

## Story
**Como** operador que executa workflows autonomos,
**Quero** que o engine tenha limites globais de duracao e custo estimado que abortam automaticamente ao serem excedidos,
**Para** que workflows runaway nao consumam recursos indefinidamente sem meu conhecimento.

## Status
Done

## Context

### Problema

O engine tem loop guard por step (max 3 retries) e timeout por step (Story 16.2), mas nao tem limites globais. Um workflow pode rodar por horas/dias se:
- Cada step completa dentro do timeout individual
- Loop guard nunca eh atingido (steps diferentes)
- Muitos steps no workflow (10+ fases)

Resultado: custo acumulado (tokens API) sem limite, duracao sem teto.

### Referencia

- Engine: `.aios-core/development/tasks/run-workflow-engine.md` (v3.0)
- Token tracking: Story 16.3 (prerequisito — fornece dados de consumo)
- Step timeout: Story 16.2 (prerequisito — fornece timeout individual)

### Design Proposto

**Limites configuráveis no workflow YAML:**
```yaml
execution_constraints:
  max_workflow_duration_hours: 4    # default: 4h
  max_estimated_cost_usd: 10.0     # default: $10 (estimativa)
  warn_at_percent: 80              # warning ao atingir 80%
```

**Checks executados antes de cada step:**
```
FUNCTION check_workflow_limits(state):
  elapsed = now() - state.started_at
  IF elapsed > max_duration: ABORT "duration_limit"
  IF elapsed > max_duration * warn_percent AND not warned:
    emit warning

  cost = estimate_cost(state.token_tracking.total_estimated)
  IF cost > max_cost: ABORT "budget_exceeded"
  IF cost > max_cost * warn_percent AND not warned:
    emit warning
```

**Estimativa de custo:** heuristica baseada em tokens (input ~$3/1M, output ~$15/1M para Opus).

## Acceptance Criteria

- [ ] AC1: Workflow YAML aceita bloco `execution_constraints` com `max_workflow_duration_hours` e `max_estimated_cost_usd`
- [ ] AC2: Defaults aplicados quando nao configurado: 4h duracao, $10 custo
- [ ] AC3: Check executado antes de cada step spawn em `yolo_continuous`
- [ ] AC4: Warning emitido ao atingir 80% de duracao ou custo (configuravel via `warn_at_percent`)
- [ ] AC5: Exceder limite causa ABORT com relatorio "duration_limit" ou "budget_exceeded"
- [ ] AC6: Estimativa de custo baseada em `state.token_tracking.total_estimated` (requer Story 16.3)
- [ ] AC7: Final Report inclui secao "Resource Usage" com duracao total e custo estimado
- [ ] AC8: Em step-by-step, warnings sao emitidos mas nao abortam (usuario decide)

## Complexity

**T-shirt size:** S (Small)
**Estimativa:** Check pre-step, calculo de custo heuristico, warnings e abort conditions.

## Scope

**IN:**
- `.aios-core/development/tasks/run-workflow-engine.md` — limites globais, warnings, abort conditions
- Heuristica de custo (tokens → USD estimado)
- State fields: `execution_constraints`, `warnings_issued`

**OUT:**
- Nao implementar billing real (apenas estimativa)
- Nao implementar rate limiting (futuro)
- Nao alterar workflows existentes (campos opcionais)

## Risks

- Estimativa de custo (heuristica tokens→USD) pode divergir significativamente do custo real, causando abort prematuro ou falha em detectar gasto excessivo. Mitigacao: defaults conservadores ($10), facilmente configuravel por workflow, e heuristica baseada em precos publicados da API.
- Max duration de 4h pode ser insuficiente para workflows complexos legitimos (ex: brownfield-discovery com 10 fases). Mitigacao: configuravel por workflow via `execution_constraints`.
