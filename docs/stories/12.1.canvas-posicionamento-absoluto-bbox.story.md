# Story 12.1 — Canvas: posicionamento absoluto via bbox no template draft

## Story
**Como** usuário do editor,
**Quero** ver os elementos do documento posicionados corretamente no canvas,
**Para** que o canvas represente visualmente o layout real do PDF original.

## Status
Done

## Context

### Problema
O canvas atual mostra todos os elementos empilhados no topo em layout de fluxo normal (block/inline). Isso ocorre porque o `template_draft.py` (Stage 27) gera HTML sem `position: absolute` e sem as coordenadas bbox convertidas para pixels CSS.

### Estado Atual do Código
**`backend/services/stages/template_draft.py`**

Função `_bbox_to_style()` existe mas NÃO é aplicada a todos os elementos:
```python
def _bbox_to_style(bbox, page_width=595, page_height=842):
    SCALE_X = 794 / page_width   # pontos PDF → pixels CSS (794px = A4 em 96dpi)
    SCALE_Y = 1123 / page_height
    x = bbox[0] * SCALE_X
    y = bbox[1] * SCALE_Y
    w = (bbox[2] - bbox[0]) * SCALE_X
    h = (bbox[3] - bbox[1]) * SCALE_Y
    return f"position:absolute;left:{x:.1f}px;top:{y:.1f}px;width:{w:.1f}px;height:{h:.1f}px"
```

Função `_generate_field_element()` gera:
```html
<div class="field-group">
  <span class="field-label">Nome:</span>
  <span class="field-value" data-bind="text: customer.name">VALE CORES</span>
</div>
```
**Sem `position:absolute`, sem `style` com bbox.**

### Causa do Problema
`_generate_html()` itera `field_mappings` e chama `_generate_field_element()`, mas:
1. `has_positioned = bbox is not None` — o check existe
2. `if has_positioned: style = _bbox_to_style(bbox)` — mas não é adicionado ao HTML output
3. O template de CSS gerado usa `.page { position: relative }` mas os filhos não são absolutamente posicionados

### Solução Necessária

Modificar `_generate_html()` e `_generate_field_element()` para:

1. **Página container:** `<div class="page" data-page="N" style="position:relative;width:794px;height:1123px;overflow:hidden">`

2. **Elemento com bbox:**
```html
<span
  data-node-id="{block_id}"
  data-xsd-path="{xsd_path}"
  data-status="{mapped|unmapped|ambiguous}"
  style="position:absolute;
         left:{x}px;top:{y}px;
         width:{w}px;height:{h}px;
         font-family:{font_name};
         font-size:{font_size}pt;
         white-space:nowrap;overflow:hidden;
         line-height:1.2"
  data-bind="text: {xsd_path}">
  {extracted_text}
</span>
```

3. **Elemento sem bbox (fallback):** Manter layout de fluxo com classe `unpositioned`

4. **Escala para PDFs não-A4:** Usar as dimensões reais da página (`page_width`, `page_height` do contexto)

5. **Garantir que `data-node-id` existe:** Para permitir que o inspector selecione pelo DOM

### Impacto em Outros Componentes
- `HTMLCanvas.vue` — Já usa iframe, não precisa mudar
- `useCanvasInteraction.ts` — Precisará do `data-node-id` para drag & drop (veja Story 12.7)
- `templateStore.ts` — `flatNodes` precisará ser indexado por `data-node-id`
- `InspectorPanel.vue` — Seleção via clique usará `data-node-id`

## Technical Notes

### Conversão de coordenadas PDF → CSS
```
PDF usa pontos (1pt = 1/72 inch)
A4 em pontos: 595 × 842 pt
A4 em pixels (96dpi): 794 × 1123 px

SCALE_X = 794 / page_width_pts   (page_width de cada página, não hardcoded)
SCALE_Y = 1123 / page_height_pts

css_x = pdf_x0 * SCALE_X
css_y = pdf_y0 * SCALE_Y  (origem PDF é bottom-left; CSS é top-left)
```

**Atenção:** PDF tem origem Y na parte INFERIOR da página. CSS tem origem no TOPO.
Conversão: `css_y = (page_height_pts - pdf_y1) * SCALE_Y`

### Data Attributes para Interatividade
```html
data-node-id="block-uuid-aqui"      → para drag, inspect, coverage
data-xsd-path="customer.name"       → para binding display
data-status="mapped|unmapped"       → para cobertura visual
data-page="1"                       → para multi-página
```
