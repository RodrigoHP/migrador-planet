# Story 20.7 — Trend Analysis com Threshold Adaptativo

## Story
**Como** time de qualidade,
**Quero** que trends sejam gerados a partir de 2+ investigacoes (nao 3+) com analise por area, tipo, dominio e MTTR,
**Para** detectar tendencias mais cedo em projetos com historico curto.

## Status
Draft

## Context

### Problema
A Fase 9 (Meta-Learning) exige 3+ investigacoes para gerar trends. Com 2 RCAs apontando para mesma area e mesmo tipo de erro, ja eh suficiente para detectar tendencia. O threshold rigido atrasa a deteccao.

### Design
- Reduzir threshold para 2+ investigacoes
- Analise por 4 dimensoes: area (diretorio), tipo (tag), dominio Cynefin, MTTR
- Strategy scorecard: classifier acertou? archaeologist encontrou suspect no top 3?
- Se 2+ RCAs mesma area/tag: recomendar audit focado

## Acceptance Criteria
- [ ] Trends gerados a partir de 2+ investigacoes (threshold adaptativo por tamanho do historico)
- [ ] Analise por 4 dimensoes: area, tipo de erro, dominio, MTTR
- [ ] Se 2+ RCAs apontam para mesma area/tag: recomendacao de audit focado
- [ ] MTTR tracking: tempo entre sintoma reportado e fix (se dados disponiveis)
- [ ] Output integrado ao relatorio da Fase 9
- [ ] Strategy scorecard: classifier acertou dominio? archaeologist encontrou suspect no top 3?

## Scope
**IN:** investigate.md (Fase 9), schema investigations.yaml
**OUT:** Dashboard visual de trends
