# Story 15.16 — Fix "_job" ausente do context: checkpoints de falha inoperantes

## Story
**Como** operador que monitora a execução do pipeline,
**Quero** que o mecanismo de checkpoint (`handle_service_failure`) funcione corretamente nos Stages 1 e 3,
**Para** poder decidir retry/abort quando um serviço falha, em vez de ficar aguardando timeout de 300s.

## Status
Done

## Context

### Problema

`run_pipeline_v2()` inicializa o context sem incluir o objeto `job`:

```python
# pipeline_orchestrator_v2.py — run_pipeline_v2()
context: Dict[str, Any] = {
    "_storage": storage,
    "_current_stage": 0,
    "_current_stage_name": "",
    "pdf_documents": pdf_documents,
    "xsd_path": xsd_path,
    "job_id": job.get("job_id", ""),
    # ⚠️ FALTANDO: "_job": job
}
```

Stages 1 e 3 fazem `context.get("_job")` para acionar `handle_service_failure`:

```python
# stage1_layout_clustering.py
job = context.get("_job", {})  # → {} (dict vazio, não o job real)

# stage3_structural_analysis.py
job = context.get("_job")  # → None
if job is not None:
    decision = await handle_service_failure(...)  # → NUNCA chamado
```

### Consequências
- **Stage 1:** `handle_service_failure` é chamado com `job = {}` vazio — sem `event_log`, sem SSE. Checkpoints ficam presos aguardando timeout de 300s.
- **Stage 3:** `handle_service_failure` nunca é chamado em caso de falha do Vision API — pipeline vai direto para fallback sem dar ao operador a opção de retry/abort.

### Fix
Adicionar `"_job": job` ao dict de inicialização do context em `run_pipeline_v2()`.

## Acceptance Criteria

1. `context.get("_job")` em Stage 1 e Stage 3 retorna o dict do job com `event_log`, `new_event`, `status`
2. `handle_service_failure` no Stage 3 recebe o job correto e consegue emitir eventos SSE
3. Teste unitário para `run_pipeline_v2()` verifica que `"_job"` está presente no context passado para os stages

## Scope

### IN
- Adicionar `"_job": job` ao context em `run_pipeline_v2()`
- Adicionar/atualizar teste unitário para verificar a presença de `_job` no context

### OUT
- Não alterar os stages 1, 3 nem a lógica de `handle_service_failure`
- Não alterar o contrato do context além desta chave
