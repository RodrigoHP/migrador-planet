# Story 31.4 — Enviar codeStore.fileContents para export

## Story
**Como** operador usando o editor de templates,
**Quero** que minhas edições no Monaco Editor sejam preservadas no ZIP exportado,
**Para** que o template reflita exatamente o que editei.

## Status
Done

## Acceptance Criteria

- [x] AC1: useExport envia codeStore.fileContents como code_overrides no payload
- [x] AC2: Se usuário editou HTML/CSS/JS no Monaco, essas versões prevalecem no ZIP
- [x] AC3: Se não houve edição, o conteúdo gerado pelo pipeline é usado

## Scope

**IN:**
- Modificar useExport para usar codeStore.fileContents diretamente no ZIP
- Bypass da chamada /api/generate quando codeStore tem conteúdo

**OUT:**
- Alterar backend

## Tasks

- [x] Task 1: useExport usa codeStore.fileContents diretamente no ZIP
- [x] Task 2: Fallback para /api/generate quando codeStore está vazio/default
- [x] Task 3: Testes unitários

## Dev Notes
Solução mais simples: useExport já tem acesso ao codeStore (via Pinia).
Em vez de chamar /api/generate e depois colocar no ZIP, podemos usar
diretamente codeStore.fileContents.html/css/js + generationStore.templateDraft
como fonte primária, e só chamar /api/generate se o codeStore estiver vazio.

Isso resolve C5 completamente: edições Monaco SEMPRE prevalecem.
