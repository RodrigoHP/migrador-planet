# Story 15.1 — Deploy Backend Railway + CORS Dinâmico

## Story

**Como** equipe de desenvolvimento,
**Quero** o backend FastAPI rodando no Railway com CORS configurável via env var,
**Para** que a API seja acessível publicamente e o frontend em produção possa se conectar.

## Status

Done

## Context

### Problema

O backend roda exclusivamente em `localhost:8000`. CORS está hardcoded para `http://localhost:5173` em `backend/main.py` (lines 27-33). O path `/tmp/jobs` está hardcoded em `routers/analyze.py` (line 60). Não existe `Procfile`. O spaCy model `pt_core_news_lg` precisa ser baixado durante o build.

### Estado Atual do Código

**`backend/main.py`** (lines 27-33):
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**`backend/routers/analyze.py`** (line 60):
```python
TMP_BASE = Path("/tmp/jobs")
```

**`backend/routers/upload.py`** (line 13):
```python
TMP_BASE = Path(os.environ.get("JOBS_DIR", "/tmp/jobs"))  # já usa env var!
```

### Scope — IN vs OUT

**IN SCOPE:**
- Criar `Procfile` na raiz do projeto
- CORS dinâmico via `ALLOWED_ORIGINS` env var (comma-separated, fallback para localhost)
- Unificar `TMP_BASE` em `analyze.py` para usar env var como `upload.py` já faz
- Configurar Railway project + env vars
- Garantir spaCy model download no build
- Validar SSE funciona pelo Railway proxy

**OUT OF SCOPE:**
- Autenticação (story 15.3)
- Redis (story 15.4)
- Frontend deploy (story 15.2)
- Custom domain

## Technical Notes

- Railway suporta Python nativo via nixpacks — detecta `requirements.txt` automaticamente
- SSE requer que Railway não feche connections idle. Railway suporta SSE nativamente.
- spaCy model: `python -m spacy download pt_core_news_lg` no build command ou `Procfile` release phase
- Railway fornece `$PORT` automaticamente
