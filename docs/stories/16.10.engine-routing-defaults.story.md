# Story 16.10 — Routing Defaults & Fallback

## Story
**Como** operador que executa workflows com decision steps em `yolo_continuous`,
**Quero** que o engine tenha routing defaults e fallback automatico quando condicoes nao podem ser avaliadas,
**Para** que workflows autonomos nunca fiquem bloqueados em decision points indefinidos.

## Status
Draft

## Context

### Problema

O Decision Router avalia condicoes como `based_on_score_9p` e roteia para steps diferentes. Porem:

1. **Valor referenciado ausente**: campo nunca foi computado por step anterior → condicao nao avaliavel
2. **Nenhuma rota match**: valor existe mas nao se encaixa em nenhum threshold declarado
3. **Ambiguidade**: multiplas rotas matcham mas nenhuma tem prioridade definida

No modo step-by-step, o engine pede ao usuario para decidir. Em `yolo_continuous`, isso contradiz a promessa de zero stops — o workflow bloqueia.

### Referencia

- Engine: `.aios-core/development/tasks/run-workflow-engine.md` (v3.0, Decision Router)
- Workflow routing: campo `routing` com `condition` e `routes[]`

### Design Proposto

**Default route** — novo campo `default: true` em uma rota:
```yaml
routing:
  condition: based_on_score_9p
  routes:
    - name: simple_flow
      threshold: "< 9"
      target_step: implement_and_test
    - name: complex_flow
      threshold: ">= 9"
      target_step: architect_review
    - name: fallback
      default: true
      target_step: implement_and_test
```

**Fallback chain em `yolo_continuous`:**
```
1. Avaliar condicao normalmente
2. Se valor ausente → usar rota `default: true`
3. Se nenhuma rota match → usar rota `default: true`
4. Se nao ha rota default → usar primeira rota + log warning
5. Se nenhuma rota existe → ABORT "routing_undefined"
```

**Dependency check pre-routing:**
```
FUNCTION pre_routing_check(routing_step, state):
  required_values = extract_dependencies(routing_step.condition)
  FOR each value in required_values:
    IF value not in state.step_outputs:
      Log warning: "Routing dependency missing: {value}"
      RETURN use_default_route()
```

## Acceptance Criteria

- [ ] AC1: Routing steps aceitam campo `default: true` em uma rota (designa fallback)
- [ ] AC2: Em `yolo_continuous`, valor ausente usa rota default automaticamente (sem parar)
- [ ] AC3: Em `yolo_continuous`, nenhuma rota match usa rota default automaticamente
- [ ] AC4: Se nao ha rota default e nenhuma match, usa primeira rota com log warning
- [ ] AC5: Se nao ha nenhuma rota definida, ABORT com "routing_undefined"
- [ ] AC6: Dependency check pre-routing valida que valores referenciados existem no state
- [ ] AC7: Em step-by-step, comportamento existente mantido (pergunta ao usuario)
- [ ] AC8: Execution log registra `routing_fallback` quando default/primeira rota eh usada
- [ ] AC9: Final Report inclui routing decisions tomadas e se fallback foi usado

- Nao implementar routing complexo (AND/OR conditions) — futuro
