# Story 10.7: Bug — Pipeline executa com stubs vazios

## Status
Ready for Review

## Story
**As a** operador,
**I want** que a tela de análise processe os arquivos de verdade,
**so that** o editor abra populado com dados reais do pipeline após a análise.

## Acceptance Criteria
1. `backend/main.py` importa e chama `register_all()` de `services.stages.register_all` na inicialização, antes de qualquer request ser atendido
2. Ao submeter uma análise, a tela de progresso exibe os 28 stages levando tempo condizente com processamento real (> 1s total)
3. Após conclusão da análise, o editor abre com dados reais: document tree, field mappings, confidence scores, layout types e template draft populados
4. `pytest backend/` passa sem erros após a alteração
5. Não há regressão nos endpoints existentes (`/api/health`, `/api/upload`, `/api/analyze`, `/api/analyze/{id}/progress`, `/api/analyze/{id}/result`)

## Bugs Identificados

### Bug 1 — CRÍTICO: Pipeline executa stubs em vez de implementações reais
- **Causa:** `backend/services/stages/register_all.py` contém `register_all()` que registra todas as 28 implementações reais no `default_registry`, mas essa função **nunca é importada nem chamada** em `backend/main.py`
- **Sintoma 1:** Tela de análise passa pelos 28 stages em milissegundos (stubs fazem `await asyncio.sleep(0)` e retornam `{}`)
- **Sintoma 2:** Editor abre completamente vazio — todas as stores (templateStore, mappingStore, confidenceStore, coverageStore, layoutStore, generationStore) recebem dados vazios
- **Arquivo afetado:** `backend/main.py` (falta import + chamada)
- **Arquivo correto:** `backend/services/stages/register_all.py` (função `register_all()` já existe e está correta)
- **Fix:** Adicionar após os imports existentes em `main.py`:
  ```python
  from services.stages.register_all import register_all
  register_all()
  ```
- **Posição correta:** Após `load_dotenv()`, antes de `app = FastAPI(...)`

## Dev Notes
- O fix já foi aplicado nesta sessão de desenvolvimento (2026-03-19)
- `register_all()` deve ser chamado **após** `load_dotenv()` pois algumas stages podem usar variáveis de ambiente ao importar
- **NÃO** chamar `register_all()` dentro de `@app.on_event("startup")` — deve ser no nível de módulo para garantir registro síncrono antes do primeiro request
- O `default_registry` é instância singleton importada de `backend/models/pipeline.py` — todos os routers que usam o pipeline já referenciam esse mesmo objeto
- Stages com dependências externas (OpenRouter, PyMuPDF) podem falhar se configuração estiver ausente — isso é comportamento esperado, não regressão deste fix
