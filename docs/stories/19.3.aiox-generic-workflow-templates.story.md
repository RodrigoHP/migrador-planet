# Story 19.3 — Generic Workflow Templates

## Story
**Como** operador que adota AIOS em projetos com tech stacks variados,
**Quero** versoes genericas dos workflows SDC e RCA que nao assumam tecnologias especificas (Vue, FastAPI, Supabase, Vitest),
**Para** que os workflows funcionem out-of-the-box em qualquer projeto independente do stack.

## Status
Draft

## Context

### Problema

Os workflows atuais contem referencias diretas a tecnologias do migrador-planet:
- `story-development-cycle.yaml` — referencias a Vitest para testes, Vue para frontend, FastAPI para backend
- `rca-investigation.yaml` — exemplos com Supabase, patterns especificos do projeto

Isso significa que ao usar AIOS em um projeto Python/Django ou Rust/Axum, os workflows geram instrucoes incorretas ou irrelevantes.

### Design

#### Genericizacao do SDC

Substituir referencias hardcoded por template variables:
- `Vitest` → `{{TEST_FRAMEWORK}}` (resolvido via project-context)
- `Vue` → `{{FRONTEND_FRAMEWORK}}` (ou removido se nao aplicavel)
- `FastAPI` → `{{BACKEND_FRAMEWORK}}` (ou removido se nao aplicavel)
- `Supabase` → `{{DATABASE}}` (ou removido se nao aplicavel)

#### Genericizacao do RCA

- Remover exemplos tech-specific
- Usar exemplos genericos (file not found, test failure, build error)
- Parametrizar ferramentas de analise (test runner, linter, type checker)

#### Backward Compatibility

- Workflows existentes no migrador-planet continuam funcionando
- Template variables sao resolvidas via `project-context.yaml` (Story 19.5)
- Se template variable nao resolvida, usa placeholder generico ("your test framework")
