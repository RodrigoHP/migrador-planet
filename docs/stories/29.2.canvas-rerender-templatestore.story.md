# Story 29.2 — Canvas Re-render via templateStore

## Story
**Como** operador editando um template,
**Quero** que qualquer mudança que faço na árvore de estrutura, no inspector ou arrastando elementos no canvas seja refletida imediatamente no canvas visual,
**Para** ter feedback em tempo real das minhas edições sem precisar recarregar a página.

## Status
InReview

## Business Value
O loop de edição visual está completamente quebrado — arrastar um elemento não move nada visualmente, editar uma propriedade não reflete no canvas. Isso torna o editor inutilizável para trabalho real. Esta story restaura o feedback visual fundamental que qualquer editor de templates precisa ter.

**Estimativa:** 3 story points

## Scope
**IN:**
- Watcher em `HTMLCanvas.vue` para mutações do `templateStore`
- Mecanismo de trigger de re-render conforme ADR 29.1 (Opção A ou B)
- `endDrag()` e `endResize()` em `useCanvasInteraction.ts` disparam re-render
- Debounce para evitar re-renders duplicados
- Testes em `HTMLCanvas.spec.ts`

**OUT:**
- Geração de HTML do zero no frontend (escopo do ADR 29.1)
- Sincronização do Code Editor com a árvore (escopo de 29.3)
- Mudanças no backend além do endpoint de regeneração (se Opção A)

## Risks

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| `deep watch` em documentTree causa lag em templates grandes | Média | Alto | Usar `mutationVersion` counter em vez de deep watch |
| Opção A com latência visível causa UX ruim | Média | Médio | Debounce 300ms + indicador visual de "atualizando" |
| Watcher entra em loop (re-render → dispara mutação → re-render) | Baixa | Alto | Flag `isRerendering` para interromper ciclos |

## Context

**Problema central (GAPs 1 + 3):**

O `HTMLCanvas.vue` tem 4 watchers mas **nenhum observa o `templateStore`**:
- `generationStore.templateDraft` → full re-render (disparado apenas pelo backend)
- `editorStore.selectedElementId` → apenas scroll
- `layoutStore.pendingScrollToLayout` → apenas scroll
- `currentPage` → apenas scroll

`useCanvasInteraction.ts` — `endDrag()` e `endResize()` chamam `templateStore.moveElement()` / `templateStore.resizeElement()`, mas o resultado visual não aparece no canvas porque nenhum watcher detecta essas mutações.

**Solução depende do ADR (29.1):**
- Opção A (trigger backend): adicionar watcher em `templateStore` que chama `generation.requestRegeneration()` com debounce
- Opção B (geração frontend): watcher dispara motor local de geração HTML

**Esta story implementa a solução escolhida no ADR 29.1.**

**Referências:**
- `frontend/src/organisms/HTMLCanvas.vue` (linhas 520-571) — watchers existentes
- `frontend/src/stores/templateStore.ts` — funções: `moveElement`, `resizeElement`, `updateNodeProperty`, `moveNode`
- `frontend/src/composables/useCanvasInteraction.ts` — `endDrag()` (linha 355), `endResize()` (linha 446)
- Gap analysis: `docs/architecture/gap-analysis-frontend-v3.md` (GAPs 1 e 3)

**Dependências:** 29.1 (ADR com opção escolhida e interface definida)

## Acceptance Criteria

- **AC1:** **Dado** que o operador edita uma propriedade no Inspector (ex: altera texto de um label), **Quando** a edição é confirmada, **Então** o Canvas reflete a mudança visualmente em até 500ms
- **AC2:** **Dado** que o operador arrasta um elemento no Canvas, **Quando** solta o elemento, **Então** a posição visual no Canvas atualiza para a nova posição
- **AC3:** **Dado** que o operador redimensiona um elemento no Canvas, **Quando** solta o handle de resize, **Então** as dimensões visuais no Canvas refletem o novo tamanho
- **AC4:** **Dado** que o operador move um nó na árvore de estrutura, **Quando** o drop é concluído, **Então** o Canvas reflete a nova posição do nó
- **AC5:** **Dado** uma edição simples de texto, **Quando** o re-render ocorre, **Então** não há flickering visível (frame sem conteúdo)
- **AC6:** **Dado** que múltiplas mutações ocorrem em sequência rápida (< 300ms), **Quando** o debounce expira, **Então** apenas 1 re-render é disparado (sem re-renders duplicados)
- **AC7:** **Dado** os testes em `HTMLCanvas.spec.ts`, **Quando** executados, **Então** cobrem re-render após `updateNodeProperty` e após `endDrag`, todos passando

## Dev Notes

### Watcher a adicionar em HTMLCanvas.vue (Opção A — trigger backend)

```typescript
// Após os watchers existentes (linha ~571)
const RERENDER_DEBOUNCE_MS = 300

let rerenderTimer: ReturnType<typeof setTimeout> | null = null

watch(
  () => templateStore.documentTree,
  () => {
    if (rerenderTimer) clearTimeout(rerenderTimer)
    rerenderTimer = setTimeout(async () => {
      await generationStore.requestRegeneration()
    }, RERENDER_DEBOUNCE_MS)
  },
  { deep: true }
)
```

### Função a adicionar em generation.ts (Opção A)

```typescript
async requestRegeneration() {
  if (!this.currentSessionId) return
  try {
    const response = await api.post('/api/template/regenerate', {
      sessionId: this.currentSessionId,
      tree: templateStore.documentTree
    })
    this.loadTemplateDraft(response.data)
  } catch (err) {
    console.warn('[generation] requestRegeneration failed:', err)
  }
}
```

### Watcher para Opção B (geração frontend)

```typescript
watch(
  () => templateStore.documentTree,
  (tree) => {
    if (!tree) return
    if (rerenderTimer) clearTimeout(rerenderTimer)
    rerenderTimer = setTimeout(() => {
      const html = frontendHtmlGenerator.generate(tree)
      generationStore.setTemplateDraft({ html, pages: splitPages(html) })
    }, 100) // debounce menor pois é local
  },
  { deep: true }
)
```

### Observação sobre deep watch

Watch com `{ deep: true }` em `documentTree` pode ser custoso se a árvore for grande.
Alternativa: usar versão/timestamp no store e observar apenas esse contador:
```typescript
// templateStore.ts — adicionar:
const mutationVersion = ref(0)
function bumpVersion() { mutationVersion.value++ }

// Em moveElement, resizeElement, updateNodeProperty, moveNode:
// Chamar bumpVersion() no final

// HTMLCanvas.vue — observar apenas o contador:
watch(() => templateStore.mutationVersion, () => { scheduleRerender() })
```
Esta abordagem é mais eficiente e recomendada.
