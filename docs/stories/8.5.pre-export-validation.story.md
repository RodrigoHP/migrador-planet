# Story 8.5: Validação Pré-Exportação

## Status
Draft

## Story
**As a** sistema,
**I want** validar o template para compatibilidade com o motor de PDF Template antes de permitir a exportação,
**so that** a saída gerada funcione corretamente em produção.

## Acceptance Criteria
1. **AC1** — Validação executa automaticamente quando "Exportar" é clicado (antes da geração do ZIP) (FR23)
2. **AC2** — Verifica: placeholder `##TEMPLATE_DATA##` presente no index.html
3. **AC3** — Verifica: chamada `ko.applyBindings` presente no base.js
4. **AC4** — Verifica: todos os atributos `data-bind` referenciam campos que existem no XSD
5. **AC5** — Verifica: todas as referências a assets (imagens, fontes) têm arquivos correspondentes em assets/
6. **AC6** — Verifica: HTML é bem-formado (sem tags não fechadas, estrutura válida)
7. **AC7** — Erros bloqueantes impedem exportação e exibem lista de erros
8. **AC8** — Avisos permitem exportação mas exibem lista de avisos (ex: campos opcionais não mapeados)
9. **AC9** — Verifica: CSS gerado é sintaticamente válido (parse sem erros)
10. **AC10** — Verifica: bibliotecas referenciadas no HTML (knockout.js, Chart.js, etc.) estão disponíveis no catálogo de Bibliotecas (IndexedDB via useBibliotecas)
11. **AC11** — Resultado da validação exibido em modal/dialog antes de prosseguir
12. **AC12** — `npm run build` passa sem erros

## 🤖 CodeRabbit Integration
> **CodeRabbit Integration**: Disabled
> CodeRabbit CLI is not enabled em `core-config.yaml`.
> Quality validation via manual review + QA gate.

## Dev Notes
- **FR23**: validação antes da exportação, verificar placeholder, ko.applyBindings, integridade de bindings, referências a assets
- Validação pode rodar no frontend (parse HTML/JS gerado) ou backend (POST /api/validate)
- Erros bloqueantes: `##TEMPLATE_DATA##` ausente, `ko.applyBindings` ausente, HTML inválido, assets obrigatórios ausentes
- Avisos: campos opcionais não mapeados, campos XSD não usados, font fallbacks em uso
- ExportChecklist.vue já existe — simplificar de checklist técnico para checklist amigável ao operador
- O ExportChecklist.vue atual tem itens técnicos como "Preview Job ID disponível" — devem ser removidos (operador não se importa)
- Considerar usar DOMParser para validação de HTML no frontend
- Regex para extrair data-bind attributes: `/data-bind="([^"]+)"/g`
- Parsing de binding expressions Knockout: `text: field`, `html: field`, `foreach: array`, `visible: condition`
