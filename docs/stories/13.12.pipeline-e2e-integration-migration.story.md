# Story 13.12 — Pipeline E2E: Full Integration Test + Migration

## Story
**Como** equipe de desenvolvimento,
**Quero** um teste end-to-end completo do pipeline v2 (Stages 1→5 + Frontend) com benchmark de performance e feature flag para migration,
**Para** garantir que o sistema completo funciona e que podemos fazer rollout gradual.

## Status
Done

## Acceptance Criteria

1. Teste e2e: PDF upload → 5 stages → PipelineResult → editor renderiza corretamente
2. Teste com PDF real (boleto bancário): Stage 5 gera CSS com fontes, cores, bordas do PDF original (NÃO hardcoded)
3. Benchmark: 100 páginas em < 60s (vs ~20 min atual)
4. Custo API: < $0.20 por job com LLM (vs ~$3-5 atual)
5. Feature flag `PIPELINE_VERSION=v2` funcional para rollout gradual
6. Pipeline v1 continua funcionando com flag `v1` — regressão zero
7. Testes existentes passam com pipeline v2
8. Frontend renderiza PipelineResult v2: layout switch, coverage multidimensional, overlay tabelas
9. SSE reporta 5 stages com sub-progress
10. Cleanup plan documentado: quais stages v1 remover quando v2 estável

- [x] **Task 2: Teste com PDF Real** (AC: 2)
  - [ ] Usar boleto bancário Bradesco como fixture
  - [ ] Verificar CSS gerado:
    - [ ] Font classes reais (não `font-family: Arial` hardcoded)
    - [ ] Color classes reais (não `color: #000000` hardcoded)
    - [ ] Borders de drawn_elements (não `border: 1px solid #ccc` hardcoded)
    - [ ] Header/footer heights de visual_regions (não `144px`/`96px` hardcoded)
  - [ ] Verificar HTML hierárquico (não flat de field_mappings)
  - [ ] Verificar tabelas como `<table>` real (não `is_table_cell → continue`)

- [x] **Task 3: Performance Benchmark + Custo API** (AC: 3, 4)
  - [ ] Gerar PDF de 100 páginas (ou usar fixture existente)
  - [ ] Medir tempo total: Stages 1→5
  - [ ] Assert: < 60s total
  - [ ] Log breakdown por stage
  - [ ] **Medição de custo API (estimativa por contagem):**
    - [ ] Instrumentar contagem de chamadas LLM em cada stage:
      - Stage 3 (GPT-4o Vision): contar chamadas `call_vision()` — tipicamente ~6 (1 por layout representativo)
      - Stage 4 (Gemini Flash batch): contar chamadas `call_batch()` — tipicamente 1-2 (batch de todos os campos)
    - [ ] Aplicar fórmula de custo:
      ```
      custo_total = (n_vision_calls × $0.03) + (n_batch_calls × $0.01)
      Exemplo: 6 × $0.03 + 2 × $0.01 = $0.20
      ```
    - [ ] Preços de referência (março 2026):
      - GPT-4o Vision: ~$0.025-0.03 por imagem (input ~$5/1M tokens, ~800 tokens/imagem)
      - Gemini Flash: ~$0.005-0.01 por batch call (~$0.075/1M tokens)
    - [ ] Assert: custo estimado < $0.20 por job
    - [ ] Logar custo estimado no output do benchmark: `{"llm_calls": {"vision": 6, "batch": 2}, "estimated_cost_usd": 0.20}`
  - [ ] **Nota:** Custo é ESTIMADO por contagem de chamadas × preço por token/imagem. Não requer chamadas LLM reais em testes com mock — basta contar as invocações e aplicar a fórmula.

- [x] **Task 4: Feature Flag Migration** (AC: 5, 6)

  - [ ] Default: `v1` (segurança — v2 opt-in durante transition)
