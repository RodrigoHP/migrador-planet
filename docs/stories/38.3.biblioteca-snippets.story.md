## Story

**As a** usuario do migrador-planet,
**I want** salvar nos estruturais do editor como componentes reutilizaveis e inseri-los em qualquer template,
**so that** posso montar templates novos mais rapido reaproveitando blocos visuais ja validados (headers, footers, tabelas padrao, etc).

## Scope

**IN:**
- Nova categoria "Componentes" no BibliotecasModal.vue
- Opcao "Salvar como componente" no context menu da arvore (TreeView)
- Serializacao recursiva de no + filhos como JSON
- Preview HTML miniatura no modal
- Insercao de componente via templateStore.addNode() com IDs unicos
- Persistencia CRUD via IndexedDB (extensao de useBibliotecas.ts)
- Import/Export de biblioteca completa como ZIP
- Testes unitarios e de integracao

**OUT:**
- Componentes compartilhados entre usuarios (sem backend/cloud sync)
- Versionamento de componentes (v1, v2, etc.)
- Busca/filtro avancado dentro da biblioteca
- Drag-and-drop de componentes do modal para o canvas
- Edicao inline de componente ja salvo (requer salvar novamente)
- Alteracoes no backend Python (feature 100% frontend)

## Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Serializacao de nos complexos (com bindings, estilos condicionais) perde dados | Media | Alto | Round-trip test: serializar → deserializar → comparar deep equal |
| Colisao de IDs ao inserir componente multiplas vezes | Media | Alto | Gerar UUIDs novos para cada no na insercao (nunca reusar IDs do JSON) |
| Preview miniatura pesado com componentes grandes | Baixa | Medio | Limitar tamanho do iframe/div, usar transform scale, lazy render |
| IndexedDB versioning conflita com stores existentes | Baixa | Medio | Incrementar versao do DB e testar migracao das stores existentes |
| ZIP import com JSON malformado causa crash | Media | Medio | Validacao de schema antes de inserir + try/catch com feedback ao usuario |

## Dev Notes

### Contexto tecnico

O `BibliotecasModal.vue` ja possui 3 categorias (Fontes, CSS, JS) com persistencia via IndexedDB usando o composable `useBibliotecas.ts`. A nova categoria "Componentes" segue o mesmo padrao, mas persiste objetos JSON (arvore de nos) em vez de arquivos de texto.

### Serializacao de nos

Cada no do template tem a estrutura definida no `templateStore`. A serializacao deve capturar:
- Tipo do no (div, span, table, img, etc.)
- Atributos e estilos inline
- Classes CSS
- Bindings de campo (field mappings)
- Estilos condicionais (se existirem)
- Filhos recursivamente

### IDs unicos na insercao

Ao inserir um componente, todos os IDs dos nos devem ser regenerados (UUID v4) para evitar colisao com nos existentes no template. Os bindings internos (referencias entre nos pai/filho) devem ser atualizados para os novos IDs.
