# Story 25.5 — SDC Bridge: Gerar Story e Disparar SDC

## Story
**Como** sistema de investigacao,
**Quero** que o fix seja implementado via SDC em vez de inline,
**Para** que o fix passe por quality gate real e @dev implemente.

## Status
Draft

## Context

### Problema
@qa implementa fixes inline na Fase 7. Isso viola separation of concerns (investigador nao deveria implementar) e bypassa o SDC (sem quality gate). O fix nao passa por code review, nao tem PR, nao tem QA gate.

### Design
Nova Fase 6.5 — SDC Bridge:

1. Gerar `fix_requirements` do output da Fase 6:
   - root_cause, fix_approach, tests_required, affected_files, constraints
   
2. Criar story draft em `docs/stories/backlog/fix-rca-{date}-{slug}.md`
   - Formato compativel com SDC
   - Status: Ready
   - Referencia ao RCA
   
3. Decisao:
   - Interativo: perguntar "Disparar SDC agora?"
   - YOLO: disparar automaticamente
   - Se nao disparar: backlog, continuar para Fase 8
   
4. Se disparar:
   - `*workflow story-development-cycle {story} --yolo`
   - Coletar resultado (commit, arquivos, testes)
   - Alimentar Fase 8 com resultado
   
5. Se SDC falhar:
   - Registrar falha
   - NAO fazer fix inline
   - Story fica no backlog

## Acceptance Criteria
- [ ] Fase 6.5 definida no investigate.md
- [ ] fix_requirements format com campos obrigatorios
- [ ] Story draft gerada automaticamente
- [ ] SDC disparado em modo YOLO / perguntado em interativo
- [ ] Resultado do SDC alimenta Fase 8
- [ ] Se SDC falha: graceful (backlog, nao inline)
- [ ] Workflow YAML atualizado

## Scope
**IN:** investigate.md (Fase 6.5), workflow YAML
**OUT:** Mudancas no SDC workflow em si
