# Story 20.8 — Cost-Aware Retry Strategy

## Story
**Como** operador com budget limitado,
**Quero** que a retry strategy adapte seu comportamento baseado no custo acumulado — skipping niveis caros quando o budget esta alto,
**Para** que retries nao consumam o budget restante com tentativas que provavelmente serao abortadas pelo circuit breaker.

## Status
Draft

## Context

### Problema

A adaptive retry strategy (Story 18.4) tem 3 niveis: context → simplification → decomposition. O nivel 3 (decomposition) spawna multiplos sub-steps e eh o mais caro. Se o workflow ja consumiu 80% do budget, gastar com decomposition provavelmente vai ativar o circuit breaker (20.6) no meio — desperdicando tokens.

### Design

#### Logica de Cost-Aware Retry

Antes de executar cada retry level, verificar o budget restante:

```
FUNCTION get_cost_aware_retry_strategy(step, state, attempt, cost_config):
  base_strategy = get_retry_strategy(step, state, attempt)  # Story 18.4
  budget_used_pct = state.cost_tracking.total_usd / cost_config.budget.per_workflow.limit_usd

  # >80% budget: skip decomposition (level 3) → abort direto
  IF budget_used_pct > 0.80 AND base_strategy == "decomposition":
    log("[COST-AWARE] Skipping decomposition (budget >80%). Aborting.")
    RETURN "abort"

  # >60% budget: skip simplification (level 2) → pula para abort
  IF budget_used_pct > 0.60 AND base_strategy == "simplification":
    log("[COST-AWARE] Skipping simplification (budget >60%). Trying context only.")
    RETURN "abort"

  RETURN base_strategy
```

#### Integracao com Story 18.4

Esta story MODIFICA o comportamento da adaptive retry, nao o substitui. A funcao `get_retry_strategy` (18.4) continua calculando o nivel base. A funcao `get_cost_aware_retry_strategy` eh um wrapper que pode downgrade ou abort baseado no budget.

#### Logging

Quando um nivel eh skipped por custo, registrar no execution_log:
```
event: cost_aware_retry_skip
step_id: implement
skipped_level: "decomposition"
reason: "budget_threshold_exceeded"
budget_used_pct: 0.83
budget_used_usd: 41.50
budget_limit_usd: 50.00
```

## Acceptance Criteria

- [ ] AC1: Quando budget >80% gasto, decomposition (level 3) eh skipped e engine faz abort direto
- [ ] AC2: Quando budget >60% gasto, simplification (level 2) eh skipped e engine faz abort direto
- [ ] AC3: Context retry (level 1) nunca eh skipped por custo — sempre tenta ao menos uma vez com failure context
- [ ] AC4: Execution log registra cada skip com motivo, percentual de budget usado, e level skipped
- [ ] AC5: Thresholds de skip (60%, 80%) sao consistentes com alert thresholds do cost-config
- [ ] AC6: Se budget limit nao configurado, cost-aware retry eh desabilitado (usa retry normal da 18.4)
- [ ] AC7: Integra com Story 18.4 como wrapper — nao duplica logica de retry strategy

## Technical Notes

- Esta story modifica o comportamento da 18.4, nao a substitui — eh um wrapper cost-aware
- Os thresholds 60% e 80% sao escolhidos para dar margem antes dos 90% (alerta) e 100% (circuit breaker)
- O context retry (level 1) nunca eh skipped porque eh barato (apenas adiciona texto ao prompt existente)
