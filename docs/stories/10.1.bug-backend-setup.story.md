# Story 10.1: Bug — Backend Setup

## Status
Done

## Story
**As a** operador,
**I want** conseguir fazer upload de arquivos no sistema,
**so that** o fluxo de migração funcione corretamente do início ao fim.

## Acceptance Criteria
1. `POST /api/upload` retorna 200 com `{"job_id": "..."}` ao receber `pdfs[]`, `xsd`, `data` (opcional) e `template_name` em multipart/form-data
2. `backend/.env` existe com `OPENROUTER_API_KEY` e `main.py` chama `load_dotenv()` ao iniciar
3. `Pillow` declarado explicitamente em `requirements.txt`
4. PDF dropzone exibe indicador visual dos arquivos selecionados dentro da zona (nome + tamanho), sem perder estado após erro
5. `npm run build` (frontend) e `pytest` (backend) passam sem erros

## Bugs Identificados

### Bug 1 — CRÍTICO: `POST /api/upload` retorna 404
- **Causa:** Frontend chama `POST /api/upload` (endpoint unificado) mas o backend tem 3 endpoints separados: `/api/upload/pdf`, `/api/upload/xsd`, `/api/upload/data`
- **Arquivo frontend:** `frontend/src/pages/UploadPage.vue:386`
- **Arquivo backend:** `backend/routers/upload.py`
- **Fix:** Adicionar endpoint `POST /api/upload` em `upload.py` que recebe `pdfs[]` (lista), `xsd`, `data` (opcional), `template_name` em um único FormData, salva os arquivos no job dir e retorna `{"job_id": uuid}`

### Bug 2 — ALTO: `OPENROUTER_API_KEY` nunca carregado
- **Causa:** `backend/main.py` não chama `load_dotenv()` e não existe `backend/.env`
- **Sintoma:** Stages de Vision AI falham com `ValueError: OPENROUTER_API_KEY environment variable is not set`
- **Fix 1:** Adicionar `from dotenv import load_dotenv` + `load_dotenv()` no topo de `backend/main.py`
- **Fix 2:** Criar `backend/.env` com `OPENROUTER_API_KEY=<valor do .env raiz>`
- **Fix 3:** Adicionar `backend/.env` ao `.gitignore` se ainda não estiver
- **Referência:** `backend/services/openrouter_client.py:59`

### Bug 4 — MÉDIO: PDF dropzone sem feedback visual após seleção
- **Causa:** As dropzones de XSD e Data mostram o nome do arquivo selecionado **dentro** da zona (`v-if="xsdFile"` / `v-if="dataFile"`). A dropzone de PDF não tem indicador visual interno — apenas uma lista separada abaixo da grade de dropzones
- **Sintoma:** Após erro de upload, o usuário percebe que os PDFs "sumiram" porque a dropzone continua mostrando só o hint, enquanto XSD e Data mostram claramente que estão selecionados
- **Arquivo:** `frontend/src/pages/UploadPage.vue:30-54`
- **Fix:** Adicionar `v-if="pdfFiles.length"` com nome(s) e contagem dentro da dropzone de PDF, similar ao padrão de XSD/Data

### Bug 3 — MÉDIO: `Pillow` não declarado em `requirements.txt`
- **Causa:** `backend/routers/assets.py` usa `from PIL import Image` mas `Pillow` não está em `requirements.txt` — está instalado apenas como dependência transitiva de `pdfplumber`
- **Risco:** Em deploy ou ambiente limpo, `pip install -r requirements.txt` pode instalar versão incompatível de `pdfplumber` que não traga Pillow
- **Fix:** Adicionar `Pillow>=10.0.0` em `requirements.txt`

## Dev Notes
- Endpoint unificado deve usar o mesmo padrão de validação de `upload.py` existente (UUID v4, path traversal guard)
- `load_dotenv()` deve ser chamado ANTES de `app = FastAPI(...)` para garantir que os routers recebam as variáveis
- Não remover endpoints legados `/api/upload/pdf` etc. — podem ser usados por testes existentes
- `backend/.env` deve conter apenas `OPENROUTER_API_KEY` no mínimo; outros valores do `.env` raiz não são necessários para o backend
