# Story 13.8 — Stage 4: Field Mapping (Batch LLM + Two-Pass + Section Scoping)

## Story
**Como** pipeline de migração,
**Quero** mapear campos do PDF para paths do XSD com batch LLM, section scoping e two-pass,
**Para** atingir ~95% de accuracy a ~$0.01 por job (vs ~$3-5 com chamadas individuais).

## Status
Done

## Context

### Pipeline Atual
Stages 23-26: XSD parsing, field matching (individual LLM calls), format detection, confidence scoring. ~3000 chamadas LLM individuais. Accuracy ~85%. Custo ~$3-5/job.

### Pipeline v2
7 sub-steps. XSD parsing (movido do Stage 2). Section↔XSD matching reduz search space. Batch LLM (1 chamada/layout). Two-pass resolve ambiguidades. Confidence heurístico (sem Claude Sonnet). Accuracy ~95%. Custo ~$0.01/job.

## Acceptance Criteria

1. **4.1 XSD Parsing:** lxml parse → `field_tree` com `flat_paths` (lista de todos os caminhos possíveis)
2. **4.2 Pair Validation:** consumir `field_pair` do Stage 3.3, validar pares existentes, parear blocos soltos restantes
3. **4.3 Format Pre-Detection:** regex ANTES do matching — date, cpf, cnpj, currency, cep, telefone → enriquece prompt LLM
4. **4.4 Section↔XSD Matching:** cruzar seções da `document_trees` com nós complexos do XSD. Reduz search space de ~80 paths para ~3-5 por campo
5. **4.5 Field Matching:** Batch LLM (1 chamada Gemini Flash por layout). Two-pass: pass 1 aceita ≥0.7, pass 2 elimina XSD paths já usados. `block_id` + `layout_type_id` obrigatórios
6. **4.6 Confidence Scoring:** 5 fatores heurísticos determinísticos (sem LLM). Per-layout (não global). Smart signals + classification_quality
7. **4.7 Consistency Validation:** orphans, unmapped, reverse mapping (XSD required sem mapping), tipo↔formato mismatch
8. `field_mappings` por layout conforme contrato 3.4
9. Custo: ~$0.01 por job (1 batch call/layout)
10. ~6s com LLM / ~2s sem
