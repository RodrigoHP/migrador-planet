# Story 15.3 — Supabase Auth Integration

## Story

**Como** administrador da plataforma,
**Quero** que o acesso à API e ao frontend seja protegido por autenticação Supabase,
**Para** que apenas usuários autorizados possam processar documentos e acessar resultados.

## Status

Draft

## Context

### Problema

A API está completamente aberta — qualquer pessoa com a URL pode submeter PDFs, consumir LLM calls ($0.20/job) e acessar resultados de qualquer job. Não há conceito de usuário no sistema. TD-02 identificado como blocker CRITICAL no brownfield audit.

### Estado Atual do Código

**Backend — Nenhuma autenticação:**
- `backend/main.py`: 8 routers registrados sem qualquer middleware de auth
- `backend/routers/analyze.py`: jobs em dict global, sem user_id
- Nenhum package de auth em `requirements.txt`

**Frontend — Nenhuma autenticação:**
- `frontend/src/router/index.ts` (lines 34-46): guards protegem por estado da sessão (jobId, analysisCompleted), não por login
- `frontend/src/stores/session.ts`: sem user state, sem token management
- `frontend/src/services/`: apenas `assetService.ts`, sem auth service
- Nenhum package Supabase client em `package.json`

### Solução

**Backend:**
1. Instalar `PyJWT` + `httpx` (para verificar JWT do Supabase)
2. Criar `backend/middleware/auth.py` com FastAPI dependency `get_current_user()`
3. Verificar JWT contra JWKS do Supabase (`SUPABASE_URL/.well-known/jwks.json`)
4. Injetar `user_id` no request state
5. Proteger todas as rotas exceto `/api/health`
6. Env var `AUTH_ENABLED` (default `true`, `false` para dev local)

**Frontend:**
1. Instalar `@supabase/supabase-js`
2. Criar `frontend/src/services/authService.ts` — Supabase client + auth methods
3. Criar `frontend/src/stores/authStore.ts` — user state, token, isAuthenticated
4. Criar `frontend/src/pages/LoginPage.vue` — email/password login
5. Atualizar router guards — redirect para `/login` se não autenticado
6. Injetar `Authorization: Bearer` header em todas as API calls

### Scope — IN vs OUT

**IN SCOPE:**
- Backend JWT verification middleware com env var toggle
- Frontend login/logout flow com Supabase Auth
- Token injection em API calls (fetch wrapper ou interceptor)
- Router guard para redirect ao login
- User associado a jobs (user_id no job state)
- Mock de auth para testes existentes

**OUT OF SCOPE:**
- Registration flow (criar users manualmente no Supabase dashboard para MVP)
- Password reset
- OAuth/social login
- Role-based access control (todos os users são iguais para MVP)
- Per-user job isolation (jobs visíveis a todos auth users para MVP)

## Technical Notes

- **JWT Verification:** Supabase usa RS256. Baixar JWKS de `{SUPABASE_URL}/auth/v1/.well-known/jwks.json`. Cache por 1h.
- **SSE + Auth:** SSE não suporta headers customizados. Usar query param `?token=xxx` ou cookie.
- **Fetch wrapper:** Criar `apiFetch()` helper que injeta Bearer token automaticamente. Usar em `assetService.ts` e composables.
- **Auth toggle:** `AUTH_ENABLED=false` deve fazer `get_current_user()` retornar user fake `{"id": "dev-user", "email": "dev@local"}`.
