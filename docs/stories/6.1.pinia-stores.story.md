# Story 6.1: Pinia Stores Foundation — 7 Novos Stores + 4 Expandidos para Estado do Editor

## Status
Draft

## Story
**As a** sistema frontend,
**I want** 7 novos Pinia stores (editor, template, inspector, coverage, confidence, testData, multiDoc) e 4 stores existentes expandidos (session, mapping, layout, generation), todos populados a partir da resposta da API do pipeline,
**so that** o editor tenha estado reativo para renderizar todos os componentes.

## Acceptance Criteria
1. `editorStore`: gerencia aba ativa (canvas/pdf/code/sync), nível de zoom, estado de seleção, aba do sidebar, toggles (coverage mode, diff mode, snap)
2. `templateStore`: mantém a árvore de estrutura do documento (source of truth) — Document > Header > Flow > Footer > elementos, com nós contendo `{ id, type, name, binding, children, properties, visibility }`
3. `inspectorStore`: rastreia nó selecionado, nível atual (page/section/component/element), propriedades para exibição
4. `coverageStore`: armazena dados de cobertura por Layout Type — `{ fields: {mapped, total}, tables: {mapped, total}, images: {mapped, total}, charts: {mapped, total}, percentage }`
5. `confidenceStore`: armazena 5 fatores por Layout Type — `{ layout_stability, anchor_detection, grid_quality, field_variability, vision_agreement, overall }`
6. `testDataStore`: gerencia lista de datasets, dataset ativo, resultados de validação (para Epic 8)
7. `multiDocStore`: gerencia lista de PDFs (base/variação), matriz de variação, detecções (para Epic 9)
8. Stores existentes expandidos: `sessionStore` (job_id, template_name), `mappingStore` (field_mappings do pipeline), `layoutStore` (layout_types, active_layout), `generationStore` (template_draft HTML/CSS)
9. Action `loadFromPipelineResult(result: PipelineResult)` no sessionStore que despacha dados para todos os stores
10. Todos os stores possuem interfaces TypeScript
11. Testes cobrem: inicialização dos stores, loadFromPipelineResult dispatching, atualizações reativas

## Dev Notes

### Shape do JSON do Pipeline
O pipeline (Epic 5) retorna um JSON com a seguinte estrutura:
```typescript
interface PipelineResult {
  document_structure: DocumentTree;       // árvore hierárquica
  field_mappings: FieldMapping[];         // mapeamentos campo→binding
  confidence_scores: Record<string, ConfidenceFactors>; // por layout type
  coverage: Record<string, CoverageData>;              // por layout type
  layout_types: LayoutType[];             // tipos de layout detectados
  template_draft: { html: string; css: string };        // HTML+CSS gerado
  ambiguous_fields: AmbiguousField[];     // campos ambíguos para revisão
  format_functions: FormatFunction[];     // funções de formatação detectadas
}
```

### Pinia 3.x com Composition API
Todos os stores devem usar o padrão setup store:
```typescript
export const useEditorStore = defineStore('editor', () => {
  const activeCenterTab = ref<CenterTab>('canvas')
  // ...
  return { activeCenterTab, /* ... */ }
})
```

### templateStore é SOURCE OF TRUTH
- A árvore de documento no templateStore é a fonte de verdade
- template.json é apenas serialização para save/export
- Nós da árvore: `{ id, type, name, binding, isOptional, children[], properties, visibility }`

### Thresholds de Cobertura e Confiança
- Cobertura: ≥95% complete ✅, 80-95% review recommended ⚠️, <80% incomplete 🔴
- Confiança: ≥95% approved ✅, 80-95% review recommended ⚠️, <80% human review 🔴
- Ambos são POR Layout Type — ao trocar layout, as métricas atualizam

### Diretório dos Stores
- Stores existentes: `frontend/src/stores/`
- Novos stores no mesmo diretório
- Types em `frontend/src/types/`
