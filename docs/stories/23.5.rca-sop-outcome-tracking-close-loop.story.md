# Story 23.5 — SOP Outcome Tracking: Fechar o Loop

## Story
**Como** sistema de knowledge management,
**Quero** que SOPs tenham counters atualizados a cada uso,
**Para** que SOPs ineficazes sejam identificados e descartados.

## Status
Done

## Context

### Problema
`sop-missing-isinstance-guard.yaml` tem `times_applied: 0`, `effectiveness_rate: null` apesar de ter sido referenciado em RCA. Nao ha instrucao clara de QUANDO e COMO atualizar os counters. O loop SOP → uso → outcome → feedback esta aberto.

### Design
Adicionar instrucoes explicitas em 3 pontos do investigate.md:

**Ponto 1 — Fase 2 (Pattern Matcher), ao aceitar SOP fast-track:**
```
IMEDIATAMENTE apos aceitar SOP fast-track:
1. Abrir arquivo do SOP: docs/qa/rca-knowledge/sops/{sop-file}.yaml
2. Incrementar: times_applied += 1
3. Atualizar: last_applied = "{data-atual}"
4. Atualizar: last_investigation = "rca-{date}-{slug}"
5. Salvar arquivo
```

**Ponto 2 — Fase 9 (Meta-Learning), effectiveness review:**
```
Para cada SOP com last_applied nos ultimos 30 dias:
1. Verificar se fix do SOP resolveu o problema (grep por mesmos sintomas)
2. SE resolveu: times_effective += 1
3. SE nao resolveu: times_ineffective += 1
4. Recalcular: effectiveness_rate = times_effective / times_applied
5. SE effectiveness_rate < 50% E times_applied >= 3: needs_review = true
```

**Ponto 3 — audit-patterns (Passo 1), periodic review:**
```
Para cada SOP em docs/qa/rca-knowledge/sops/:
1. SE needs_review = true: alertar e sugerir revisao
2. SE effectiveness_rate = 0% E times_applied >= 3: sugerir deprecacao
```

**Retroativo:**
Atualizar `sop-missing-isinstance-guard.yaml`:
- `times_applied: 1` (referenciado em rca-2026-03-29)
- `last_applied: "2026-03-29"`
- `last_investigation: "rca-2026-03-29-analyzing-page"`
