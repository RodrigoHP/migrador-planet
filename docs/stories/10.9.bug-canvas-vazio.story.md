# Story 10.9: Bug — Canvas do editor vazio após pipeline completar com 200 OK

## Status
Done

## Story
**As a** operador,
**I want** que o canvas do editor mostre o template gerado com os campos mapeados do PDF e XSD,
**so that** eu possa visualizar e editar o layout do documento após a análise completar.

## Acceptance Criteria
1. Após upload de PDF + XSD + DATA e pipeline completar (todos 200 OK), o canvas exibe ao menos uma página com campos visíveis derivados do XSD
2. A aba Canvas do editor não exibe uma página completamente branca quando o pipeline completou com sucesso
3. O `context["field_tree"]` é populado com os campos do XSD em toda execução de pipeline que inclui `schema.xsd` no job dir
4. O `context["field_mappings"]` contém mapeamentos com `xsd_field_path` não-vazio após a análise
5. O `template_draft.html` gerado pelo Stage 27 contém ao menos um `<div class="field-group">` com conteúdo visível
6. `pytest backend/tests/` passa sem erros após as correções

## Bugs Identificados

### Bug 1 — CORRIGIDO: xsd_parser não deriva xsd_path do job_id (commit e3b1bda)
- **Causa:** `xsd_parser.execute()` verifica apenas `context["xsd_path"]`. O pipeline inicia com `context = {"job_id": job_id}` sem nenhum path definido. Stage 1 ("Upload & Storage") é um stub que retorna `{}` sem setar caminhos.
- **Consequência em cascata:**
  - `context["field_tree"] = None`
  - `field_matching` (Stage 23): `flat_paths = []` → todos os mappings têm `xsd_field_path = ""`
  - `template_draft` (Stage 27): `_generate_field_element` retorna `""` quando `path == ""` → nenhum campo gerado
  - `template_draft.html` = página vazia (sem campos)
  - Canvas renderiza iframe com HTML vazio → página branca
- **Fix aplicado:** `xsd_parser.execute()` agora auto-deriva `schema.xsd` a partir de `job_id` quando `xsd_path` não está no contexto — idêntico ao comportamento de `text_extraction.py`
- **Arquivo:** `backend/services/stages/xsd_parser.py`
- **Testes adicionados:** `backend/tests/test_xsd_parsing.py::TestXsdParserExecuteAutoDerive` (3 testes)

### Bug 2 — CORRIGIDO: Canvas vazio por `_generate_field_element` retornar `""` quando `xsd_field_path` está vazio
- **Sintoma:** Após reiniciar o backend com a correção do Bug 1, o canvas continua mostrando página branca
- **O que foi descartado:**
  - `analysisCompleted` é setado (rota /editor não redireciona → guard passa)
  - `generationStore.templateDraft` não é null (caso contrário mostraria "Nenhum template carregado")
  - Pipeline completa com todos 200 OK (upload, analyze, progress, result)
  - OPENROUTER_API_KEY ausente mas field_matching usa difflib como fallback — não bloqueia
  - "Registry indisponível – layout tratado como novo" — Registry Lookup (Stage 11) gracioso, não falha
- **Hipótese confirmada (análise estática do código):** Combinação das hipóteses 1 e 5
  - `field_matching` (Stage 23) gera `field_mappings` com `xsd_field_path=""` quando `flat_paths` vazio (XSD não parseado) OU quando difflib não encontra candidatos suficientes
  - `_generate_field_element` em `template_draft.py` linha 150-151: `if not path: return ""` — descartava TODOS os mappings sem `xsd_field_path`, resultando em template HTML sem nenhum `<div class="field-group">`
  - Mesmo quando o PDF é lido com sucesso e labels/values são extraídos pelo `semantic_analysis`, o canvas ficava branco porque nenhum campo era renderizado
- **Fix aplicado:** `_generate_field_element` agora possui fallback: quando `xsd_field_path=""` mas `label_text` ou `pdf_text` existem, renderiza `<div class="field-group">` estático com o texto do PDF — canvas exibe campos visíveis mesmo sem matching XSD
- **Arquivo:** `backend/services/stages/template_draft.py`

### Bug 3 — A VERIFICAR: Localização dos arquivos de upload
- **Sintoma:** Usuário não consegue encontrar os arquivos uploadados na pasta do projeto
- **Causa raiz:** Backend usa `Path("/tmp/jobs")` que em Windows resolve para `C:\tmp\jobs` (não dentro do projeto)
- **Impacto:** Os arquivos EXISTEM mas o usuário não sabe onde procurar
- **Ação:** Documentar que `C:\tmp\jobs\{jobId}\` é onde ficam os arquivos; considerar configurar `TMP_BASE` via variável de ambiente

## Dev Notes

### Arquitetura do fluxo canvas → template
```
Upload (POST /api/upload) → /tmp/jobs/{jobId}/
  - input.pdf
  - schema.xsd
  - data.xml / data.json

Pipeline context = {"job_id": jobId}
  Stage 29 (xsd_parser) → context["field_tree"] = {flat_paths: [...], root_nodes: [...]}
  Stage 2  (text_extraction) → context["parsed_documents"] = [{pages: [{text_blocks: [...]}]}]
  Stage 19 (semantic_analysis) → text_blocks anotados com semantic_label
  Stage 23 (field_matching) → context["field_mappings"] = [{xsd_field_path, label_text, ...}]
  Stage 27 (template_draft) → context["template_draft"] = {html, css, coverage}
  Stage 28 (pipeline_result) → context["result_json"] com template_draft

Frontend (AnalyzingPage.vue)
  fetchAndLoadResult() → session.loadFromPipelineResult(result)
    → generationStore.loadTemplateDraft(result.template_draft)
       → generationStore.templateDraft = {html, css}

HTMLCanvas.vue
  pages = computed → generationStore.templateDraft.html
  → parseia [data-page] (não existe no template_draft → fallback página 1)
  → renderiza iframe com html+css inteiro
```

### Por que canvas aparece branco mesmo com HTML não-vazio
- `template_draft.html` pode ter estrutura válida mas sem texto visível:
  - Labels do PDF (detectados via `semantic_label=label`) com `label_text` vazio → `<span class="label">` não gerado
  - `data-bind="text: path"` spans renderizam como string vazia (sem KnockoutJS no iframe)
- CSS: `.flow { position: absolute; top: 1.5in; bottom: 1in; overflow: hidden }` — se nenhum campo tiver texto visível, o flow parece vazio

### Localização dos arquivos uploadados (Windows)
- Path Python: `/tmp/jobs` → Windows resolve para: `C:\tmp\jobs`
- Estrutura: `C:\tmp\jobs\{job_id}\input.pdf`, `C:\tmp\jobs\{job_id}\schema.xsd`
