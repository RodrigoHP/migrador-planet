## Resumo Executivo

A hipótese original — que `pages[].images[]` do Mistral conteria bbox de tabelas raster e poderia substituir GPT-4o Vision — **nao se confirmou empiricamente**. Para todos os 5 PDFs testados, `images[]` retornou vazio.

**Porem, foi identificado um caminho alternativo mais robusto**: PyMuPDF (`page.get_images()` + `page.get_image_bbox()`) extrai bbox das imagens raster diretamente do PDF com **precisao superior** ao GPT-4o Vision, e **sem custo de API**.

**Recomendacao: eliminar GPT-4o Vision por completo**, substituindo-o por uma combinacao de:
1. **Mistral** como trigger de deteccao de tabela raster (ja funciona sem GPT-4o)
2. **PyMuPDF** para bbox da imagem raster (mais preciso que GPT-4o)
3. **`extract_header/extract_footer`** do Mistral para zones (AC4 PASS)

## Resultados por AC

### AC1 — Bbox de imagem disponivel e preciso

**Resultado: FAIL (mas com achado alternativo)**

**Dados medidos:**
```
PDF                    | PyMuPDF images | Mistral images[]
-----------------------|----------------|------------------
corp-convenio-1.pdf    | 4 (1 grande)   | 0
boleto-cond-1.pdf      | 9              | 0
boleto-grd-1.pdf       | 5              | 0
boleto-duda-1.pdf      | 5              | 0
2via-sicoob-1.pdf      | 3              | 0
```

**Analise:** Mistral processa imagens JPEG embedded como conteudo OCR e coloca o resultado em `tables[]` ou no markdown — mas **nao expoe o bbox da imagem em `images[]`**. O campo `images[]` so e preenchido quando Mistral inclui referencias `![img-X.jpeg]` no markdown, o que nao ocorreu em nenhum dos PDFs testados (todos os rasters eram barcodes, logos ou tabelas que o Mistral conseguiu OCR completamente).

**Achado alternativo — PyMuPDF e mais preciso:**

Para `corp-convenio-1.pdf` (tabela raster JPEG 2174x1337 px):

| Fonte | x0 | y0 | x1 | y1 |
|-------|----|----|----|----|
| GPT-4o Vision | 50 | 500 | 550 | 620 |
| PyMuPDF (ground truth) | 27.7 | 377.3 | 582.9 | 718.8 |
| Erro GPT-4o | 22.3 | 122.7 | 32.9 | 98.8 |

GPT-4o subestimou a altura da tabela em **~122 pontos** (y0) e **~99 pontos** (y1). PyMuPDF devolve o bbox exato sem custo.

### AC2 — Conversao de coordenadas correta

**Resultado: PARTIAL (formula correta, mas sem dados para validar via Mistral)**

A formula de conversao foi validada indiretamente:

```python
dpi = page["dimensions"]["dpi"]  # Mistral retornou 93 dpi para corp-convenio-1.pdf
scale = 72.0 / dpi               # 72/93 = 0.774

# Verificacao: pagina Mistral = 791x1023 px @ 93 dpi
# PDF rect = 612x792 pts
# 791 * 72/93 = 612.0 pts -> correto
# 1023 * 72/93 = 792.0 pts -> correto
```

A conversao esta matematicamente correta. Porem, como `images[]` ficou vazio, nao ha como comparar bbox Mistral x GPT-4o diretamente.

**Alternativa PyMuPDF para bbox:**
```python
import fitz
doc = fitz.open(pdf_path)
page = doc[page_index]
for img in page.get_images(full=True):
    bbox = page.get_image_bbox(img)  # Rect em pontos PDF -- diretamente comparavel
```

### AC3 — Correlacao `images[]` <-> `tables[]` via markdown

**Resultado: N/A (mecanismo nao se aplica a PDFs de boleto)**

O markdown retornado pelo Mistral para todos os PDFs testados contem apenas referencias de tabela (`[tbl-N.html]`), sem referencias de imagem (`![img-N.jpeg]`). O mecanismo de correlacao via markdown pressupoe que a tabela raster aparece como `![img-N.jpeg]` no markdown, o que nao ocorre quando Mistral consegue extrair o conteudo da imagem como HTML.

**Amostra de markdown** (`corp-convenio-1.pdf` pagina 0):
```
VALE CORES COMERCIAL EIRELI - EPP/SP
...
[tbl-0.html](tbl-0.html)
[tbl-1.html](tbl-1.html)
```

Sem referencias `![img-X.jpeg]` — o mecanismo de correlacao de markdown nao e necessario para esse tipo de PDF.

## Achado Central: PyMuPDF como Alternativa Superior

O achado mais relevante da spike e que **PyMuPDF ja pode fornecer o bbox preciso de imagens raster**, sem custo de API e com maior precisao que GPT-4o Vision:

```python
# Substituicao proposta para _run_3_2 + _extract_raster_table_mistral
import fitz

def _get_raster_image_bboxes(pdf_path: str, page_index: int) -> list[dict]:
    """Retorna bboxes de imagens raster em pontos PDF, via PyMuPDF."""
    doc = fitz.open(pdf_path)
    page = doc[page_index]
    bboxes = []
    for img in page.get_images(full=True):
        rect = page.get_image_bbox(img)
        bboxes.append({
            "bbox": [rect.x0, rect.y0, rect.x1, rect.y1],
            "width_px": img[2],
            "height_px": img[3],
        })
    doc.close()
    return bboxes
```

Para `corp-convenio-1.pdf`:
- PyMuPDF bbox: `[27.7, 377.3, 582.9, 718.8]` -- exato
- GPT-4o bbox: `[50, 500, 550, 620]` -- erro maximo de 123 pts

## Analise: `images[]` do Mistral — quando popula?

Com base nos testes, `images[]` parece ser preenchido apenas quando:
1. A imagem raster e processada como tabela pelo Mistral → aparece em `tables[]` (nao em `images[]`)
2. Logos e barcodes sao "engolidos" pelo OCR como contexto visual → nao aparecem em `images[]`
3. O campo seria populado para imagens que o Mistral inclui como `![img-N.jpeg]` no markdown — o que so ocorre quando o conteudo nao pode ser OCR'd como texto ou tabela (ex: fotos, graficos)

Nenhum dos PDFs de boleto/convenio testados produziu esse cenario.

## Recomendacao: Eliminar GPT-4o Vision (caminho alternativo)

**Recomendacao: ELIMINAR GPT-4o Vision** — mas por caminho diferente do hipotetizado.

### Plano de implementacao (Story 46.2)

| Substituicao | Atual (GPT-4o) | Proposto |
|---|---|---|
| Trigger para chamar Mistral | GPT-4o detecta `table_area` | Mistral chamado incondicionalmente por pagina; se `tables[]` nao vazio -> tabela detectada |
| Bbox da tabela raster | GPT-4o Vision estimativa | PyMuPDF `get_image_bbox()` -- preciso |
| Deteccao de zona header | GPT-4o Vision | `extract_header=True` do Mistral |
| Deteccao de zona footer | GPT-4o Vision | `extract_footer=True` do Mistral (quando nao vazio/`"#"`) |
| Classificacao barcode/logo | GPT-4o + PIL | PIL diretamente via PyMuPDF `extract_image()` |

### Economia mantida
- $0.01/cluster eliminado (GPT-4o Vision)
- ~8s latencia eliminada (chamada GPT-4o)
- **Bonus:** bbox PyMuPDF e mais preciso que GPT-4o (erro reduzido de ~100 pts para ~0 pts)

### Risco residual
- Raster tables que Mistral nao consiga OCR (conteudo corrompido, resolucao muito baixa): `tables[]` ficaria vazio -> fallback necessario
- Mitigacao: verificar se `tables[]` nao vazio antes de registrar detection
