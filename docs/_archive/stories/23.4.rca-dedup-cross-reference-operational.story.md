# Story 23.4 — Dedup Check: Cross-Reference Operacional

## Story
**Como** investigador na Fase 0,
**Quero** que duplicatas sejam detectadas automaticamente com criterios concretos,
**Para** que nao reinvestigue bugs ja conhecidos.

## Status
Done

## Context

### Problema
2 RCAs do mesmo bug family (`'list' has no attribute 'get'`, Stage 5, AP-001) existem sem cross-reference. Instrucoes de dedup sao genericas ("buscar por symptoms/tags") sem definir matching concreto. `dedup_status` declarado no schema mas ausente nos registros.

### Design
Reescrever dedup check na Fase 0 com instrucoes concretas:

**Step 1 — Query sources (4 fontes, 30 dias):**
1. `cat docs/qa/rca-knowledge/investigations.yaml` — RCAs anteriores
2. `git branch -a | grep -i "fix\|hotfix\|bug"` — branches ativas
3. `gh pr list --state open --search "{error_message_keywords}"` — PRs abertos
4. `grep -rl "{keywords}" docs/stories/ | head -10` — stories recentes

**Step 2 — Match criteria concretos:**
- **Error message match:** substring exata da mensagem de erro → +40 pts
- **File overlap:** 2+ arquivos em comum com `affected_files` de RCA anterior → +30 pts
- **Tag overlap:** 2+ tags em comum → +20 pts
- **Anti-pattern match:** mesmo AP-ID referenciado → +10 pts

**Step 3 — Classificacao:**
- Score > 90: **DUPLICATE** → parar, referenciar RCA existente, justificar
- Score 50-90: **RELATED** → anotar cross-reference bidirecional, continuar
- Score < 50: **NEW** → continuar sem restricoes

**Step 4 — Output obrigatorio:**
```yaml
## Dedup Check Results
| Fonte | Match | Score | Classificacao |
|---|---|---|---|
| rca-2026-03-29-... | error msg + files + tags | 85/100 | RELATED |

**dedup_status:** related
**related_rcas:** ["rca-2026-03-29-analyzing-page"]
**Action:** Continuar investigacao, cross-reference anotado
```

**Step 5 — Cross-reference bidirecional:**
Se RELATED: atualizar `related_rcas` no registro da RCA anterior tambem.
