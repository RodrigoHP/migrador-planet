# Story 16.4 — Observabilidade & Execution Log

## Story
**Como** operador que executa workflows longos em `yolo_continuous`,
**Quero** ter visibilidade em tempo real de qual step esta executando, quanto tempo cada step levou, e alertas quando algo parece travado,
**Para** que eu possa monitorar o progresso e intervir rapidamente se necessario.

## Status
Done

## Context

### Problema

Quando um workflow roda em `yolo_continuous`, o usuario inicia e espera o Final Report. Nao ha visibilidade intermediaria: qual step esta rodando, quanto tempo ja passou, quantos retries ocorreram, se o loop guard esta proximo do limite. Para workflows longos (6+ fases, 30+ min), isso eh um ponto cego critico.

### Referencia

- Engine: `.aios-core/development/tasks/run-workflow-engine.md` (v3.0)
- State file ja salvo apos cada step (persistencia existe)

### Design Proposto

**Execution Log** — array append-only no state file com eventos estruturados:

```yaml
execution_log:
  - timestamp: "2026-03-29T10:05:30Z"
    event: step_started
    step_id: root_cause
    agent: qa
  - timestamp: "2026-03-29T10:15:30Z"
    event: step_completed
    step_id: root_cause
    elapsed_ms: 600000
  - timestamp: "2026-03-29T10:15:35Z"
    event: handoff_generated
    from_agent: qa
    to_agent: sm
  - timestamp: "2026-03-29T10:30:00Z"
    event: loop_guard_warning
    target_step: qa_gate
    current_loops: 2
    max_loops: 3
```

**Progress Display** — apos cada step, emitir resumo:

```
[yolo_continuous] Step 3/9 completed: implement_and_test (@dev) — 8m32s
  Next: documentation_and_qa_gate (@qa)
  Total elapsed: 22m15s
```

**Hang Detection** — se step excede 2x o timeout esperado, emitir warning:

```
⚠️ Step root_cause (@qa) running for 12m (expected ~5m) — may be hanging
```

## Acceptance Criteria

- [ ] AC1: State file contem array `execution_log` com eventos append-only
- [ ] AC2: Eventos registrados: `step_started`, `step_completed`, `step_failed`, `step_timeout`, `handoff_generated`, `loop_guard_warning`, `workflow_aborted`, `workflow_completed`
- [ ] AC3: Cada evento tem `timestamp`, `event`, e campos contextuais relevantes
- [ ] AC4: Progress display emitido apos cada step com formato `[yolo_continuous] Step N/M completed: ...`
- [ ] AC5: `elapsed_ms` registrado para cada step completado
- [ ] AC6: Hang detection warning emitido quando step excede 2x o timeout esperado
- [ ] AC7: Comando `*run-workflow {name} status` le execution_log e exibe resumo formatado
- [ ] AC8: Final Report inclui secao "Execution Timeline" com duracoes por step

**OUT:**

## Risks

- Append-only execution_log pode crescer excessivamente em workflows com muitos retries e loop_guard loops. Mitigacao: limitar a 500 eventos no log; eventos mais antigos sao compactados em summary.
- Progress display depende de `total_steps` conhecido antecipadamente. Steps dinamicos (on_failure routing) podem alterar o total. Mitigacao: exibir "Step N completed" sem "of M" quando total eh indeterminado.
