# Story 20.6 — Anti-Pattern Detection Rules

## Story
**Como** time de qualidade,
**Quero** que `*audit-patterns` execute automaticamente os search_patterns dos anti-patterns registrados no codebase,
**Para** prevenir ativamente que padroes conhecidos reentrem no codigo.

## Status
Draft

## Context

### Problema
Anti-patterns sao registrados com search_pattern (regex) e scope, mas so sao detectados se alguem roda `*audit-patterns` manualmente. Nenhuma automacao impede que o mesmo padrao entre de novo. Alem disso, a Fase 8 nao obriga a criacao de search_pattern no anti-pattern.

### Design
- `*audit-patterns` le known-anti-patterns.md e executa cada search_pattern no scope
- Resultado: lista de matches atuais com localizacao (arquivo:linha)
- Fase 8 do investigate.md torna search_pattern obrigatorio quando possivel
- Output formatado como actionable (pode virar story ou fix imediato)

## Acceptance Criteria
- [ ] `*audit-patterns` le known-anti-patterns.md e executa cada search_pattern no escopo definido
- [ ] Resultado: lista de matches atuais no codebase com localizacao (arquivo:linha)
- [ ] Para cada match, referencia o anti-pattern ID e severidade
- [ ] Output formatado como actionable (pode virar story ou fix imediato)
- [ ] Documentacao de como adicionar novos anti-patterns com search_pattern
- [ ] Fase 8 do investigate.md gera anti-pattern com search_pattern obrigatorio quando possivel

## Scope
**IN:** investigate.md (Fase 8), audit-patterns task, schema anti-patterns
**OUT:** Integracao CI/CD (pre-commit hooks)
