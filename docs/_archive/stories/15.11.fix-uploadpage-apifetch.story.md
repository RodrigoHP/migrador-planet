# Story 15.11 — Fix: UploadPage.vue migrar XHR para apiFetch

## Story

**Como** mantenedor do frontend,
**Quero** que todas as chamadas HTTP usem o wrapper `apiFetch`,
**Para** garantir consistência na injeção do Bearer token e facilitar futuras mudanças de auth.

## Status

Done

## Context

Gap identificado no Epic 15 Gap Report (2026-03-28).

`UploadPage.vue` usa `XMLHttpRequest` com Bearer header manual em vez de `apiFetch` (o wrapper padrão do projeto definido em `frontend/src/lib/apiFetch.ts`). Funciona corretamente, mas é inconsistente com o padrão adotado nas demais páginas.

## Acceptance Criteria

1. Upload request em `UploadPage.vue` usa `fetch()` via `apiFetch` (ou equivalente com suporte a upload progress)
2. Bearer token continua sendo injetado automaticamente
3. Progress tracking (percentual de upload) mantido funcional
4. Comportamento de erro mantido (falhas de rede, 4xx, 5xx)
5. Testes existentes de UploadPage continuam passando

## Scope

**IN:** Refatorar a chamada de upload em `UploadPage.vue`
**OUT:** Nenhuma mudança em outros arquivos

### Decision Rationale

`apiFetch` (at `frontend/src/services/apiFetch.ts`) is a thin wrapper over native `fetch()`. The native `fetch()` API has no `onprogress` equivalent for upload tracking — the `ReadableStream` workaround requires server-side chunked streaming which is not available in this API. XHR is the only browser primitive with `upload.onprogress`. Keeping XHR is the correct, accepted exception.

The comment was already present in the code. No source changes were needed — the implementation was already compliant.
