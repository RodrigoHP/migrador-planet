## Context

Stories 29.2 e 29.3 dependem de uma decisão arquitetural sobre como propagar mudanças do `templateStore` para o `HTMLCanvas.vue`. Existem duas opções:

**Opção A — Trigger Backend (debounce + round-trip HTTP)**
- Mutação no `templateStore` → debounce (300-500ms) → request ao backend → novo HTML entregue via `generationStore.templateDraft` → watcher existente no HTMLCanvas dispara
- Reutiliza engine de geração já existente no backend (`stage5_template_generation.py`)
- Impacto nas stores: `generation.ts` ganha função `requestRegeneration()` que chama endpoint
- Prós: menor esforço de frontend, engine consistente com o que vai para produção
- Contras: latência de 200-800ms, dependência de rede, UX pode parecer lenta em edições rápidas

**Opção B — Geração HTML no Frontend**
- Motor de geração HTML implementado no frontend que observa `templateStore` diretamente
- Sem round-trip, atualização em tempo real
- Requer reescrever a lógica de geração em TypeScript
- Prós: UX fluida, offline-capable, sem latência
- Contras: duplicação da lógica backend, maior esforço, possível divergência entre geração frontend vs backend

**Contexto atual do código:**
- `HTMLCanvas.vue` tem watcher em `generationStore.templateDraft` → full re-render (funciona)
- `generation.ts` só tem `loadTemplateDraft()` — sem lógica de geração local
- Backend tem endpoint de geração (`/api/template/generate` ou similar) já funcional
