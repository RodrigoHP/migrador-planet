# Story 27.2 — Debt: Imagens do editor embutidas como base64 no template HTML

## Story

**Como** usuário que substitui imagens no editor visual,
**Quero** que a imagem substituída apareça corretamente no canvas (preview),
**Para** que o que vejo no editor seja idêntico ao HTML exportado, sem dependências de servidor.

## Context

Na Story 27.1 o pipeline de processamento de PDF foi corrigido: `StorageGateway.upload_asset()` agora retorna `data:image/{mime};base64,{b64}` para imagens.

**Problema pendente:** O editor visual (`ImageInspector.vue`) ignora esse retorno e seta `src = "assets/${response.filename}"` — um caminho relativo. Quando o HTML do template é renderizado no `HTMLCanvas.vue` via `<iframe srcdoc="...">`, o browser não consegue resolver caminhos relativos (iframes com `srcdoc` não têm base URL). A imagem fica quebrada no preview.

**Ironia do bug:** O campo `AssetResponse.path` retornado pelo backend (`POST /api/templates/{template_id}/assets`) **já contém** a data URI — porque `storage.upload_asset()` foi corrigido na 27.1. O frontend simplesmente descarta esse valor e constrói o path relativo manualmente.

**Referência:** `backend/routers/assets.py:113-120` — `storage_path = await storage.upload_asset(...)` → `path=storage_path` (já é base64). `ImageInspector.vue:330` — `assets/${response.filename}` (descarta `response.path`).

## Acceptance Criteria

**AC-1 — doUpload usa data URI:**
Após upload bem-sucedido via `ImageInspector.doUpload()`, o `src` do nó é `response.path` (data URI `data:image/...;base64,...`) — não mais `assets/${response.filename}`.

**AC-2 — Preview no canvas funciona:**
Imagem substituída aparece corretamente no `HTMLCanvas.vue` (iframe srcdoc) imediatamente após a substituição, sem recarregar a página.

**AC-3 — doRemove funciona após a mudança:**
O botão "Remover" continua funcionando. Como `src` não é mais `assets/...`, o nó deve armazenar `assetFilename` como property separada para que `doRemove()` saiba qual arquivo deletar no backend.

**AC-4 — onGallerySelect usa data URI:**
Ao selecionar um asset existente da galeria (`AssetGallery`), o `src` também é data URI. O endpoint `GET /api/templates/{template_id}/assets` retorna campo `dataUri: str` com o conteúdo base64 de cada arquivo. Frontend usa `asset.dataUri` em `onGallerySelect`.

**AC-5 — assetService.ts atualizado:**
Interface `AssetResponse` adiciona campo `path` (já existe, mas frontend usava errado — nenhuma alteração de schema necessária). Interface `AssetInfo` adiciona campo `dataUri: string`.

**AC-6 — Testes unitários:**
- `assetService.spec.ts` — mock da response inclui `dataUri` e verifica que o serviço o expõe corretamente
- `ImageInspector.spec.ts` (se existir) — verifica que após `doUpload`, `src` começa com `data:image/`

**AC-7 — LocalGateway e SupabaseGateway não modificados:**
Os gateways de storage já estão corretos (Story 27.1). Zero alteração nesses arquivos.

## Dev Notes

**AC-1 — Fix trivial em doUpload:**
```js
// ANTES (linha 330):
templateStore.updateNodeProperty(props.node.id, 'src', `assets/${response.filename}`)

// DEPOIS:
templateStore.updateNodeProperty(props.node.id, 'src', response.path)
templateStore.updateNodeProperty(props.node.id, 'assetFilename', response.filename)
```
`response.path` já contém `data:image/png;base64,...` — o backend retorna via `upload_asset`.

**AC-3 — doRemove adaptado:**
```js
// ANTES:
if (src && src.startsWith('assets/')) {
  const filename = src.replace('assets/', '')
  await deleteAsset(templateId.value, filename)
}

// DEPOIS:
const assetFilename = p.value['assetFilename'] as string | undefined
if (assetFilename) {
  await deleteAsset(templateId.value, assetFilename)
}
```

**AC-4 — GET /assets com dataUri (backend):**
```python
# assets.py — list_assets endpoint:
import base64, mimetypes
from pathlib import Path

for f in sorted(assets_dir.iterdir()):
    if f.is_file() and _SAFE_FILENAME_RE.match(f.name):
        content = f.read_bytes()
        ext = f.suffix.lower()
        mime = mimetypes.types_map.get(ext, 'image/png')
        data_uri = f"data:{mime};base64,{base64.b64encode(content).decode('ascii')}"
        url = await storage.get_signed_url(...)
        result.append(AssetInfo(
            filename=f.name,
            path=f"assets/{f.name}",
            size=f.stat().st_size,
            thumbnailUrl=url,
            dataUri=data_uri,
        ))
```

**Nota sobre isSvgSource:** A computed `isSvgSource` usa `src.toLowerCase().endsWith('.svg')`. Com data URI, isso vai ser sempre `false`. Se o toggle SVG inline precisar funcionar para SVGs editados manualmente no editor, adicionar verificação por `assetFilename.endsWith('.svg')` também.
