# Story 21.9 — Swiss Cheese Severity Scoring

## Story
**Como** investigador analisando barreiras de defesa na Fase 5,
**Quero** quantificar o impacto relativo de cada barreira falhada,
**Para** priorizar quais defesas reforcar primeiro com base em criticality real.

## Status
Done

## Context

### Problema
A barrier analysis atual lista barreiras como "failed/absent" sem indicar qual teria mais impacto se corrigida. Exemplo: no RCA stage5-document-trees, 6/6 defesas falharam — mas qual single fix teria prevenido o bug? O Code Level guard? O teste? O linter? Sem scoring, todas parecem igualmente importantes.

### Design
Para cada barreira falhada, avaliar **criticality** com pergunta contrafactual:
- "Se APENAS esta barreira estivesse presente e funcionando, o bug teria sido prevenido?"
  - **Sim, definitivamente** → Criticality: HIGH (esta barreira sozinha preveniria)
  - **Provavelmente** → Criticality: MEDIUM (reduziria impacto significativamente)
  - **Nao necessariamente** → Criticality: LOW (contribuiria mas nao preveniria sozinha)

Output: ranking de barreiras por criticality, com recomendacao de "fix this first".

## Acceptance Criteria
- [ ] Fase 5 do investigate.md inclui scoring de criticality para cada barreira falhada
- [ ] Criticality definida por pergunta contrafactual ("se apenas esta barreira funcionasse...")
- [ ] 3 niveis: HIGH (preveniria sozinha), MEDIUM (reduziria), LOW (contribuiria)
- [ ] Output inclui ranking de barreiras por criticality
- [ ] Recomendacao "fix this first" baseada no ranking
- [ ] Template de relatorio (Fase 8) inclui coluna Criticality na tabela Swiss Cheese
- [ ] Fase 7 prioriza fixes defensivos pelo ranking de criticality

## Scope
**IN:** Fase 5 do investigate.md, template de relatorio, Fase 7
**OUT:** Metricas quantitativas de probabilidade (subjetivo ok)
