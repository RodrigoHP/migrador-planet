# Story 18.5 — Confidence Scoring

## Story
**Como** operador que executa workflows yolo_continuous,
**Quero** que subagentes retornem um score de confianca (0.0-1.0) no step_output e que o engine tome decisoes baseadas nesse score,
**Para** que problemas de qualidade sejam detectados antes de chegar ao QA gate, reduzindo ciclos desperdicados.

## Status
Draft

## Context

### Problema

Steps retornam `status: completed|failed` — binario. Nao existe como sinalizar:
- "Completei mas com baixa confianca"
- "3 de 5 ACs cobertos"
- "Codigo funciona mas tem tech debt"

O @dev sabe que nao cobriu tudo, mas nao tem como comunicar isso ao engine. O resultado: QA pega codigo incompleto, rejeita, loop de volta. Tempo e tokens desperdicados.

### Design

#### Schema extension

Novo campo opcional no `step_output`:

```yaml
step_output:
  status: completed
  confidence: 0.75          # NOVO: 0.0-1.0, opcional, default 1.0 se ausente
  confidence_notes: "AC #4 e #5 precisam de clarificacao do PO"  # NOVO: opcional
  outputs:
    key: value
```

#### Engine behavior por faixa

```
confidence >= 0.8  → CONTINUE normalmente (high confidence)
0.5 <= confidence < 0.8 → CONTINUE mas marca para review extra
  - Adiciona flag: step_results[id].needs_extra_review = true
  - Injeta nota no proximo step: "Step anterior completou com confidence {score}: {notes}"
confidence < 0.5 → SOFT FAILURE
  - Trata como failure: tenta melhorar antes de avancar
  - Prompt: "Seu resultado tem baixa confianca ({score}). {notes}. Tente melhorar os pontos fracos."
  - Se melhora para >= 0.5 → continua
  - Se permanece < 0.5 apos retry → on_failure route ou abort
```

#### Subagent prompt instruction

Adicionar ao `subagent-step-prompt.md`:

```markdown
## OUTPUT FORMAT

Your response MUST include:
```yaml
step_output:
  status: completed|failed
  confidence: <0.0-1.0>  # How confident are you in this output? 1.0 = fully covers all requirements
  confidence_notes: "<brief explanation if confidence < 0.8>"
  outputs:
    <required outputs>
```
```

#### Backward compatibility

- `confidence` e opcional no schema
- Se ausente, engine assume `1.0` (full confidence) — zero impacto em workflows existentes
- Output parser extrai confidence se presente, ignora se ausente
- Funciona com todos workflows existentes sem modificacao
