# Story 15.3 — Supabase Auth: Google OAuth + Frontend Integration

## Story

**Como** dono da plataforma,
**Quero** autenticar via Google com um clique e ter todas as chamadas de API protegidas automaticamente,
**Para** que nenhum usuário não autorizado consuma LLM calls ou acesse resultados sem ser eu.

## Status

Done

## Context

### Problema

A API está protegida no backend (PR #23 implementou `middleware/auth.py`), mas o **frontend não envia nenhum token** — todas as chamadas chegam ao backend sem `Authorization` header e retornam 401. O sistema está quebrado em produção enquanto `AUTH_DISABLED` não estiver como `true` no Railway.

Adicionalmente, o fluxo email/password tem fricção desnecessária para um sistema single-user. Google OAuth resolve com 1 clique.

### Estado Atual do Código

**Backend — JÁ IMPLEMENTADO (PR #23):**
- `backend/middleware/auth.py`: `require_auth` dependency com `AUTH_DISABLED` flag e verificação JWT HS256
- `backend/main.py`: todos os 8 routers protegidos com `Depends(require_auth)`
- `backend/requirements.txt`: `PyJWT` já adicionado
- `backend/tests/conftest.py`: mock de auth já presente
- **Nenhuma mudança necessária** — controle de acesso delegado ao Supabase dashboard

**Frontend — NADA IMPLEMENTADO:**
- `frontend/src/router/index.ts`: guards por sessão (jobId), sem auth
- `frontend/src/stores/session.ts`: sem user state ou token
- `frontend/src/services/`: apenas `assetService.ts` com `fetch()` puro
- `frontend/src/pages/AnalyzingPage.vue`: usa `EventSource` para SSE — não suporta headers
- `frontend/src/pages/UploadPage.vue`: usa `XMLHttpRequest` e `fetch()` sem headers de auth
- `@supabase/supabase-js`: não instalado

### Solução

**Backend:** Nenhuma mudança — controle de acesso feito diretamente no Supabase dashboard (ver Technical Notes).

**Frontend (nova implementação):**
1. Instalar `@supabase/supabase-js`
2. Criar `lib/supabase.ts` — cliente Supabase singleton
3. Criar `services/authService.ts` — Google OAuth: `signInWithGoogle`, `signOut`, `getSession`, `onAuthStateChange`
4. Criar `services/apiFetch.ts` — wrapper `fetch()` que injeta `Authorization: Bearer {token}` automaticamente
5. Criar `stores/authStore.ts` — `user`, `token`, `isAuthenticated`, `initialize()`
6. Criar `pages/LoginPage.vue` — página com único botão "Entrar com Google"
7. Criar `pages/AuthCallback.vue` — handler do redirect OAuth (`/auth/callback`)
8. Editar `router/index.ts` — adicionar `/login` e `/auth/callback`, guard global de auth
9. Editar `pages/AnalyzingPage.vue` — substituir `EventSource` por `fetch + ReadableStream` (suporta headers); substituir `fetch()` por `apiFetch()`
10. Editar `pages/UploadPage.vue` — adicionar header auth no `XMLHttpRequest`; substituir `fetch()` por `apiFetch()`
11. Editar `services/assetService.ts` — substituir `fetch()` por `apiFetch()`
12. Editar `App.vue` — chamar `authStore.initialize()` no `onMounted`

### Scope — IN vs OUT

**IN SCOPE:**
- Google OAuth via Supabase (signInWithOAuth)
- Controle de acesso single-user via Supabase dashboard (signups desabilitados)
- `apiFetch()` wrapper com `Authorization: Bearer` header
- SSE via `fetch + ReadableStream` (sem token na URL)
- Router guard global → redirect `/login` se não autenticado
- `AuthCallback.vue` para processar redirect do Google
- Restauração de sessão no boot da aplicação (`getSession`)
- Mocks de auth nos testes existentes (backend já tem, frontend precisa)

**OUT OF SCOPE:**
- Email/password login
- Registration flow (usuários criados manualmente no Supabase dashboard)
- Password reset
- Role-based access control
- Per-user job isolation
- Refresh token automático (Supabase SDK gerencia)

## Technical Notes

- **Google OAuth callback URL:** Configurar `https://[projeto].vercel.app/auth/callback` no Supabase dashboard (Authentication → URL Configuration → Redirect URLs) e no Google Cloud Console
- **Supabase Google Provider:** Authentication → Providers → Google → habilitar; inserir Client ID e Secret do Google Cloud Console
- **Controle de acesso single-user (Supabase dashboard — zero código):**
  1. Faça login com seu Google uma vez (cria o usuário no Supabase)
  2. Authentication → Settings → "Enable sign ups" = **OFF**
  3. A partir daí, nenhum novo Google account consegue entrar — Supabase bloqueia na origem
- **fetch + ReadableStream para SSE:**
  ```typescript
  const res = await apiFetch(`/api/analyze/${jobId}/progress`)
  const reader = res.body!.getReader()
  const decoder = new TextDecoder()
  // loop: reader.read() → decoder.decode(chunk) → parse 'data:' lines
  ```
- **apiFetch dev local:** Quando `authStore.token` é null (dev sem auth), envia request sem header — funciona com `AUTH_DISABLED=true` no backend
