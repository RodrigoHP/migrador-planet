## Technical Notes

- No dedicated asset store exists in the codebase. Assets are managed via backend API (assetService.ts) and stored as data URIs in image node properties.
- The implementation walks the DocumentTree looking for `type: 'image'` nodes with `data:` URIs in their `src` property.
- On save: data URIs are parsed to binary, written to `assets/` folder, and metadata saved in `assetReferences`.
- On load: binary files from `assets/` are converted back to data URIs and injected into matching image nodes by `assetFilename`.
- Filename deduplication handles multiple images with the same name.
- Backward compatibility: ZIPs without assets/ or with only .gitkeep still load correctly.
