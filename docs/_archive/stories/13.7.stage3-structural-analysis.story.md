# Story 13.7 — Stage 3: Structural Analysis (NER + GPT-4o Vision + Hierarchy)

## Story
**Como** pipeline de migração,
**Quero** classificar cada bloco (label/dynamic), detectar regiões visuais, parear label-value, e construir árvore hierárquica,
**Para** que o Stage 4 tenha uma estrutura de documento completa para fazer field mapping.

## Status
Done

## Context

### Pipeline Atual
Stages 12-16 + 19-22: multi_example_analysis, stability_classification, variant_detection, semantic_analysis, visual_segmentation, visual_interpretation, vision_self_check. 7 stages separados, 2-4 chamadas Vision opcionais.

### Pipeline v2
1 stage com 4 sub-steps. Vision OBRIGATÓRIO (1 chamada combinada). spaCy NER para classificação. Label-value pairing incluído (movido do Stage 4). Hierarquia Builder usa 4 sinais.

## Acceptance Criteria

1. **3.1 Multi-Example Analysis:**
   - Consome `_raw_text_blocks` (texto real de todas as páginas)
   - 3 camadas de classificação: estatística (variação entre PDFs) → regex (CPF, CNPJ, datas, moeda, CEP, telefone) → spaCy NER (nomes, locais, organizações)
   - Output: `block_classifications` por `block_id` com `classification` (label/dynamic/likely_dynamic) + `confidence`

2. **3.2 Visual Analysis:**
   - GPT-4o Vision: 1 chamada combinada (segmentation + interpretation + self-check)
   - OBRIGATÓRIO — mas com fallback se operador escolher continuar sem (via handle_service_failure)
   - Output: `visual_analysis` com `regions[]`, `consistency_score`, `html_suggestion` por região
   - Inclui detecção: barcodes (format, area), charts (type), imagens

3. **3.3 Semantic Classification:**
   - Classificar blocos + parear label-value (movido do Stage 4.2)
   - Tipo semântico `likely_dynamic` para campos que regex/NER detecta como dinâmicos mas estatística não confirma
   - Threshold label-value "abaixo" = 3.5% da altura da página (proporcional, não 30pts fixo)
   - Usar font_size + cor + posição para scoring de pares

4. **3.4 Hierarchy Builder:**
   - 4 sinais em cascata: visual_regions (3.2) + drawn_elements (Stage 2) + grid_info (Stage 2) + gap proporcional
   - Label-value pairs como nós `field`
   - Seções condicionais como nós com `variant: "conditional"` + `present_in_pdfs: [...]`
   - Imagens, charts, barcodes incluídos na árvore
   - `source` em cada nó: "visual" | "threshold" | "drawn"

5. `document_trees` hierárquico por layout conforme contrato 3.3
6. `intelligence` com `block_classifications` por `block_id`
7. 3.1 e 3.2 executam em paralelo (async)
8. ~20s com Vision / ~5s sem
9. Dependência: `spacy` + `pt_core_news_lg` (~50MB)
