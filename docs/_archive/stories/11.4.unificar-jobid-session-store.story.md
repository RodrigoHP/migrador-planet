# Story 11.4 — Unificar jobId/job_id no session store

## Story
**Como** desenvolvedor do sistema,
**Quero** que o session store use uma única propriedade para o ID do job,
**Para** eliminar a ambiguidade e potenciais race conditions causados por dupla nomenclatura.

## Status
Done

## Context
O audit identificou que `session.ts` define **duas propriedades distintas** para o mesmo dado:

```typescript
// session.ts lines 11-12, 30-31
jobId: string | null      // camelCase — usado pela maioria dos componentes
job_id: string | null     // snake_case — duplicata, origem do backend
```

O `resetProcessing()` zera ambos. Vários componentes acessam um ou outro, criando inconsistência.

## Acceptance Criteria

1. **Propriedade única** — `session.ts` mantém apenas `jobId: string | null` (camelCase, padrão frontend).
2. **Sem `job_id`** — A propriedade `job_id` é removida do state, getters e actions do session store.
3. **Backend bridge** — Na chamada `POST /api/analyze`, o body ainda envia `{job_id: session.jobId}` (snake_case para o backend), sem mudar o contrato da API.
4. **TypeScript clean** — `tsc --noEmit` sem erros após a mudança.
5. **Testes atualizados** — `stores/__tests__/sessionStore.spec.ts` atualizado; sem referências a `job_id` nos testes.
6. **Sem regressão** — Todos os componentes que usavam `session.job_id` migrados para `session.jobId`.
