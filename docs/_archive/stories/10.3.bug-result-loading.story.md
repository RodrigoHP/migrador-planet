# Story 10.3: Bug — Resultado da análise não carrega no editor

## Status
Done

## Story
**As a** operador,
**I want** que após a análise completar, os dados do pipeline sejam carregados no editor automaticamente,
**so that** eu possa ver e editar o template gerado sem precisar de ações manuais.

## Acceptance Criteria
1. Após o SSE completar (todos os blocos verdes), `GET /api/analyze/{job_id}/result` é chamado automaticamente
2. O resultado é carregado em todos os stores via `session.loadFromPipelineResult()` antes de navegar para `/editor`
3. O editor exibe os dados da análise (template, campos, estrutura de documento) em vez de "Nenhum template carregado"
4. Se `document_structure` vier vazio ou sem `root` do backend, o `loadTree` não lança exceção (trata graciosamente)
5. Se `fetchAndLoadResult` falhar, o erro real é logado no console (`console.error(e)`) E a mensagem de erro exibida inclui o status HTTP ou a causa
6. `pytest` e `npm run build` e `vitest` passam sem erros

## Bugs Identificados

### Bug 1 — CRÍTICO: `fetchAndLoadResult` não chamado após SSE completar
- **Causa:** Após SSE emitir stage 28 completed, o código fazia `session.analysisCompleted = true` + `router.push('/editor')` SEM buscar o resultado do backend. O editor abria com todos os stores vazios.
- **Sintoma:** Editor mostra "Nenhum template carregado" / "Nenhum documento carregado" após análise completa
- **Arquivo:** `frontend/src/pages/AnalyzingPage.vue` — bloco de detecção de conclusão (linhas ~307-315)
- **Fix já implementado localmente:** Função `fetchAndLoadResult()` adicionada e chamada após SSE completar. Esta função faz `GET /api/analyze/{jobId}/result`, chama `session.loadFromPipelineResult(data.result)` e navega para `/editor`. O callback do SSE foi tornado `async`.

### Bug 2 — CRÍTICO: `loadFromPipelineResult` lança exceção quando `document_structure` está vazio
- **Causa:** O backend pode retornar `document_structure: {}` (dict vazio) se o Stage 7 não produziu resultado. `templateStore.loadTree({})` é chamado, e internamente `buildFlatMap(tree.root, map)` acessa `tree.root = undefined` → TypeError.
- **Sintoma:** "Erro ao carregar resultado da análise." mesmo com todos os stages verdes e `/result` retornando 200 OK
- **Arquivos:**
  - `frontend/src/stores/session.ts` — `loadFromPipelineResult()` linha ~78
  - `frontend/src/stores/templateStore.ts` — `loadTree()` linha ~109
- **Fix:** Em `loadTree`, verificar `if (!tree || !tree.root) return` antes de chamar `buildFlatMap`. Em `session.ts`, checar `if (result.document_structure && result.document_structure.root)` antes de chamar `templateStore.loadTree()`.

### Bug 5 — MÉDIO: Erro genérico sem stack/causa
- **Causa:** O `catch (e)` em `fetchAndLoadResult` não loga `e` — impossível debugar qual store ou operação lançou a exceção.
- **Sintoma:** Usuário vê "Erro ao carregar resultado da análise." sem nenhuma informação útil. Desenvolvedor não consegue diagnosticar sem breakpoint manual.
- **Arquivo:** `frontend/src/pages/AnalyzingPage.vue` — `fetchAndLoadResult()` catch block
- **Fix:** Adicionar `console.error('[AnalyzingPage] fetchAndLoadResult error:', e)` no catch. Enriquecer a mensagem de erro com o status HTTP quando disponível.
