# Story 13.4 — Stage 1: Layout Clustering (Pool Único + 3 Camadas)

## Story
**Como** pipeline de migração,
**Quero** agrupar páginas de layout idêntico via clustering tolerante com 3 camadas de defesa,
**Para** que os stages seguintes processem apenas páginas representativas (~6 em vez de 100).

## Status
InReview

## Context

### Pipeline Atual
`page_clustering.py` usa KMeans + Silhouette Score. Problemas:
- Sem tolerância a conteúdo variável (datas, nomes mudam entre páginas)
- Sem detecção de template incompatível
- Sem validação LLM
- Sem checkpoint humano

### Pipeline v2
Pool único (todas as páginas de todos os PDFs juntas). 3 camadas: prevenção (9 steps), detecção (4 steps), correção (2 steps). Homogeneity Check detecta templates misturados.

## Acceptance Criteria

1. **Camada 1 — Prevenção** (steps 1.1-1.9):
   - 1.1: Page Classification (text/scanned/blank) com `is_processable`. Blank/scanned marcadas mas não excluídas
   - 1.2: Block Extraction (`get_text("blocks")`) + preservar `_raw_text_blocks` (texto real pré-abstração)
   - 1.3: Normalization (rotation via `page.rotation`, coords normalizadas 0-1)
   - 1.4: Content Abstraction (DATE/NUMBER/TEXT_S/TEXT_L via regex)
   - 1.5: Region Filtering Adaptativo (excluir header/footer por PDF, threshold adaptativo)
   - 1.6: Tolerant Similarity Matrix (geometry 0.8 + density 0.2, block matching ±0.05)
   - 1.7: Graph Clustering (NetworkX, threshold 0.85)
   - 1.8: Consensus Check (hierarchical valida)
   - 1.9: Representative Selection (weighted degree — página mais conectada)

2. **Camada 2 — Detecção** (steps 1.10-1.13):
   - 1.10: Cluster Quality Score
   - 1.11: pHash Cross-Check (imagehash)
   - 1.12: Representative Validation
   - 1.13: LLM Cluster Validation (Gemini Flash ~$0.003)

3. **Camada 3 — Correção** (steps 1.14-1.15):
   - 1.14: Auto-correction (merge clusters similares, split clusters heterogêneos, isolate outliers)
   - 1.15: Confidence Score (quality + pHash + consensus + LLM)

4. **Validação** (step 1.16):
   - Homogeneity Check: `shared_ratio < 0.20` → `template_mismatch`
   - Se mismatch detectado: checkpoint humano com opção de remover PDF incompatível

5. **Checkpoint Humano** condicional:
   - Triggers: `low_confidence`, `auto_correction`, `template_mismatch`, `always_confirm`
   - Via SSE event + `handle_service_failure()` do orquestrador

6. `_raw_text_blocks` preservado no context (texto real de TODAS as páginas, pré-abstração)

7. Output conforme contrato 3.1: `clusters[]` com `cluster_id`, `pages[{pdf_id, page_index}]`, `representative_page`, `page_count`, `confidence`

8. `pdf_id` como `str` em todo o stage

9. Performance: ~5.5s para 100 páginas (sem LLM) / +$0.003 com LLM

### Content Abstraction Regex
```python
ABSTRACTION_PATTERNS = [
    (r'\d{2}/\d{2}/\d{4}', 'DATE'),
    (r'\d{4}-\d{2}-\d{2}', 'DATE'),       # ISO
    (r'R\$\s*[\d.,]+', 'NUMBER'),
    (r'\d+[.,]\d{2}', 'NUMBER'),
    (r'[A-Z][a-z]+ \d{4}', 'DATE'),        # "Março 2026"
    (r'\d{3}\.\d{3}\.\d{3}-\d{2}', 'CPF'),
    (r'\d{2}\.\d{3}\.\d{3}/\d{4}-\d{2}', 'CNPJ'),
]
# text len < 20 → TEXT_S, >= 20 → TEXT_L
```
