# Story 12.3 — Bug: Painel Campos sempre vazio — fieldNavItems não populado

## Story
**Como** usuário do editor,
**Quero** ver os campos identificados no painel lateral "Campos",
**Para** entender quais informações foram extraídas do PDF e seu status de mapeamento.

## Status
Done

## Context

### Problema
O painel "Campos" (aba na sidebar esquerda) mostra "nenhum campo identificado" mesmo quando o pipeline extraiu e mapeou campos do PDF.

### Root Cause

**`frontend/src/stores/mapping.ts`**

```typescript
// session.ts chama:
mappingStore.loadPipelineFields(result.field_mappings)
```

`loadPipelineFields()` popula `mappingStore.fields[]` (array interno), MAS `FieldNavigator.vue` lê `mappingStore.fieldNavItems[]` — que é um computed/getter diferente que NUNCA é populado corretamente.

**Evidência:**
```typescript
// FieldNavigator.vue linha ~108:
const fields = computed<FieldNavItem[]>(() => mappingStore.fieldNavItems)

// mapping.ts:
state: () => ({
  fields: [] as FieldMapping[],
  fieldNavItems: [] as FieldNavItem[],  // ← Nunca recebe dados
})

// loadPipelineFields() faz:
this.fields = entries.map(e => transformEntry(e))
// MAS NÃO faz:
// this.fieldNavItems = ...  ← ausente!
```

### Tipos Envolvidos

**Backend retorna (`result.field_mappings`):**
```typescript
interface FieldMappingEntry {
  pdf_text: string        // "VALE CORES COMERCIAL EIRELI"
  label_text: string      // "Pagador"
  xsd_field_path: string  // "boleto.pagador.nome"
  confidence: number      // 0.95
  is_ambiguous: boolean
  candidates: [{path, score}]
  page_number: number
  pdf_index: number
  bbox: [x0, y0, x1, y1]
  status: "mapped" | "unmapped" | "ambiguous"
}
```

**FieldNavigator precisa (`FieldNavItem`):**
```typescript
interface FieldNavItem {
  id: string           // Unique identifier (use xsd_field_path ou uuid)
  name: string         // label_text (display name)
  path: string         // xsd_field_path (XSD binding)
  status: "mapped" | "unmapped" | "ambiguous"
  value: string        // pdf_text (extracted value)
  confidence: number
  pageNum: number
  bbox: [number, number, number, number] | null
  isSelected: boolean
}
```

### Solução

**`frontend/src/stores/mapping.ts`**

1. Em `loadPipelineFields()`, após popular `this.fields`, popular também `this.fieldNavItems`:

```typescript
loadPipelineFields(entries: FieldMappingEntry[]) {
  this.fields = entries.map(e => transformEntry(e))

  // NOVO: Popula fieldNavItems
  this.fieldNavItems = entries.map((e, i) => ({
    id: e.xsd_field_path || `field-${i}`,
    name: e.label_text || e.pdf_text?.substring(0, 30) || `Campo ${i+1}`,
    path: e.xsd_field_path || '',
    status: e.status || (e.xsd_field_path ? 'mapped' : 'unmapped'),
    value: e.pdf_text || '',
    confidence: e.confidence || 0,
    pageNum: e.page_number ?? 0,
    bbox: e.bbox || null,
    isSelected: false,
  }))
}
```

2. **Agrupamento por status:** Adicionar getter `fieldNavItemsByStatus`:
```typescript
fieldNavItemsByStatus: computed(() => ({
  mapped: fieldNavItems.filter(f => f.status === 'mapped'),
  unmapped: fieldNavItems.filter(f => f.status === 'unmapped'),
  ambiguous: fieldNavItems.filter(f => f.status === 'ambiguous'),
}))
```

3. **Seleção:** Quando usuário clica em FieldNavItem, deve:
   - Definir `isSelected = true` no item
   - Chamar `inspectorStore.selectNodeByPath(item.path)`
   - Chamar `editorStore.highlightElement(item.id)`
   - Rolar canvas até o elemento
