# Story 23.2 — Validacao de Schema Obrigatoria no Registro

## Story
**Como** investigador na Fase 8,
**Quero** que o registro seja rejeitado se campos obrigatorios v6.0 estiverem ausentes,
**Para** que nenhuma investigacao futura tenha dados incompletos.

## Status
Done

## Context

### Problema
O schema em `investigations.yaml` declara campos v6.0 como comentarios mas nao ha enforcement. Investigadores podem registrar sem `confidence_score`, `dedup_status`, etc. e o sistema aceita silenciosamente.

### Design
Na Fase 8 do investigate.md, ANTES de registrar a investigacao:
1. Checklist de campos obrigatorios com lista explicita
2. Para cada campo ausente, instrucao de como preencher
3. Template pre-preenchido com todos os campos (null para opcionais, REQUIRED para obrigatorios)
4. NAO prosseguir para registro ate checklist completa

Campos obrigatorios v7.0:
- `id`, `date`, `trigger`, `severity`, `domain`, `tags` (basico)
- `confidence_score` (v6.0)
- `dedup_status` (v6.0)
- `sop_fast_track_used` (v6.0)
- `effectiveness` (v5.0)

Campos opcionais (null permitido):
- `related_rcas`, `effectiveness_reviewed_at`, `sop_generated`

## Acceptance Criteria
- [ ] Fase 8 do investigate.md inclui checklist de validacao pre-registro
- [ ] Lista explicita de campos obrigatorios vs opcionais
- [ ] Template pre-preenchido com TODOS campos v6.0
- [ ] Instrucao clara: nao registrar se obrigatorios faltando
- [ ] Workflow YAML atualizado com validation step

**IN:** Fase 8 do investigate.md, template de registro
