# Story 31.1 — Garantir css/style.css no ZIP de export

## Story
**Como** operador usando o editor de templates,
**Quero** que o ZIP exportado contenha o CSS completo em css/style.css,
**Para** que o template funcione visualmente ao ser aberto offline.

## Status
Done

## Acceptance Criteria

- [x] AC1: ZIP contém template/css/style.css com conteúdo não-vazio
- [x] AC2: CSS do codeStore (Monaco) é usado no ZIP, não regenerado
- [x] AC3: Backend legacy export.py inclui css/style.css no ZIP

## Scope

**IN:**
- Verificar e corrigir inclusão do CSS no ZIP (frontend e backend)

**OUT:**
- Refatorar geração de CSS no stage5

## Tasks

- [x] Task 1: Verificar useExport.ts — CSS já incluído via JSZip ✓
- [x] Task 2: Verificar export.py — CSS já incluído ✓
- [x] Task 3: Adicionar teste unitário confirmando CSS no ZIP

## Dev Notes
Análise do código existente mostra que AMBOS os caminhos já incluem css/style.css:
- Frontend (useExport.ts L119): `cssFolder.file('style.css', generated.css ?? '')`
- Backend (export.py L38): `zf.writestr("css/style.css", css)`

O gap real é que o conteúdo pode ser vazio se o pipeline não gerou CSS. A Story 31.4
vai resolver o envio do codeStore para o export, garantindo que o CSS editado prevaleça.
