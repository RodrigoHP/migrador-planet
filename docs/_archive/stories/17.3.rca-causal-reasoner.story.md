# Story 17.3 — Causal Reasoner Agent

## Story
**Como** investigador que precisa entender a cadeia causal de um bug,
**Quero** que o sistema construa um grafo causal multi-branch (nao linear) com logica AND/OR,
**Para** que causas multiplas e interacoes entre falhas sejam capturadas em vez de seguir apenas 1 cadeia linear como no 5 Whys.

## Status
Done

## Context

### Problema

O 5 Whys segue UMA cadeia linear: A→B→C→D→raiz. Mas muitos bugs reais tem:
- **Multi-causa (AND)**: A E B precisam ocorrer juntos para causar C
- **Alternativas (OR)**: A OU B podem causar C independentemente
- **Ciclos de feedback**: A causa B que agrava A
- **Causas latentes**: condicao existia ha meses, trigger recente ativou

O 5 Whys nao captura nenhum desses padroes. Tecnicas como FTA (Fault Tree Analysis) e H-SCM (Hierarchical Structural Causal Models) resolvem isso com grafos causais.

### Inspiracao

- **FTA (Fault Tree Analysis)**: Arvore logica AND/OR de falhas (Bell Labs, 1962)
- **H-SCM** (NDSS 2025): Modelos causais hierarquicos, >95% F1-score
- **CIRCA**: Grafos causais a partir de call graphs com testes de intervencao
- **Judea Pearl**: Inferencia causal formal — "A causou B" ≠ "A correlaciona com B"

### Design Proposto

**Causal Reasoner** — constroi grafo causal a partir dos dados do Archaeologist:

```
Input: top_suspects do Archaeologist + sintomas + stack trace

Construcao do grafo:
  1. EFFECT NODE (raiz do grafo)
     Bug observado: "TypeError em pipeline stage 5"

  2. INTERMEDIATE NODES
     Condicoes intermediarias derivadas do stack trace:
     - "drawn_elements retorna string em vez de dict"
     - "stage 3 nao valida tipo de retorno"
     - "config permite bypass de validacao"

  3. ROOT NODES (folhas)
     Causas raiz candidatas derivadas do Archaeologist:
     - "Commit abc123: refatorou extract sem type guard"
     - "Dependencia X atualizada com breaking change"
     - "Test coverage de stage 3 = 0%"

  4. LOGIC GATES
     AND: "drawn retorna string" AND "stage 5 nao tem guard" → TypeError
     OR: "commit abc123" OR "dep X update" → "drawn retorna string"

  5. EVIDENCE TAGS
     Cada node recebe nivel de evidencia:
     - Confirmed: reproduzido, comprovado por teste
     - Correlated: dados sugerem, nao comprovado
     - Hypothesized: teoria sem evidencia direta

Output:
  causal_graph:
    effect: "TypeError em pipeline stage 5"
    gates:
      - type: AND
        inputs: ["drawn_returns_string", "no_guard_stage5"]
        output: "effect"
      - type: OR
        inputs: ["commit_abc123", "dep_x_update"]
        output: "drawn_returns_string"
    nodes:
      - id: commit_abc123
        type: root_cause
        evidence: confirmed
        description: "Refatoracao removeu type guard"
      - id: dep_x_update
        type: root_cause
        evidence: hypothesized
        description: "Update de dep X pode ter mudado retorno"
      - id: no_guard_stage5
        type: contributing_factor
        evidence: confirmed
        description: "Stage 5 nao valida tipo de input"
      - id: no_test_stage3
        type: contributing_factor
        evidence: confirmed
        description: "Zero testes para stage 3"
    root_causes:
      primary: commit_abc123
      contributing: [no_guard_stage5, no_test_stage3]
    multi_branch: true
    whys_depth: 4
```

### Evolucao do 5 Whys → 5 Whys Multi-Branch

| 5 Whys Linear (v3.0) | Multi-Branch (v4.0) |
|----------------------|---------------------|
| Why? → Why? → Why? → Why? → Root | Why? → {Branch A, Branch B} → {AND/OR} → Roots |
| 1 cadeia | N cadeias paralelas |
| 1 root cause | N root causes + contributing factors |
| Sem logica formal | AND/OR gates |
| Sem evidencia | Evidence grading por node |

## Risks

- Construcao de grafo causal por LLM pode gerar estruturas incorretas (gates AND quando deveria ser OR, ou vice-versa). Mitigacao: Hypothesis Challenger (17.5) valida o grafo; override manual disponivel.
- Prompt engineering para grafos causais eh complexo e pode produzir resultados inconsistentes entre execucoes. Mitigacao: schema YAML rigido com validacao de estrutura.
- Grafos muito profundos (>7 niveis) podem diluir a qualidade da analise. Mitigacao: limite de profundidade configuravel (default 5).
