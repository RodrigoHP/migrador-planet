# Story 13.3 — Orquestrador v2: SSE Sub-Progress + Checkpoint de Falha

## Story
**Como** operador do sistema,
**Quero** um orquestrador que execute 5 stages com progresso granular e tratamento de falhas transparente,
**Para** que eu acompanhe cada sub-step e decida o que fazer quando algo falha.

## Status
Done

## Context

### Pipeline Atual
- `backend/routers/analyze.py` orquestra 28 stages via `PipelineDefinition` + `default_registry`
- SSE reporta stage-level (stage N de 28)
- Sem checkpoint de falha — se LLM/Vision falha, pipeline falha silenciosamente

### Pipeline v2
- 5 stages substanciais com sub-steps internos
- SSE reporta: stage (1-5) + sub-step + progress percentual
- `handle_service_failure()` — operador decide (retry/fallback/abort)
- Context dict passa entre stages (contratos 3.1→3.5)

## Acceptance Criteria

1. Novo `pipeline_orchestrator_v2.py` que executa 5 stages sequenciais
2. Aceita `pdf_documents[{id: str, path: str, name: str}]` + `xsd_path: str` como input
3. SSE reporta: `{stage, stage_name, status, progress_pct, sub_step, sub_progress_pct, summary}`
4. `handle_service_failure()` implementado conforme Seção 12 da arquitetura
5. Endpoint `POST /jobs/{job_id}/handle-failure` para resposta do operador
6. Context dict com `_storage`, `_current_stage`, `_current_stage_name` injetados
7. `pdf_id` como `str` desde a entrada (consistente em todo pipeline)
8. Feature flag `PIPELINE_VERSION` (v1 ou v2) — v1 usa orquestrador atual, v2 usa novo
9. Frontend adapta barra de progresso para 5 estágios + sub-barra
10. Timeout de 300s para checkpoint — default action = fallback
