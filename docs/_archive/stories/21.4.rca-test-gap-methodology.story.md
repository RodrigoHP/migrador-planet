# Story 21.4 — Test Gap Analysis Metodologia Step-by-Step

## Story
**Como** investigador executando `/investigate`,
**Quero** uma metodologia concreta para identificar quais testes deveriam ter detectado o bug e por que falharam,
**Para** que a Fase 5 produza recomendacoes de teste actionable em vez de observacoes genericas.

## Status
Done

## Context

### Problema
A Fase 5 v5.0 diz "buscar testes que passaram mas deveriam ter falhado" e lista 4 causas (cenario nao coberto, mock incorreto, assertion fraca, dados insuficientes), mas nao define COMO encontrar esses testes nem como classificar a causa. Na pratica, o investigador escreve "nenhum teste cobre X" sem analise profunda.

### Design
Metodologia em 4 steps:
1. **Mapear**: funcao/modulo afetado → testes existentes (grep por imports, describe blocks, test names)
2. **Classificar cada teste**: (a) Nao relacionado, (b) Relacionado e falhou (ok), (c) Relacionado e passou (gap!)
3. **Para cada gap**: diagnosticar causa usando decision tree:
   - Teste nao exercita o code path do bug? → **Cenario nao coberto**
   - Teste usa mock que mascara o bug? → **Mock incorreto**
   - Teste exercita o path mas assertion nao valida o aspecto afetado? → **Assertion fraca**
   - Teste exercita o path mas dados de entrada nao disparam o bug? → **Dados insuficientes**
4. **Gerar recomendacao**: para cada gap, descrever teste especifico que deveria ser adicionado/corrigido

## Acceptance Criteria
- [ ] Fase 5 do investigate.md inclui metodologia de 4 steps para test gap analysis
- [ ] Step 1 (mapear) define como encontrar testes relacionados (grep patterns)
- [ ] Step 2 (classificar) define categorias claras com exemplos
- [ ] Step 3 (diagnosticar) inclui decision tree para causa raiz do gap
- [ ] Step 4 (recomendar) gera especificacao de teste corretivo por gap
- [ ] Output da Fase 5 alimenta Fase 7 como input obrigatorio
- [ ] Template de relatorio (Fase 8) inclui tabela de test gaps com diagnostico

## Scope
**IN:** Fase 5 do investigate.md, template de relatorio na Fase 8
**OUT:** Geracao automatica de codigo de teste (responsabilidade do @dev na Fase 7)
