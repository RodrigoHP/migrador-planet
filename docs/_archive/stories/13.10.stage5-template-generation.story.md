# Story 13.10 — Stage 5: Template Generation (Tree-Driven HTML + CSS-from-Extraction)

## Story
**Como** pipeline de migração,
**Quero** gerar HTML hierárquico a partir de `document_trees` e CSS a partir dos dados visuais extraídos,
**Para** que o template gerado reproduza fontes, cores, bordas e layout do PDF original (não hardcoded).

## Status
Done

## Context

### Pipeline Atual — O Problema Central
`template_draft.py` (Stage 27) **hardcoda tudo**:
- Font: `Arial` (ignora fontes extraídas)
- Color: `#000000` (ignora cores do texto)
- Borders: `#ccc` (ignora drawn_elements)
- Header: `144px`, Footer: `96px` (ignora visual_regions)
- Tabelas: `is_table_cell → continue` (PULA tabelas)
- HTML: flat de `field_mappings` (ignora hierarquia)

### Pipeline v2
HTML de `document_trees` (hierárquico). CSS de dados extraídos (fonts, cores, drawn_elements, visual_regions). Coverage multidimensional. Overlay per-layout. VariationMatrix. PipelineResult completo.

## Acceptance Criteria

1. **5.1 Tree-Driven HTML:** walk `document_trees` → HTML hierárquico
   - `<table>` real com `<!-- ko foreach -->` para data rows
   - Condicionais com `<!-- ko if -->` para seções variant
   - Nós section → `<div class="section">`
   - Nós field → `<span>` com data-bind
   - Filtrado por `layout_type_id`

2. **5.2 CSS-from-Extraction:** CSS gerado de dados reais, NÃO hardcoded
   - Fonts de `text_blocks[].font_name` → `font-family` classes
   - Colors de `text_blocks[].color` → `.c-{hex}` classes
   - Borders de `drawn_elements[type=line]` → `border-{side}` no elemento mais próximo
   - Backgrounds de `drawn_elements[type=rect, fill_color]` → `background-color`
   - Zone heights de `visual_regions` → `.header`/`.footer` height
   - Text alignment de positional analysis → `text-align`
   - Page dimensions de `pages[].width/height` → `.page` width/height
   - `@font-face` declarations se fontes customizadas

3. **5.3 Coverage:** multidimensional — fields(60%) + tables(25%) + images(15%). Contagem real de nós na document_tree mapeados vs total

4. **5.4 Overlay Items:** per-layout (filtrado `layout_type_id`). Cada campo mapeado tem overlay com bbox

5. **5.5 VariationMatrix Assembly:** `variant` + `present_in_pdfs` → VariationMatrix + Detections automáticas

6. **5.6 PipelineResult Assembly:**
   - `trees_by_layout` (document_tree por layout)
   - `validation_result` (do Stage 4.7)
   - `intelligence` (do Stage 3.1)
   - `block_classifications_confirmed`
   - `multi_doc` (VariationMatrix + Detections)
   - Confidence normalizada 0-100 TODOS os fatores (G18)
   - `layout_types[]` pre-populado com documentTree/confidence/coverage (G19)
   - 8 campos novos no PipelineResult type (G20)
   - `template_draft` monolítico: `{html, css}` do layout ativo (G21)

7. **5.7 Persistência:** Supabase via StorageGateway com checkpoint (handle_service_failure se falha)

8. ~3s para ~6 representativas

### CSS-from-Extraction — Pseudocódigo
```python
def generate_css_from_extraction(enriched_docs, visual_analysis, drawn_elements):
    css_rules = []
    # 1. Fonts de text_blocks → font-family classes
    for font in unique_fonts:
        css_rules.append(f".f-{sanitize(font)} {{ font-family: {font}; }}")
    # 2. Colors de text_blocks[].color → .c-xxx classes
    for color in unique_colors:
        hex_color = f"#{color:06x}"
        css_rules.append(f".c-{color:06x} {{ color: {hex_color}; }}")
    # 3. Borders de drawn_elements[type=line]
    # 4. Backgrounds de drawn_elements[type=rect, fill_color]
    # 5. Zone heights de visual_regions
    # 6. Text alignment de positional analysis
    # 7. Page dimensions
    return "\n".join(css_rules)
```
