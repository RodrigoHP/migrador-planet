# Story 20.5 — Test Gap Analysis na Barrier Analysis

## Story
**Como** investigador analisando barreiras que falharam,
**Quero** que a Fase 5 identifique QUAIS testes especificos deveriam ter detectado o bug e por que falharam,
**Para** transformar a barrier analysis de checklist binario para analise causal de gaps no test suite.

## Status
Draft

## Context

### Problema
A Fase 5 (Barrier Analysis) analisa o Test Level como worked/failed/absent. Nao identifica qual teste especifico deveria ter falhado e por que nao falhou (cenario nao coberto? mock incorreto? assertion fraca?). Isso resulta em "adicionar teste" como recomendacao generica em vez de "corrigir teste X que deveria ter pego Y".

### Design
Na Fase 5, adicionar step no Test Level:
1. Buscar testes existentes que cobrem funcao/modulo afetado
2. Para cada teste que passou mas deveria ter falhado: analisar por que
3. Gerar lista de test gaps com recomendacao de fix
4. Passar test gaps como input para Fase 7

## Acceptance Criteria
- [ ] Fase 5 inclui step: buscar testes existentes que cobrem funcao/modulo afetado
- [ ] Para cada teste que passou quando deveria ter falhado: analisar por que (cenario nao coberto? mock incorreto? assertion fraca?)
- [ ] Output inclui lista de test gaps com recomendacao de fix para cada
- [ ] Fase 7 (Solucao) recebe test gaps como input obrigatorio para criar testes corretivos
- [ ] Documentacao atualizada no investigate.md (Fase 5)
- [ ] Template de relatorio (Fase 8) inclui secao "Test Gap Analysis"

## Scope
**IN:** investigate.md (Fase 5, Fase 7, Fase 8)
**OUT:** Automacao de test generation
