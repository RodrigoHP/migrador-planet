# Story 15.14 — Fix context["layout_types"]: Stage 5 gera templates vazios

## Story
**Como** operador que processa um PDF,
**Quero** que o Stage 5 receba a lista de layout types correta do Stage 3,
**Para** que o template gerado contenha HTML/CSS real com os dados do documento (não um template vazio).

## Status
Done

## Context

### Problema
`context["layout_types"]` é lida pelo Stage 5 na linha ~1353 de `stage5_template_generation.py`:

```python
layout_types = context.get("layout_types", [])  # SEMPRE retorna []
```

Porém **nenhum stage em todo o pipeline grava esta chave**. Evidência (grep retornou zero matches):

```bash
grep -r 'context\["layout_types"\]\s*=' backend/
# → nenhum resultado
```

O Stage 3 (`stage3_structural_analysis.py`) constrói `intelligence` — dicionário mapeando `cluster_id` → dados do cluster (classificações, visual analysis, etc.). A partir desse `intelligence`, deve-se derivar `layout_types` e gravá-lo em `context["layout_types"]` ao final do `run_stage3`.

### Consequência
Stage 5 recebe `layout_types = []` → gera HTML/CSS vazio → template inútil para o editor.

### Fix esperado
Ao final de `run_stage3()`, derivar `layout_types` a partir de `intelligence` e gravar em `context["layout_types"]`. Consultar Stage 5 para entender o contrato exato de cada item (quais campos são esperados ao iterar sobre `layout_types`).

## Acceptance Criteria

1. `grep -r 'context\["layout_types"\]' backend/services/stages/` retorna pelo menos 1 match de escrita (com `=`)
2. Stage 5 recebe lista não-vazia quando pipeline roda com PDF válido
3. Template gerado contém HTML/CSS com conteúdo real (não string vazia)
4. Teste unitário verifica que `context["layout_types"]` é populado após `run_stage3()`

## Scope

### IN
- Derivar `layout_types` a partir de `intelligence` no `run_stage3()`
- Gravar `context["layout_types"]` antes do retorno do stage 3
- Adicionar/atualizar teste unitário para a derivação

### OUT
- Não alterar o contrato de consumo do Stage 5
- Não refatorar `intelligence` ou `run_stage3` além do necessário
- Não alterar stages 1, 2, 4

## Dependencies
- Story 13.10 (Stage 5 implementado): context["layout_types"] já consumido

## Complexity
**M (3 pts)** — Requer leitura cuidadosa do Stage 5 para entender o contrato de `layout_types`, depois derivação simples a partir de dados existentes em `intelligence`.

## Business Value

## Risks

- Derivação incorreta gera templates com estrutura errada (silenciosamente)
