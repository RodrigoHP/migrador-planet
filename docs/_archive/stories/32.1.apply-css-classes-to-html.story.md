# Story 32.1 — Aplicar classes CSS (.c-{hex}, .border-N, .bg-N) nos elementos HTML

## Story
**Como** operador usando o editor de templates,
**Quero** que as cores de texto, bordas e backgrounds gerados pelo CSS sejam aplicados nos elementos HTML,
**Para** que o template renderizado tenha fidelidade visual proxima ao PDF original.

## Status
Done

## Acceptance Criteria

- [x] AC1: Elementos de texto (span label/value/standalone) recebem classe `.c-{hex}` correspondente a sua cor
- [x] AC2: A funcao `_step_5_2_css_from_extraction` retorna um dicionario de mapeamentos (color_map, border_rules, bg_rules) alem do CSS string
- [x] AC3: `run_stage5` executa a geracao de mapeamentos CSS antes de 5.1 para que 5.1 possa referencia-los
- [x] AC4: Testes existentes continuam passando (zero regressao)
- [x] AC5: Novos testes verificam que spans de texto possuem classe `.c-{hex}`

## Scope

**IN:**
- Adicionar classe `.c-{hex}` em text spans baseado no campo `color` do node
- Reestruturar `run_stage5` para gerar color_map antes do HTML
- Novos testes unitarios

**OUT:**
- Bbox overlap matching para border-N/bg-N (complexidade alta, ganho marginal — rects/lines ja renderizam inline)
- Alteracoes no frontend

## Tasks

- [x] Task 1: Extrair logica de color_map do _step_5_2 em funcao reutilizavel
- [x] Task 2: Em _tree_to_html e _generate_field_html, adicionar classe .c-{hex} nos spans de texto
- [x] Task 3: Ajustar run_stage5 para gerar color_map antes de 5.1
- [x] Task 4: Escrever testes unitarios

## Dev Notes
A abordagem mais simples e segura: o node ja tem campo `color` (int). Basta converter para hex e
adicionar `.c-{hex}` na classe do span. A classe CSS ja e gerada pelo 5.2. Nao precisa reordenar
os steps — a informacao de cor ja esta no node.
