# Story 42.9 — Frontend CI TypeScript Gate

## Status: Done

## Descricao

Verificar e garantir que o CI do frontend captura erros de TypeScript de forma estrita. O CI atual tem `npm run typecheck` mas não é confirmado se está em modo strict. Esta story garante que o gate é robusto e adiciona eslint ao CI se não existir.

## Acceptance Criteria

- [x] AC1: `frontend/tsconfig.json` tem `"strict": true` (ou equivalente: `strictNullChecks`, `noImplicitAny`, `strictFunctionTypes`)
- [x] AC2: `npm run typecheck` no CI falha em erros de tipo reais (verificado com teste de regressão intencional)
- [x] AC3: GitHub Actions job `frontend-quality` executa: `tsc --noEmit` + `eslint` + `prettier --check`
- [x] AC4: CI falha em PRs com erros TypeScript, lint ou formatação
- [x] AC5: Zero erros TypeScript com tipos alinhados de 42.8

## Escopo

### IN
- `frontend/tsconfig.json` — verificar/habilitar strict mode
- `.github/workflows/ci.yml` — job frontend-quality
- `frontend/package.json` — scripts `typecheck`, `lint`, `format:check`

### OUT
- Corrigir erros TypeScript existentes (coberto em 42.8)
- Alterar regras ESLint (já configurado na Story 40.4)

2h

## Dev Notes

### Verificação do tsconfig atual

```bash
# Verificar se strict está ativo
cat frontend/tsconfig.json | grep -E "strict|noImplicit|strictNull"
```

Se não tiver `"strict": true`, adicionar e verificar quantos erros aparecem. Se muitos, habilitar flags individualmente começando por `"strictNullChecks": true`.

### CI job frontend

```yaml
# .github/workflows/ci.yml
frontend-quality:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-node@v4
      with: { node-version: '20' }
    - run: cd frontend && npm ci
    - run: cd frontend && npm run typecheck      # vue-tsc --noEmit
    - run: cd frontend && npx eslint src/ --max-warnings 0
    - run: cd frontend && npx prettier --check src/
```
