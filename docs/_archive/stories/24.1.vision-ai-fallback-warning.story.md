# Story 24.1: Propagar warning quando Vision AI usa fallback

## Status
Done

## Story
**As a** usuário do sistema,
**I want** ser notificado quando a análise Visual AI não está disponível,
**so that** eu saiba que recebi análise em qualidade reduzida (~75%) e possa tomar ação (configurar API key).

## Contexto
**RCA:** `rca-2026-03-31-custo-api-zero`

Quando `OPENROUTER_API_KEY` não está configurada, `get_client()` lança `ValueError`
que é capturado silenciosamente em `stage3_structural_analysis.py:456`. O pipeline
continua em modo fallback (`_fallback_visual_analysis`) sem nenhuma notificação ao usuário.

O campo "CUSTO API" exibe `$0.00` — indistinguível de "Vision AI chamada gratuitamente".

**Impacto:** Usuário recebe análise estrutural de ~75% de qualidade sem saber.

**Causa raiz:** `except (ValueError, ImportError): vision_available = False` — nenhum
warning é adicionado ao context ou propagado via SSE.

## Acceptance Criteria

1. Quando `OPENROUTER_API_KEY` está ausente ou inválida ao inicializar Vision AI:
   - `context["_pipeline_warnings"]` contém entry: `"Vision AI desabilitado: <motivo>. Análise estrutural rodando em modo fallback (~75% qualidade)."`
2. Quando `VISION_AI_ENABLED=false` está definido:
   - `context["_pipeline_warnings"]` contém entry: `"Vision AI desabilitado via configuração (VISION_AI_ENABLED=false)."`
3. O `pipeline_orchestrator_v2.py` inclui no SSE summary do evento `pipeline_completed`:
   - `vision_ai_used: true` quando `_vision_api_calls > 0`
   - `vision_ai_used: false` quando `_vision_api_calls == 0`
4. Warnings do `_pipeline_warnings` são propagados no SSE summary (campo `warnings`)
5. Teste `test_stage3_vision_fallback_warning`: quando `OPENROUTER_API_KEY` ausente → warning em `context["_pipeline_warnings"]`
6. Teste `test_orchestrator_summary_vision_ai_used_flag`: `vision_ai_used=true/false` presente no summary
7. Nenhum teste existente regride

## Scope

**IN:**
- `backend/services/stages/stage3_structural_analysis.py` — adicionar warning ao context quando fallback
- `backend/services/pipeline_orchestrator_v2.py` — incluir `vision_ai_used` no SSE summary
- `backend/tests/` — adicionar testes para os dois cenários acima

**OUT:**
- Não alterar frontend nesta story (será feito em 24.2)
- Não alterar `openrouter_client.py`
- Não modificar lógica de fallback existente (apenas adicionar notificação)
