# Story 14.15 — Fix: ChartInspector retrocompatibilidade com InspectorColorPicker

## Story

**Como** usuário do editor visual,
**Quero** que o inspetor de gráficos continue funcionando após as mudanças do ColorPicker,
**Para** não ter regressões visuais ao editar cores de elementos de gráfico.

## Status

Done

## Context

Gap identificado no Epic 14 Gap Report (2026-03-28).

A story 14.6 expandiu `InspectorColorPicker` com opacity slider, cores recentes, e paleta do documento. O AC6 de 14.6 afirmava retrocompatibilidade com `ChartInspector.vue`, mas não há evidência de que o componente foi testado/verificado após as mudanças.

4. Testes do ChartInspector (se existirem) continuam passando

### Analysis

`ChartInspector.vue` EXISTS and USES `InspectorColorPicker` (line 84-88 in template, line 195 in script imports).

**Usage in ChartInspector:**
```html
<InspectorColorPicker
  label="Cor"
  :model-value="ds.color"
  @update:model-value="(v) => updateDatasetColor(idx, v)"
/>
```

Only `label` and `model-value` are passed — the original required props. All new props added in story 14.6 have safe defaults in `InspectorColorPicker`:
- `enableAlpha` — default `true` (opacity slider shown, harmless for color editing)
- `showPresets` — default `false` (transparent/inherit presets hidden, appropriate for dataset colors)
- `documentColors` — default `() => []` (no palette shown, no regression)

No incompatibilities found. No changes required.
