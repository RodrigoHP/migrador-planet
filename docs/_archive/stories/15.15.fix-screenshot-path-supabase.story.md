# Story 15.15 — Fix screenshot_path Supabase: Vision API = 0 em produção

## Story
**Como** operador que usa o sistema em produção (STORAGE_MODE=supabase),
**Quero** que o Stage 3 consiga ler as screenshots capturadas pelo Stage 2,
**Para** que a Vision API seja chamada e a análise visual dos documentos funcione corretamente.

## Status
Done

## Context

### Cascata de Falha (STORAGE_MODE=supabase)

```
Stage 2: _take_screenshot() → upload_screenshot() retorna path Supabase
         ex: "jobs/abc123/screenshots/page_0_0.png"
         ↓
Stage 3: load_image_as_base64(screenshot_path) → open(path, "rb")
         "jobs/abc123/screenshots/..." NÃO existe em disco
         → FileNotFoundError (capturado silenciosamente)
         → _fallback_visual_analysis() usado
         → _vision_api_calls NÃO incrementado
         ↓
Completion: _vision_api_calls = 0 → Vision = 0, api_cost = 0
```

### Comportamento com STORAGE_MODE=local
`upload_screenshot()` retorna path local real → `open()` funciona → Vision funciona. **O bug só se manifesta em produção.**

### Localização do problema
- **Escrita:** `backend/services/stages/stage2_deep_extraction.py` — função `_take_screenshot()` (linha ~472)
- **Leitura:** `backend/services/stages/stage3_structural_analysis.py` — função `_run_3_2()` (linha ~483)

### Opções de fix

**Opção A (preferida):** `_take_screenshot()` retorna sempre o path local, independente do storage mode. A PNG é salva localmente para processamento e também uploaded para o storage remoto. Dois paths distintos: um para upload (Supabase), um para processamento (local).

**Opção B:** Stage 3 `_run_3_2()` verifica se `screenshot_path` é arquivo local existente (`os.path.isfile(screenshot_path)`). Se não, faz download do storage antes de chamar `load_image_as_base64`.

**@dev deve avaliar e escolher a melhor opção.**

## Acceptance Criteria

1. Pipeline com `STORAGE_MODE=supabase` e PDF válido → `context["_vision_api_calls"] > 0` ao final do Stage 3
2. `screenshot_path` no `page_data` é um path de arquivo existente em disco durante a execução do Stage 3
3. `load_image_as_base64(screenshot_path)` não lança `FileNotFoundError`
4. Com `STORAGE_MODE=local`: comportamento preservado (sem regressão)
5. Teste unitário (ou de integração) verifica que Vision é chamada quando screenshot está disponível

## Scope

### IN
- Corrigir `_take_screenshot()` ou `_run_3_2()` para garantir path local disponível
- Preservar o upload para Supabase (não remover funcionalidade de armazenamento)
- Adicionar/atualizar teste que verifica o comportamento com storage remoto

### OUT
- Não alterar a interface do `StorageGateway` além do necessário
- Não refatorar o sistema de storage (Epic 13.1/13.2 já cobre o design)
- Não alterar stages 1, 4, 5

Sem este fix, Vision API = 0 em produção para todos os usuários. A análise visual de documentos — feature central do pipeline v2 — nunca funciona em produção.

## Risks

- Cleanup do arquivo local após Stage 3 pode ser necessário
- Fix incorreta pode quebrar STORAGE_MODE=local (testar ambos os modos)
