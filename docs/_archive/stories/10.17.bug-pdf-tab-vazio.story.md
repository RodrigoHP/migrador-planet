# Story 10.17: Bug — Aba PDF do editor mostra "Nenhum PDF disponível" após análise

## Status
Done

## Story
**As a** operador,
**I want** que a aba PDF do editor exiba os PDFs que foram enviados durante o upload,
**so that** seja possível visualizar os documentos de referência enquanto edita o template, em vez de ver "Nenhum PDF disponível para visualização."

## Acceptance Criteria
1. Após upload bem-sucedido (status HTTP 200-299), `session.uploadedPdfs` contém um `PdfFile` para cada PDF enviado, com `name`, `sizeKB` (arredondado), `pages: 0` e `bytes: ArrayBuffer`
2. No início de `startAnalysis()`, `session.uploadedPdfs` é resetado para `[]` antes de fazer o upload (garante que reenvios não acumulem entradas duplicadas)
3. A aba PDF do editor (`PDFReference.vue`) exibe os documentos disponíveis no seletor em vez da mensagem de estado vazio
4. Os testes existentes de `UploadPage.spec.ts` e `PDFReference.spec.ts` continuam passando sem alteração

## Dev Notes

### Causa raiz
`PDFReference.vue` lê `sessionStore.uploadedPdfs` para renderizar o seletor de documentos e o PDF. O array era inicializado como `[]` em `session.ts` e **nunca populado** durante o fluxo de upload.

Em `UploadPage.vue`, a função `startAnalysis` usa XHR com callback `xhr.onload` (não-async). Ao receber resposta 200, apenas salvava `session.jobId` e redirecionava para `/analyzing` — os bytes dos PDFs nunca eram salvos.

### Solução implementada
Dentro do `xhr.onload`, o código de sucesso foi extraído para uma função async `handleSuccess()` que:
1. Faz `await pdf.arrayBuffer()` para cada PDF em `pdfFiles.value`
2. Monta objetos `PdfFile` com `pages: 0` e `sizeKB: Math.round(pdf.size / 1024)`
3. Atribui o array resultante a `session.uploadedPdfs`
4. Depois chama `router.push('/analyzing')`

O reset `session.uploadedPdfs = []` foi adicionado no início de `startAnalysis()` antes do upload.

### Por que `pages: 0`
No momento do upload, o pipeline ainda não processou os PDFs — a contagem de páginas só estaria disponível após a análise completa. O valor `0` é um placeholder válido; `PDFReference.vue` usa `pdf.bytes` para carregar o documento via pdfjs, que determina o `totalPages` real em tempo de execução.
