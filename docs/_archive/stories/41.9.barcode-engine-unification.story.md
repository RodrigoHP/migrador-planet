# Story 41.9: Barcode Engine Unification — JsBarcode everywhere, remove python-barcode

## Status
Done

## Story
**As a** operador,
**I want** que barcodes sejam renderizados com JsBarcode tanto no Canvas do editor quanto no template exportado,
**so that** o preview WYSIWYG seja fiel ao output final, todos os formatos (incluindo MSI e CODABAR) funcionem em ambos os contextos, e o backend não dependa mais de python-barcode.

## Context

### Problema identificado (@architect + @aios-master, 2026-04-09)

Existem atualmente **duas engines de barcode incompatíveis**:

| Contexto | Engine | Limitação |
|----------|--------|-----------|
| Backend (stage5) | `python-barcode` | Não suporta MSI; gera SVG estático |
| Canvas iframe | SVG estático do backend | Preview ≠ export; MSI aparece como CODE128 |
| Export (base.js) | JsBarcode (CDN → local) | Script tag já injetado (Story 31.5), mas **calls JsBarcode no base.js ausentes** |

Gap crítico: `barcodeCodeGen.ts` não existe em produção. `BarcodeInspector.vue` exibe o código gerado apenas como texto de referência — os calls `JsBarcode("#id", ko.unwrap(data.campo), {...})` **nunca são incluídos no base.js exportado**.

### Solução

Unificar em JsBarcode como única engine:
1. **`barcodeCodeGen.ts`** — módulo análogo a `chartCodeGen.ts`
2. **`useExport.ts`** — incluir barcode JS section no base.js
3. **Stage5 (backend)** — gerar placeholder div, remover python-barcode
4. **Canvas iframe** — injetar JsBarcode inline para renderização WYSIWYG

## Acceptance Criteria

### barcodeCodeGen.ts (AC1-3)
- [x] AC1: `generateBarcodeHtmlSnippet(node)` → `<div id="{nodeId}" data-type="barcode" data-format="{format}" data-value="{previewValue}" style="..."></div>`
- [x] AC2: `generateBarcodeJsBlock(node)` → `JsBarcode("#{nodeId}", ko.unwrap(data.{campo}), { format: "{format}", lineColor: "#000", width: {w}, height: {h}, displayValue: {bool} })`
- [x] AC3: `buildBarcodeJsSection(nodes[])` → agrega todos os nós `type === 'barcode'` não-hidden em bloco comentado `// ── Barcodes ──`

### Export — base.js (AC4)
- [x] AC4: `useExport.ts` chama `buildBarcodeJsSection()` e inclui o resultado no base.js gerado, após o bloco de charts

### Canvas iframe WYSIWYG (AC5-7)
- [x] AC5: `useCanvasIframe.ts` — `buildPageSrcdoc()` detecta `data-type="barcode"` no HTML; se presente, lê `JsBarcode.all.min.js` de `/public/libs/` (fetch com cache em variável de módulo) e injeta como `<script>` inline no `<head>` do srcdoc
- [x] AC6: Script de inicialização injetado no srcdoc após `</body>`:
  ```js
  document.querySelectorAll('[data-type="barcode"]').forEach(function(el) {
    var format = el.dataset.format || 'CODE128'
    var value = el.dataset.value || '0000000000'
    el.innerHTML = ''
    try { JsBarcode(el, value, { format: format, displayValue: true }) } catch(e) {}
  })
  ```
- [x] AC7: Todos os formatos renderizam corretamente no Canvas: CODE128, CODE39, EAN13, EAN8, UPC, ITF, **MSI**, CODABAR

### Backend — stage5 (AC8-9)
- [x] AC8: `stage5_template_generation.py` — função `_barcode_to_svg_content()` substituída por stub que retorna `""`; barcode nodes geram `<div id="{nodeId}" data-type="barcode" data-format="{format}" data-value="{value}" style="position:absolute; left:{x}px; top:{y}px; width:{w}px; height:{h}px;"></div>` via `_barcode_placeholder_html()`
- [x] AC9: `python-barcode` removido de `requirements.txt` (não presente em pyproject.toml)

### Testes (AC10-11)

- [x] AC11: Testes unitários cobrem: `generateBarcodeHtmlSnippet`, `generateBarcodeJsBlock`, `buildBarcodeJsSection` (vazio, um nó, múltiplos nós, nó hidden excluído)

### Regressão (AC12)
- [x] AC12: `CANVAS_INTERACTION_SCRIPT` (click, drag, resize) continua funcionando normalmente após injeção do JsBarcode — injeção é feita no `<head>` (lib) e após o interaction script (init), sem interferência

### Decisões de implementação

1. **buildPageSrcdoc permanece síncrono**: A lib é pré-carregada via `getJsBarcodeLib()` no init do módulo (fire-and-forget). O cache `_jsBarcodeLib` fica disponível para as chamadas síncronas do template Vue sem mudar a assinatura.
2. **_barcode_to_svg_content mantido como stub**: Backward-compat para imports externos; sempre retorna `""`.
3. **html_tree.py calcula bbox_dict inline**: Evita passar parâmetros extras para `_barcode_placeholder_html`.
