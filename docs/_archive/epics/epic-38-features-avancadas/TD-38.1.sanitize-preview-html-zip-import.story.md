## Descricao

Ao importar um ZIP de componentes na Biblioteca, o campo `previewHtml` do JSON eh persistido diretamente no IndexedDB e renderizado via `v-html` sem regeneracao.
Um ZIP crafted poderia injetar HTML/JS malicioso (self-XSS).

## Problema Tecnico

- **Arquivo:** `frontend/src/organisms/BibliotecasModal.vue` (linhas 349-372)
- O handler `handleImportComponents` faz `JSON.parse(content) as BibliotecaComponent` e persiste `comp` diretamente via `db.put('components', comp)`
- O campo `comp.previewHtml` vem do JSON do ZIP sem regeneracao
- `BibliotecaComponentList.vue:14` renderiza via `v-html="item.previewHtml"`

## Fix Proposto

No loop de import do ZIP, apos o parse do JSON, regenerar `previewHtml` chamando `generatePreviewHtml()` com o node tree deserializado:

```typescript
import { generatePreviewHtml, deserializeNode } from '@/composables/useBibliotecas'

// Dentro do loop de import:
const node = deserializeNode(JSON.parse(comp.data))
comp.previewHtml = generatePreviewHtml(node)
```

## Criterios de Aceitacao

- [x] AC1: Import ZIP regenera `previewHtml` via `generatePreviewHtml()` em vez de usar valor do arquivo
- [x] AC2: Campo `previewHtml` original do JSON importado eh descartado
- [x] AC3: Teste unitario cobre cenario de ZIP com previewHtml malicioso
- [x] AC4: Componentes importados exibem preview correto apos regeneracao

## Escopo

**IN:** Import ZIP no BibliotecasModal.vue
**OUT:** Export ZIP, salvamento manual de componentes (ja usa generatePreviewHtml)
